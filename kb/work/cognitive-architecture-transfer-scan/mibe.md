## Provisional ontology

No Mibe-specific ontology is safe to assert from memory.

The scan failure exposes a useful meta-ontology for comparative work:

- **Listed item:** a name inherited from a survey or comparison.
- **Identity evidence:** enough bibliographic or project information to know which system the name denotes.
- **Source confidence:** confidence that the description is faithful to primary material.
- **Transfer conjecture:** a potentially useful idea, which may or may not remain attributable after grounding.
- **Abstention:** an explicit refusal to fill a comparison cell without evidence.
- **Grounding debt:** the unresolved checks required before comparison or attribution.

## Transfer candidates

- **`MIBE-1` — allow unknown as a first-class survey value.** A blank or abstention is more informative than a plausible generic description that contaminates later synthesis.
- **`MIBE-2` — separate identity grounding from theory grounding.** Before reading mechanisms, confirm that names, versions, authors, and successor projects refer to the intended architecture.
- **`MIBE-3` — preserve provenance per comparison cell.** Broad matrices should be able to show whether a claim came from a primary paper, project documentation, a secondary survey, or model memory.
- **`MIBE-4` — prioritize grounding by decision value.** Obscurity alone does not justify research effort. Investigate Mibe only if a credible hint suggests a mechanism absent from better-documented architectures or if completeness becomes the explicit goal.

These candidates generalize the workshop's epistemic boundary: early conjecture generation is useful only when uncertainty remains visible enough to prevent accidental promotion.

## Method worth borrowing

The method here is an **abstention audit**. Hide item names and ask whether each row's claims contain system-specific mechanisms or generic cognitive-architecture prose. Rows that could describe almost any system should be marked unresolved and queued for identity checks rather than retained as summaries.

## Non-transfer and failure modes

- This document contains no insight attributable to Mibe.
- Treating absence of recall as evidence of insignificance would confuse model familiarity with historical value.
- Completing every row can become cargo-cult thoroughness when the workshop exists to find useful transfers, not to reproduce an encyclopedia.
- Later grounding may show that "Mibe" is misspelled, renamed, inaccessible, or not comparable at all.

2. What problem and level of analysis does the architecture address?
3. What state types and processing cycle distinguish it from its contemporaries?
4. Is there any mechanism that changes a live Commonplace design question enough to warrant deeper reading?
