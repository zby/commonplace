Passes, by name. Run passes with a depth in increasing depth; a pass with depth `any` may run at any point.

- `abstractions` (effort: judgment; depth: 3): Use when an artifact uses a coined or registered abstraction (retained adaptation) where the ordinary word (learning) would carry the sentence, or mixes the abstraction and the ordinary word for one thing. The operator decides its proposals before any is applied.
- `audit-a-prior-pass` (effort: simple; depth: any): Use when an automated improvement pass has weakened or cut a passage and the operator wants to know whether the review finding justified it before restoring anything.
- `narrow-overclaims` (effort: judgment; depth: 2): Use when a sentence about other systems, other people, or the artifact's own method asserts more than the available evidence shows, or when the operator says a sentence is too strong. This workflow runs it only when `must-keep` is not empty.
- `opening-and-title` (effort: judgment; depth: 6): Use when an artifact's TL;DR uses terms it never defines, ends on jargon, or its title carries a metaphor or bare term that reads wrongly before the body explains it.
- `place-external-systems` (effort: simple; depth: any): Use when an artifact should position named external systems against its own criteria or obligations, so readers can locate their systems on it, and the placements must survive the systems' authors reading them.
- `plain-wording` (effort: simple; depth: 5): Use when an artifact's wording should be simplified: decorative figures made literal, unusual words made common, and redundant exclusions cut, without stripping the metaphors that carry the argument or the terms the KB registers. The operator decides its proposals before any is applied.
- `readability-and-flow` (effort: judgment; depth: 4): Use when claims are settled but sections repeat, interrupt each other, or bury the point; sentences need a second reading; or repeated openings hide the distinction a reader scans a list or table for.
- `repair-claim-title` (effort: judgment; depth: the depth of its finding's criterion): Repair a claim-strength finding when the note already supports a more informative title without any body edits. Each entry names one review result file as `finding` and takes the depth of that result's criterion; list one entry per finding.
- `split-out-a-treatment` (effort: simple; depth: 1): Use when a discussion has produced an argument larger than the artifact needs, and the operator wants the artifact kept simple while the full treatment is retained where later editing passes will not load it. This workflow does not run it: it is left for the interactive path.
- `fix-strategy-taxonomy` (effort: judgment; depth: the depth of its finding's criterion): Use to fix one review finding on one note by the named strategy whose pattern it matches; also the codebook of named fix strategies. Each entry names one review result file as `finding` and takes the depth of that result's criterion; list one entry per finding.
