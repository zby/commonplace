# Review of the implementation plan, 2026-08-24

External review from the workshops that produced this one's input —
[source-grounding](../source-grounding/README.md) and
[literature-disposition](../literature-disposition/README.md). Read in full:
`plan.md`, `implementation-surface.md`, `cleanup-plan.md`, `README.md`, and the
caller-boundary and decision sections of both drafts.

These are review findings, not decisions. The workshop owns its own calls; where
this review disagrees it says so and gives the evidence.

**Verdict: the plan is sound and further along than the stage suggests.** The
concerns below are about stated scope and one missing state, not about the
architecture.

## What is load-bearing and should not be traded away

Named because each is the kind of property that gets quietly dropped under
schedule pressure, and each is doing real work here.

1. **The context-cost boundary is designed for rather than hoped for.** An
   untriggered write loads no ingest, no snapshot, and no grounding instruction —
   only a short local check that runs after drafting. This is the property that
   decides whether the mechanism is adoptable at all. Any later change that moves
   source reading onto the common write path forfeits it.
2. **The re-ingestion hazard was caught.** `cp-skill-ingest` always dispatches
   `mode: create` and replaces the output, so without intervention a same-checksum
   re-ingest would silently erase accumulated claims. Capturing `preserved_claims`
   with its digest before mutation, passing both to every attempt, verifying after
   handoff, and failing closed on a changed checksum is the right shape. This is
   the failure that would have destroyed the mechanism without anyone noticing.
3. **Both verification hops stay distinct**, including the explicit statement
   that the second "does not imply that an absent source was reverified." That is
   exactly the honesty the retention analysis required — the guarantee available
   under ignored snapshots is attested-once with a recomputation path, not
   standing enforcement, and the plan does not overstate it.
4. **Worked-case-first ordering.** Steps 1 and 2 produce a real `Claims` section
   and a held-out case *before* the ADR is finished. Reversing this would fix a
   contract shape from the armchair.

## Concerns

### 1. The trigger cannot fire on the defect that created the debt

The trigger requires a claim "tied to a named external source." The defect this
workshop exists to answer is the opposite case:
`agents-navigate-by-deciding-what-to-read-next` states information scent in near
canonical form and **names nobody**. A writer reproducing that note today would
not trip the check, because there is no named source to be ungrounded against.

So the invariant prevents *ungrounded use of a named source*, not *unattributed
use of an existing tradition*. That is a real and defensible V1 scope, but the
plan currently carries it only in "upgrade triggers," as a broader-detector
question. **State it in the ADR's consequences.** Otherwise the ADR reads as
closing a hole it does not close, and a later reader will not know to keep
looking.

The complement is a write-time check asking whether the literature already
settles the claim — measured absent across the whole corpus, since every novelty
and economy test is intra-KB. Correctly out of V1 scope; worth naming as the
thing that finishes the job.

### 2. Fail-closed with only two exits

From the grounding worker's caller boundary: "The caller may save the target only
after every dependency it **retains** is `SUPPORTED`," with `CONTRADICTS` and
`BLOCKED` prohibiting the candidate claim, and missing source bytes blocking
rather than being filled from recall.

That leaves an author whose source is genuinely unreachable — paywalled, dead
URL, worker undispatchable — with two options: delete the claim, or do not save.
Both discard real work, and the second is worse because it blocks an authoring
path for a reason unrelated to the rest of the note.

There is an honest third state already in the KB's vocabulary: ADR 042 and ADR
046's grounding-layer markers, `verbatim` / `paraphrase layer` / `second-hand`.
Saving with the dependency visibly marked unresolved would preserve the work,
assert nothing false, and leave a greppable trace the cleanup channel can find.

Worth deciding **before** the gate is wired rather than after an author hits it,
because the failure lands on the ordinary write path where the cost of a wrong
default is highest.

### 3. A small ownership seam

`cleanup-plan.md`'s debt classes cover source-relative defects well — class 3
("the local claim is broader or more confident than the source") and class 4
("the source contradicts the local claim") are exactly right, and were arrived at
independently of the disposition workshop's parallel finding.

What no class covers is a claim that is defective **regardless of any
literature**: an unscoped generalization, a category error, or a claim that is
analytic where a dependent treats it as empirical. Three such are already
recorded in
[three-channels.md](../literature-disposition/three-channels.md) Channel 2, two
of them with an ADR resting on them. They are not this workshop's to fix, but
neither workshop's stated governing question currently claims them — the
disposition workshop asks retire/thin/rewrite/leave, which is disposition rather
than repair. One line naming the owner would close it.

### 4. Two calls to make deliberately rather than by default

**The empty-section cost.** 284 ingests each gain a permanently-empty `## Claims`
section, most of which will never be populated. This is defensible — the empty
state is the signal, and it matches enforced-or-omitted mark semantics used
elsewhere in the KB — and it gives the pull procedure a fixed place to write. But
make it an explicit decision with the reason recorded, because the alternative
(template-only for new ingests, schema check phased in) is not obviously worse
and will be raised later by someone who was not here.

**ADR length.** The draft runs 307 lines. Its own promotion gate is right —
promote only after it describes shipped behavior — but at that size it risks
becoming the design document rather than the decision record, which makes it hard
to supersede cleanly. Worth a trim pass at promotion, moving option-space
material into whatever survives this workshop.

## One corroboration worth recording

`cleanup-plan.md` states "A model suggestion is a reading assignment, not
evidence" and separates deterministic provenance signals from model-suggested
literature matches. The disposition workshop's
[claim inventory](../literature-disposition/claim-inventory.md) independently
reached the same rule and applies it to every tradition placement it records.
Two artifacts derived from different directions converging on that discipline is
a signal it is the right one, and it should survive into whatever gets promoted.
