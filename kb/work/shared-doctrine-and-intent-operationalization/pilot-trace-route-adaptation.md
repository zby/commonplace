against a real target. It follows the same commission through the committed
control and the doctrine-compressed candidate and asks whether every actor can
select a different means without changing the contribution, evidence, or

The scenario fixes one artifact and one contribution: explain a causal
dependency from named, authorized source paths. It excludes sibling mutation.
The parent proposes a chronological evidence table but labels it advisory.
Source-only reading reveals that chronology would merge two causally distinct
stages. A dependency ledger or scoped prose can preserve the distinction from
the same evidence. The route change needs no new source, target access,
mutation, or authority.

The scenario does not specify new versus edit mode. The commission must resolve
that before work starts. The trace therefore keeps the shared path and states
the second reveal as `original.md` for edit mode or an explicit confirmation of
new mode. The route-adaptation result is the same in either branch because it
is discovered before the incumbent reveal and is not derived from the target.

## Classification before execution

| Item | Class | Consequence |
|---|---|---|
| One note explaining the causal dependency | Fixed contribution | A representation that loses either causal stage fails acceptance even if it looks complete. |
| Authorized source paths and their roles | Fixed evidence boundary | The reconstructor may reorganize their contents but may not add a source or treat the incumbent as evidence. |
| No sibling change | Fixed mutation and coordination boundary | Authoring and promotion may touch the target and workflow-owned run state only; optional lineage or other library changes require separate authority and are absent here. |
| Chronological evidence table, expressly advisory | Deliberately delegated means | It is a proposal, not a constraint. Execution evidence may reject it. |
| Dependency ledger versus scoped prose | Deliberately delegated means; harmless variation once both meet acceptance | Either may be selected from the source structure. Headings, row order inside a dependency group, and phrasing are irrelevant if the causal relation, basis, scope, and qualifiers remain recoverable. |
| Chronology that collapses two causal stages | Outside acceptance | It is not a permitted “irrelevant variation.” The worker must change the means or return. |
| A binding chronological table that cannot preserve the contribution | Gap between commitment and achievable result | No worker owns the commitment. Control returns to the parent and then the user. |

The advisory adaptation changes representation only. It does not change what
counts as evidence, the source set, any source-side proposition, target or
sibling access, mutation rights, or the actor that owns acceptance. Freezing a
reconstruction changes workflow state, not evidence or authority.

## Binding-route counterfactual

The counterfactual changes one commission fact: the chronological table is an
explicit user-owned external commitment, not an advisory parent proposal.

### Baseline counterfactual

1. **Commission.** The parent records the table under binding constraints and
   external commitments. It does not label it advisory. The causal dependency,
   authorized source set, and no-sibling boundary remain fixed.
2. **Reconstruction.** The reconstructor discovers that chronology collapses
   two causally distinct stages. Its structural discretion exists only inside
   the assigned result and evidence boundary. Replacing the table would violate
   that boundary; keeping it would fail the contribution. It returns the exact
   conflict and a resume point rather than writing a dependency ledger as if
   authorized.
3. **Parent control.** The parent does not verify or freeze the reconstruction.
   Because the baseline directly fixes the authority boundary and leaves
   integration/recovery with the parent, the parent asks the user whether to
   relax the format, narrow/change the contribution, or stop.
4. **Convergence.** If the user relaxes the commitment, the governing brief has
   changed and reconstruction restarts before either author reveal. If the user
   retains both incompatible requirements, the run stays blocked and retained.
   No author, reviewer, or promotion step runs.

The finding changes neither evidence nor authority. A later user decision may
change the binding constraint, but that is an explicit new authority event,
not worker adaptation. If a worker nevertheless changed the format and the
error survived parent verification, the exact-byte reviewer must block the
intent/authority mismatch and route it upstream; review is defense in depth,
not the intended first detection point.

### Candidate counterfactual on Codex

The state sequence is the same, with two candidate-specific sources of
control:

- the candidate directly says the parent alone owns user-owned decisions; and
- verified ambient root doctrine classifies the incompatible, unowned choice
  as a gap and requires return or escalation.

The reconstructor therefore returns to the parent; the parent returns the
format/contribution decision to the user. It does not silently reinterpret an
external commitment as an advisory means. Relaxation restarts reconstruction;
insistence stops the run. Evidence and authority remain unchanged until the
user makes a new decision.

## Consumption-path assessment

### Verified Codex root-doctrine path

The workshop's step-0 evidence establishes that a fresh Codex worker with
parent-turn inheritance disabled receives root `AGENTS.md` as ambient
repository instruction. The same is true of Codex review workers because the
review CLI does not launch a separate model runtime. On this path:

- “parent retains scheduling, integration, and recovery” is genuinely
  inherited with binding force;
- “nested delegation requires explicit authorization; silence means no” is
  genuinely inherited;
- the candidate stage packet plus ambient root doctrine is complete without
  the parent conversation;
- exact collection/type contracts are still passed because the skill requires
  them; they are not assumed from a link chase; and
- the candidate's advisory adaptation and binding return both pass.

The candidate's remaining explicit controls are correctly task-specific. Live
mutation, user-owned decisions, evidence isolation, role inputs and outputs,
accepted digests, drift, repair, validation, and rollback are not regenerated
from generic doctrine.

### Canonical skill path with unverified root delivery

The canonical skill is projected into both `.agents/skills/` and
`.claude/skills/`. This checkout's `CLAUDE.md` points to `AGENTS.md`, but the
workshop records only documented Claude Code discovery: its direct fresh-worker
probe ended before proving binding delivery. Under the workshop's own decision
rule, that path must be treated as having no inherited Commonplace doctrine
beyond what its packet explicitly carries.

On that path the candidate cannot take credit for the two removed control
classes:

1. who retains scheduling, integration, and recovery across worker returns;
2. whether a worker may create nested delegates when its packet is silent.

The stage-specific ownership clauses still strongly bound the ordinary trace,
and the explicit parent ownership of user decisions makes the binding
counterfactual likely to return correctly. That plausible result is not enough:
the candidate says its commissions are deltas from a baseline whose delivery
has not been established. A worker could produce a good-looking reconstruction
while violating topology or recovery control. Behavioral fidelity is judged on
the actual consumption path, not from the final artifact alone.

The baseline is safer on this path because its skill directly retains the
parent-control and no-delegation rules for the executing parent to carry into
the commissions. The baseline still has to be executed correctly; its
advantage is that the needed rules exist in the invoked canonical skill rather
than only in an unverified ambient surface.

The candidate should either remain scoped to verified Codex workers or add a
path-sensitive fallback such as: when root-doctrine delivery to a fresh worker
is unverified, frontload the parent scheduling/integration/recovery and
no-nested-delegation defaults into that worker's packet, or stop before
reconstruction. A successful Claude probe would also remove this blocker, but
the live canonical skill cannot assume that future result now.

paragraph. Both ordinary traces have nine states through promotion preflight:
commission/brief, reconstruction, reconstruction verification, first author

## Final judgment

The advisory route is correctly adaptable in both texts: the worker changes a
means, preserves contribution/evidence/isolation, and changes no authority. The
binding route correctly returns under the baseline and under the candidate's
verified Codex consumption path. The candidate does not yet preserve the full
control boundary on every canonical path through which it is available.

**Baseline: PASS.**

**Candidate: FAIL overall (PASS on the verified Codex path; FAIL the canonical
consumption-path completeness test while Claude root delivery remains
unverified).**

**Recommendation: REVISE.** Keep the doctrine-delta framing, but add an
explicit unverified-path fallback for parent scheduling/integration/recovery
and no nested delegation, or retain the baseline wording until root delivery is
proved for every supported canonical worker path.
