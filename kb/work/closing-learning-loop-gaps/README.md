# Closing the learning-loop gaps

Posed by the operator on 2026-11-28, following the reconciliation of the oracle-amplification notes into [What gaps remain in our learning loop?](../../theory/questions/what-gaps-remain-in-our-learning-loop.md).

## Goal and starting premise

Commonplace's initial assumption was that the remaining automation gaps in its fixed-weight [selection-based learning](../../theory/definitions/selection-based-learning.md) loop could be closed by turning weak LLM oracles into strong ones via amplification, with current LLMs supplying weak oracles across all gaps. Our own oracle-amplification and loop-architecture notes narrow that premise: amplification strengthens local filtering over reached candidates under a settled check, but cannot substitute for search, supply missing evidence, resolve contested trade-offs, localize causal blame in mixed prose/code, or detect when a check measures the wrong property; meanwhile stagnant per-instance discrimination, shared content biases, and field consensus priors constrain where LLMs even clear `TPR > FPR` with decorrelated errors.

This workshop turns the resulting gap list into concrete, falsifiable empirical probes and lightweight instrumentation on Commonplace's own work, so we can establish—rather than guess—which internal update decisions transfer to computation, which require external/causal signals or structural search, and where costs outweigh gains.

## Evaluation and authority boundaries

- **Commissioning boundary:** This framing authorizes drafting concrete track protocols, inspecting existing repository history and logs (`kb/workflow-state/`, git history, retained reports) to identify candidate cases, and preparing frozen fixtures. **Paid model runs, batch sweeps, and edits to live library instructions, review gates, or validators require explicit operator go-ahead per track.** Listing a track below does not commission its execution.
- **No self-grading:** Evaluate judges, candidate updates, and revised checks against unseen/fresh work or frozen ground-truth replay sets, never on a judge's own prose rationale. Keep coverage separate from verdicts and verdicts separate from adopted changes.
- **Mandatory bias and cost controls:** Any pairwise comparison must run in both presentation orders (given position bias already measured in [replaying-operator-rulings](../replaying-operator-rulings/README.md) and Mazur's benchmark). Report failure dimensions separately (for example, Arm 1 / Arm 2 / Arm 3, or operative revision / downstream gain / selectivity) and log compute and human-supervision costs alongside outcomes.
- **Deliberately left open:** Track ordering, exact case batches, base models, and budgets are left to execution and operator selection so live evidence and repo-history inspection decide which probe is cheapest and sharpest next. Re-check priorities after the first completed track rather than locking a multi-track sequence upfront.

## Candidate tracks

Tracks 1 and 2 are the lowest-effort starting candidates because their experimental designs are already specified in the draft articles; the operator chooses which track to commission first.

| Track | Gaps targeted | Core test / mechanism | What counts against / return to decision |
|---|---|---|---|
| **1. Single-call `TPR − FPR`, error correlation, and 3-arm inquiry test** | Weak-oracle qualification; active inquiry & open verdicts | On 15–25 real Commonplace decisions with historical ground truth (e.g., log-to-note promotions, routing fixes, or review-driven revisions), run the [three-arm paired test](../../articles/can-an-llm-judge-which-changes-are-worth-making.md#testing-the-bet-without-asking-the-judge-to-grade-itself) with swapped order: (1) decisive fact in packet, measuring raw `TPR − FPR` and cross-prompt/model error correlation; (2) decisive fact discoverable via tools under a strict budget; (3) incomplete records or priority conflict where **Open** is warranted. | If Arm 1 fails `TPR > FPR` or errors stay correlated across prompts/models, drop voting amplification for that decision class. If Arm 1 passes while Arm 2 or 3 fails, shift effort to active-inquiry tooling and abstention rather than judge repetition. |
| **2. Selective double-loop criterion revision on a frozen replay suite** | Selective criterion revision; targeted credit assignment | Execute the [proposed routing-check experiment](../../articles/testing-autonomous-selection-based-learning.md#a-first-experiment-repairing-a-misleading-routing-check): build a frozen replay set of 20–30 unseen past notes/proposals with known routing or gate outcomes, pair 2–3 genuinely misleading checks with 2–3 sound checks accompanied by unrelated failure traces, and report *operative revision*, *downstream gain*, and *selectivity* separately. | If revised checks over-edit sound checks (poor selectivity) or regress sound proposals, diagnose whether the failure is trace localization, over-eager rewriting, or missing negative examples before expanding double-loop automation. |
| **3. Orthogonal and metamorphic checks vs. same-distribution voting** | Oracle amplification limits; whole-loop net gain | Instead of N-sample majority vote over one prompt/packet, compare cheap orthogonal pairings on Track 1 cases: evidence-ablation metamorphic checks (remove one load-bearing fact/quote and check whether the verdict weakens), swapped-order pairwise checks, stance-filtered review kept outside the judge prompt, and bounded reversible trials with scheduled outcome checks. | Drop any check pair whose added compute does not beat the single-call or fixed-gate baseline on `TPR − FPR` or net downstream gain. |
| **4. Active-context load manifests and a bounded withholding sweep** | Accretion plateau; credit assignment in mixed prose/code | Capture which `COLLECTION.md`, skills, review gates, and linked notes actually loaded during a run to narrow blame to the active slice. On one bounded slice (10–15 rules in a single review bundle or routing doc against a fixed replay set), run a withholding sweep removing or merging one rule at a time to test whether outcomes actually degrade. | If withholding shows low-value/redundant rules that local admission checks would have kept, test a periodic withholding-pruning loop against an append-only baseline; if replay variance swamps rule effects, tighten replay determinism first. |
| **5. Decision-attribution log and recurrence-triggered structural search** | Autonomous noticing; structural search; bootstrap transfer | Log who supplied each internal update decision (*notice, diagnose, propose, select, install*) across the next 20–30 real updates to Commonplace's own instructions/checks/validators. Mine recurring review findings from `kb/workflow-state/` and git history to run one structural-search + spec-mining trial (proposing a deterministic validator rule, merged rule, or shared definition while forbidding one-off local exceptions), then test withholding the operator on that single update class. | Use the attribution counts to pick the highest-frequency operator decision for the next transfer test; if structural proposals still require operator selection to avoid regressions, record that as the active transfer frontier. |
