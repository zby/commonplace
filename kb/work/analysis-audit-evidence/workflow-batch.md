## Acceptance and audit boundaries

Use standard run checks and stop conditions. Independently check publication
integrity and the workflow's bounded account before integration; a completed
engine status alone is not that check. Do not require runtime experiments or
exhaustive inventories where the method permits bounded implementation findings.
If a consequential blocker occurs, preserve evidence and stop that execution;
no automatic rewriting of frozen outputs or state. Record the disposition before
continuing or replacing a target; do not silently count a failed run as complete.

The single batch auditor should inspect accepted results and available traces,
prioritize workflow usefulness and recurring operational failures, and separate
source changes, model variability, repair work and measured timing. Retain local
and cross-run findings separately, including successful safeguards and audit
limits. Nested coordinator traces are embedded in this parent session's tool
results; absence of a standalone child session file does not mean missing work.
Do not implement session tools during the audit merely to complete a proposed
feature list. Record recurring extraction/search needs for the later workshop.
