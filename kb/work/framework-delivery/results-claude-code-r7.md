# Delivery probe results: Claude Code, revision 7

- Harness and version: Claude Code 2.1.310, fresh headless sessions (`claude -p --permission-mode default --output-format stream-json`) started in the scratch project; the orchestrating session ran Claude Code 2.1.309
- Model: claude-opus-5-5 in every probe session, the configured default, no override; the orchestrating agent was claude-fable-5-1
- Operating system: Linux (Ubuntu 24.04.5, x86_64)
- uv and Python versions: uv 0.13.4; Python 3.12.8 for the tool environment
- Tester (agent or person) and date: Claude Code agent (Fable 5.1), 2026-10-24, at the operator's request
- Probe package revision (see PROTOCOL.md): revision 7, at commit `926318b06`; scope: cases 0, 8, 9, 10 and 11 only, since cases 1–7 passed with revision 4 ([results-claude-code-r4.md](./results-claude-code-r4.md)) and the protocol says those results stay valid

**Result.** Every case in scope passed as supplied, with no package modification, no workaround, no permission prompt and no denial. Init wrote the revision 7 output set and `--check` reported ten `ok`. The skill index in the imported `library.md` led three fresh sessions straight to the real skill with no native stub present (case 9). A general-purpose sub-agent did the delegated read under the same project read rule (case 10). The echo skill reported `ECHO-V1 kumquat` (case 11), but Claude Code substituted `$ARGUMENTS` at **both** places in the stub, so the stub's second sentence lost its placeholder; the agent coped and flagged it. The real `commonplace-init` writes the same two sentences, so this finding applies to it.

**Method deviation.** The request asked for one sub-agent per case. A sub-agent started with the Agent tool inherits the parent session's working directory, so it loads this repository's `CLAUDE.md` and skill directories, not the scratch project's import of `library.md` and its stubs (observed: the headless sessions' init records list skills per working directory). Cases 9 and 11 depend on exactly those project-level mechanisms, so sub-agents from this session could not test them. Each case therefore ran as a fresh headless session in the scratch project, as in revision 4. Each session was a new context that had not done the setup and received only the protocol's prompt. Three sessions ran concurrently for case 9; they shared no state beyond the read-only project files.

## Consequences for the design

- **Observed:** the revision 7 output set installs and checks clean in Claude Code on Linux: ten `ok`, templates written once and preserved on rerun.
- **Observed:** the skill index alone is enough in Claude Code when `CLAUDE.md` imports `library.md`. In three of three sessions with no native skill present, the agent went directly to the real `SKILL.md` and resolved its three relative links, with no exploratory read and no failure. The route cost no more tool calls than the stub route in revision 4 (four reads). **Inferred:** the index can stand in for native skills in this harness for a check named in the prompt; whether it triggers on an unnamed task, as the router did in case 4, was not tested.
- **Observed:** a sub-agent with a fresh context did the delegated read, and the one project-level read rule covered the sub-agent as well as the parent. No emulation was needed and nothing was added by hand.
- **Observed:** Claude Code substitutes `$ARGUMENTS` at every occurrence in the stub it loads, including the sentence "Where the real skill refers to `$ARGUMENTS`, use these." The agent still reported `ECHO-V1 kumquat`, taking the argument from the stub's first sentence as that sentence directs, but it reported the stub as looking wrong. **Inferred:** the second sentence should not contain the literal placeholder, for example "Where the real skill names its argument placeholder, use these." This applies to `commonplace-init`, whose `library.py` writes the same two sentences (lines 200–201 at commit `105095c2e`). The real skill's own `$ARGUMENTS` line reaches the agent unsubstituted, as the design expects; the stub's first sentence carried the value correctly.
- **Observed:** headless `-p` mode expanded the slash command into the prompt instead of calling the Skill tool. Both routes delivered the stub's text and the agent followed it the same way. **Inferred:** stub-following does not depend on which route the harness uses to load the stub.
- **Observed:** a fresh clone without init fails safely with one failed read; the stop-and-ask rule in the revision 5 `AGENTS.md` was followed and the agent did not search for the library.
- **Observed:** an Agent-tool sub-agent is bound to its parent's project, so a protocol runner inside Claude Code cannot use sub-agents as the fresh sessions the protocol asks for; headless sessions started in the project are the route. This is a note for probe runners, not a design problem.
