# Brief: Getting started with Commonplace

## Intent

Write for someone with a running agent and a real task, not someone studying the software. Give them one useful thing to try immediately. Then offer a few short “How do I …?” starting points they can choose by the result they want. Success is a reader recognizing their situation, asking in their own words, and knowing what to look for in the reply.

## Must keep

- Lead with commissioning a note from a rough thought. Follow the same note through connections to existing knowledge, suggestions for useful sources, ingestion of the reader’s selections, and revision in light of those sources. The example topic is the writer’s choice.
- Use ordinary requests a person could say, not incantations to copy exactly. Show what comes back and, where it matters, what the operator still needs to decide.
- Let the reader distinguish asking to inspect something from asking to change it. Tell them about consequential effects before suggesting the request, not in a technical caveat afterward.

## Must exclude

- Do not make the reader learn command names, file layouts, or the agent’s workflow before trying a task. The agent can find and explain those details on request. Point elsewhere for setup or troubleshooting when it blocks the first step.
- Do not turn the page into a catalogue. Select starting points; leave exhaustive coverage to the reference guide.
