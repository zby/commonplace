Where it lives is not what it is

An architectural vocabulary for retained adaptation in agentic systems

Zbigniew Łukasiak position paper + 141-system corpus
→ / space to advance · N for notes

~30s. Introduce yourself. The title is the whole thesis: where a retained artifact lives — its storage — does not tell you what it is or how it acts. A position paper, but with corpus evidence at the end: 141 agent-memory systems reviewed from source code.

01 · The problem

Agents adapt by retaining artifacts — and we classify them by where they're stored

  • Prompts, workflows, validators, memories, adapters, checkpoints.
  • Managed under storage labels: memory system vector store flat files prompt registry model store
  • Position: storage-first classification is architecturally insufficient.
§1

~1 min. Agents don't adapt only by changing weights — they adapt by retaining artifacts: prompts, workflows, validators, memories, adapters, checkpoints. Today the field manages and names these by where they're stored: "memory system", "vector store", "prompt registry".

The position: storage tells you how to access, delete, version, and roll back — but it hides how the artifact acts, what evidence reviews it, and what invalidates it. That's what the rest of the talk supplies.

02 · One lesson, many forms

A coding agent keeps mishandling dependency resolution

One lesson, five retained shapes — each with different review, invalidation, and rollback obligations:

Natural-language reflection

Acts only if retrieval carries it forward.

Derived prompt summary

Can go stale after its source is fixed.

Lockfile validator

Blocks cheaply; must be tested.

Conflict-check script

Fast, repeatable; fails systematically.

Learned scoring weights

Nothing to read — only probes.

§1

~1 min. Concrete case: a coding agent keeps installing incompatible versions, ignoring lockfile constraints. The surrounding system can retain that lesson in any of these five shapes. Walk two or three, not all five: a reflection affects behavior only if retrieval carries it forward; a validator blocks execution cheaply but must be tested like control logic; learned weights give you nothing to read — only behavioral probes.

Punchline: calling all five "memory" hides exactly these differences.

03 · The vocabulary

A four-field record for every retained artifact

fieldrecordswhy the architect cares
storage_substrate Where state persists: files, repos, vector stores, registries. Access, deletion, versioning, rollback.
representational_form Natural-language, symbolic, or distributed-parametric. Inspection method, review evidence, execution cost.
lineage Source material, or a derived view or learned update. What to invalidate on source change.
behavioral_authority Consumer × channel × force. Who acts on it, with what force.

Unit of classification: the operative part, not the stored object.

§2–§6

~1 min. The proposal: a four-field record per retained artifact. Storage stays — it's a legitimate operational field (access, deletion, versioning, rollback) — but it's one field of four, not the classification.

Stress the unit: the record applies to the operative part and its consumption path, not the stored object. A skill package bundles natural-language guidance, code, tests, and activation metadata — those parts get split because they need different review evidence and different rollback.

Terminology note (say once, briefly): the submitted paper says "prose" where I now say "natural-language" — the category was renamed because its boundary is interpretive, not editorial; fragments and structured records qualify too.

04 · Representational form, derived

Two axes generate the three forms

localized unit
non-localized
consequences assigned by a defined consumer

symbolic

Code, schemas, validators — an implementation adjudicates.

unoccupied

reinterpreted on each consumption

natural-language

Reflections, notes, policies, prompts — no adjudicator; two readings can both be reasonable.

distributed-parametric

Weights, adapters, embeddings — no addressable unit.

§5

~1.5 min — centerpiece. The paper lists three forms; here I derive them from two questions. First: does a defined consumer assign the consequences? For code, an implementation adjudicates — if two consumers disagree, one of them is wrong. Natural language has no adjudicator — two readings can both be reasonable. That's underspecification, not a defect of any particular text. Second: is there an identifiable unit carrying the content, or is it spread across numerical state?

The fourth cell — assigned consequences without a localized unit — is unoccupied, not impossible: vector-symbolic architectures aim exactly there. If agent systems ever retain state of that shape, the carve gains a fourth form.

05 · Inspection follows from the axes

Read, test, or probe — derived, not stipulated

  • Defined semantics to check against → test symbolic artifacts.
  • Interpretation only → read natural-language artifacts.
  • Nothing to point at → probe distributed-parametric artifacts.
  • Revisability rides localization alone: prompts and validators revise item by item; weights don't.
§5

~45s. The payoff of deriving rather than stipulating: the inspection rule falls out of the axes. A localized unit with defined semantics can be checked against them — test. A localized unit without them yields its content only to interpretation — read. A non-localized artifact offers nothing to point at, so only behavior is observable — probe.

And revisability rides the localization axis alone — which is why a prompt and a validator are both revisable one item at a time while weights are not, despite sitting on opposite sides of the semantics axis.

06 · Lineage & behavioral authority

Where it came from, and what force it carries

  • lineage — source vs. derived: what to invalidate, regenerate, or retire.
  • authority — force ranges from advice through instruction to enforcement and learning input.
  • Exposed failure modes: stale derived views; untrusted natural language in high-authority channels; poisoned records behind opaque retrieval.
§6

~1 min. The remaining two fields, briefly. Lineage is deliberately not a full provenance model — it records just enough to know what to invalidate, regenerate, or retire when a source changes. Authority is consumer × channel × force, and force is a spectrum: advice that may be ignored, instruction, execution-blocking enforcement, ranking influence, learning input.

The failure modes connect to security the audience knows: prompt injection is exactly untrusted natural language entering a high-authority channel (Greshake et al.); memory poisoning hides behind opaque retrieval (AgentPoison, MemoryGraft). And a stale derived view can govern behavior after its source is fixed — a repair target no storage label surfaces.

The reframe to land: the design question is not whether a lesson is "in memory" but whether its current form and authority are justified — natural-language advice for the uncertain, symbolic control for the frequent or safety-critical, retrieval or learned state where generalization outweighs direct inspection.

§8 · system-level counts; descriptive corpus, not a field sample

~1.5 min. 141 agent-memory and context-engineering systems, each reviewed from source code with the same four-field record. One storage family dominates: 98 keep retained state in plain files or repositories. "Repositories" means the handful of systems where git itself is the memory mechanism — versioning, diffs, clone/pull distribution are part of the storage model — as opposed to systems that merely write files.

The point of the bars: hold storage fixed and the other fields still pull systems apart — an architect who knows only "it's in files" cannot predict enforcement, learned parts, activation direction, or lineage. And natural-language and symbolic parts appear in all 141, so form discriminates only below the system, at the operative part.

Q&A ammunition: the corpus is opportunistically assembled, seeded by a file/wiki-heavy comment thread (Karpathy), so the 98/141 describes this collection, not the field — the argument rests on within-substrate variation, which doesn't need representativeness. Counts are system-level presence, not per-artifact. Reviews ran under one saved contract; reviewer consistency is future work, along with a pre-registered sampling frame and design-review trials.

09 · Takeaway

Takeaway

Storage locates retained state. Form, lineage, and authority determine how it acts — and what review it admits.

For each retained lesson: stay natural language, become symbolic control, surface through retrieval, or learn into numerical state?
