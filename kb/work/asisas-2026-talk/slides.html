Where it lives is not what it is

An architectural vocabulary for retained adaptation memory in agentic systems

Zbigniew Łukasiak position paper + 141-system corpus
→ / space to advance · N for notes

~30s. Introduce yourself. The title is the whole thesis: where a memory lives — its storage — does not tell you what it is or how it acts. A position paper, but with corpus evidence at the end: 141 agent-memory systems reviewed from source code.

The struck-out terms on the slides are the submitted paper's vocabulary; the talk deliberately renames them — say "memory" with the room, then unpack it.

01 · The problem

Agents adapt through retained artifacts memory — and we classify it by where it's stored

  • Prompts, workflows, validators, memories, adapters, checkpoints.
  • Managed under storage labels: memory system vector store flat files prompt registry model store
  • Position: storage-first classification is architecturally insufficient.
§1

~1 min. Agents don't adapt only by changing weights — they retain things: prompts, workflows, validators, memories, adapters, checkpoints. The talk calls all of it memory — the room's word — where the paper says "retained artifacts"; the strikeout marks the renaming. Today the field manages and names memory by where it's stored: "memory system", "vector store", "prompt registry".

The position: storage tells you how to access, delete, version, and roll back — but it hides how the artifact acts, what evidence reviews it, and what invalidates it. That's what the rest of the talk supplies.

02 · The usual first question

“Should the memory be a database or flat files?”

A coding agent keeps mishandling dependency resolution. The lesson can be retained as:

  • Failure reflection natural-language · advice
  • Conflict-check validator symbolic · enforcement
  • Derived prompt summary natural-language · instruction
  • Learned scoring weights distributed-parametric · probe-only

Every one of these can be saved into a database or stored as flat files. The answer settles backup, access, and deletion — not how the lesson acts.

§1

~1 min. The first architecture question teams actually ask about agent memory: database or flat files? Concrete case: a coding agent keeps installing incompatible versions, ignoring lockfile constraints. The lesson can be retained in any of these shapes — and every one of them can be saved into a database or stored as flat files: the reflection is advice whether it's a Markdown file or a table row; the validator blocks execution either way; the weights are unreadable either way.

Punchline: the storage answer settles backup, access, and deletion mechanics only. What changes review, invalidation, rollback, and force is which shape the lesson takes — and the database-vs-files debate never mentions that.

03 · Same job, same place

A validator script vs. a validating prompt

Both check the same dependency rule; both are small text files in the repo.

hooks/check-lockfile.sh“check deps before install” in AGENTS.md
form symbolic — an interpreter adjudicates natural-language — the model interprets
force enforcement — blocks the action instruction — can be weighed away
failure systematic, reproducible interpretive, varies per run

Storage cannot tell them apart. What can — form, lineage, authority — is the vocabulary of the next slides.

§2–§6

~1 min. Take the sharpest pair from the example: a validator script and a validating prompt. Same job — check the dependency rule — and the same storage answer: both are small text files in the repo. Every storage-side operation treats them identically: version them, diff them, delete them, roll them back.

Everything an architect actually needs differs: the script's semantics are adjudicated by an interpreter, so you test it and it blocks the action, failing the same way every time; the prompt is interpreted by the model on each run, so you read and trial it, it can be weighed away against competing instructions, and it fails interpretively. This pair motivates the paper's proposal: record form, lineage, and behavioral authority alongside storage, per operative part — the next slides define them.

Terminology note (say once, briefly): the struck-out terms mark two deliberate renamings from the submitted paper — "retained artifacts" → memory (use the room's word, then unpack it), and "prose" → natural-language (the boundary is interpretive, not editorial; fragments and structured records qualify too).

~15s beat — talk over the picture. A barrier and a no-traffic sign (Vienna Convention C2 — Polish B-1) encode exactly the same rule on the same road: closed to all vehicles. The barrier is the validator script: it blocks — nobody drives through it, and it fails the same way every time. The sign is the validating prompt: an instruction the driver interprets — and can weigh away against whatever else is on their mind.

And from the storage layer the two roads look identical — git diff sees no difference. Then advance: so what does tell them apart? The four-field record.

04 · The vocabulary

A four-field record for every retained artifact memory

  • storage_substrate — where the state persists
  • representational_form — prose natural-language, symbolic, or distributed-parametric
  • lineage — source material, or derived or learned from it
  • behavioral_authority — who consumes it, with what force

Unit of classification: the operative part, not the stored object.

§2–§6

~45s. The proposal: a four-field record per memory. Storage stays — it's a legitimate operational field — but it's one field of four, not the classification. Per field, what it records and why the architect cares:

storage_substrate — files, repos, vector stores, registries → access, deletion, versioning, rollback. representational_form — natural-language, symbolic, or distributed-parametric → inspection method, review evidence, execution cost. lineage — source material, or a derived view or learned update → what to invalidate on source change. behavioral_authority — consumer × channel × force → who acts on it, and whether it advises, instructs, or enforces.

Stress the unit: the record applies to the operative part and its consumption path, not the stored object. A skill package bundles natural-language guidance, code, tests, and activation metadata — those parts get split because they need different review evidence and different rollback.

05 · Representational form, derived

Two axes generate the three forms

localized unit
non-localized
consequences assigned by a defined consumer

symbolic

Code, schemas, validators — an implementation adjudicates.

unoccupied

reinterpreted on each consumption

prose natural-language

Reflections, notes, policies, prompts — no adjudicator; two readings can both be reasonable.

distributed-parametric

Weights, adapters, embeddings — no addressable unit.

§5

~1.5 min — centerpiece. The paper lists three forms; here I derive them from two questions. First: does a defined consumer assign the consequences? For code, an implementation adjudicates — if two consumers disagree, one of them is wrong. Natural language has no adjudicator — two readings can both be reasonable. That's underspecification, not a defect of any particular text. Second: is there an identifiable unit carrying the content, or is it spread across numerical state?

The fourth cell — assigned consequences without a localized unit — is unoccupied, not impossible: vector-symbolic architectures aim exactly there. If agent systems ever retain state of that shape, the carve gains a fourth form.

If time allows, the inspection payoff in one breath: the review method falls out of the axes — test symbolic artifacts (defined semantics to check against), read natural-language ones (interpretation only), probe distributed-parametric ones (nothing to point at).

~15s beat — talk over the picture. The grid's second axis in one picture: the same circle, twice. On the left it is an addressable unit — you can point at it, revise it, delete it, and it's gone. On the right the circle is still plainly there, but no dot is the circle: the content is spread across the state. Remove any dot and the circle persists; there is nothing to point at.

That is the distributed-parametric cell — weights, adapters, embeddings — and it is why they are probed, not read, and why prompts and validators revise item by item while weights don't.

06 · Lineage & behavioral authority

Where it came from, and what force it carries

  • lineage — source vs. derived: what to invalidate, regenerate, or retire.
  • authority — force ranges from advice through instruction to enforcement and learning input.
  • Exposed failure modes: stale derived views; untrusted natural language in high-authority channels; poisoned records behind opaque retrieval.
§6

~1 min. The remaining two fields, briefly. Lineage is deliberately not a full provenance model — it records just enough to know what to invalidate, regenerate, or retire when a source changes. Authority is consumer × channel × force, and force is a spectrum: advice that may be ignored, instruction, execution-blocking enforcement, ranking influence, learning input.

The failure modes connect to security the audience knows: prompt injection is exactly untrusted natural language entering a high-authority channel (Greshake et al.); memory poisoning hides behind opaque retrieval (AgentPoison, MemoryGraft). And a stale derived view can govern behavior after its source is fixed — a repair target no storage label surfaces.

07 · The record in use

The record in use

The question is not whether a lesson is “in memory” — but whether its form and authority are justified.

Natural-language advice for the uncertain · symbolic control for the frequent or safety-critical · learned state where generalization outweighs inspection.

§7

~45s. The reframe to land, spoken over the dependency lesson: each shape it can take admits a different action. The reflection is natural-language advice — rollback is delete the record and refresh the index. The conflict-check script is symbolic enforcement — revert it or put it behind a feature flag. The derived Markdown prompt is natural-language instruction — regenerate the entry when its source changes. The semantic-retrieval package (natural language + embeddings) carries ranking influence — rebuild the index.

Walk one contrast aloud (reflection vs. script is the sharpest), then land the sentence on the slide: the design question is not whether the lesson is "in memory" but whether its current form and authority are justified.

08 · Evidence from a system corpus

Hold storage fixed — the other fields still pull systems apart

98/141
agent-memory systems keep retained state in files or repositories
acts as an enforced gate53
includes a distributed-parametric part37
pull-only activation39
trace-extracted lineage70

Substrate predicts none of this — and natural-language and symbolic parts appear in all 141 systems: form discriminates at the operative part.

§8 · system-level counts; descriptive corpus, not a field sample

~1.5 min. 141 agent-memory and context-engineering systems, each reviewed from source code with the same four-field record. One storage family dominates: 98 keep retained state in plain files or repositories. "Repositories" means the handful of systems where git itself is the memory mechanism — versioning, diffs, clone/pull distribution are part of the storage model — as opposed to systems that merely write files.

The point of the bars: hold storage fixed and the other fields still pull systems apart — an architect who knows only "it's in files" cannot predict enforcement, learned parts, activation direction, or lineage. And natural-language and symbolic parts appear in all 141, so form discriminates only below the system, at the operative part.

Q&A ammunition: the corpus is opportunistically assembled, seeded by a file/wiki-heavy comment thread (Karpathy), so the 98/141 describes this collection, not the field — the argument rests on within-substrate variation, which doesn't need representativeness. Counts are system-level presence, not per-artifact. Reviews ran under one saved contract; reviewer consistency is future work, along with a pre-registered sampling frame and design-review trials.

09 · Takeaway

Takeaway

Storage locates retained state. Form, lineage, and authority determine how it acts — and what review it admits.

For each retained lesson: stay natural language, become symbolic control, surface through retrieval, or learn into numerical state?

~45s, aim to land at 9:30. Close on the thesis: storage locates retained state; form, lineage, and authority determine how it acts and what review it admits.
