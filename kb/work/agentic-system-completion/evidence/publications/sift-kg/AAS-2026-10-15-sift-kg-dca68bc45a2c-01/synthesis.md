# sift-kg synthesis

## Bounded synthesis

sift-kg is a document-derived knowledge system, not an enclosing agent runtime. It extracts entities and relations, builds a saved graph, offers identity maintenance and derived prose, and returns selected retained state to a caller. This account covers its shipped CLI, library drivers, prompts, agent skill and downstream consumers at commit `d786991c024f5401f113fc0cb70aee96dd1bd3bf`, with an applicability cutoff of 2026-10-15. The evidence is SRC-1 implementation and doctrine/design, with attributed example reports, not reproduced operation. No target code, tests, providers or examples were executed, and no full execution trace or causal experiment was supplied. External host orchestration, provider internals and deployed permissions are outside the boundary. See [boundary](boundary.md#boundary-and-evidence) and its [Source register](boundary.md#source-register).

### From a document request to retained assertions

The representative workflow is the bundled skill's create/update-and-answer procedure. A host agent receives documents, requests permission for paid extraction, invokes extraction and build, optionally runs resolve/review/apply, then retrieves graph context and answers the user. The host owns these command boundaries and final delivery; the skill does not implement a scheduler. Within each stage Python owns progression, while completion models interpret selected inputs and return data or prose. They do not select arbitrary tools through the inspected adapter. The convenience library pipeline advances extract → build → optional narrate, omitting the separate review branch. See [workflow account](workflow.md#workflow-account), [RT-BAP-agent-skill](runtime.md#rt-bap-agent-skill) and the bounded executor finding [RT-ABS-tool-execution](runtime.md#rt-abs-tool-execution).

Extraction reads supported documents, optionally uses OCR, divides text into overlapping character windows and supplies a generated first-chunk summary to chunk calls. Independent calls receive selected domain guidance and text, not an accumulating conversation. Parsed returns escape into per-document JSON; the summary is transient rather than a persisted conversational checkpoint. The parser admits constructible typed items and skips malformed ones. Explicit-source and quotation instructions are model policies, not checks of entailment or verbatim quotation. Imported assertions retain unknown source warrant. See [RT-RTE-document-extraction](runtime.md#rt-rte-document-extraction), [MEM-OBJ-document-extraction](memory.md#mem-obj-document-extraction) and [EPI-RTE-extraction-shape](epistemic.md#epi-rte-extraction-shape).

These bounds matter during an update. Cache identity checks model string, domain name and chunk size, not source contents or domain contents. Same-stem paths share an output identity. Exhausted chunk failures can yield persisted empty results without a document-level error. A force rerun is recovery, not automatic freshness detection. Bulk cost checks precede semaphore admission and omit earlier discovery/summary work; direct extraction and some narration calls have different coverage. The budget is therefore best-effort accounting, not a hard spend cap. These are conditional implementation findings, not measured error or overspend rates. See [RT-RTE-document-extraction](runtime.md#rt-rte-document-extraction).

### From retained extractions to a maintained graph

Build reloads retained extraction JSONs into a fresh graph, automatically collapses names, aggregates entities and relation support, and optionally normalizes types and directions. It saves graph state before producing review flags. Pending flags therefore do not quarantine assertions from retrieval. Original-document deletion alone does not remove orphan extraction files, and rebuilding does not automatically preserve prior graph surgery. See [RT-RTE-graph-build](runtime.md#rt-rte-graph-build) and the memory report's [build annotation](memory.md#annotations).

The graph is not merely a lossless index. Entity aggregation can overwrite attributes or select higher-confidence content. Canonical relations retain mentions and support metadata but expose representative evidence through query; combined confidence is not a validated truth probability or proof of independent observations. A specific normalization rule also changes semantics: with postprocessing enabled and TRAVELED_FROM not valid in the active domain, its mapping to TRAVELED_TO can replace an origin assertion with a destination assertion while keeping endpoints. Under ordinary relation meanings the former does not entail the latter. This supports a conditional source-level conjecture finding, not an observed incident or a classification of all cleanup as conjecture. See [MEM-OBJ-graph-data](memory.md#mem-obj-graph-data), [MEM-OBJ-relation-support](memory.md#mem-obj-relation-support) and [EPI-RTE-relation-normalization](epistemic.md#epi-rte-relation-normalization).

Optional resolution supplies selected names, aliases and identity attributes in overlapping batches or embedding clusters to a model. It persists sameness/variant proposals with reasons and confidence. Review first applies automatic thresholds, then offers human decisions on remaining drafts; default CLI auto-confirmation starts at 0.85. Separate application admits confirmed entity merges with valid node IDs and removes rejected relation triples. Direct YAML editing is another status-setting path, without authenticated writer identity. Build's earlier pre-deduplication bypasses this proposal gate. Thus the invariant is confirmed-status admission to the surgery engine, not universal human approval. Confirming a proposed variant does not insert an edge. Reasons inform reviewers, but surgery consumes statuses and IDs rather than the reasons as rules. See [RT-RTE-entity-resolution](runtime.md#rt-rte-entity-resolution), [RT-RTE-review-application](runtime.md#rt-rte-review-application), [RT-CLM-merge-approval](runtime.md#rt-clm-merge-approval) and [MEM-OBJ-merge-proposals](memory.md#mem-obj-merge-proposals).

Rejection prevents a proposal's surgery; it is not undo of earlier changes. Quitting review can leave earlier automatic confirmations intact. Missing nodes can prevent even confirmed proposals from applying. Rebuild can restore rejected extraction-derived relations and replace previous merges. Exact recovery needs an external saved copy rather than an inspected reversible decision history. See [workflow account](workflow.md#workflow-account) and [MEM-OBJ-relation-review](memory.md#mem-obj-relation-review).

### From saved state to a later consumer

Optional narration selects ranked graph subsets and name-matched extraction contexts to generate descriptions, themes and narrative. Description prompts cap relations and contexts; name-only joins can share contexts between distinct same-name entities. Regex style checks can trigger one model rewrite, but do not verify factual equivalence. Returned prose is automatically retained. Themes and description sidecars lack a coordinated graph-revision freshness guarantee, and graph surgery does not automatically update existing prose or exports. See [RT-RTE-narrative-generation](runtime.md#rt-rte-narrative-generation), [EPI-RTE-style-rewrite](epistemic.md#epi-rte-style-rewrite), [MEM-OBJ-entity-descriptions](memory.md#mem-obj-entity-descriptions) and [MEM-OBJ-communities](memory.md#mem-obj-communities).

Later CLI lookup is caller-requested. Query selects an exact ID or substring/alias match, ranks ambiguous candidates by substantive degree and returns a hop-limited neighborhood with selected evidence and support fields. Hop depth is not a token budget. Query omits node contexts, provenance nodes and full mention lists; search and exports deliver different fields and are not universally metadata-filtered. Topology computes properties of the saved graph, not proof of real-world connectivity or absence. Project orientation through info is a separate consumer of counts, statuses and file existence. See [RT-RTE-graph-retrieval](runtime.md#rt-rte-graph-retrieval), [MEM-RTE-project-info](memory.md#mem-rte-project-info) and [RT-RTE-view-export](runtime.md#rt-rte-view-export).

The system consequently supports explicit reuse of structured document interpretations across invocations. It also automatically supplies retained domains, graph subsets and statuses to internal consumers after stage invocation; that internal selection is distinct from caller-facing pull and does not establish automatic injection into a host session. Optional embeddings select resolution batches, not a durable vector retrieval store. The skill affords direct loading for small graphs and prescribes topology/query for larger ones, but the host owns context assembly, eviction and subsequent answers. See [RT-RTE-schema-discovery](runtime.md#rt-rte-schema-discovery), [RT-RTE-entity-resolution](runtime.md#rt-rte-entity-resolution), [RT-RTE-narrative-generation](runtime.md#rt-rte-narrative-generation) and [RT-BAP-agent-skill](runtime.md#rt-bap-agent-skill).

### What changes, and what improvement remains unestablished

The strongest supported behavior-shaping contribution is reusable corpus-derived guidance: discovery automatically admits localized domain definitions, and later extraction/build consume them. This changes future inputs and fixed-code transformations. If those definitions are treated as a local theory of corpus organization, the runtime separately supports theory-builder condition 1, localized replaceable content, as afforded; condition 2, consumption, as wired, with model semantic uptake unobserved; condition 3, content-directed criticism, as uninspected; and condition 4, retained criticism shaping a next round, as uninspected. Schema reuse alone establishes neither of the latter conditions. See [RT-RTE-schema-discovery](runtime.md#rt-rte-schema-discovery) and [MEM-OBJ-discovered-domain](memory.md#mem-obj-discovered-domain).

Improved capacity for future action through criticism of a consumed theory is not established: no criticism-to-revision trace or independent outcome comparison is supplied. Reflection is independently unestablished because the corpus schema is not shown to represent sift-kg's own operation. Automatic generation does not establish an autonomous theory builder; the internal criticism and iteration operations remain unestablished. Stage automation and external host ownership are separately supported facts, not a general autonomy grade. Exercised self-improvement at this repository boundary is likewise unestablished: reusable guidance reaches later consumers in code, but the records do not close an objective-bearing evidence-to-update-to-subsequent-operation causal chain. Style rewriting concerns an external prose product under unchanged instructions, not demonstrated revision of an operational theory. See [RT-RTE-schema-discovery](runtime.md#rt-rte-schema-discovery), [RT-RTE-narrative-generation](runtime.md#rt-rte-narrative-generation) and the epistemic [bounded conclusion](epistemic.md#bounded-conclusion).

For document navigation and explicit neighborhood lookup, the implemented contribution is persistence plus selective delivery. For source-faithful factual answers, universally human-approved identities, coordinated withdrawal or demonstrated learning, that same evidence is insufficient. Retention and operational admission do not establish evidence-consuming factual acceptance or subsequent lifecycle integration. Trace-fed learning also remains undetermined, rather than established absent across all possible document contents and feedback origins. These distinctions are preserved by [EPI-RTE-extraction-shape](epistemic.md#epi-rte-extraction-shape), [RT-RTE-review-application](runtime.md#rt-rte-review-application) and [profile verification](profile-verification.md#verification).

Paired source/output evaluations would change the assessment of extraction and prose fidelity; linked reviewer evidence with criteria, intended use and scope would support narrower acceptance findings. A supplied host-session trace would establish bounded uptake, while a controlled comparison would be needed for answer benefit or component attribution. Content-based invalidation, revision-bound decisions/sidecars and replay or transactional withdrawal would change the identified freshness and recovery guarantees. A retained content-directed criticism, its operative revision and subsequent use would change the theory and self-improvement assessment only for the links it actually establishes. These are resolving conditions for the gaps above, not claims that such mechanisms or outcomes already exist.
