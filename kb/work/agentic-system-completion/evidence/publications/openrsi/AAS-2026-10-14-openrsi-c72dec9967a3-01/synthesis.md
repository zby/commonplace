# OpenRSI synthesis

## Bounded synthesis

OpenRSI implements an improvement plane for machine-learning engineering: it constructs executable tasks, searches for solution programs, retains evaluated experience and supplies selected experience to operator training. Its strongest supported contribution is the wiring of these mechanisms, including durable experience-to-context and experience-to-parameter-update paths. The unresolved question is whether a particular update entered later operation and improved capacity. The evidence does not establish that historical chain. The project's own claim is bounded meta-evolution, not solved general recursive self-improvement. See [RT-CLM-meta-evolution](runtime.md#rt-clm-meta-evolution), [RT-RTE-sft-training](runtime.md#rt-rte-sft-training) and [MEM-RTE-summary-cache](memory.md#mem-rte-summary-cache).

This account covers SRC-1, `https://github.com/FrontisAI/OpenRSI`, at commit `71ae803a035d5e3b78c19fa49ed9f67d0550cbaa`, with an applicability cutoff of 2026-10-14. The source-release boundary includes Gym task construction and evaluation, ERL experience production and training, and Evo test-time search. These are separately runnable stages, not one demonstrated autonomous cycle. Evidence is inspected implementation plus attributed design and reported operation. No target execution, supplied execution trace or causal experiment establishes successful operation or benefit. External weights, full corpora, task releases, services and the upstream RL trainer are outside the captured evidence. See the [boundary and Source register](boundary.md#source-register).

### From task construction to an evaluation contract

Gym uses a graph to acquire task information, inspect files, generate a description, generate and retry preparation code, and generate a metric module. Code owns stage routing; models author descriptions and executable artifacts. Explicit query construction selects what each model sees. Preparation retries receive a recent code/feedback tail, not the complete preceding reasoning. Empty graph-message updates do not establish erasure under the append/merge reducer. See [RT-RTE-gym-build](runtime.md#rt-rte-gym-build) and its memory annotation in [the memory account](memory.md#on-rt-rte-gym-build).

The generated metric later becomes executable scoring machinery. Compilation establishes syntax, not fidelity to task intent. Separately invoked package checks inspect required files and CSV relationships and execute a schema-valid sample submission for a finite score. That score is a smoke test, not a model-quality baseline. Optional semantic review receives selected package evidence and code. Deterministic failures can gate that review and affect CLI status; report-schema validation does not verify the truth of each model reason, and a low recommendation alone is not an enforced task-use veto. These distinctions bound the claim of “verifiable” packages. See [RT-OBJ-metric](runtime.md#rt-obj-metric), [EPI-RTE-package-validation](epistemic.md#epi-rte-package-validation), [EPI-RTE-quality-judgment](epistemic.md#epi-rte-quality-judgment), [EPI-RTE-quality-disposition](epistemic.md#epi-rte-quality-disposition) and [EPI-CLM-verifiable-packages](epistemic.md#epi-clm-verifiable-packages).

### From configured search to delivered code

The representative workflow is the shipped MLE-Bench invocation. An operator supplies tasks, endpoints and budgets; the adapter writes configuration and launches preparation and a runner. The runner creates task/sample subprocesses. Each solver chooses operators and parents; configurable Draft, Improve, Debug, Crossover and Analyze clients propose or assess programs. Separate client roles do not establish distinct or pinned model weights. Generated Python crosses into executable authority only at the selected task backend. See [RT-RTE-evolution-search](runtime.md#rt-rte-evolution-search), [RT-CMP-generic-llm](runtime.md#rt-cmp-generic-llm) and [RT-BAP-execution-authority](runtime.md#rt-bap-execution-authority).

Evaluations supply validity and fitness; buggy programs enter bounded Debug attempts. Non-buggy candidates compete for island admission against average island fitness, not necessarily against their parent or the best solution. Score authority depends on protocol and configuration: self-validation can trust model-printed scores, analysis can supply judgment, and test-score override can change selection. With experience disabled, Analyze runs for every node before deterministic finite fitness overrides its metric and bug flag; experience-enabled operation instead prioritizes deterministic evidence before fallback. Thus executable evaluation is not a universal independent oracle. See [RT-RTE-sandbox-evaluation](runtime.md#rt-rte-sandbox-evaluation), [the epistemic ledger](epistemic.md#authority-route-ledger) and [the workflow repair annotation](workflow.md#on-rt-rte-evolution-search).

Budget checks govern scheduling and admission, not strict preemption of every external call. Async search serializes commits and can reject completed work after a stop condition. Execution grants also differ: isolated Gym preparation, direct imports, NatureBench local Python, Docker and remote execution are not interchangeable security boundaries. Actual containment depends on deployment and remains unobserved. See [RT-RTE-async-search](runtime.md#rt-rte-async-search), [RT-RTE-gym-build](runtime.md#rt-rte-gym-build) and [RT-RTE-naturebench-execution](runtime.md#rt-rte-naturebench-execution).

Delivery is weaker than solution certification. Final selection can fall back to a seeded random code-bearing node when no scored candidate qualifies, or write empty code when none exists. Code files are written before optional test-phase evaluation. A zero subprocess exit is distinct from the stricter resume-completeness predicate. NatureBench can reuse search-stage scores instead of obtaining fresh final evidence. Neither `valid_code_final.py` nor process success establishes a valid or improved solution. See [WF-RTE-final-delivery](workflow.md#wf-rte-final-delivery).

### From evaluated attempts to later behavior

Search history, active solutions and derived experience are separate objects. The journal retains code, plans, logs, scores and relationships, including attempts no longer eligible as active solutions. Cards and a strategy board derive structured experience from those attempts. Optional summaries describe a method and compare it with its parent. Software admits two nonempty summary fields; it does not establish their semantic truth. Existing node/card/cache content takes precedence over regeneration. See [MEM-OBJ-journal](memory.md#mem-obj-journal), [MEM-OBJ-experience-card](memory.md#mem-obj-experience-card), [MEM-OBJ-rich-summary](memory.md#mem-obj-rich-summary) and [MEM-RTE-summary-cache](memory.md#mem-rte-summary-cache).

Later operator calls receive code-selected context rather than the entire prior conversation. Improve selects ancestry and shared-parent siblings; Debug prioritizes matching error signatures. Summary fields are clipped to 420 characters, with count limits rather than a global token ceiling. Legacy memory operators remain alternatives. Checkpoint/cache loading is requested read-back; subsequent automatic prompt selection supplies context without a foreground model retrieval request. This establishes retained, trace-fed context wiring, not actual reliance or improved capacity. RL's similarly named sibling renderer selects children of the current parent, so it is not equivalent to Evo's selector. See [MEM-RTE-targeted-memory](memory.md#mem-rte-targeted-memory), [RT-BAP-operator-guidance](runtime.md#rt-bap-operator-guidance) and [the memory annotation on RL training](memory.md#on-rt-rte-rl-training).

SFT makes a different projection of experience. Software selects examples using score/feedback, length, validation/test-gap, top-k and reward-deduplication criteria. Reconstructed conversations reach tokenization and loss masking; selection metadata can remain in a separate manifest without reaching the loss consumer as reasons. Actor updates, checkpoints and rollout weight refresh are implemented. The shipped launcher's asynchronous timing is only coarsely covered: rollout refresh depends on `update_weights_interval`, not an unconditional refresh after every update. See [MEM-OBJ-alignment-dataset](memory.md#mem-obj-alignment-dataset), [RT-RTE-sft-training](runtime.md#rt-rte-sft-training), [RT-CMP-training-models](runtime.md#rt-cmp-training-models) and [report-verification limits](report-verification.md#limits).

RL instead returns rewards through hooks to external training machinery and retains programs in SQLite for later selection. Negative cheating/holdout verdicts can bypass ordinary execution and incur penalties while still permitting storage. Some judge failures allow continuation; missing credentials are a separate exception. Database membership therefore certifies neither legitimacy nor uniform parent eligibility. SQL pruning, active-population filtering and reward-baseline consumers have different rules. The unavailable upstream optimizer cannot be inferred from the vendored SFT trainer. See [RT-RTE-rl-training](runtime.md#rt-rte-rl-training), [MEM-OBJ-rl-program](memory.md#mem-obj-rl-program), [EPI-RTE-hack-judgment](epistemic.md#epi-rte-hack-judgment) and [EPI-RTE-hack-disposition](epistemic.md#epi-rte-hack-disposition).

### What the supported mechanisms establish

For bounded task search, the release implements consequential feedback: scores affect parent selection, Debug and final output; retained experience can reach later proposals; selected traces can drive numerical updates. For explanatory knowledge production, the same evidence is narrower. Outcome comparisons do not isolate the cause of success, and cached comparative prose is candidate experience rather than an evidence-accepted explanation. Admission for training use is not acceptance of every proposition in an example. See [the epistemic bounded conclusion](epistemic.md#bounded-conclusion).

The independent property conclusions remain separate:

- **Learning:** durable trace-fed updates and numerical adaptation are wired. Improved capacity for future action, including improvement caused by criticism of a consumed theory, is unestablished. No causal comparison supports that stronger attribution.
- **Theory-builder conditions 1–4:** the runtime does not establish a formulated-theory route with separately evidenced localized theoretical content, content-dependent consumption, content-directed criticism and retained criticism shaping iteration. Code replacement, score selection and requested comparison alone do not establish those conditions. This is not a finding that hidden model processing lacks them.
- **Reflection:** representations of attempts and requested parent comparisons are supported; reliable reflection and the required two-way causal relation are not established merely by their delivery.
- **Autonomy:** computation chooses, evaluates, repairs and selects candidates inside an operator-configured bounded search without per-candidate human approval. This does not establish an autonomous theory builder or an autonomous release-wide training/deployment cycle.
- **Self-improvement:** the training pathway supports a marked dispositional, improvement-directed parameter-update claim at the improvement-plane boundary. Exercised self-improvement remains unestablished: the exact changed artifact's entry into live Evo serving and subsequent operation causally depending on that change are missing. Successful improvement requires additional outcome evidence even if those links are closed.

These conclusions follow the separate route limits in [RT-RTE-evolution-search](runtime.md#rt-rte-evolution-search), [RT-RTE-sft-training](runtime.md#rt-rte-sft-training), [RT-CLM-meta-evolution](runtime.md#rt-clm-meta-evolution), [the workflow account](workflow.md#workflow-account) and [the epistemic conclusion](epistemic.md#bounded-conclusion); they are not a system-wide epistemic grade.

A linked run record connecting evaluated experience, admitted dataset, exact checkpoint, deployed model identity and later behavior would change the exercised-path assessment. A controlled comparison varying the relevant update would address benefit attribution at that comparison's scope. Concrete summaries checked against their input evidence would permit stronger semantic classifications; traces of claim-specific criticism and consequential revision would address theory-building questions. None is supplied here. No additional source files were read for this synthesis.
