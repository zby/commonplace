# fragility-grid synthesis

## Bounded synthesis

### Scope and progression

Fragility-grid is a model-evaluation workflow, not an autonomous agent runtime. It asks how multiple-choice correctness and model rankings vary with prompt format, option order and scoring method. This account covers the selected collection-to-analysis subsystem in SRC-1 at commit `3f51444ead009d8351de1b6b19bf901c4da3d420`, with an applicability cutoff of 2026-10-18. It includes the shipped sweep, collector, inference adapter, retained measurements and CPU consumer, but not the repository's other experiments. The evidence is inspected implementation and attributed design/results, not observed execution or a causal experiment. No target tests or model calls were run, and released numerical values were not independently checked ([boundary](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)).

An operator selects model keys, benchmarks, item count, permutations, backend and GPU resources. In the representative `run_fragility.sh` workflow, shell workers take model keys from a locked queue and launch one collector subprocess per assignment. Fixed shell and Python rules own progression; models return answer text or continuation scores. Default scope is eight model keys, four benchmarks, 300 items and six permutations, not the release's reported twelve-model, 3,679-item experiment. Two additional shipped launchers vary scheduling and defaults, so this representative trace is not a complete launcher comparison ([RT-RTE-sweep-driver](runtime.md#rt-rte-sweep-driver), [workflow account](workflow.md#workflow-account), [report verification limits](report-verification.md#limits)).

The collector loads benchmark items separately for each model. It uses fixed shuffle seeds and reserves the first five items without using them as demonstrations. Imported dataset labels supply the expected-answer oracle; the workflow does not independently establish their truth. TruthfulQA is reduced to four options before evaluation. At default settings each item crosses 24 generation configurations and two likelihood configurations. This implements same-loaded-item comparison within an invocation; equality across model invocations additionally depends on stable external data ([EPI-OBJ-benchmark-items](epistemic.md#epi-obj-benchmark-items), [RT-OBJ-config](runtime.md#rt-obj-config), [RT-CLM-grid-purpose](runtime.md#rt-clm-grid-purpose)).

### Answer production and measurement

Each generation call receives an independent question/options frame and format instructions. Earlier answers, aggregate results and gold labels are not inserted into that frame. Likelihood scoring instead evaluates one continuation against a stem and selects the largest mean token score. This is fixed experimental enumeration, not model-led delegation or conversational memory retrieval. Model weights are unchanged in the inspected inference paths, but checkpoint and tokenizer loading do not pin immutable revisions ([RT-RTE-generation-grid](runtime.md#rt-rte-generation-grid), [RT-RTE-likelihood-grid](runtime.md#rt-rte-likelihood-grid), [RT-CMP-roster-model](runtime.md#rt-cmp-roster-model)).

Generated labels are parsed, mapped through the option permutation and compared with gold. Unparsed responses become zero bits rather than requests for correction. These checks establish dataset-relative agreement conditional on gold and extraction fidelity, not answer truth. Excluding fuzzy restatement parsing does not exclude parser noise: the inspected first-match parser selects A from `Not A; B is correct.` This is a source-level counterexample, not an observed response or an estimate of error frequency. Likewise, generation assumes backend return cardinality through `zip`; a short return could leave missing bits, but no such backend failure was observed ([EPI-RTE-label-extraction](epistemic.md#epi-rte-label-extraction), [EPI-RTE-gold-comparison](epistemic.md#epi-rte-gold-comparison), [RT-RTE-generation-grid](runtime.md#rt-rte-generation-grid)).

Backend controls are route-specific. Chat rendering retries without the thinking-disable flag on a tokenizer `TypeError`; likelihood scoring bypasses chat rendering. HF generation truncation does not establish the same guard for HF likelihood scoring. CUDA OOM recovery halves HF generation chunks down to one item, then propagates failure; it covers neither vLLM nor likelihood calls. These are conditional controls and best-effort recovery, not backend equivalence, universal context clipping or guaranteed completion ([RT-CMP-engine](runtime.md#rt-cmp-engine), [RT-RTE-backend-recovery](runtime.md#rt-rte-backend-recovery)).

### Retention, later consumers and delivery

After all requested benchmarks for a model finish evaluation, fixed software writes per-item JSONL records and a model summary. Records retain correctness bits, question text, gold and instrumentation, but not raw answers or complete rendered prompts. Later CPU analysis loads only item IDs and bits, derives model/benchmark identities from filenames and reconstructs configuration keys using the legend's permutation count. It does not recheck answer extraction or authenticate common question identity. Matching files can therefore carry stale or manually changed inputs into analysis; a newly written legend can coexist with older records ([RT-OBJ-records](runtime.md#rt-obj-records), [RT-RTE-record-analysis](runtime.md#rt-rte-record-analysis), [MEM-OBJ-config-legend](memory.md#mem-obj-config-legend)).

The strongest supported trace-fed behavioral contribution is a durable completion marker: automatic summary production follows model-call outcomes, and a later shell worker skips the model when that summary path exists. This qualifies as wired trace learning in the memory comparison's behavior-shaping-write sense. It is not evidence of improved future capacity, parameter training or scientific acceptance. The consumer reads existence, not summary explanations, numerical quality or request compatibility. CPU analysis separately pulls bit mappings; reporting artifacts afford human inspection but do not enter subsequent model context through the inspected collector ([RT-OBJ-summary](runtime.md#rt-obj-summary), [RT-BAP-summary-skip](runtime.md#rt-bap-summary-skip), [MEM-OBJ-analysis](memory.md#mem-obj-analysis), [profile verification](profile-verification.md#verification)).

Delivery means local artifact publication, not certification of a complete sweep. The collector frees its engine on evaluation failure, but writes no completed-model result from that failed evaluation. Later persistence can fail partway through multiple files. Workers continue after failed children. A caught gated-access skip can also end normally without new artifacts; report verification establishes this branch through the HF missing-token check, not as a guarantee about vLLM access errors. CPU analysis processes available records, writes `analysis.json`, then attempts figures independently. Empty inputs return early, and figure failures are tolerated. Neither a child `OK` nor the final shell message establishes all-model or all-figure success ([workflow account](workflow.md#workflow-account), [RT-RTE-record-analysis](runtime.md#rt-rte-record-analysis), [report verification](report-verification.md#verification)).

### What the analysis warrants

The CPU stage computes descriptive bands, ranks, gap decompositions, bootstrap intervals and discrimination-based subset comparisons over retained bits. Pairwise analysis intersects two models' IDs; compression uses items shared by all models and skips insufficient item/model counts. Seeded cutoff tie-break draws and champion margins qualify simplistic winner claims. They remain implementation safeguards, not verified empirical results ([EPI-RTE-statistical-check](epistemic.md#epi-rte-statistical-check)).

A robust-subset interval containing zero licenses the program's tied label, not affirmative equivalence. Combining that interval with a nonzero reference gap automatically emits a manufactured-gap label; the numerical premises do not establish causal manufacture or that fragile items represent mental uncertainty. Similarly, the plotted any-item/all-item envelope need not be attained by any single configuration. The artifact retains these interpretations, but publication is not an evidence-consuming acceptance of their broader explanatory truth ([EPI-RTE-result-labeling](epistemic.md#epi-rte-result-labeling), [EPI-OBJ-analysis-output](epistemic.md#epi-obj-analysis-output)).

For the scenario of comparing fixed harness configurations on stable benchmark inputs, the implementation supports conditional measurement and descriptive comparison. It does not independently establish the release's magnitudes, finer component causes, behavior of all compression methods or byte-identical reproduction. Separate seeded generators contradict the literal single-generator description without proving that fixed-environment reruns differ ([EPI-CLM-headline-results](epistemic.md#epi-clm-headline-results), [EPI-CLM-reproducible-analysis](epistemic.md#epi-clm-reproducible-analysis)).

These findings do not establish a theory-building or model-led revision cycle. The accepted runtime does not separately assess theory-builder conditions 1–4; configuration scores and retained outcomes alone cannot substitute for localized theory consumption, content-directed criticism and its iteration. Criticism of a consumed theory improving future capacity is not established. Model-internal reflection remains uninspected; fixed orchestration is not autonomous theory building. The summary-marker pathway changes later scheduling, but its observed exercise and improvement-directed attribution are unestablished, so exercised self-improvement is not demonstrated. These are separate limits, not a negative inferred from fixed weights or from one another ([RT-RTE-record-analysis](runtime.md#rt-rte-record-analysis), [RT-CMP-roster-model](runtime.md#rt-cmp-roster-model), [RT-BAP-summary-skip](runtime.md#rt-bap-summary-skip), [epistemic bounded conclusion](epistemic.md#bounded-conclusion), [profile verification](profile-verification.md#verification)).

The assessment would change with provenance-linked run traces and raw answers, immutable item/model/tokenizer manifests, completeness and compatibility checks at reload/resume, controlled repeatability comparisons, and experiments addressing the specific explanatory claims. A claimed improvement cycle would additionally need a retained update, its later exercised consumer and objective-relative evidence; the current scheduling marker alone does not supply those findings. No additional source reads were made for this synthesis.
