# Intent-based compaction of analysis instructions

- **Commissioned:** 2026-10-01, by the operator: reread the skill instructions and types and assess whether an Auftragstaktik-inspired method could compact them.
- **Result:** there is a concrete reduction in analyst job instructions. Most type text fixes shared meanings and acceptance, so delegating investigation choices does not remove it.
- **Status:** review and an unadopted candidate; no live instruction changed and no analyst trial ran.
- **Reading boundary:** the orchestrator skill and driver, all six job instructions, worker rules, both shared contracts, the runtime, memory, epistemic and overview types, the pending reconciliation type, and the instruction/type-spec authoring contracts. The working tree is concurrently separating reconciliation from synthesis; this review does not treat that unfinished interface as the final design.

## The applicable method

The [writing skill](../../instructions/cp-skill-write/SKILL.md) already requires intent before instructions and permits alternate means unless a dependency, commitment, coordination rule or comparison requires the particular step. The [instruction type](../../types/instruction.md) carries the same rule.

Use the mechanism described in [intent-framed delegation](../../notes/intent-framed-delegation-is-a-control-regime-not-a-short-prompt.md): preserve purpose, binding boundaries, acceptance and return conditions; let the worker choose means when source inspection reveals which means fit. A worker can select a search strategy or investigation order from the target's implementation. It cannot infer Commonplace's selected taxonomy, a parser's required labels, another worker's ownership, or the required breadth of a withheld comparison.

This is a change in which decisions the instruction fixes. Merely replacing the instructions with the name Auftragstaktik would leave those decisions ambiguous. The [methodology compression note](../../notes/weight-resident-methodologies-compress-behavior-in-context.md) makes the same distinction between a model's available repertoire and a delivered project requirement.

Delivering that material only for method maintenance is another possible reduction, provided the dependency links remain available to maintainers. It is a routing change, not a gain from delegated judgment, and is not included in the candidate measurement below.

### What each omission relies on

| Former procedural instruction | Surviving owner or deliberate choice |
|---|---|
| Perform the six investigation stages in order | Deliberately delegated search and inspection order; the output still follows the type. |
| Fill boundary, object inventory, ledger, claim comparison and conclusion | Epistemic type's Required blocks, explicitly inherited by the candidate. |
| Split sequential transformations and distinct consequential functions; describe non-truth-apt updates separately | Epistemic type's Assessment limits, ledger split criteria and content/update relations. |
| Name remaining classifications and needed evidence for indeterminate edges | Epistemic type's definition of indeterminate. |
| Keep non-changing routes' consequential function and authority | Epistemic type's material-route boundary and ledger fields. |
| Separate heterogeneous operative parts | Epistemic type's object-inventory split criteria and shared record contract. |
| Include only findings changing the answer | Epistemic type's Bounded conclusion. |
| Distinguish direct inspection from supplied runtime findings | Epistemic type's coverage-table contract; the candidate still requires that table. |
| Honor write scope and return a problem when completion needs extra authority or access | Supplied worker rules, explicitly inherited by the candidate. |

The candidate retains early completion for storage-only targets, assessment of unsupported knowledge-production claims, target/domain before evaluator judgment, parametric uncertainty, canonical-split flags, peer isolation and deterministic validation. The type's content-classification checking order is binding; discretion over investigation order does not override it.

## Limits and the next useful check

The measured saving is mostly elimination of production steps and repetition of delivered type requirements. It does not establish that a model will recover those requirements equally well, or that shorter text will fix truncated reads. The total-packet reduction is modest because the definitions remain necessary.

The [Luna follow-up](./parameterized-luna-followup.md) records omitted cleanup/evaluation coverage, incomplete reads and unsupported claims of direct inspection even after explicit coverage instructions. Keep concrete coverage obligations and bounded-read controls. Required sections and valid citations alone are insufficient evidence of a complete analysis.

A discriminating trial would compare the old and candidate job instructions with the same frozen source, runtime input, shared contracts, model and launch settings. Required checks: complete delivered reads, actual source-operation coverage, no unsupported inspection receipts, correct object/function splits, classifications and licenses, validation retries and final acceptance. A bounded absence must still name its search boundary and cannot silently become a system-wide negative. Repeated runs would be needed before claiming a reliable effect across executions.

The ongoing reconciliation/synthesis changes should settle before a full-workflow comparison, so a result can be attributed to this instruction change. This review performed source inspection and deterministic document validation. The candidate remains unadopted pending evidence about worker behavior.
