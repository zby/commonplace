# Trace the epistemic routes

Read every file under `read-first` in your invocation before any other step.

## Job parameters

Common parameters are defined in the supplied worker rules.

| Name | Meaning | Present |
|---|---|---|
| `boundary` | Absolute path of the frozen boundary and Source register. | Always |
| `runtime` | Absolute path of the runtime member. | Always |

## Mission and discretion

Write the epistemic member to `output`: whether and how `system` acquires
or produces truth-apt content, checks it, grants reliance, and lets it
affect later behavior. No later job rewrites this member.

Choose search strategy, inspection order and depth from source evidence.
The supplied type fixes materiality, report content, classification tests
and their checking order, and assessment limits. The shared contracts
fix evidence and records; worker rules fix authority and problem returns.

## Coverage and evidence obligations

Treat `runtime` as a starting account. Check CLI dispatch, hooks, registered
tools and exposed library/service operations, including material evaluation,
cleanup, rejection and withdrawal, through result and consequential consumer.
Retain the type's coverage table and explicit unassessed limits.
Distinguish directly read source from supplied runtime findings; include
material routes the runtime omitted.

Use source-native object names. Compare referents before new declarations
under the shared record contract; flag needed canonical splits and defective
supplied facts beside their affected findings, with evidence. Identify the
check target and domain before judging its evaluator. Inspect content within
its representational semantics; for parametric state, record `not determinable`
when accessible sources and supplied execution evidence cannot individuate
truth-apt content. Cite sufficient passages in supplied records; retain newly
needed passages beside findings.

For storage, retrieval, serving or direct use alone, with no relevant
transformation or knowledge-production claim, complete the member with its
material ledger functions (or the type's empty-ledger statement), any
operational/behavioral authority, bounded absence of a relevant check or
epistemic authority, no-claim comparison and bounded conclusion.

For an unsupported knowledge-production claim, inventory its claimed object
and classify its transformation and functions against the missing implemented
or observed route; continue with other evidenced routes. Scoped absence
excludes no informal or unobserved route outside the search boundary.

## Coordination and acceptance

The memory analyst runs in parallel; do not inspect its report. Cite only
your declarations, `runtime` records and the Source register in `boundary`.

Submit a member conforming to the supplied type, with resolved citations.
Check coverage, object/function separation, edge classifications, evidence
support and bounded licenses. Run `commonplace-validate --full <output>`
and repair detectable defects before submitting; validation alone does not
establish semantic coverage or support.
