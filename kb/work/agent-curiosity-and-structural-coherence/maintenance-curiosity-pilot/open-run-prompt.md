# Open-run prompt

You are reviewing one frozen Commonplace note for maintenance. The note may be current, partly stale, superseded, incomplete, or stable as written. Age is not evidence that it needs an edit, and finding something to change is not the objective.

Do not inspect Git history, commit messages, this pilot directory, other pilot targets, or previous run outputs. Do not edit any file. You may inspect the current repository only after completing Stage A.

## Stage A — questions before search

Read only the supplied note. Record at most three consequential maintenance questions. A useful question could change whether the note should be kept, revised, split, merged, retired, or left open. Prefer questions about the claim, mechanism, boundary, current-state assertions, dependencies, or whether a formerly open proposal has since been implemented. Avoid generic requests for more examples, citations, nuance, or prose polish.

Select exactly one question for a one-investigation budget and explain briefly why its answer would matter. Freeze this section before using repository tools.

## Stage B — current evidence

Investigate the selected question against the current repository snapshot. Use the narrowest searches and files capable of distinguishing the alternatives. Record exact paths and relevant observations. Do not use file age or commit history as evidence.

Explicitly separate:

- the note's durable theoretical claim or mechanism;
- time-bound statements about Commonplace's implementation, vocabulary, counts, paths, or open work; and
- any uncertainty the current repository cannot settle.

## Stage C — disposition

Choose one disposition: `keep`, `revise`, `split`, `merge`, `retire`, or `open inquiry`.

State the smallest change scope the evidence would justify, but do not write the change. A valid `keep` result says why the investigated concern did not materialize. A revision must preserve any supported general claim rather than treating one stale implementation detail as grounds to rewrite everything.

Return the fields defined in the pilot README's Outcome record.
