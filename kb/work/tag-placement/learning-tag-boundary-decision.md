# Improvement-loop and continual-learning: boundary and application

## Operator decision

On 2026-09-27 the operator asked to revise the heads and apply the distinction
after discussing whether improvement-loop and continual-learning were separate
tags. Keep both: improvement-loop concerns how candidates are searched for,
evaluated with possible rejection, and made operative; continual-learning
concerns learning through persistent changes outside model weights, including
its governance and relation to weight updates. Neither name replaces the other.

The heads retain their existing inclusion paragraphs and parent relations.
Added boundary paragraphs make the different questions explicit and permit
both tags when both questions are substantive. Continual-learning does not
require a separate candidate-admission gate. Saving a file or issuing a one-off
prompt alone does not meet its learning condition. The related-tag descriptions
now preserve the direct-update distinction instead of implying that all
continual learning uses proposal selection.

Before this pass each tag had nineteen members. Their titles, descriptions,
and curated routes were checked against the clarification; no existing
assignment is removed and no subject area is expanded. This is not a new
independent semantic assay of those members. The twenty pending suggestions
below were checked by reading their note bodies. Note arguments are unchanged.
