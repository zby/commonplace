# Phase 2 — Make every membership consumer use the resolver

**State:** blocked only on Phase 1's resolver contract. Inventory can begin
earlier.

## Outcome

Remove independently reimplemented tag-membership sets. Validator, generated
augmentation, connect, navigation recipes, impact expansion, and every mark
skip rule consume the same projection-relative resolver result.

This is the phase that closes the original behavioral contradiction. It does
not relocate heads.

## Consumer inventory

Inventory by role before editing:

- tag-readme mark validation and invalidation/impact expansion;
- ProperDocs tag-page augmentation and footer routing;
- `cp-skill-connect` candidate discovery;
- AGENTS and navigation by-tag recipes;
- any writer, reviewer, or full-pass rule that skips work because `complete` or
  `covered_by` is present;
- installed copies and generated templates of those consumers.

The inventory is complete only when code search and manifest projection agree;
one named consumer is not evidence that all consumer classes were covered.

## Work

1. Replace mark validation and impact selection with the resolver.
2. Replace ProperDocs membership enumeration with the resolver while retaining
   authored head content and build-time generated tails.
3. Put connect's deterministic tag/path collection behind the package resolver
   rather than shell pipelines or runtime-specific Grep/Read choreography.
4. Rewrite recipes and skip rules to call or describe the resolver. State next
   to every mark shortcut that task-level discovery remains open.
5. Add one cross-consumer fixture whose same tag spans at least two
   participating collections plus an independent embedded KB.
6. Use V1 to run all source and installed scopes without fail-fast behavior.

## Acceptance

- Every inventoried consumer returns or consumes the same membership set.
- The `learning-theory` and `artifact-analysis` starting witnesses either
  satisfy the adopted contract or fail visibly until repaired.
- A mark can suppress a redundant exact membership query but never broader
  task search.
- A zero-member query returns an empty bounded result and cannot widen into a
  repository search.
- Source, fresh-install, and vendored-root fixtures agree on root isolation.
