## 1. Resolve the conflict over validator-kept changes (definition, check 4, note)

**Change:** Delete the bullet "A deterministic check is a degenerate on-balance judgment" and replace it with this rule: a change kept because a fixed check passed meets condition 2 only when the named system's own loop holds, and can revise, the judgment that this check is enough for this kind of change. Rewrite check 4 to place the individual patches as well as the repair rules: patches are outside for the repairer alone, and inside for team plus repairer. If the note is to carry the "one measure is the only reasonable one" case, add it there explicitly.

**Reason:** As written, the draft says a validator-passed change meets condition 2. Check 4 places the repairer alone outside on J, and the draft's own "What the term does not cover" excludes retention bound to a formula. The draft's own example also undercuts the premise: check 4 notes that "the link resolves" is not the only reasonable measure, because it may not resolve to the intended page. The on-balance note defines no degenerate case of this kind.

## 2. Settle what "each change" in condition 2 quantifies over (definition, checks)

**Change:** Say whether condition 2 covers every write to the named store or only changes retained as learning. Also allow a judgment to attach to a standing retention policy, such as ADR 085's deletion rule or a rule that keeps logs, so that it need not be made for each individual write. Then add a check case for a write kept under such a policy, and re-place KSI explicitly under the chosen reading.

**Reason:** The draft's stated purpose is to cover all learning in Commonplace. But Commonplace keeps many writes by default (logs, ingests, automatic fixes), and "Retention without a judgment" puts these outside the term. So the scope claim and the condition cannot both hold. The checks already flag that KSI's placement flips on this question.

## 3. Align the wording of condition 2 with the test actually applied (definition)

**Change:** Replace "not bound to one measure fixed beforehand" with the checks' wording: "not bound to a measure the loop cannot question or set aside." Then make the training-team example, the PRODIGY background entry, and "What the term does not cover" use that same wording.

**Reason:** "Fixed beforehand" tests the wrong property. It would exclude a loop that keeps a pre-registered requirement it is free to revisit, which the note explicitly endorses as binding. It would also admit a loop that picks its measure ad hoc but can never question it. Every placement that matters (gradient training, PRODIGY, Recuris) actually turns on whether the loop can question the measure, not on when the measure was chosen.
