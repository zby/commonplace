**On the question itself:** a learner that uses one fixed measure should be outside the definition only when its named system cannot question whether that measure is enough. Using one measure should not by itself exclude it. The draft already leans this way: case 8 admits a fixed score that the loop may override, and PRODIGY-with-Minton is admitted. But it places this test in the wrong condition and states it in ways that contradict each other.

### 1. Move the fixed-measure exclusion from condition 2 to condition 3

**Draft definition**
- Rewrite condition 2 as: "each change is kept or dropped by an on-balance judgment, which may reduce to a single measure where that is the only reasonable one."
- Extend condition 3 so that later rounds can find wrong both a retention verdict and the basis on which retention was decided, including the claim that a measure suffices.
- Edit the "Retention bound to a fixed measure" bullet and the PRODIGY background entry to say they fail condition 3, not condition 2.

**Checks**
- Change J and C to match.
- Rewrite the discriminators for case 4, case 7 (including the "regardless of whether … C" sentence) and the Recuris row so they cite C.

**Note**
- Add the sentence the draft's "degenerate judgment" bullet relies on but the note never states: when one measure is the only reasonable one, the on-balance verdict is that measure's verdict.

**Reason:** As written, the "degenerate judgment" bullet says a validator pass meets condition 2, while case 4 and the "does not cover" list say a validator-only repairer fails it. The draft's own text ("what must stay open is the claim that this one measure is enough") names the real difference. That difference is whether the judgment about the measure can be criticized, which is condition 3's subject. "Fixed beforehand" is the wrong test: a measure chosen afterwards that can't be questioned should fail, and a fixed score the loop can override (case 8) should pass.

### 2. Settle what "each change" covers, and let changes admitted by a rule count when the outer loop owns the rule

**Draft definition**
- State that condition 2 applies to candidate learning changes, not to every write such as logs and attempt records.
- State that a change admitted by a rule meets condition 2 when the rule was adopted by the system's own outer loop and that loop can revise it.

**Checks**
- Answer the "Which writes count as changes?" question in the same terms, and update KSI's store note to match.

**Reason:** The draft says the term must cover all learning in Commonplace and is checked on the outermost loop. Yet condition 2 requires that each change be kept by a judgment, and most Commonplace changes are admitted directly by validators. Without this clause, either the stated purpose fails or the outermost-loop rule silently overrides the "each". The checks file already flags the same gap in the KSI placement.

### 3. Add check cases that pin down the fixed-measure boundary

Add two stipulated cases to the checks file:

- **(a) Inside on C.** A single automated loop keeps changes only when a validator passes. The same loop can, for a stated reason about future work, suspend or narrow that validator and later reverse that decision.
- **(b) Outside on C.** A loop keeps changes by a measure that is in fact the only reasonable one for its question. Nothing inside the named boundary can raise whether it suffices.

**Reason:** Cases 4, 7 and 8 mix measure-fixing with other differences: team versus program, and theory criticism versus retention. So none of them isolates the question under review. Case (a) shows that one measure plus in-loop criticism is enough. Case (b) shows that being correct by luck is not enough. Together they make the answer to "should a fixed-measure learner be outside?" a tested placement rather than an inference.
