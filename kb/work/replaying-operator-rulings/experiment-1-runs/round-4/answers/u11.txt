**Answer to the question.** A learner should not fall outside the definition merely because it keeps or drops changes by one fixed measure. It should fall outside when the named system cannot question that measure.

Most of the materials already draw the line there:

- The checks phrase J as "without being bound to a measure it cannot question."
- The draft's own exclusion speaks of a formula the system "cannot question whether … is the right one."
- Case 4 and the Recuris row both turn on whether the measure can be revised inside the boundary.

Two parts of the draft draw the line elsewhere:

- **Condition 2 as written** ("not bound to one measure fixed beforehand") would exclude Commonplace's own validator loops. That defeats the stated purpose of covering all the learning in Commonplace.
- **The "degenerate judgment" note** says a validator pass "meets the condition" without qualification. That conflicts with case 4, where the repairer alone fails J.

## 1. Restate condition 2 so that an unquestionable measure is what excludes, and qualify the degenerate-judgment note

**Change (definition).** Replace the last sentence of condition 2 with: "The judgment is a step of the learning loop. It may apply a single measure, but the named system must be able to question whether that measure suffices and revise it." Then change the note's sentence to: "So a change kept because a validator passed meets the condition when the named system can also revise the validator; the validator alone does not."

**Reason.** As drafted, condition 2 contradicts the degenerate-judgment note, the "does not cover" bullet, and checks J, 4, 7 and 8. With one test, all four place fixed-measure learners consistently. The new test also keeps the intended exclusions: Recuris, the case 7 builder, and PRODIGY alone stay outside because their measures lie beyond what they can revise.

## 2. Add a check for the case the purpose depends on: a validator-kept change inside Commonplace

**Change (checks).** Add case 9: "Commonplace, store = the KB; a link patch kept because the validator passed. The system's outer loop can judge where the validator suffices and change it." Expected result: inside on S, J, C, with the patch learned only if the comparison shows it. The discriminators should be:

- against case 4, the repairer as a separate system is outside;
- against case 5, the weights fail S, so an outer loop cannot bring them in.

Also extend case 4's placement from "its repair rules" to the patches that the team-plus-repairer system keeps.

**Reason.** The draft says the term covers all learning in Commonplace and that "a loop with a fixed measure may sit inside a deliberative one." No check currently tests that claim, so a wording change could silently drop validator-retained changes. The added case also blocks a misreading of the outermost-loop rule. Gradient training inside a research team is excluded for illegibility (S), not for its fixed loss.

## 3. Have the on-balance note state the degenerate case the draft relies on

**Change (note).** Extend "Known requirements need not be weighed afresh" with an explicit sentence: "When only one measure is reasonable for a question, such as whether a link resolves, the on-balance judgment reduces to it. That only one measure is reasonable is itself a claim from purpose, and it remains open to challenge, for example by asking whether the link resolves to the intended page."

**Reason.** The draft's handling of fixed measures cites this note, but the note only says that a pass answers a defined question. It never says that a single measure can be the whole reasonable set. Stating it in the note grounds change 1 in the same "reasonable measures" machinery used for the learned/open verdicts. It also explains why a validator pass alone does not make a change *learned*, as case 4's discriminator already says.
