# Ten candidate changes to the deliberative learning draft

1. **Change:** Change the genus from "learning that meets three conditions" to "a way of learning (a process of retaining changes) that meets three conditions."
   **Adopt.** The draft says Simon's learning is a lasting change in capacity, yet also says a loop that improves nothing is "still doing deliberative learning," so the genus "learning" contradicts the no-success-condition paragraph.

2. **Change:** Reword condition 2 from "not bound to one measure fixed beforehand" to "not bound to a measure that the named loop cannot question." Then state in the deterministic-check note, and in the autonomous claim's "no measure given to it," that a validator pass meets the condition only when the same loop can question whether that validator suffices.
   **Adopt.** As written, the note admits any validator-passed change while the exclusion and case 4 (repairer alone is outside on J) reject it, and validators are themselves measures fixed beforehand.

3. **Change:** Define what "each change" quantifies over: the candidate changes put up for retention in the named store, not every write to it.
   **Adopt.** The checks show the placement of Knowledge-Centric Self-Improvement (KSI) flipping on this. Read literally, Commonplace itself would fail, since it logs and writes things no judgment selects (case 2).

4. **Change:** Narrow the purpose sentence to say the term covers the learning of the Commonplace system judged at its outermost loop, not every inner loop or write within it.
   **Adopt.** "All the learning that happens in Commonplace" overclaims, because the draft itself excludes fixed-measure inner loops and judgment-free retention that occur inside Commonplace.

5. **Change:** Rephrase condition 3's last sentence as a capability: the system *can* correct, by changing what it does next and undoing the change where possible.
   **Adopt.** As written, it reads as an obligation to undo whenever possible and as a claim that correction happens, which clashes with the note that the condition "does not require that a change can be undone" and with case 3.

6. **Change:** Require that retained changes be reversible.
   **Reject.** Commonplace deletes things, and case 3 places correction on the judgment, not on restoring the file.

7. **Change:** Require a language-model judge, so that only autonomous loops qualify.
   **Reject.** Human and mixed judgment are explicitly members (case 1, Warp, the bootstrap), and autonomy is the separate conjecture under test.

8. **Change:** Require content-directed criticism, so that each retained change carries an explanation that can be criticized.
   **Reject.** Case 6 deliberately keeps the unexplained prompt variant inside, and adding this would merge the term into the theory-builder definition.

9. **Change:** Add a success condition, so that only loops whose retained changes improve later work count.
   **Reject.** The draft deliberately separates the process from the "learned" verdict, and merging them would make the name usable as evidence of improvement, which the Misuse section forbids.

10. **Change:** Count "better on some measures, tied on the rest" as "learned."
    **Reject.** That would break alignment with the on-balance note, which reserves improvement for "every reasonable measure favors the successor," and would let a single-measure gain pass as learned.

## The three I would make

- **#2 (condition 2 and the deterministic-check note).** This is a direct internal contradiction that already misplaces a stipulated case.
- **#3 (the "each change" quantifier).** The checks file shows placements depend on it, and the literal reading excludes Commonplace itself.
- **#1 (the genus).** The definition's own sentences currently contradict each other about whether a loop that learns nothing is "learning."
