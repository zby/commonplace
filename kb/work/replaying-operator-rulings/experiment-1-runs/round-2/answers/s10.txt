# Three proposed changes to the deliberative learning draft

## 1. Delete the bullet "A deterministic check is a degenerate on-balance judgment"

Remove it from the notes on condition 2. Its claim that "a change kept because a validator passed meets the condition" contradicts condition 2 itself ("not bound to one measure fixed beforehand"). It also contradicts the exclusion "Retention bound to a fixed measure" and check case 4, where the repairer alone fails J. The outermost-loop rule already places validators correctly: a fixed check counts when it sits inside an outer loop that judges whether that check is enough. So the bullet adds a contradiction and does nothing else.

## 2. Change the scope of condition 2 from "Each change" to "The changes the named loop retains for future work"

As written, condition 2 can be read as covering every write to the store. The checks show this flips the KSI placement, because KSI logs every attempt but selects only the distilled claims. The same reading would also exclude Commonplace's own default writes, which defeats the stated purpose of covering all the learning in Commonplace. The draft already says a claim names a system and the store it changes. Tying the quantifier to that named store and loop resolves the problem without adding a new condition.

## 3. Cut the verdict list and its "three points" from "When a change was learned"

Keep the one-sentence definition of "learned" and the point that keeping a change is not the same as having learned it. For the verdicts, cite the on-balance note. The five verdicts restate that note almost word for word, and two parallel copies will drift. The draft has already started drifting: it drops the note's statement that "better on some, tied on the rest" can still justify the step. The term deliberately has no success condition, so the definition only needs to say where the success claim is defined, not repeat that definition.
