# Three proposed changes to the deliberative learning definition

## 1. Bind the judgment to the store it changes, and drop "checked on the outermost loop"

**Change.** Replace "They are checked on the outermost loop that the system runs itself" with this rule:

> A claim names a system, a store, and the loop that retains changes to that store. Condition 2 is met only by a judgment that is the step retaining changes to *that* store. Judgments made elsewhere, such as designers choosing a formula, count only for the store they themselves change.

Then rewrite the PRODIGY bullet so that it matches:

- **PRODIGY's learned rules:** fail condition 2.
- **PRODIGY's code and utility formula, as revised by Minton:** can pass.

**Reason.** The outermost-loop rule contradicts the draft's own model-training example. In that example, an inner loop (gradient training) is placed separately from the outer research loop. The bigger problem is that, as written, anyone can admit any automated system by drawing the boundary around its designers ("PRODIGY taken together with Minton"). That is exactly what the checks file forbids ("do not credit an automated loop with judgments its designers make elsewhere"), and it would make the term useless for comparing other people's systems.

## 2. Define "bound to a measure" by authority, not timing, and restrict the deterministic-check note to match

**Change in condition 2.** Replace "not bound to one measure fixed beforehand" with this test:

> Someone inside the named boundary can, within the loop, reject a change the measure would admit, or revise the measure, for a stated reason about future work.

**Change in the note "A deterministic check is a degenerate on-balance judgment".** Make it conditional. A validator-gated change meets condition 2 only when that same loop holds the authority to override or revise the validator. This is case 4: the repairer alone is outside; team plus repairer is inside.

**Reason.** As drafted, the note lets any fixed gate (Recuris's held-out gate, PRODIGY's utility formula) pass simply by asserting that its measure is "the only reasonable one". That contradicts the draft's own exclusion of "retention bound to a fixed measure". "Fixed beforehand" also points at the wrong thing. A measure the loop chose yesterday and can revise is fine. A measure fixed by someone outside the boundary is not, whenever it was chosen. The checks already apply the authority test ("who, inside the named boundary, may decide otherwise"), so the definition should state it.

## 3. Scope the quantifier in "Each change"

**Change.** Replace "Each change is kept or dropped…" with:

> Each change the claim covers is kept or dropped…

Then add that a claim must:

- declare which writes to the named store are candidate learning changes;
- state which writes are retained without judgment, such as attempt logs and indexes;
- exclude those unjudged writes from the claim, without counting them against it.

**Reason.** Almost every real system mixes judged changes with automatic writes. Under the literal "each change", KSI's placement flips depending on whether its attempt log counts. Left unspecified, appliers will resolve this inconsistently. Some will exclude nearly everything; others will quietly narrow the store until the claim passes. Requiring the scope to be declared makes placements reproducible across reviewers and keeps a claim about distilled guidance from passing as a claim about the whole system.
