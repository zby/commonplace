## 1. Condition 2: bind the test to whether the loop can question the measure

**Change:** Replace "It is not bound to one measure fixed beforehand" with: "The retaining step is not bound to any rule it cannot question or override, however many measures that rule combines and whenever it was fixed." Revise the deterministic-check note to match: a change kept because a validator passed meets the condition only if the same loop could have rejected or revised that validator.

**Reason:** As written, adding a second fixed test would move a system across the boundary, since it is no longer bound to "one measure". The checks reject that ("several tests in a fixed rule are still a fixed rule", Recuris). "Fixed beforehand" is the wrong discriminator: case 8 uses a score fixed in advance and still passes because the loop can override it. The current note says a validator pass meets the condition, which puts the lone link repairer of case 4 inside, against both the checks and the draft's own exclusion of "retention bound to a fixed measure".

## 2. Condition 2: limit "each change" to the changes the claim covers

**Change:** Replace "Each change is kept or dropped" with "Changes claimed as learning in the named store are kept or dropped". State that other writes to the same store, such as logs, caches and generated indexes, are outside the claim and do not disqualify it.

**Reason:** Under "each", a system that adds one automatic log write would fall out of the term. KSI's placement already flips this way depending on whether the store is the distilled guidance or the whole KB. That also defeats the stated purpose of putting all the learning in Commonplace under one name, because Commonplace makes many writes no one judges individually.

## 3. Condition 1: define legibility by function, not by medium

**Change:** Replace "prose, structured text and code" with "a store in which each retained change can be read and pointed at on its own, so that a judgment about that change can be made and contested". The list can stay as examples.

**Reason:** The medium list draws the line in the wrong place. Weights serialized as JSON count as "structured text", while a readable threshold stored in a binary config does not, so a change of file format moves a system across the boundary. The draft's own note says legibility matters because it makes a judgment about a single change possible. The criterion should state that property directly.
