**Correction:** `tests/scenarios/write-a-note.md` is wrong to say installed projects "copy COLLECTION.md and the type-specs" and have "identical forks." Under the shipped model, the project holds no copy of the library, so global type specs, skill bodies, and methodology notes are read in place from the installed package (located via `.commonplace/library.md`, with types at `../../types/` from the skill's real location); only the user's own `COLLECTION.md` files are scaffolded into the project. **Consequence:** a maintainer who checks Fork 2/3 context budgets against `kb/types/note.md`, `kb/instructions/cp-skill-*/SKILL.md`, or the `commonplace/kb/notes/` escalation path in an installed project will measure files that don't exist there, so the per-fork hop and byte accounting for the installed variant needs to be redone against library-resident paths.
