## 1. Make Condition 2 count judged rules and judged retention, so the definition can cover all of Commonplace's learning

**Change.** Reword Condition 2 so that a change qualifies if either:
- a judgment made it, or
- it came from a standing rule that the system adopted by judgment and can still revise.

Also count a judgment to keep or remove contents as the operative judgment, even when additions are automatic. Then update the other files to match:
- **Draft.** Change the session-trace bullet and the "Change without a judgment" exclusion.
- **Checks.** Change case 2 to "inside, for the logging rule". Change case 11 to "outside only if the solver cannot revise its store-everything rule". Answer the open question "Which writes count as changes?" by applying the quantifier at the level of the rule.

**Reason.** The draft says the term should "put all the learning that happens in Commonplace under one name". It also says that storing session traces in Commonplace "is learning but not deliberative", which contradicts that purpose. The only cases that Condition 2 excludes and Condition 3 does not are of this kind: contents added by a deliberated rule, or added by default and later pruned on evidence. Excluding them contradicts the draft's own remark that introducing automatic storage "is itself a change that can be deliberated and later revisited".

## 2. Stop requiring the judgment in Condition 2 to be an "on-balance" verdict that the change improves later work

**Change.** Rewrite Condition 2 as "a decision to make the change, reached by weighing its expected effects on later work". This decision may rest on an Open comparison or on reversibility. Keep "on balance", in the note's strict sense, only for the "learned" verdict. Add a sentence to the note saying that a decision taken under an Open verdict is the normal input to the learning loop.

**Reason.** The note defines "on balance" as every reasonable measure favoring the successor, so Condition 2 currently requires the judge to judge the change an improvement. That excludes decisions the draft and note explicitly endorse. Examples are ADR 085's deletion, taken "without claiming it won that comparison", and keeping the routing instruction because reversibility "tip[s] the judgment" while "not evidence that the instruction has improved later work". "Open is the usual verdict for a recent change", so as written the condition excludes most real Commonplace changes, even though no other condition excludes them.

## 3. Treat Condition 1 as a scope condition and give "legible" a test that cases 14 and 16 apply consistently

**Change.** Say plainly that Condition 1 restricts the term to stores whose units the judging step can read, cite and trace to a particular change, and that it is not needed for Condition 3. Move "legibility enables targeted criticism" into a note on the benefits of legibility. Then re-check case 14 against case 16 under that test.

**Reason.**
- **The stated reason is not what does the work.** The draft accepts coarse stack rollback as satisfying Condition 3 (graded attribution, case 16), so its stated justification for Condition 1 ("targeted criticism") excludes nothing. Its real role is excluding opaque-parameter learners such as gradient training.
- **There is no test for which numeric state counts as legible.**
  - Case 14 passes Condition 3 only through changes in numeric selection weights, which the draft counts as store edits.
  - Case 16 fails Condition 1 because a probability distribution is "opaque", even though Schmidhuber's stack records each modification separately.
  - Without a stated test, the two placements look stipulated.
