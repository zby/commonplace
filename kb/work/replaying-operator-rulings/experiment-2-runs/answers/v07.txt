**Adopt Version 1.**

1. Version 1's third condition preserves what the project was trying to name. The earlier name "conjectural learning" and the operator's rulings both treat judgments of improvement as conjectures that later evidence can overturn. Version 2 demotes that idea to an optional property, so the name no longer commits to it.
2. That condition is what separates the systems the KB most needs to tell apart. Under Version 1, a fixed-benchmark prompt search (case 9), the Darwin Gödel Machine (case 13) and the lone link repairer (case 4) fall outside, while the Huxley-Gödel Machine (case 14) falls inside. Under Version 2, all of these become deliberative learners, and the difference is pushed into a side report.
3. If correction is not required, the single-loop/double-loop classification has a gap. Both versions define single-loop as making *and reversing* changes under a fixed criterion. A Version 2 learner with correction *none* and no displacement, such as a memory file nobody revises, is then neither single-loop nor double-loop.
4. Version 1 matches the checks file, the double-loop ruling and the graded-attribution cases (13–16) without flipping any placement. Version 2 would flip several placements and explains none of the flips.
5. Version 2 also has unrevised remnants. It still says "if each meets the three conditions", and it has a bullet that says "Neither is a condition" and then "Being open to criticism is not a condition."

**What to keep from Version 2:** the bullet "A claim about capacity needs an account, and a claim about an episode needs the episode." It requires saying what brings the evidence back, who or what considers it, and which edit can follow. It should go into Version 1's notes on condition 3, together with Version 2's example that addressability does not guarantee correction. Version 1's condition 3 is a capacity ("evidence *can* count against"), and that requirement makes it checkable. It also blocks the easy misreading that an editable store is enough to meet the condition.
