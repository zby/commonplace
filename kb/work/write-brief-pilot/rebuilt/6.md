# Brief: Analyse an agentic system (main skill)

## Governing question

How should a single coordinator agent turn inspectable sources for one external agentic system into a characterization that is evidence-bounded, reproducible, and comparable across systems? The system may be a runtime, an orchestration framework, a memory/context system, or a narrower model-dependent mechanism. The output is one exact result and a generated public review. Neither may overclaim what the system does, whether it learns, or what its guarantees cover.

## Audience and reader update

The executor is a forked Opus agent that invokes this skill with no prior context. The secondary readers are maintainers who rely on the skill as the owner of production for the `agentic-system-analysis-result` and run-state types. The same readers use it for the publication tooling (ADR 023 quote anchoring, ADR 083 carriers following exact-result consumers) and as the entry point from the agent-memory-systems index. The executor must be able to run the whole lifecycle on first reading: open the run, freeze sources, trace the runtime, run both lenses, reconcile, validate, publish, and hand off. It must know exactly where its authority ends.

## Target claim or purpose

A user-invocable skill whose goal sentence states the job: analyse one external agentic system at one frozen evidence boundary. It identifies what the system wires, where its responsibilities end, and what its memory/context and epistemic routes support. It runs a runtime baseline plus two mandatory lenses and writes one exact result. From that result it publishes a compact generated review. Memory/context analysis goes to a fresh specialist whose typed report the parent integrates.

## Must keep

- **Authority statement.** Say what invocation authorizes: the run directory, one generated review under `kb/agentic-systems/reviews/`, its identical retained result copy, and the memory specialist input and report. Say what it does not authorize: source worktree changes, indexes, surveys, transfer scans, landscape synthesis, other retained reports, and Git staging or commits.
- **Failure rule.** Fix correctable failures while the run stays `running`. Mark a run `failed` only on abandonment or uncertain public state. Never resume a failed run; start a new run ID. Keep no ledgers or receipts.
- **Destination inspection before any source reading.** Use the publication tool's metadata-only check and record the incumbent digest. Prohibit reading prior-review prose or audits. Prior-analysis exposure fails the run and requires a fresh coordinator.
- **Scope test and classification.** Include the scope test, the target classes, and the three boundary kinds. Out-of-scope and blocked results are typed and not published.
- **Source freezing.** Keep the allowlist and the limits on what a supplied repo authorizes. Git reads must be commit-addressed and never from the worktree. Non-Git sources become hashed immutable captures. Truncated output is not evidence. An absence claim needs a recorded search boundary.
- **Quote anchoring.** Retain minimal verbatim quotes for load-bearing findings, in the exact blockquote-plus-anchor format that publication matches against the pinned source. Quote each passage once in the result. The result must not depend on the local specialist report.
- **Conclusion-status ladder.** Keep the vocabulary and the rule that no status is ever upgraded (presence to activation, claim to affordance, affordance to wiring, and so on). Keep the definitions of read-back, activation, behavioral authority, and guarantee strength.
- **Theory-builder vocabulary.** Keep the four conditions, each with its own status. Keep persistence and addressability as graded findings above the minimums. Keep learning separate from membership, rationale separate from criticism, reflection, autonomy recorded role by role, and revision selection as "reach among revisions that fit". These must track the canonical definitions in `kb/notes/definitions/`.
- **Canonical register.** Keep the register discipline (`SRC/CMP/OBJ/RTE/CLM/ABS/BAP`): parent-owned monotonic IDs, no reuse, splits with superseded dispositions, and lens-local tags.
- **Runtime baseline.** Trace an ordinary invocation. Enumerate alternate paths before judging any guarantee. Pick two to four forcing cases. Run dynamic checks only after preflight; a check that never reached the target supports nothing. Audit each route. Inventory distributed-parametric components with their pin or drift status. Record revision-admission routes with proposer, decider, veto, answer oracle, and operating mode, without assigning an autonomy grade.
- **Lenses.** Both lenses always run, at brief or full depth. The memory specialist gets a frozen, hashed input with no legacy reviews. The epistemic lens goes through the separate epistemic-architecture procedure as a sparse overlay, keeping its own status vocabulary.
- **Reconciliation.** Use exact ID tokens. Record conflicts and do not silently strengthen them. Claim independent convergence only when it was actually independent.
- **Synthesis shape.** Organize the synthesis by system. Forbid rankings, adoption advice, epistemic grades, Commonplace deltas, and maturity models. State theory-builder conditions, learning, reflection, autonomy, and self-improvement as independent properties, not a ladder.
- **Semantic verification and publication.** Run semantic verification before publication; structural validation is not enough. Publish through prepare-then-publish, with the exact generated-review frontmatter fields, retention of identical bytes, incumbent recovery copies, and rollback behaviour.
- **Downstream staleness.** Keep the downstream staleness reporting, noting that the comparisons and historical CSV are not rebuilt. Transfer scans are separately commissioned, run only after completion, and never edit the analysis.
- **Handoff and Verify.** Keep the handoff command and the Verify checklist.
- **Rests-on links** to the runtime-separation, memory-crosscutting, storage-versus-activation, and definition notes.

## Exclusions

- Do not explain why each step exists; that rationale lives in the linked notes.
- No Commonplace transfer recommendations. That is the scan skill's job.
- No landscape synthesis. That is a separate skill.
- No drafting of a second memory analysis by the parent.
- No resume or recovery protocol for changed source pins.
- No legacy review type as a production target.
- No JSON validation receipts in the result.

## Scope, modality, and terminology

Prescriptive and imperative, with explicit decision points ("if out of scope… stop"). Terms must match the result type and the canonical definitions exactly: the conclusion statuses, "theory builder", "addressable", "tentative theory", "behavioral authority", "read-back", and "activation". Never translate the epistemic procedure's `implemented` into a conclusion status. Describe source-native mechanisms before mapping them to Commonplace ontology. Keep the text dense but executable. It is long because the result contract is large, not because it carries rationale.

## Reserved decisions

- Changing the authorization boundary, or letting the skill commit or touch comparisons.
- Changing the conclusion-status vocabulary or the theory-builder criteria. These are owned by the definitions and the result type.
- Relaxing the source-only independence rule or the fresh-specialist requirement.
- Adopting the open proposals that point at this skill (normalized autonomy and revision fields, checked inline shared blocks).
- Changing the model or fork settings.
