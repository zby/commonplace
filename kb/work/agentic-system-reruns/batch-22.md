## Source policy

The fresh route includes acquisition, rather than borrowing an old checkout or
snapshot. For the nine known Git sources, use the ordinary fresh-analysis
default: acquire the repository's default-branch tip at launch time and freeze
its full commit. Old commits in the manifest are provenance, not the new run's
revision selection. This can change the evidence version; a later result must
not be presented as a controlled same-pin repair experiment. No new commit or
source snapshot has been acquired or selected during this preparation.

For NAMS, freshly capture the supplied document under the new boundary job's
source rules, retaining its exact URL, bytes/hash, capture time and coverage
limits. Do not reuse the old snapshot, treat the blog URL as a repository or
silently substitute a guessed implementation repository. If further sources are
needed, the native source boundary must establish them explicitly.

For the three source-reselection cases, a later authorized source-selection
phase may inspect and acquire candidate evidence for the named system in its
own new workspace. Before opening the operational analysis, record the chosen
identity, implementation boundary, source route and exact revision or document
hash. Selection must establish an implemented system appropriate to the requested
question; a fresh copy alone does not establish that. Do not guess an archive
commit, silently substitute Letta Code, choose a different catalog-listed
project, infer private implementation access or classify a kit from its link.
A different project identity or an expressly historical Letta target returns to
the operator with a concrete source proposal before analysis. If no suitable
implementation is found, retain a source-selection stop, not an invented source,
a forced analysis or an automatic inventory exclusion. These gates belong to
batch 22; they do not remove its three targets.

## Isolation and preservation

All thirteen get newly prepared worktrees and newly allocated immutable run IDs at
a committed method revision selected for the eventual release. No new method
is pinned merely because preparation currently runs at an older checkpoint.
Use the ordinary
[analysis skill](../../agentic-system-analyses/instructions/analyse-agentic-system/SKILL.md)
and its prepared command environment. Do not reuse a previous preparation,
reset an old run, copy accepted members, import old audit feedback, clone from
old checkouts, use alternates/shared object stores, or move/delete old files.
Fresh analytical workers receive source-only native handoffs, not predecessor
reports or this workshop's semantic findings. Parent-held lineage metadata is
for protection and bookkeeping, not analytical evidence.

The six incident predecessors remain held, with unresolved collateral effects
and original evidence intact. New content does not establish that old foreign
writes/removals were harmless. Ownership of each new destination must be
established independently. The operator has explicitly commissioned new lineages
for ACE and Agent Skills without requiring resolution of the old unfinished run
or reservation. Their old mutable attempt state is not a launch gate for the
new work. This does not authorize resuming, resetting, taking over or cleaning
an old workspace, terminating old writers, or accepting unknown past collateral
loss. Keep new writes disjoint even if an old session remains active.

Do not touch any old run, preparation, source tree, snapshot, publication,
refusal, reset archive or integration record. Preserve all existing canonical
sets and root files. Proposed new destinations and sibling preparation records
must be absent, not symlinks, and disjoint from every predecessor. Existing
paths are a stop, not permission to reuse or clean them. Preserve failure and
partial-acquisition evidence; no automatic retry or cleanup.

## Release and execution boundary

This is **batch creation only**: no worktree preparation/install, network probe,
clone/fetch/capture, run opening, native reset/judge/advance, model coordinator,
publication, exclusion, integration or owner release has occurred. The operator
separately authorized committing the preparation and contract clarification;
that does not authorize execution or publication/integration commits.
The [checker](./bash-22.sh) defaults to read-only `--check` and has no launch
mode. A successful check establishes bindings and destination absence, not
writer idleness or source suitability.

The [profile contract](../../agentic-system-analyses/types/agentic-system-memory-profile.md)
now explicitly counts a warranted local learning negative toward partial
classification, without deriving system-wide absence under incomplete coverage.
The validator and its tests have not yet been aligned. This contract-only
change is not a runnable method release. Finish that alignment and its required
verification before admitting new runs against the changed contract, including
Secure LLM Wiki. Do not patch its old frozen method or supply its old audit as
source evidence to fresh workers.

Before eventual launch: authorize acquisition and analysis, select a committed
method, establish exclusive ownership of each new destination, recheck canonical incumbents by exact
source identity, and finish an execution release record. Source-selection
cases must resolve their gates before operational analysis. Where a different
source identity changes the target, obtain the operator's mapping decision.
Use project-scoped analytical delegation through the exposed harness tool;
never substitute a Bash agent CLI. Prefer serial target admission initially;
internal worker scheduling follows the native driver and its limits. Stop on
unsupported interfaces, source ambiguity, preparation/acquisition failure,
uncertain effects or any unexpected external write. Do not silently retry or
advance past such a stop.

New completed publications require a new fixed intake and independent exact-byte
audit, including operational scope, followed by separate integration authority.
They do not inherit old positive audits or clear old incidents. A source stop or
local out-of-scope result is not publication completion.
