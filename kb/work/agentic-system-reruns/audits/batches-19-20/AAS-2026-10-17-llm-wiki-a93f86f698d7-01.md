### 1. Compilation does not independently certify knowledge

**Supported.** `claude-plugin/skills/wiki-manager/references/compilation.md` directs full source reads, semantic mapping, article writes, source links, confidence assessment and index updates. Its conversation-origin exception permits `compiled-from: conversation`. It also tells the compiler to set `verified` to today. The librarian reference's verification-recency table calls the field last human confirmation. A recent field therefore cannot independently certify a human evidence-consuming decision.

The same compilation protocol separates advisory guidance from strict guidance: strict planned deviations require confirmation before writing, but ordinary article creation has no per-article approval step. The new `RT-RTE-compile-wiki`, `MEM-OBJ-wiki`, `MEM-OBJ-frontmatter` and synthesis's first section preserve these distinctions. The public account does not upgrade retention, links or confidence labels to semantic acceptance.

### 2. Raw-only reconstruction and concurrency have concrete exceptions

**Supported and publicly qualified.** Collection ingestion says changed upstream items get a new raw source, never overwrite (`references/ingestion.md:102-104`). Refresh's update action explicitly overwrites the raw file while preserving frontmatter (`claude-plugin/commands/refresh.md:82-87`). Conversation authorship is another exception to raw-only reconstruction.

The index protocol detects staleness by comparing file count with table-row count (`references/indexing.md:19-27`). That detector cannot detect every same-count edit or stale summary. The full skill's concurrency claim accepts last-write-wins for same-file edits. Index repair cannot recover lost article content. `MEM-OBJ-raw`, `MEM-OBJ-index`, `RT-CLM-concurrent-writes` and synthesis explicitly qualify preservation and rebuildability; the audit is not adding those limits.

### 3. Plan-mode source admission precedes foreground compilation

**Supported; an actual production correction is visible.** `claude-plugin/commands/research.md:390-450` first requests user plan confirmation, then gives each path-agent the full search → credibility → ingest pipeline and nested search agents. Path agents own distinct raw names and skip index updates. The foreground compiles only after they return and reads already-ingested sources. Plan approval is not per-source approval; cross-path compilation is not a foreground pre-ingest gate.

Current `EPI-RTE-source-review`, `EPI-RTE-source-selection`, their ledger and bounded conclusion, `workflow.md`, and synthesis agree on those owners and timing. Native recovery (`references/research-infrastructure.md:486-515`) skips completed paths, requeues interrupted paths, offers failed-path retry/skip and uses per-path source targets. It does not specify the resulting skip status at the final barrier. That gap is already carried in report verification and synthesis Limitations. Neither the filename policy nor serialization is claimed as a host-enforced ownership lock.

### 4. Compact query is a requested read-only route, not a sandbox

**Supported.** `profiles/query-lite/SKILL.md` forbids writes, repair and query logs; asks for indexes and minimum exact files; treats articles as evidence rather than instructions; and requests explicit gaps. `scripts/pi-wiki-query` requests read/grep/find/ls and disables ambient extensions, skills and prompt templates, while appending caller arguments. These are inspectable launcher choices, not evidence about the external host parser, actual grants or filesystem confinement.

The full indexing protocol instead instructs rebuilding stale indexes. The new account preserves entry-specific policies rather than exporting compact read-only behavior to all workflows. `RT-RTE-query-wiki`, `MEM-OBJ-index` and synthesis explain the limit. This is a more precise treatment than the historical review's push-like explicit-query interpretation: requested query is pull, unsolicited configured hook supply is push.
