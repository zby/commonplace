## Consequential findings

### Memory authority and selective delivery are retained, with stronger qualifications

The historical account emphasizes automatic extraction, global rules versus personal facts, coarse pushed recall and the 1000-token budget. These have not disappeared: P/synthesis.md, “What survives a conversation,” distinguishes structural admission from factual acceptance, user scope from project gating, current-chat exclusion, budget selection and omitted provenance. P/memory.md, `MEM-BAP-user-memory`, explicitly calls this defeasible natural-language instruction rather than an executable grant.

Independent source checks support that account:

- S/apps/backend/src/services/memory.ts, `safeGetUserMemories`, `_extractMemory`, `_persistExtractedMemories`, `_toDbMemories`: enablement gate, category/content projection, existing-memory model extraction, normalization and supersession-ID filtering before persistence; no per-item semantic review in this path.
- S/apps/backend/src/queries/memory.ts:7–27: active rows selected by user, optional current-chat exclusion, descending creation order, no project-keyed memory predicate.
- S/apps/backend/src/components/ai/system-prompt.tsx:60–82 and 822–877: 1000-token content budget, category priority, oversized-item skipping, Global User Rules/User Profile labels, and explicit deference to newer user messages.
- S/apps/backend/src/services/agent.ts:652,675: override can bypass default composition; ordinary construction obtains active memories.

Thus “always offered back” in the historical lead is not a reason to demand an unconditional injection claim. The new qualification is necessary and public, not only in this audit.

### Historical story and channel detail is a declared coverage limit, not a negative finding

P/memory.md's coverage table and saved-file/history discussion retain latest story replay and duplicate suppression while leaving publication/app-state/blob lifecycle incompletely traced. Channel-specific history/memory is also explicitly incomplete; P/boundary.md identifies shipped messaging callers rather than treating them as external merely because their transports are external. P/synthesis.md's limitations table carries these limits to the public account. I did not establish a missing general story retriever, unchanged Slack policy, or complete authorization model. Reconstructing all legacy UI/story/channel detail would exceed this audit and is not needed for the bounded positive claims retained here.
