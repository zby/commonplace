## Consequential discrepancy checks

1. **Historical “lock” and two-phase ingest wording is too strong without qualifications.** S/internal/core/ingest.go reads all current entries and opens lifecycle state; `FinalizeIngest` in S/internal/core/ingest_finalize.go rereads the live inbox, archives its entries, clears it, scans, optionally commits and completes the row. It accepts no prepared subset or semantic completion receipt. This supports the publication's distinction between a session row and enforced partial-batch safety. P/synthesis.md, “Capture becomes a mechanical session, then agent-written content,” explicitly warns about unprocessed and concurrently appended entries, nontransactional recovery and caller inspection of `already_in_progress`. The historical account's favorable lock description does not warrant weakening these warnings. No target execution was performed by this auditor.

2. **“Deterministic upkeep only” does not guarantee meaning preservation.** Historical write-side treatment classifies collection regeneration as derived-view upkeep rather than synthesis. S/internal/collections/books.go:29–42 and 89–106 infer a probable title from attribution separators and emit it as a book grouping; a location can occupy that position. S/internal/collections/projects.go:60–65 maps `stable` to `Shipped`. P/synthesis.md, “Retained content and access state have different consequences,” names both non-entailment mechanisms and correctly labels them source-level deductions, not executed counterexamples. Literal `book:` imports remain separate. This is useful refinement, not an unsupported claim of observed fabricated content.

3. **The missing-frontmatter contradiction has an implementation-supported public resolution.** S/internal/core/scan.go:221–232 deletes the frontmatter row on parse failure despite its comment that path queries should succeed. S/internal/manifest/wikilinks.go:74–83 lists only joined frontmatter/file rows; S/internal/manifest/queries.go:30–35 begins Query from that list. Ordinary Query visibility therefore does not follow from scan tolerance. P/reconciliation.md preserves the discrepancy; P/report-verification.md resolves it against implementation; P/synthesis.md's limitations table states the exclusion and rejects the comment as a guarantee. Keeping the historical reconciliation record is not a concealed unresolved public promise.

4. **Graph rebuilding is not complete withdrawal.** S/internal/core/scan.go:142–169 replaces outgoing edges only for current listed pages. That is consistent with P's warning that disappeared bodies and surviving lookup state differ; it does not establish complete removal of a deleted page's edges. P/synthesis.md explicitly denies automatic derived-claim retraction and complete graph withdrawal. This narrows the historical “rebuilds wikilink edges” phrasing appropriately. The audit did not independently examine every graph query or deletion branch.

5. **No operation or learning benefit is smuggled in through completion.** P/overview.md distinguishes deterministic checks from semantic certification. P/synthesis.md opens with the sole-source, no-target-execution and external-harness boundaries, separates metadata lookup from body reading and answer dependence, and leaves learning, reflective operation and exercised self-improvement unestablished. Its explicit limitations also retain provenance/admission uncertainty, incomplete freshness, unresolved extractor associations and an incomplete epistemic object inventory. These qualifications are public already, not repairs supplied only by this report.
