## Consequential findings

1. **Core coverage survives.** The new synthesis retains the historical architecture: host-agent semantic maintenance, raw/wiki separation, index-guided BM25/qmd retrieval, section expansion, structural diagnostics, and CLI/MCP scaffolding. It makes protocol versus executable behavior more explicit. Commonplace recommendations and adoption comparisons are historical transfer material, not missing system characterization.
2. **The historical log classification is narrowed appropriately.** The older active review calls operation history trace-extracted evidence. `AGENTS.md` prescribes agent-written timeline entries; it does not establish extraction from authenticated session/tool traces. `stats.py` parses headings with `\w+`, excludes hyphenated operations such as `answer-filed`, and returns no entry bodies. The new synthesis's authored-history and incomplete-parser qualifications are supported and publicly visible. It does not replace unavailable evidence with a system-wide trace-learning absence.
3. **Coverage is not semantic admission.** `ingest.py` labels a raw file ingested from its `raw_file` association without checking summary substance. `search.py` ranks current file text, including frontmatter, without a disputed-claim withdrawal filter. The synthesis correctly prevents readers from treating coverage, lint or retrieval availability as accepted truth or faithful integration.
4. **Known profile limits are actually carried.** `new_page.py` reads a project template and performs fixed placeholder substitution. The profile omits its separate symbolic-consumer classification and groups changed-template loading with unknown host loading. Profile verification identifies both limits; the public synthesis repeats them with the conclusions withheld. Positive form and pull findings remain supported elsewhere. These limitations justify the qualified disposition rather than an audit-only repair.
5. **Changed guidance is an affordance, not demonstrated improvement.** `sync_agents.py` copies canonical instructions to five fixed scaffold/example targets. `AGENTS.md` requests co-evolution. Neither establishes automatic log-derived changes, deployed-project migration or changed later behavior. The public account already preserves those boundaries.
