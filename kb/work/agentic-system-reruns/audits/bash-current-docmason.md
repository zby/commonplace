## Historical comparison and consequential findings

The checklist's historical link resolves to [the retained legacy DocMason review](../../../agent-memory-systems/reviews/docmason.md), checked 2026-06-04 at `b3e3e0ea0937309b4218f7ebf77bf72641fc1a5b`. The old and new revisions differ. I used the old account as omission leads, not source truth, and did not inspect an old source checkout.

1. **The main architectural coverage survives with better qualifications.** File-backed private inputs, compiled evidence, host-owned reasoning, canonical ask governance, selective retrieval, interaction-memory promotion and generated adapters remain in the new account. The synthesis describes compact delivery without claiming host-window eviction or isolated agents. Its source boundary excludes the deployed ancillary release service and supplies no private corpus, generated KB or host execution. These qualifications are already public, not repairs made only here.

2. **Answer admission is not factual certification or universal mediation.** The legacy language about published truth and binding answer governance is stronger than the new synthesis. Frozen `skills/canonical/ask/SKILL.md` specifies completed/boundary delivery, prohibits final business replies while blocked, permits `mixed`, `external-source-verified`, `model-knowledge` and `governed-boundary` support, and prescribes one rewrite/retrace. The synthesis correctly treats this as host protocol alongside invoked Python controls, not proof that every reply is KB-grounded. Published report verification also distinguishes heuristic trace diagnostics from entailment. No coverage regression is established by this narrowing.

3. **Lower-trust interaction participation is supported, not truth promotion.** Frozen `src/docmason/retrieval.py`, `memory_score_adjustment` (lines 2277–2330), excludes interaction families for external-factual queries and workspace-corpus minimal mode, and otherwise applies lexical thresholds, policy and rank priors. This supports the synthesis's conditional-memory account and preserves the historical distinction between corpus evidence and conversation-derived context. Actual uptake and improvement remain unobserved.

4. **Historical warm-start coverage is omitted locally, but the omission is disclosed.** The old review explicitly describes automatic answer-history evidence pointers. At the new frozen revision, `src/docmason/front_controller.py`, `warm_start_evidence` and `question_execution_profile` (lines 342–487), still select up to three historical records using question-token overlap, domain and applicable corpus-signature checks. They return evidence pointers rather than old answer text. `src/docmason/ask.py`, `_prepared_turn_response` (lines 1995–2066), includes this warm-start payload. The new memory profile's read-back axes expressly leave answer-history consumers uninspected; the synthesis Limitations table and report-verification Limits retain incomplete answer-history/all-consumer coverage. The profile establishes pull and optional hook push without asserting that these exhaust read-back or that inferred lexical push is absent. This is a real local coverage loss, not a false absence or an undisclosed completeness claim. A future separately authorized analysis could recover the full producer-to-delivery path; this audit does not patch or upgrade the frozen profile.

The new publication additionally retains overlay freshness, promoted-unit withdrawal, parser-recovery curation, semantic transformation and benefit limits. The synthesis carries the report/profile limits rather than silently relying on verifier acceptance.
