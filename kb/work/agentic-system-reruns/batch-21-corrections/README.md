## Recovery policy and stop conditions

For a later authorized release, first confirm exclusive ownership and that no
prior same-run writer can continue. Commit the complete preparation, review the
active manifest and use the prepared command environment for each case. Hashes,
terminal attempt metadata and absence of a process are not ownership clearance.

The supported sequence is: guard all bindings; externally invoke the pinned
origin reset API; verify its exact dependency closure, completed reset and
predecessor-publication archive; verify all preserved upstream members; deliver
all role-specific operator refusals with exact installed/latest version and
`--findings TEXT`; verify every refusal is effective; then follow the ordinary
frozen driver. There is no `--findings-file` interface. Native author correction
and fresh dependent verification remain separate. No ad hoc acceptance,
role replacement, forced positive or manual active-state repair is permitted.

The current reset implementation is pinned to `f12f9a746`. Older methods lack
its reset CLI and pending-reset fence, so external exclusion must also fence
old commands during reset. Frozen method files remain unchanged. Most old
methods ignore the newer reset budget floor: retained author counts still
apply. Every retained model currently has initial headroom, but dependency
refreshes or failed corrections can consume it. Exhaustion is a stop, not
permission for another budget-reset cycle. The two newer batch-20 methods use
the floor. The manifest records both families and every model's original count.

Stop on binding changes, open attempts, uncertain effects, pending resets,
changed/integrated incumbents, changed source/method, unsupported native
behavior, failed coordinator or validation, exhausted budget or source/record
conflict beyond the frozen role. Preserve logs, events, partial state and
archives. Do not mechanically refresh hashes, retry, clean or patch methods.
The seven unselected held own publications, all 182 canonical sets and retained
root files remain protected. Target scope and incident holds are unchanged.

## Checker and future operator launcher

```bash
bash kb/work/agentic-system-reruns/bash-21-corrections.sh --check
```

Default and `--check` are read only. The original `bash-21.sh` remains a read-only
25-case checker with **no launch mode**. This separate correction script's
`--confirm-idle` is reserved for a **separately authorized operator launch**.
It refuses a dirty/non-main origin, uncommitted launch inputs, possible same-run
processes and any existing one-shot output directory. It dispatches sequentially,
stops at the first failure and preserves reset/feedback/coordinator/inspection
evidence under external `outputs/batch-21-corrections/`. It does not integrate.
An assistant must use its exposed project-scoped delegation tool for analytical
coordinators; this operator shell launcher is not permission to substitute a
Bash agent CLI for that tool.

Completion requires a current internally completed publication, no open
attempts and matching publication effect/map. It does **not** establish semantic
correction. Newly produced bytes need a new fixed intake, independent exact-byte
audit and separately authorized integration. Original audits and intakes remain
historical evidence, not approvals for future bytes.

## Rejected mechanisms and evidence

- [Initial mechanism review](../batch-21-correction-mechanism.md): resetting
  report verification removes AREX's intended synthesis author. Historical
  versions alone do not restore correction readiness.
- [Application-reset review](../batch-21-application-route-review.md): resetting
  only a verdict application lets it reapply an old acceptance and supersede
  the newly supplied refusal before a worker reads it. All nine such routes
  were rejected; keeping a verifier output is not the same as keeping its
  installed member.
- [AREX downstream-reset review](../batch-21-arex-route-review.md): preserving
  application completion fixes that initial scheduling issue. **It does not
  clear verifier self-correction.** A subsequent disposable regression found
  that applying the corrected verifier can put two versions of that verifier
  into a scoped relation's basis. Its prospective future-application conclusion
  is superseded by the fixture result. The review is retained unchanged.
- [Rejected verifier-route manifest](./proposals/verifier-route.json): preserves
  the pre-counterexample candidate; it is not executable release input.
- [Final AREX synthesis-scope review](../batch-21-arex-synthesis-route-review.md)
  assesses the accepted-record-only alternative. This avoids self-refusing a
  verifier; it does not permit the synthesis author to repair underlying records.
