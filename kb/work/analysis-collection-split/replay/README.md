# Profile replay result

Commission: phase 2 of [the implementation plan](../plan.md), using the operator's
required Luna workers. The live run and current types remained unchanged until
both replays and their independent rechecks passed on 2026-10-04.

Each classifier received stripped copies of the five retained members, the
workshop profile type/schema and jobs, shared source/record contracts, worker
rules, collection contracts and root doctrine. The memory mapping and Comparison
rationale were removed. The historical overview was the replay boundary input.
No classifier or verifier received an incumbent profile. The parent compared
results afterwards. The workers could optionally inspect named ambiguities at
the pinned source revision; all four read audits record zero source reads.
Input receipts retain the original and stripped-copy SHA-256 hashes. Historical
members and manifests were never rewritten.

Both initial profiles recovered all twenty axes' assessments and value sets.
Three per-value strengths were initially weaker: session-log feed in run 01,
and parametric representation and imported lineage in run 02. Parent review
identified wired witnesses already in RT-RTE-1/RT-RTE-3 and
MEM-OBJ-3/MEM-RTE-3 respectively. One bounded correction restored those strengths
while retaining unknown persistence or provenance limits beside their claims.
Initial independent verification of run 02 proposed inferred-judgment for
retrieval synthesis. The classifier disputed it: the record's selection
predicate is top-k selection followed by parser acceptance/fallback, while the
model generates a new view. Independent recheck agreed that generation does
not establish judgment selecting retained parts for delivery and cleared the
blocker. Initial candidates, audits and verification reports are preserved
with `.initial` names.

[Final axis comparison](./axis-comparison.json): all twenty assessments, value
sets and per-value bases match the retained profiles. No axis weakened because
a needed fact was missing from the records. Both final independent reports
have Blockers exactly `none`. Keep the no-new-evidence limit. The initial
strength errors and signal dispute were classification errors, not missing
records or newly acquired evidence.

[Model provenance](./model-provenance.json) records each worker's session ID,
trace path, observed turn-context model and trace hash at parent inspection.
Every initial and correction/recheck turn reports exactly `gpt-6-luna`. The
parent checked actual session records, separately from the requested model.
Worker read-audit metadata alone was not treated as proof of model identity.

The two sets cover one source, and their authors had the axes in view. This is
a narrow feasibility gate; it does not prove that future source-native analysts
will record sufficient facts or that the separation improves analyses. The
first regenerated analysis remains a separately commissioned outcome check.
