# Check collection contract coverage

## Result and boundary

The split draft covers the collection definition's authoring surfaces after the
repairs below. The shortening draft preserves the existing layout and generated
review behavior while removing duplicated instruction and analytical detail.
Neither is a deployed contract. Their explicit collection-read dependency and
conditional maintenance route still need implementation. This check does not
adopt the split, migrate evidence, or establish improved analytical quality.

The source is the current [collection contract](../../../agentic-systems/COLLECTION.md).
The standard is the [collection definition](../../../reference/definitions/collection.md)
and [authoring composition](../../../reference/collections-and-types.md#authoring-composition).
Rules about a kind belong to its type; operational procedures need an actual
required consumer. Moving a rule into an optional document does not preserve it.
The file is a coverage audit, not an independent agent review.

## Repairs made during this check

1. The split purpose now includes run state and local types. They are owned by
   the new collection, although they are not analytical report prose.
2. Title rules apply to titled reports. Run-state/type titles and exact-heading
   worker fragments keep their own formats. The synthesis and verification jobs
   do not produce full titled reports; a universal report title rule contradicted
   their literal output grammar.
3. The split link grammar now permits local type specs to link the governing
   shared method contracts in agentic-systems. Mechanical relocation creates
   cross-collection links: suppressing this destination would make moved types
   violate their own collection contract.
4. Both split owners and the shortening contract require method authors to load
   the maintenance draft before changing instructions/shared contracts/types.
   Promotion must rewrite its draft link to the canonical instruction. The draft
   route binds the applicable author, without adding the procedure to analyst
   read-first lists. The maintenance draft alone previously supplied no upstream
   mandatory route.
5. The split retains the native account independently of mappings, routing for
   theory/raw captures, and the prohibition on prospecting unrelated web sources.

## Explicit loading gaps and fixes

- **All analysis jobs:** `AnalyseAgenticSystem.job` currently supplies the job,
  worker rules and role extras, but not COLLECTION.md. Add the selected contract
  to read-first and hashed inputs for either alternative. The root writing rule
  already makes it mandatory; do not count current omission as a legitimate saving.
- **Method authors:** the repaired candidate contracts provide the conditional
  maintenance route. Promote its target with the contracts. Do not put the whole
  maintenance instruction into every worker packet.
- **Ordinary theory-account authors:** H provides a conditional shared-record
  route. The repaired O draft now supplies the same route; analyst jobs already have
  the shared records dependency. A definition link alone would not supply all
  operational distinctions formerly present in COLLECTION.md.
- **Split coordinator/code:** add both contracts, new types and publication
  instruction to the method-change guard and explicit maintenance inputs. Existing
  METHOD_PATHS names only the old collection/types. The publication instruction
  draft is not currently loaded or enforced. Until this consumer change lands,
  its gates cannot replace live generated-review checks.
- **Archives and migration evidence:** preserve bytes and markers; declare any
  exceptional migration authority and map before retyping current sets. Historical
  bytes do not silently acquire the new contract's current-schema requirements.

## Link and format probe

A Markdown-link scan of the two current retained sets found 24 links, all within
the current analysis owner; they are supporting member links after relocation.
The current local types contain 15 within-owner links and two notes links. The
within-owner count includes shared instruction links, which cross owners after
the split, and the generated-review type, which stays historical. Remove/update
current overview publication references as the plan requires. This bounded sample
supports the narrowed worker grammar; it is not evidence about every future source
or historical artifact. Citation anchors in code spans are covered by the source
contract, not counted as Markdown outbound links.

The role instruction templates confirm that boundary/synthesis/verification
outputs are fragments. Runtime, memory, epistemic and assembled reconciliation
are typed reports. All write somewhere under working collection state, so all
currently need the collection read even when they produce no retained member.

## Complexity check

Neither design changes the fact that current packets omit the mandatory collection
read. Both can supply it as one literal read-first path and hashed dependency.
The role constructors already supply job, worker, source, record and member-type
paths directly; the split does not inherently simplify that part further.

The split creates additional cross-owner type-to-method links. Workers already
receive the needed shared contracts literally, so those links must not become
new execution-time searches. Ordinary authors still conditionally read the Theory
account and maintenance instruction; candidate contracts name those files directly
with links, and promotion must preserve resolvable paths. Relevant linked definition
reads remain under root vocabulary doctrine and are not eliminated by either layout.

The candidate routing is specified and locally resolvable. Dependency hashing and
literal contract insertion are not deployed or exercised by this documentation
check; verify them with the eventual packet-builder change. The split's type
relocation and publication rewrite remain additional consumer work.

## Decision implication

Both designs can remove most of the incumbent's mandatory reading cost.
The split retains a smaller shared input and a boundary against method/comparison
rule growth. Shortening avoids relocation, retyping and pin/redirect migration.
Publication by reference is independent of either layout: it can be implemented
in the existing collection if adopted. Do not credit that publication change as
an input saving from the split.
