# software-factory

Software factories in the Greenfield sense: configured, family-specific software-production environments, the development work that builds and revises that reusable machinery, and the larger software house that stays responsible for software evolving for external users. The defining notes are [software factory](../notes/definitions/software-factory.md), [factory development](../notes/definitions/factory-development.md), and [software house](../notes/definitions/software-house.md). Notes here ask when agentic systems become factories and what it would mean for a factory to learn. A software factory is not a theory builder: the factory is production machinery for a declared product family, while [theory-builder](./theory-builder-README.md) covers systems that criticize and revise stated theories. A child of [self-improving-systems](./self-improving-systems-README.md).

## Definitions and boundaries

- [Software factory](../notes/definitions/software-factory.md) — the configured environment for one declared family; implies no learning or autonomy
- [Factory development](../notes/definitions/factory-development.md) — revising reusable family-level machinery, as opposed to solution development on one product
- [Software house](../notes/definitions/software-house.md) — the complete persistent producer, including people and machinery; wider than any factory it uses
