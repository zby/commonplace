# Vocabulary collision ledger

Follow the matching term for its writing decision.

| Term | Uses to distinguish |
|---|---|
| [allocation](./vocabulary-collisions/allocation.md) | Assignment of functions, search, or effort |
| [higher-order concerns / second-order lessons](./vocabulary-collisions/higher-order-concerns-second-order-lessons.md) | Revision dependencies and reflection on prior commitments |
| [operational](./vocabulary-collisions/operational.md) | Lineage label, programming-language semantics, measurement, and practical use |
| [projection](./vocabulary-collisions/projection.md) | Executor choice, context view, LLM call, installed skill, and mathematical map |
| [provisional](./vocabulary-collisions/provisional.md) | Revocable search judgment and ordinary uncertainty |
| [refinement](./vocabulary-collisions/refinement.md) | Program refinement, iterative improvement, and theory repair |
| [worker](./vocabulary-collisions/worker.md) | Delegated agent and ordinary actor |

Add a term when a workshop, review, or writing task identifies competing uses and decides to retain both. Remove the entry when a rename, definition, or retirement resolves the collision. Record the reason in the commit.

The [vocabulary invariant](../theory/vocabulary-collisions-prevented-at-write-time-not-read-time.md) explains which collisions matter. The [write-time collision controls proposal](./proposals/write-time-vocabulary-collision-controls.md) considers graded reservation.
