# Tag scope is declared where membership claims are made

Tags today have no declared scope, and the system's consuming surfaces disagree about what scope they assume: the validator enforces the tag-README marks over one collection, one navigation recipe sweeps three collections, another sweeps one, and the reader-facing wording of the `complete` mark ("every note carrying the tag") names no scope at all. The build splits the difference within a single page view: a rendered note's tag link routes across collection boundaries to the nearest declared landing page, whose generated listing enumerates only that landing's own collection — so the reader arrives on a page whose "complete" tail omits the note they came from. The disagreement is also live, validator-invisible falsehood: four artifacts outside `kb/notes/` currently falsify a declared mark at the scope readers are told to assume.

The reframing this proposal rests on: a bare tag string needs no scope. An `rg` sweep is always explicit about the paths it searches, so tagging a note commits to nothing scope-shaped. Scope becomes real only where a **membership claim** is made — a `complete` or `covered_by` mark, a documented sweep recipe, a skip rule that lets a consumer trust a mark instead of sweeping, or a built index that presents itself as the tag's full listing. The build is where the stakes are highest: ADR 025 makes the generated tail the completeness surface for human readers ("completeness is the build's job"), so whatever scope the tail enumerates *is* the tag's de facto extent for the published site. So the design question is not "what scope do tags have" but "what scope do membership claims declare and enforce, and how do readers learn it."

The first version (2026-07-24) held three options open. This revision converges on one design: **one repo-wide namespace** — a tag string has one sense everywhere; **one membership scope** — every membership claim ranges over the library layers, with the workshop and capture layers excluded; **eviction of data-shaped tags** into typed frontmatter fields; and **one home for tag heads** — a new `kb/tags/` collection whose goal is connecting, populated as the obligatory last adoption step. The scope question and the adjacent "should there be two kinds of tag" question resolve together: the split the corpus supports is not global tags versus local tags but tags versus fields.

## Current state (as of 2026-08-19)

- **Enforcement is collection-scoped.** The validator's `complete`/`covered_by` checks build membership from a single-collection scan (`collect_collection_tag_index(collection_dir)` in `src/commonplace/lib/index_generated.py`, consumed by the `tag-readme` type rule in `validation.py`). Impact expansion likewise constructs a same-collection README path, so editing a tagged artifact never re-validates a head in another collection.
- **The build's two tag surfaces use different scopes.** The generated per-tag tail enumerates only the landing page's own collection, but the rendered **Tags:** footer link resolves by proximity (`_find_tag_index` in `src/commonplace/docs/properdocs_hooks.py` walks up to four directory levels), so a `kb/reference/` note tagged `kb-maintenance` links across the boundary to `kb/notes/kb-maintenance-README.md`. Routing is effectively repo-scoped while enumeration is collection-scoped.
- **Reader-facing surfaces disagree.** The `tag-readme` type spec and `navigation.md` state the `complete` claim without a scope qualifier; `AGENTS.md`'s by-tag recipe sweeps `kb/notes/ kb/reference/ kb/instructions/`; `navigation.md`'s canonical recipe sweeps `kb/notes/` only; the hub `tags-README.md` is the one surface that qualifies its own mark ("complete over the tag pages in this collection").
- **The namespace is already shared in practice.** 20 tag strings appear in more than one collection, keeping one sense across them; the collection difference is register (theory in `kb/notes/`, description in `kb/reference/`), not meaning. `kb/reference/` carries 16 distinct tags, 15 shared with `kb/notes/`. `kb-maintenance` appears in 21 `kb/notes/` files and 18 `kb/reference/` files (mostly proposals) — the reference side invisible to every curated surface. 11 of the 21 tag-READMEs already link outside `kb/notes/` editorially while their enforced claims stay single-collection.
- **The genuinely divergent usages are not topics.** `trace-learning` (103 members, only in `kb/agent-memory-systems/`) is a machine-read boolean — `systems_matrix.py` derives a matrix column from `"trace-learning" in tags` — and `x-article`/`x-thread`/`x-post` in `kb/sources/` classify capture format. Data fields wearing tag syntax.
- **Four artifacts falsify a declared mark at repo scope**, all validating clean at collection scope: `kb/agent-memory-systems/trace-learning-techniques-in-related-systems.md` and two `kb/sources/` A-MEM ingest reports carry `learning-theory` with none of its six declared `covered_by` children; `kb/reference/proposals/revise-behavioral-authority-decomposition.md` carries `artifact-analysis`, whose README declares `complete` and does not link it. The first was the sole violation in this proposal's first version; the other three accumulated in the four weeks since.
- **Free-form decay is observable.** ADR 004 made tags freeform and predicted a known-tags registry; none was built. Eight `kb/work/` artifacts still carry `llm-interpretation-errors` after that tag's rename to `llm-reliability`, and one `kb/work/` artifact carries a literal template placeholder in its tag slot. Nothing detects either.
- **Marks currently declared:** `complete` on the hub, `discovery-README.md`, and `artifact-analysis-README.md`; `covered_by` on `learning-theory-README.md`. ADR 026 made the marks enforced-or-omitted precisely because a claim that tells exhaustive consumers to stop looking must never be silently false — the property the scope mismatch violates at repo scope.
- **`tags` is a schema field** on `note-base.schema.yaml`, and [collections never own frontmatter semantics](../collections-never-own-frontmatter-semantics.md): a collection may not relativize what a committed field value means. That boundary's sanctioned moves permit extending a value set (each value meaning one thing everywhere) and pushing a collection-local distinction into a typed field on a collection-local type; a per-collection tag *namespace* — same string, two senses — is the move it refuses.
- **`cp-skill-connect` is coherent under collection scope today**: it prospects per destination collection and reads the destination's own `<tag>-README.md`, skipping the by-tag `rg` only for that destination when the mark is present.

## Proposed design

Scope attaches to the membership claim, not the string. The design fixes the claims' scope once and derives the rest.

**1. One namespace: a tag string has one sense repo-wide.** Everywhere, including the workshop and capture layers. This is the corpus's de facto state for the shared strings, and it is what the frontmatter-semantics boundary requires of a schema field. Register stays encoded by placement: the tag names the topic, the collection names the register; fragmenting the namespace to encode register would duplicate what the path already says. Same-string-different-sense becomes an error rather than an idiom; the screen against it is the registry rider below.

**2. One membership scope: the library.** Every membership claim ranges over the library layers — all of `kb/` except the workshop subtree (`kb/work/`) and the capture subtree (`kb/sources/`). "Every membership claim" is literal: the `complete` and `covered_by` checks, the generated per-tag tail, the documented by-tag recipes, and every skip rule consume the same membership definition. No claim gets its own range — per-claim scope variation is the disagreement this proposal exists to repair. The exclusion is by layer subtree, not collection identity, which sidesteps nested collections under `kb/work/` (e.g. `kb/work/dialectical-sample/`).

Tags on excluded artifacts keep the universal sense and remain reachable by explicitly-pathed `rg`; they neither satisfy nor violate any mark. Why these two layers: workshop artifacts are rewritten or deleted, so counting them makes every mark churn with drafting — and their tag hygiene is observably the weakest (the rename stragglers and the placeholder all live there); capture artifacts are tagged at ingest time without taxonomy discipline (both bare-`learning-theory` violations are ingest reports).

**3. Data-shaped tags become typed fields.** `trace-learning` becomes a field on the review type, read directly by `systems_matrix.py`; the `x-*` genre markers become a capture-format field on source types. This is the boundary note's sanctioned move: a collection-local distinction lands on a collection-local type whose spec owns the field with fixed meaning. After eviction, what remains in `tags:` is a single topical navigation vocabulary — and "two kinds of tag" is answered: the two kinds are tags and fields.

**4. Tag heads move to `kb/tags/`, a collection whose goal is connecting.** A library-wide head does not belong in a profile collection: `kb/notes/` is the theoretical profile, and a head makes no claims of its own — it earns its place by connecting library artifacts across collections by topic. The new collection mirrors `kb/types/` as a global surface: its `COLLECTION.md` declares the `tag-readme` type (the row leaves `kb/notes/COLLECTION.md`), a thin text contract on top of the type spec, and an outbound-link policy spanning every library collection — the posture 11 of the 21 heads already practice, gained natively instead of as a per-type carve-out in notes' link table. This also retires the center-of-mass alternative (heads scattered to their tags' dominant collections), which would have forced every collection to declare the type.

The move is the **obligatory last step of adoption** — not a free choice and not a follow-on. The semantic flip (validator, build, recipes, mark wording) ships first on stable paths; then all heads (21 today, the hub included) relocate mechanically under already-correct semantics via `commonplace-relocate-note` (consumers rewritten, published URLs redirected), with the entry points in `AGENTS.md` and `navigation.md` updated in the same change. Adoption is not complete while any head lives in a profile collection.

**Rider — known-tags registry.** Registered tag strings (at least: every tag with a README) become reserved terms via [write-time vocabulary collision controls](./write-time-vocabulary-collision-controls.md), screening new senses and catching rename stragglers and placeholder leaks at write time. Adoptable separately; nothing above depends on it.

### What flips

Under this design, the surfaces that were directionally right are `AGENTS.md`'s multi-collection recipe and the build's cross-boundary tag-link routing. What changes: the validator's membership query widens from one collection to the library, and impact expansion follows a changed artifact's tags to their heads across collection boundaries; the generated tail enumerates library-wide, restoring agreement with the routing that already feeds it readers; `navigation.md`'s recipe widens to match `AGENTS.md`'s, and both state the library boundary; the mark wording in the `tag-readme` type spec gains its qualifier ("every library artifact carrying the tag"). Head resolution becomes a lookup — one head per tag — rather than same-collection path construction or the proximity walk; the heads' end state is `kb/tags/` (commitment 4), and lookup-based resolution is what lets the semantic flip ship first on today's `kb/notes/` paths. A `complete` head must link every library member, cross-collection ones included; sectioning is editorial, the weight gates are unchanged, and a tag whose library membership outgrows the gates takes ADR 026's existing exits (drop to selective, split). Routing stays wider than membership: an excluded artifact's footer tag link may still route to the head, whose tail owes it nothing — by declaration rather than by accident.

### Operativity

The change is consumed through five channels: the **validator** (binding — marks checked against the library-scope membership query; impact expansion re-validates a head when any library artifact's tags change); the **build** (tail generator and footer router read the same membership definition; the tail is ADR 025's completeness surface, so this is where readers feel the repair); the **frontloaded recipes** in `AGENTS.md` and `navigation.md` (advisory — they must state the library boundary, or agents will "verify" marks with repo-wide sweeps and report false violations); **`cp-skill-connect`'s skip rule** (licensing — a mark comes to license skipping the by-tag sweep across all library destinations at once, strengthening today's per-destination skip); and **`systems_matrix.py`** (binding code consumer of the evicted `trace-learning` field). The `kb/tags/` `COLLECTION.md` joins the system-definition surface as the heads' binding authoring contract. No new oracle: the marks keep ADR 026's enforcement machinery and warrant; only the membership query's declared range changes.

## Alternatives considered

1. **Formalized collection scope** — a tag is `(collection, string)`; the same string in two collections is two tags; the footer router stops at the collection boundary. Rejected: it entrenches the fragmentation (`kb-maintenance`'s reference side stays invisible to every curated surface, and no mark can ever license the union sweep); it hardens a state no consumer fully inhabits, since heads, recipes, and the build's routing already behave cross-collection; and formalizing per-collection senses for a schema field is the move the frontmatter-semantics boundary refuses.
2. **Unqualified repo scope** — marks checked over all of `kb/`. Rejected: it drags drafts and captures into membership, so marks churn with workshop activity and `complete` tails enumerate capture noise. An eligibility rule is needed regardless, and stating that rule *is* the library boundary above — unqualified repo scope is this design minus the honesty about eligibility.
3. **Declared per-README dual scope** — a `scope: kb` opt-in on the tag-README, defaulting to collection scope. Rejected: readers must track which kind of promise each mark makes, and every consumer must read the field or it decays into decoration. Once data-shaped tags are evicted, no current tag needs a per-README exception, so the mechanism would ship without a user.

## Free choices

- **Boundary mechanism.** Hardcode the two excluded subtrees, or add a participation declaration to each layer's `COLLECTION.md`. Hardcoding is the cheaper v1; the declaration generalizes if more layers appear. Either way the boundary is stated where the recipes live.
- **Excluded-layer footer links.** Whether a `kb/work/` or `kb/sources/` page's tag footer routes to the head (navigation without membership) or renders plain text.
- **Sources topic tags.** Whether non-genre tags remaining on ingests after eviction stay as search-only convenience or are dropped; revisit membership if a sources-side consumer ever wants tag routing rather than an explicit sweep.
- **Evicted field shapes.** Boolean `trace_learning` versus an enum; the capture-format field's name and values — implementation detail for the adopting ADR.
- **Registry rider timing.** With adoption or separately.

## Adoption criteria

- One membership definition — library scope — is stated once and consumed by the validator, the tail generator, the footer router, both by-tag recipes, and every skip rule; no surface states or enforces a different range, and every surface that states a mark's meaning names the boundary.
- The build is coherent for library artifacts: a tag link from a library artifact lands on a head whose generated tail includes it.
- The four live falsifications resolve on the new terms: the two ingest reports leave membership by exclusion; the `kb/agent-memory-systems/` note gains one of `learning-theory`'s declared children or the children list is revised; the `artifact-analysis` head links its proposals member or that member drops the tag.
- `trace-learning` and the `x-*` markers no longer appear in `tags:`; `systems_matrix.py` reads the typed field.
- Marks remain enforced-or-omitted at the declared scope: no reader is licensed to skip a sweep wider than what is checked.
- Last, completing adoption: every head including the hub lives in `kb/tags/`, whose `COLLECTION.md` declares the type and the connecting contract; the type row has left `kb/notes/COLLECTION.md`; entry points route to the new paths; published URLs redirect. No head remains in a profile collection.

## Risks

- **Blast radius grows with the library.** Every new library collection widens every mark's membership, so `complete` becomes harder to hold as the KB grows. The mitigations are ADR 026's existing exits and weight gates; the residual risk is more frequent exits, not silent falsehood.
- **Sharpened collision stakes.** With local senses outlawed, a same-string-different-sense pair is an error rather than an idiom; until the registry rider ships, the error is still discovered by a confused reader.
- **Partial adoption reproduces the disease.** Flipping prose without the validator, or the validator without the tail, recreates marks that read one scope and check another. The adopting change must move enforcement, build, and wording together.
- **The boundary can become tribal knowledge.** An agent that does not know the excluded layers may sweep repo-wide, find a workshop draft carrying a covered tag, and report a false violation. The boundary must ride the recipes, not live only in this proposal.
