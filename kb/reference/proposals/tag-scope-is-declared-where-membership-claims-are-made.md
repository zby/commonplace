# Tag scope is declared where membership claims are made

Tags today have no declared scope, and the system's consuming surfaces disagree about what scope they assume: the validator enforces the tag-README marks over one collection, one navigation recipe sweeps three collections, another sweeps one, and the reader-facing wording of the `complete` mark ("every note carrying the tag") names no scope at all. The build splits the difference within a single page view: a rendered note's tag link routes across collection boundaries to the nearest declared landing page, whose generated listing enumerates only that landing's own collection — so the reader arrives on a page whose "complete" tail omits the note they came from. The disagreement is also live, validator-invisible falsehood: four artifacts outside `kb/notes/` currently falsify a declared mark at the scope readers are told to assume.

The reframing this proposal rests on: a bare tag string needs no scope. An `rg` sweep is always explicit about the paths it searches, so tagging a note commits to nothing scope-shaped. Scope becomes real only where a **membership claim** is made — a `complete` or `covered_by` mark, a documented sweep recipe, a skip rule that lets a consumer trust a mark instead of sweeping, or a built index that presents itself as the tag's full listing. The build is where the stakes are highest: ADR 025 makes the generated tail the completeness surface for human readers ("completeness is the build's job"), so whatever scope the tail enumerates *is* the tag's de facto extent for the published site. So the design question is not "what scope do tags have" but "what scope do membership claims declare and enforce, and how do readers learn it."

The first version (2026-07-24) held three options open. This revision converges on one design: **one namespace per KB** — a tag string has one sense everywhere within its KB; **one membership scope** — every membership claim ranges over the declaring KB's library layers, with the workshop and capture layers excluded; **eviction of data-shaped tags** into typed frontmatter fields; and **one home for tag heads** — a new `kb/tags/` collection that keeps the heads' introduction role, populated as the obligatory last adoption step. The scope question and the adjacent "should there be two kinds of tag" question resolve together: the split the corpus supports is not global tags versus local tags but tags versus fields.

## Current state (as of 2026-08-20)

- **Enforcement is collection-scoped.** The validator's `complete`/`covered_by` checks build membership from a single-collection scan (`collect_collection_tag_index(collection_dir)` in `src/commonplace/lib/index_generated.py`, consumed by the `tag-readme` type rule in `validation.py`). Impact expansion likewise constructs a same-collection README path, so editing a tagged artifact never re-validates a head in another collection.
- **The build's two tag surfaces use different scopes.** The generated per-tag tail enumerates only the landing page's own collection, but the rendered **Tags:** footer link resolves by proximity (`_find_tag_index` in `src/commonplace/docs/properdocs_hooks.py` walks up to four directory levels), so a `kb/reference/` note tagged `kb-maintenance` links across the boundary to `kb/notes/kb-maintenance-README.md`. Routing is effectively repo-scoped while enumeration is collection-scoped.
- **Reader-facing surfaces disagree.** The `tag-readme` type spec and `navigation.md` state the `complete` claim without a scope qualifier; `AGENTS.md`'s by-tag recipe sweeps `kb/notes/ kb/reference/ kb/instructions/`; `navigation.md`'s canonical recipe sweeps `kb/notes/` only; the hub `tags-README.md` is the one surface that qualifies its own mark ("complete over the tag pages in this collection").
- **The namespace is already shared in practice.** 20 tag strings appear in more than one collection, keeping one sense across them; the collection difference is register (theory in `kb/notes/`, description in `kb/reference/`), not meaning. `kb/reference/` carries 16 distinct tags, 15 shared with `kb/notes/`. `kb-maintenance` appears in 20 `kb/notes/` files and 18 `kb/reference/` files (mostly proposals) — the reference side invisible to every curated surface. 11 of the 21 tag-READMEs already link outside `kb/notes/` editorially while their enforced claims stay single-collection.
- **Heads are introductions by recorded intent, and the strongest are authored ones.** ADR 026 defines the head as "narrative orientation plus selective editorial picks", keeping the "introduction to a tag" role when enumeration moved to the build. In the corpus, 5 of the 21 heads (`self-improving-systems`, `tool-loop`, `learning-theory`, `computational-model`, `links`) are substantial authored introductions whose framing prose — reading instructions, entailment denials, area syntheses, a prior-work positioning — currently has no other home in the graph; 13 more open with a real orientation paragraph; 3 (the hub included) are plain routers.
- **Library membership is notes-dominant for most tags.** 16 of the 20 tags with heads have at least 80% of their library members in `kb/notes/`; only `kb-maintenance` (nearly half its members in `kb/reference/`) and `tool-loop` (about a third outside `kb/notes/`) are strongly mixed, with `observability` and `architecture` marginal. `kb/instructions/` currently contributes no members to any tag. Widening membership to the library changes the subject most heads introduce only slightly.
- **The theoretical profile's claim machinery does not engage heads.** Heads escape `kb/notes/` claim titles through the generic indexes exception; the reach gate has run on no head, and no review pair carries the `tag-readme` type spec as criterion (general prose and structure gates have run on one head). The concrete guidance heads draw from the notes contract is its outbound-link grammar, not the claim machinery.
- **The genuinely divergent usages are not topics.** `trace-learning` (103 members, only in `kb/agent-memory-systems/`) is a machine-read boolean — `systems_matrix.py` derives a matrix column from `"trace-learning" in tags` — and `x-article`/`x-thread`/`x-post` in `kb/sources/` classify capture format. Data fields wearing tag syntax.
- **Four artifacts falsify a declared mark at repo scope**, all validating clean at collection scope: `kb/agent-memory-systems/trace-learning-techniques-in-related-systems.md` and two `kb/sources/` A-MEM ingest reports carry `learning-theory` with none of its six declared `covered_by` children; `kb/reference/proposals/revise-behavioral-authority-decomposition.md` carries `artifact-analysis`, whose README declares `complete` and does not link it. The first was the sole violation in this proposal's first version; the other three accumulated in the four weeks since.
- **Free-form decay is observable.** ADR 004 made tags freeform and predicted a known-tags registry; none was built. Eight `kb/work/` artifacts still carry `llm-interpretation-errors` after that tag's rename to `llm-reliability`, and one `kb/work/` artifact carries a literal template placeholder in its tag slot. Nothing detects either.
- **Marks currently declared:** `complete` on the hub, `discovery-README.md`, and `artifact-analysis-README.md`; `covered_by` on `learning-theory-README.md`. ADR 026 made the marks enforced-or-omitted precisely because a claim that tells exhaustive consumers to stop looking must never be silently false — the property the scope mismatch violates at repo scope.
- **`tags` is a schema field** on `note-base.schema.yaml`, and [collections never own frontmatter semantics](../collections-never-own-frontmatter-semantics.md): a collection may not relativize what a committed field value means. That boundary's sanctioned moves permit extending a value set (each value meaning one thing everywhere) and pushing a collection-local distinction into a typed field on a collection-local type; a per-collection tag *namespace* — same string, two senses — is the move it refuses.
- **Shipped systems already implement mint-your-own vocabulary.** `commonplace-init` seeds user collections with zero tags and no heads; the machinery ships shared — `kb/types/tag-readme.md` plus schema, the marks validator, and the promoted skills, which degrade cleanly at zero tags — and `AGENTS.md.template` instructs consuming projects to create heads "as they emerge" at 5+ notes per tag. This repo's vocabulary travels only as read-only library content: the full install vendors our `kb/notes|reference|instructions` under `kb/commonplace/` (ADR 021), heads and marks included, and the template's by-tag recipe sweeps host and vendored trees together.
- **Install isolation of marks is accidental.** Because today's checks are collection-scoped, host heads and vendored `kb/commonplace/` heads validate against disjoint corpora; no surface declares that boundary.
- **`cp-skill-connect` is coherent under collection scope today, and only the notes destination benefits.** Its curated-heads step prospects per destination collection and reads the destination's own `<tag>-README.md`, skipping the by-tag `rg` only for that destination when the mark is present. Heads exist only in `kb/notes/`, so the step finds one only when the destination is notes; every other destination silently gets no curated tag signal, because the skill treats a missing head as "this tag has no head", not as an error.

## Proposed design

Scope attaches to the membership claim, not the string. The design fixes the claims' scope once and derives the rest.

**1. One namespace per KB: a tag string has one sense KB-wide.** Everywhere within the KB, including the workshop and capture layers. This is the corpus's de facto state for the shared strings, and it is what the frontmatter-semantics boundary requires of a schema field. Register stays encoded by placement: the tag names the topic, the collection names the register; fragmenting the namespace to encode register would duplicate what the path already says. Within a KB, same-string-different-sense becomes an error rather than an idiom; the screen against it is the registry rider below. The index is the KB root, not the repository: where two KBs share a workspace — a consuming project's own `kb/` with the vendored library under `kb/commonplace/`, or a reader install's vendored checkout (`commonplace/`) inside the project root — the same string in each is two namespaces, not a collision, and neither side is forced off ordinary words the other uses.

**2. One membership scope: the declaring KB's library.** Every membership claim ranges over the library layers of the KB that declares it — all of its `kb/` except the workshop subtree (`kb/work/`), the capture subtree (`kb/sources/`), and any embedded foreign KB root (in consuming projects, the vendored library under `kb/commonplace/`). "Every membership claim" is literal: the `complete` and `covered_by` checks, the generated per-tag tail, the documented by-tag recipes, and every skip rule consume the same membership definition. No claim gets its own range — per-claim scope variation is the disagreement this proposal exists to repair. The exclusions are by subtree, not collection identity, which sidesteps nested collections under `kb/work/` (e.g. `kb/work/dialectical-sample/`).

Tags on the two excluded layers keep the KB-wide sense and remain reachable by explicitly-pathed `rg`; they neither satisfy nor violate any mark. Why these two layers: workshop artifacts are rewritten or deleted, so counting them makes every mark churn with drafting — and their tag hygiene is observably the weakest (the rename stragglers and the placeholder all live there); capture artifacts are tagged at ingest time without taxonomy discipline (both bare-`learning-theory` violations are ingest reports). The foreign-KB exclusion is different in kind: an embedded KB is another corpus — its strings belong to its own namespace and its marks range over its own library, so neither side's artifacts enter the other's claims. Cross-KB sweeps (the scaffold's fused by-tag recipe spans host and vendored trees) stay navigation, wider than membership by declaration — the same move the routing surfaces make for the excluded layers.

**3. Data-shaped tags become typed fields.** `trace-learning` becomes a field on the review type, read directly by `systems_matrix.py`; the `x-*` genre markers become a capture-format field on source types. This is the boundary note's sanctioned move: a collection-local distinction lands on a collection-local type whose spec owns the field with fixed meaning. After eviction, what remains in `tags:` is a single topical navigation vocabulary — and "two kinds of tag" is answered: the two kinds are tags and fields.

**4. Tag heads move to `kb/tags/`, a global collection that keeps their introduction role.** The reason a library-wide head does not belong in a profile collection is contract fit, not that heads are mere routers: the head's recorded identity is an introduction to its tag (ADR 026, above), and what fails around it in `kb/notes/` is the profile itself — the claim machinery does not engage heads, and their cross-collection link posture has no per-type license in notes' outbound table. The new collection mirrors `kb/types/` as a global surface, where short is not contract-free. Its `COLLECTION.md` declares the `tag-readme` type (the row leaves `kb/notes/COLLECTION.md`) and a text contract that carries the introduction function:

- a quality goal of accurate subject introduction, discriminating context phrases, and routing economy — connecting is what a good head does by introducing well, not a replacement goal;
- an outbound-link grammar spanning every library collection, restating the `kb/work/` and `kb/sources/` link exclusions heads currently inherit from notes' contract;
- topical `<tag>` titles;
- authoring-time orientation guidance, which today lives only on maintenance-path surfaces (the type spec and the audit instruction), never in a collection contract — and the collection contract is what authors load.

The contract accepts the existing heads as written, authored framing prose included; that is what keeps the relocation mechanical.

The `kb/types/` mirror stops at the contract when shipping. `kb/types/` ships to the shared, user-extendable surface, but heads are knowledge artifacts under ADR 021's isolation split: `commonplace-init` scaffolds `kb/tags/` empty with its `COLLECTION.md` and never seeds this repo's vocabulary into user space — consuming projects mint their own tags on the shipped machinery, as `AGENTS.md.template` already instructs. This repo's heads ship read-only with the rest of the library (`kb/commonplace/tags/` after adoption), and the one-head-per-tag lookup is per KB root.

The move is the **obligatory last step of adoption** — not a free choice and not a follow-on. The semantic flip (validator, build, recipes, mark wording) ships first on stable paths; then all heads (21 today, the hub included) relocate mechanically under already-correct semantics via `commonplace-relocate-note` (consumers rewritten, published URLs redirected), with the entry points in `AGENTS.md` and `navigation.md` updated in the same change. The flip-first interim briefly widens the cross-collection posture on the mark-carrying heads before the contract that licenses it exists; the relocation closes that gap — a further reason it is mandatory rather than a follow-on. The automatic consumer rewrite covers links, not conventions: `cp-skill-connect`'s curated-heads step resolves heads per destination with no KB-wide lookup (current state above), so it must be rewritten to the `kb/tags/` lookup in the same change, and `kb/instructions/maintain-curated-indexes.md` is checked for the same pattern. Adoption is not complete while any head lives in a profile collection.

**Rider — known-tags registry.** Registered tag strings (at least: every tag with a README) become reserved terms via [write-time vocabulary collision controls](./write-time-vocabulary-collision-controls.md), screening new senses and catching rename stragglers and placeholder leaks at write time. Reservation is per KB root — nothing is reserved across a KB boundary. Adoptable separately; nothing above depends on it.

### What flips

Under this design, the surfaces that were directionally right are `AGENTS.md`'s multi-collection recipe and the build's cross-boundary tag-link routing. What changes: the validator's membership query widens from one collection to the library, and impact expansion follows a changed artifact's tags to their heads across collection boundaries; the generated tail enumerates library-wide, restoring agreement with the routing that already feeds it readers; both by-tag recipes widen to the library boundary and state it (`AGENTS.md`'s three-collection sweep was directionally right, not the endpoint); every surface that states a mark's meaning — the `tag-readme` type spec, `navigation.md`, the skip-rule wording — gains the scope qualifier ("every library artifact carrying the tag"); a declared mark comes to license skipping the by-tag sweep for every library destination at once, and curated-head signal reaches the non-notes destinations that today get none. Head resolution becomes a lookup — one head per tag per KB root — rather than same-collection path construction or the proximity walk; the heads' end state is `kb/tags/` (commitment 4), and lookup-based resolution is what lets the semantic flip ship first on today's `kb/notes/` paths. A `complete` head must link every library member, cross-collection ones included; sectioning is editorial, the weight gates are unchanged, and a tag whose library membership outgrows the gates takes ADR 026's existing exits (drop to selective, split). Routing stays wider than membership: an excluded artifact's footer tag link may still route to the head, whose tail owes it nothing — by declaration rather than by accident. A foreign-KB page's footer resolves within its own KB root: routing, like membership, does not cross a root.

### Operativity

The change is consumed through six channels: the **validator** (binding — marks checked against the library-scope membership query; impact expansion re-validates a head when any library artifact's tags change); the **build** (the tail generator reads the membership definition, while the footer router resolves by the one-head-per-tag lookup — routing declaredly wider than membership; the tail is ADR 025's completeness surface, so this is where readers feel the repair); the **frontloaded recipes** in `AGENTS.md` and `navigation.md` (advisory — they must state the library boundary, or agents will "verify" marks with repo-wide sweeps and report false violations); **`cp-skill-connect`'s skip rule and curated-heads step** (licensing — the widened skip license of "What flips", with the skill text a lockstep consumer: a missing head reads as "no head", so an unedited skill degrades silently instead of failing); the **scaffold** (`commonplace-init` — binding: it ships commitment 4's split, and its `AGENTS.md.template` recipes state the KB boundary); and **`systems_matrix.py`** (binding code consumer of the evicted `trace-learning` field). The `kb/tags/` `COLLECTION.md` joins the system-definition surface as the heads' binding authoring contract. Review-sweep targeting is path-scoped, so `kb/tags/` must enter sweep scope in the adopting change or heads drop out of the gate-review population with no surface reporting it. No new oracle: the marks keep ADR 026's enforcement machinery and warrant; only the membership query's declared range changes.

## Alternatives considered

1. **Formalized collection scope** — a tag is `(collection, string)`; the same string in two collections is two tags; the footer router stops at the collection boundary. Rejected: it entrenches the fragmentation (`kb-maintenance`'s reference side stays invisible to every curated surface, and no mark can ever license the union sweep); it hardens a state no consumer fully inhabits, since heads, recipes, and the build's routing already behave cross-collection; and formalizing per-collection senses for a schema field is the move the frontmatter-semantics boundary refuses.
2. **Unqualified repo scope** — marks checked over all of `kb/`. Rejected: it drags drafts and captures into membership, so marks churn with workshop activity and `complete` tails enumerate capture noise — and in consuming projects it swallows the vendored `kb/commonplace/` corpus into every host mark. An eligibility rule is needed regardless, and stating that rule *is* the library boundary above — unqualified repo scope is this design minus the honesty about eligibility.
3. **Declared per-README dual scope** — a `scope: kb` opt-in on the tag-README, defaulting to collection scope. Rejected: readers must track which kind of promise each mark makes, and every consumer must read the field or it decays into decoration. Once data-shaped tags are evicted, no current tag needs a per-README exception, so the mechanism would ship without a user.
4. **Center-of-mass placement** — each head lives in the collection holding its tag's dominant membership. Rejected: it forces every collection to declare the `tag-readme` type and fragments the heads' authoring contract, while 16 of the 20 tags are notes-dominant, so the scattering changes nothing for most heads and hands the mixed ones (`kb-maintenance`, `tool-loop`) an arbitrary host.

## Free choices

- **Boundary mechanism.** Hardcode the excluded subtrees, or add a participation declaration to each layer's `COLLECTION.md`. Hardcoding is the cheaper v1; the declaration generalizes if more layers appear. The foreign-KB exclusion can likewise be hardcoded to `kb/commonplace/` or generalized to a declared library-root marker (ADR 021's read-only namespace is the precedent to generalize). Either way the boundary is stated where the recipes live.
- **Excluded-layer footer links.** Whether a `kb/work/` or `kb/sources/` page's tag footer routes to the head (navigation without membership) or renders plain text.
- **Sources topic tags.** Whether non-genre tags remaining on ingests after eviction stay as search-only convenience or are dropped; revisit membership if a sources-side consumer ever wants tag routing rather than an explicit sweep.
- **Evicted field shapes.** Boolean `trace_learning` versus an enum; the capture-format field's name and values — implementation detail for the adopting ADR.
- **Head-only syntheses.** Whether framing claims that currently live only in heads (the `tool-loop` resolution section, the `self-improving-systems` profile argument) should later be distilled into notes — where the claim machinery can engage them — with the head keeping the summary; a maintenance question under the new contract, not an adoption gate.
- **Registry rider timing.** With adoption or separately.

## Adoption criteria

- One membership definition — library scope — is stated once and consumed by the validator, the tail generator, both by-tag recipes, and every skip rule; the footer router resolves by the one-head-per-tag lookup, wider than membership by declaration; no surface states or enforces a different range, and every surface that states a mark's meaning names the boundary.
- The build is coherent for library artifacts: a tag link from a library artifact lands on a head whose generated tail includes it.
- The four live falsifications resolve on the new terms: the two ingest reports leave membership by exclusion; the `kb/agent-memory-systems/` note gains one of `learning-theory`'s declared children or the children list is revised; the `artifact-analysis` head links its proposals member or that member drops the tag.
- `trace-learning` and the `x-*` markers no longer appear in `tags:`; `systems_matrix.py` reads the typed field.
- Marks remain enforced-or-omitted at the declared scope: no reader is licensed to skip a sweep wider than what is checked.
- In a consuming project no membership claim crosses a KB root: host marks are unaffected by `kb/commonplace/` artifacts and vice versa; `commonplace-init` scaffolds `kb/tags/` empty with its contract and ships this repo's heads read-only under `kb/commonplace/tags/`; cross-KB sweeps are documented as navigation, not membership.
- Last, completing adoption: every head including the hub lives in `kb/tags/`, whose `COLLECTION.md` declares the type and the introduction-function text contract of commitment 4; heads relocate content-unchanged; the type row has left `kb/notes/COLLECTION.md`; consumers that constructed head paths (`cp-skill-connect`'s curated-heads step, and `kb/instructions/maintain-curated-indexes.md` if it shares the pattern) resolve heads by lookup; `kb/tags/` is in review-sweep scope; entry points route to the new paths; published URLs redirect. No head remains in a profile collection.

## Risks

- **Blast radius grows with the library.** Every new library collection widens every mark's membership, so `complete` becomes harder to hold as the KB grows. The mitigations are ADR 026's existing exits and weight gates; the residual risk is more frequent exits, not silent falsehood.
- **Sharpened collision stakes.** With local senses outlawed, a same-string-different-sense pair within a KB is an error rather than an idiom; until the registry rider ships, the error is still discovered by a confused reader.
- **Partial adoption reproduces the disease.** Flipping prose without the validator, or the validator without the tail, recreates marks that read one scope and check another. Consumers extend the risk from falsehood to silence: relocating the heads without the `cp-skill-connect` edit fails silently (the lockstep-consumer channel in Operativity). The adopting change must move enforcement, build, wording, and path-constructing consumers together.
- **Adoption can break installs.** The library widening removes the collection scoping that today accidentally keeps host and vendored marks disjoint in consuming projects. An adopting change that states the range as "all of `kb/`" instead of the declaring KB's library hands every host mark the vendored corpus and every vendored mark the host's — silent falsification in both directions. The scaffold channel must ship the boundary together with the semantics.
- **The boundary can become tribal knowledge.** An agent that does not know the excluded layers may sweep repo-wide, find a workshop draft carrying a covered tag, and report a false violation. The boundary must ride the recipes, not live only in this proposal.
