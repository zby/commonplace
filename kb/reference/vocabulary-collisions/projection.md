# Projection

Keep projection as ordinary language. For the relation between a permitted set and an artifact inside it use [program refinement](../../theory/definitions/program-refinement.md); for an executor's unchecked output write "candidate refinement". Do not write "projection model" or "valid projection".

## Senses

Ordinary: an executor's silent collapse of a permitted set to one outcome, formerly the central term of [progressive constraining](../../theory/progressive-constraining-commits-only-after-patterns-stabilize.md) and its neighbours, now reworded there. Context view: the active-context projection in [context-operation interface](../../theory/context-operation-interface-bounds-context-policy.md). LLM-call projection in the [select/call lemma](../../theory/any-symbolic-program-with-llm-calls-is-a-select-call-program.md). Skill projection: installed copies of skills in install docs. Mathematical: linear and idempotent maps onto a subspace.

## Why these uses are retained

The executor sense was defined only in a note since deleted, and its uses read as metaphor; the other senses name their object.

## When to reconsider

A note relies on a mathematical property of projection, such as linearity or idempotence, to carry an argument.
