# 130-The operator-decision record is a query over the state tree

**Status:** accepted
**Date:** 2026-11-13

## Context

Three procedures improve one note after review: the full improvement pass,
the fix procedure and the simplification passes. Each stops for an operator
somewhere. Each kept the operator's answers in its own shape:

- the full pass in packet resolution fields with a rationale;
- the fix procedure in the agent's `rejected` and `deferred` statuses in a
  free-form fix report;
- the simplification passes in strike lists and operator records inside the
  revise run directory.

Nothing read the third shape across runs. Nothing consumed the fix
procedure's deferred items. So no one could see which kinds of edit the
operator reliably accepts, or see one note accumulate repairs across runs.

The design proposal
[one improvement pipeline with graded authority](../proposals/one-improvement-pipeline-with-graded-authority.md)
weighed three options. A and B add a shared authority vocabulary. C builds
only the record, as evidence for a later decision to move a stop. A review on
2026-11-12 proposed C first, as a bounded evidence-gathering step.

Two earlier decisions shaped C:

- Strike reasons are required. Since 2026-11-13 the revise workflow takes a
  reason with every strike and blocks deleted, edited or added entries, with
  [resolve a strike list](../../instructions/simplification-passes/resolve-a-strike-list.md)
  as the session procedure. Each run therefore holds its proposed list and
  its strikes with reasons.
- The record is a surface of the
  [unresolved frontier](../definitions/unresolved-frontier.md). Procedures
  for reading it are deferred to that frontier work. What C required now was
  only that the record be easy to locate from one path.

On 2026-11-13 the operator decided that the record stays under
`kb/reports/state/`. [ADR 128](./128-one-ignored-operational-tree-under-kb-reports-state.md)
makes that tree the publication boundary of a future state repository, and
[ADR 129](./129-workflow-run-bundles-live-under-the-state-tree-and-are-kept.md)
keeps run bundles there by default. One force stays open against that
location. Operator answers cannot be regenerated by rerunning a workflow,
unlike run bundles. Their retention bar is higher than the tree's, and the
tree is only as durable as the state repository's commit cadence.

## Decision

The operator-decision record is a read-only query, not a file. One
subcommand exposes it: `commonplace-review decisions [--note PATH]
[--class NAME] [--json]`, documented in the
[commands reference](../commands.md) and the
[review system README](../README-REVIEW-SYSTEM.md).

The query reads what the workflows already write under `kb/reports/state/`:

- the operator records in revise and full-pass run directories
  ([ADR 127](./127-review-runs-as-workflows-over-result-files.md));
- the full-pass packets;
- the fix reports.

It writes no state and launches nothing. The record's location is the
state tree. No new file holds it.

Each entry says who proposed and who decided: `operator`, `agent`,
`version-guard`, or `pending` for an unanswered stop. An agent's packet
disposition is an agent entry, never an operator decision. Each entry also
says whether the decision covered one item or a bundle. An answered strike
list gives one item entry per proposed entry, with its reason. A publication
approval is one bundle entry for the final text, not one approval per edit.

Entries are grouped by note, so repairs on one note can be read across runs.
Within a note they are ordered by time where known. Operator approvals now
record `answered-at`, and invalidating an answer removes its time with it.

The query computes no statistic: no approval rate, no count per class.

## Considered alternatives

A new append-only file of decisions. Rejected: the run directories,
packets and fix reports already hold every answer. A second copy would need
a writer at every stop and could drift from the run that produced it. A
query reads the answers where the workflow binds them.

Entries tracked in the main repository when each is written. Rejected for
now. A tracked entry would lose its binding to the run directory, which
stays ignored. It would add a commit at every stop. And tracking would imply
a curated status that a raw answer has not earned. Whether a later reading
promotes read entries into the tracked record is deferred with the reading
procedures.

Option A, shared authority grades at each stop over the same record, and
option B, one pipeline in code with three intake profiles. Not taken here.
Both remain open in the proposal under their own adoption criteria. C is the
record half of A, so this decision does not foreclose A.

Computing approval rates or per-class counts. Rejected: an approval rate is
the wrong statistic for moving a stop, and no reading procedure exists yet to
say which statistic is right.

## Consequences

An operator or agent can find every recorded decision on one note from one
command. Strike reasons, packet resolutions and publication approvals are
readable across runs. The listing keeps operator judgment apart from agent
judgment, so a later grade decision cannot count an agent's disposition as
an operator's.

The operativity path is weak by design. The consumer is an operator or agent
deciding whether to move a stop, or meeting another repair on a note. The
channel is the command's listing, named from the commands reference and the
review system README. The force is informational: no procedure yet requires
reading the record. That requirement comes with the reading procedures.

This decision does not:

- move any stop or change any grade, and it automates nothing;
- touch the policy in
  [full improvement pass closure](../full-improvement-pass-closure.md)
  against trust-dial automation and reduced audit sampling;
- compute any statistic across runs;
- record a grade or a procedure version per entry; entries carry the action
  class only;
- bind fix-procedure entries to a run. The fix procedure has no run
  directory, so its reports are listed once, by path, and their free-form
  tables are not parsed into items;
- promote packets, strikes or approvals into the tracked record.

The record is only as durable as the state tree. Until a state repository
commits it, it exists on the machine that ran the workflows. It covers only
the three procedures named here and only the records they already write.
A decline that never reaches a written record, such as a revision
assessment that does not recommend a pass, is absent from it.
