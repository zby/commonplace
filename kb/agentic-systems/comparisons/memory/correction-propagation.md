# How corrections propagate through retained memory

## Question and scope

When retained information is corrected, invalidated or withdrawn, which dependent representations—and which future consumers—reflect the change?

Correction propagates only as far as a connected maintenance route. Graphiti changes temporal status or selected graph availability; Mem0 explicitly replaces text and local retrieval representations; Hindsight removes dependent observations and has a further route toward repairing standing pages. These remain different operations, not grades on one forgetting scale. OpenKB adds a consequential countercase: source-association cleanup can leave the associated prose intact. SQLite Graph Memory separates current source links from refresh-dependent indexed text. Project Wiki specifies host-led correction of canonical records, without implementing a universal semantic cascade.

This is a selective mechanism comparison, not a per-system catalog or population estimate. It uses six accepted current sets from the population frozen at repository commit `bf2da04db03fb4cb60be52d1bb04e638a79eda79`: 243 accepted sets, comprising 225 code-grounded and 18 doc-grounded sets. Those totals describe the input population, not how often any correction mechanism occurs. All six selected sets are code-grounded overall; Project Wiki's semantic correction route is nevertheless procedural, not executable repair.

## Architectural distinctions

An **update** replaces an identified record's content. **Temporal invalidation** can retain an assertion while ending its validity interval. A **contradiction** is a relationship between assertions, not proof that the newer assertion is correct. Detection and disposition are separate: detecting contradiction need not cause replacement.

**Source deletion** withdraws an input. **Dependent-record cleanup** removes or marks associated representations. **Index refresh** changes what can be selected. **Derived prose repair** revises claims constructed from the input. Re-embedding corrected text does not retract a summary that incorporated the old text. Removing a source pointer does not subtract that source's contribution from a surviving paragraph.

The final boundary is the consumer. A fresh query can see changed store contents while a running conversation still contains an earlier result. A provenance pointer can identify a dependency without triggering repair. Multiple source IDs may represent repetition or derivation rather than independent corroboration. Neither a deletion response nor a support count establishes complete forgetting or adequate remaining warrant.

## Changing facts and retrieval representations

### Graphiti: temporal disposition and service-specific withdrawal

Graphiti's ingestion route retrieves selected comparison candidates, obtains duplicate/contradiction judgments and applies index and time checks. It can write `invalid_at` and `expired_at` while retaining the old edge; a newer contradictory candidate can also expire an incoming older assertion. Candidate retrieval is not exhaustive, and normalized-text/endpoint reuse can bypass model contradiction checking. This is conditional temporal reconciliation, not a newer-input truth rule ([comparison](../../../agentic-system-analyses/retained/getzep--graphiti/epistemic.md#epi-rte-fact-comparison), [disposition](../../../agentic-system-analyses/retained/getzep--graphiti/epistemic.md#epi-rte-fact-disposition)).

Temporal fields do not establish globally current-only delivery. The inspected basic-search default has empty filters, and fallback date predicates depend on supplied filters. MCP fact formatting retains dates and episode references; the shipped notebook sends bare fact strings. That consumer loses the metadata needed to distinguish historical from current assertions unless the distinction remains in the text ([filtering and withdrawal](../../../agentic-system-analyses/retained/getzep--graphiti/memory.md#mem-clm-withdrawal-scope), [display](../../../agentic-system-analyses/retained/getzep--graphiti/memory.md#mem-clm-display-lineage)).

Deletion differs by service. MCP calls core episode removal, which selects an edge when the removed episode is its **first** episode reference. For references `[A, B]`, removing A selects the edge despite B. This code-derived counterexample contradicts the MCP description's multiply-supported-fact preservation promise. Nodes use mention counts. REST instead directly deletes the episode node without core cleanup; backend incident-edge effects remain incompletely inspected ([removal](../../../agentic-system-analyses/retained/getzep--graphiti/epistemic.md#epi-rte-episode-removal), [reconciliation](../../../agentic-system-analyses/retained/getzep--graphiti/reconciliation.md#independent-convergence-and-integration-dispositions)).

Surviving summaries are another layer. Entity summaries can append fact strings or use model generation; communities derive from entity summaries; sagas fold selected episodes into a previous summary. None establishes a deletion-triggered rebuild of all surviving prose. Even explicit community rebuilding would not establish correction if its entity-summary inputs remained unrepaired. The inspected removal body does not regenerate entity, community or saga prose or retract the notebook's separate checkpoint ([summary inputs](../../../agentic-system-analyses/retained/getzep--graphiti/memory.md#mem-obj-community-node), [withdrawal scope](../../../agentic-system-analyses/retained/getzep--graphiti/memory.md#mem-clm-withdrawal-scope)).

### Mem0: explicit replacement, independent retained context

At this revision, ordinary inferred Python addition is additive: prior facts guide extraction and bounded deduplication, but a contradictory new input does not automatically replace the old assertion. Explicit update is separate ([addition](../../../agentic-system-analyses/retained/mem0ai--mem0/runtime.md#rt-rte-extract-add)).

Python update preserves the ID, replaces text and embedding, refreshes hash and lemmatized matching terms, writes history and attempts entity unlinking/relinking when text changes. This connects correction to several local retrieval representations. Entity links supply ranking boosts, not a proposition-level dependency graph. Cleanup is best effort; vector, history and entity changes are not one cross-store transaction. The OpenClaw atomic-update description therefore cannot be inferred from this local route, and hosted atomicity remains unknown ([mutation](../../../agentic-system-analyses/retained/mem0ai--mem0/memory.md#on-rt-rte-direct-write), [entity index](../../../agentic-system-analyses/retained/mem0ai--mem0/memory.md#mem-obj-entity-links)).

Deleting the vector record writes old text to history and does not delete the separate recent-message tail. History has a requested inspection route, not an established automatic answer reader. Recent messages are explicitly reloaded into later extraction: old source text remains available to that consumer, without proving actual re-extraction. Expiry is narrower still: default public search hides expired payloads, whereas direct ID reads and extraction's private vector lookup are counterpaths ([history](../../../agentic-system-analyses/retained/mem0ai--mem0/memory.md#mem-obj-history), [messages](../../../agentic-system-analyses/retained/mem0ai--mem0/memory.md#mem-obj-messages), [private extraction lookup](../../../agentic-system-analyses/retained/mem0ai--mem0/memory.md#on-rt-rte-extract-add)).

Coding-agent and Pi recall suppress IDs already shown in a session. That filter does not establish revision-aware redelivery after replacement under the same ID. Nor may local Python mutation semantics be assigned to their opaque hosted backend. The unanswered question is whether a supported backend/integration pairing reconnects changed text to an already-informed consumer ([coding recall](../../../agentic-system-analyses/retained/mem0ai--mem0/memory.md#mem-rte-coding-recall), [Pi recall](../../../agentic-system-analyses/retained/mem0ai--mem0/memory.md#mem-rte-pi-memory)).

### SQLite Graph Memory: refresh-dependent snippets beside current links

SQLite Graph Memory indexes external Markdown into persisted vectors and text snippets; query-time graph expansion separately reads live source links. A source edit therefore does not itself replace the indexed excerpt. Caller-triggered refresh drops rows for changed or removed files, but matching size/mtime can reuse a prior hash without rereading bytes. Full regeneration is available; automatic scheduling is not implemented by the index entry point, and three successive artifact writes are not an atomic snapshot ([index admission](../../../agentic-system-analyses/retained/tonydzi--sqlite-graph-memory/runtime.md#rt-rte-index-admission), [live notes](../../../agentic-system-analyses/retained/tonydzi--sqlite-graph-memory/memory.md#mem-obj-notes)).

This permits current links to select older stored prose. Optional PageRank adds a process-local boundary: its cache fingerprint expects optional hashes absent from the indexer's metadata, so unchanged path/row layout can leave an importing long-lived process with an old graph. MCP's new per-query child does not share that cache horizon ([selection annotation](../../../agentic-system-analyses/retained/tonydzi--sqlite-graph-memory/memory.md#on-rt-rte-recall-options)).

The portable instructions prescribe closing wrong records, retaining reasons and preferring open validity windows. The ordinary index strips frontmatter and recall does not enforce `valid_to` filtering. The entity-shaped graph CLI path can add a superseding note without removing the old seed or guaranteeing replacement delivery after ranking; A/B and evaluator compositions differ. Thus replacement access is wired, but temporal reliance remains a separate host instruction. Even after refresh, a correction reason outside the stored snippet prefix need not reach the consumer ([temporal boundary](../../../agentic-system-analyses/retained/tonydzi--sqlite-graph-memory/runtime.md#rt-clm-temporal-scope), [recall options](../../../agentic-system-analyses/retained/tonydzi--sqlite-graph-memory/runtime.md#rt-rte-recall-options), [snippet metadata](../../../agentic-system-analyses/retained/tonydzi--sqlite-graph-memory/memory.md#mem-obj-brain-meta)).

## Repairing standing prose

### Hindsight: withdraw mixed-source derivatives, then maintain pages

Hindsight separates extracted raw facts, consolidated observations and persistent mental-model documents referenced by knowledge-tree pages. “Raw” means pre-consolidation, not necessarily verbatim source text.

The inspected PostgreSQL withdrawal path identifies observations referencing **any** outgoing source, deletes those observations and their history, and resets consolidation markers on surviving co-sources. Future consolidation can reconstruct from what remains. It removes the whole mixed-source derivative rather than assuming the remaining prose is still supported. Other stores and every deletion caller were not fully inspected ([source withdrawal](../../../agentic-system-analyses/retained/vectorize-io--hindsight/epistemic.md#epi-rte-source-withdrawal)).

Raw-memory curation also supports editing, archive invalidation and restoration. Invalidated facts leave live recall for an archive retaining text, optional reason and restoration descriptors, but not embeddings/search vectors. Restoration recomputes retrieval representations; it does not restore every former derivative byte. This is reversible live withdrawal, not physical erasure ([curation](../../../agentic-system-analyses/retained/vectorize-io--hindsight/memory.md#mem-rte-memory-curation), [archive](../../../agentic-system-analyses/retained/vectorize-io--hindsight/memory.md#mem-obj-curation-archive)).

Standing-page refresh reads accumulated `based_on` grounding, checks source existence and can request removal of unsupported prose. Full refresh rebuilds grounding; delta refresh retains historical grounding and prunes retracted IDs only when the retraction pass is handled. Pending consolidation can defer retraction to avoid unsaying a replacement still being processed. Named refresh failures preserve the previous document and progress marker instead of installing an incomplete candidate ([page maintenance](../../../agentic-system-analyses/retained/vectorize-io--hindsight/memory.md#mem-rte-page-maintenance)).

This is not immediate universal repair. Post-commit refresh nudges cover automatic pages, catch scheduling failures and can defer behind pending work; manual pages require owner action. The complete edit/retraction executor and scheduler were not exhaustively inspected. Stored pages can remain stale until maintenance succeeds. Delivery can expose current/stale indications, but already delivered prose remains a separate copy. A filesystem mirror adds another stage: successful synchronization can prune removed pages and overwrite local drift; failed fetch returns before pruning ([curation scheduling](../../../agentic-system-analyses/retained/vectorize-io--hindsight/memory.md#mem-rte-memory-curation), [page delivery](../../../agentic-system-analyses/retained/vectorize-io--hindsight/memory.md#mem-rte-page-delivery), [mirror](../../../agentic-system-analyses/retained/vectorize-io--hindsight/memory.md#mem-rte-filesystem-mirror)).

### OpenKB: association cleanup is not subtraction from prose

OpenKB's compiled concept/entity pages combine model-authored bodies with code-managed source lists. Selected old bodies enter later full-page rewrite calls. Source lists identify contributing documents at page granularity, not sentence-level dependencies ([page metadata](../../../agentic-system-analyses/retained/vectifyai--openkb/memory.md#mem-obj-page-frontmatter), [body update](../../../agentic-system-analyses/retained/vectifyai--openkb/memory.md#on-rt-obj-wiki-pages)).

Source removal edits source lists and selected links, deleting a page when its last source disappears unless keep-empty is selected. It does not semantically regenerate surviving multisource bodies. The retained code-derived counterexample is decisive: a page with sources A and B and body “A says P” can lose A from its source list while retaining that prose. Hindsight's inspected mixed-source observation cleanup instead withdraws the derivative and requeues surviving sources. Neither behavior determines whether P is true; they differ in whether old mixed-source content remains available after a known dependency is removed ([withdrawal](../../../agentic-system-analyses/retained/vectifyai--openkb/epistemic.md#epi-rte-source-withdrawal)).

Other maintenance does not close this gap automatically. Workbench/API body replacement preserves existing frontmatter, so descriptions and source lists can diverge from edited content. Recompile can consume selected old bodies and is not established as clean-room reconstruction. Semantic lint produces an advisory report, not automatic semantic repair ([page edit](../../../agentic-system-analyses/retained/vectifyai--openkb/memory.md#mem-rte-page-edit), [maintenance annotation](../../../agentic-system-analyses/retained/vectifyai--openkb/memory.md#on-rt-rte-wiki-maintain)).

Saved explorations, reusable chat history and generated skills are separate descendants. Session code supplies sanitized SDK history on later turns; sanitization removes image payloads, not the remaining text/tool history. Generated portable skills deliberately omit producer-wiki links and are not automatically installed. The inspected source-removal route does not revoke those products or downstream installed copies. Their existence establishes separate retention/consumer boundaries, not an observed instance of stale reuse ([history](../../../agentic-system-analyses/retained/vectifyai--openkb/memory.md#mem-obj-session-history), [skill package](../../../agentic-system-analyses/retained/vectifyai--openkb/memory.md#mem-obj-skill-package), [reconciliation](../../../agentic-system-analyses/retained/vectifyai--openkb/reconciliation.md#routes-and-independent-convergence)).

### Project Wiki: semantic correction has an assigned owner, not a code cascade

Project Wiki here means `giodra96/project-wiki`, not the separately analyzed LLM Project Wiki. Its shipped procedure separates extracted intake provenance from canonical project records. Bad extraction before integration is rejected/superseded and regenerated; after integration, the host must also correct affected canonical records and append audit history. Merely relabeling the intake does not complete repair ([intake provenance](../../../agentic-system-analyses/retained/giodra96--project-wiki/memory.md#mem-obj-intake-provenance)).

Requirement-to-source-chunk edges live in a sidecar. Deterministic checks compare those edges with integrated-ledger targets, but reciprocal edges do not establish entailment or automatically revise requirement prose. Ordinary coding is instructed to read canonical pages through indexes, not terminal intake; provenance remains available for investigation. This separates normal reliance from historical availability, by policy rather than filesystem denial ([canonical sidecar](../../../agentic-system-analyses/retained/giodra96--project-wiki/memory.md#mem-obj-requirement-evidence), [routing](../../../agentic-system-analyses/retained/giodra96--project-wiki/memory.md#mem-obj-wiki-routing)).

Maintenance assigns low-risk repairs to the host and requires human confirmation for enumerated high-impact meaning changes. Stale records are marked superseded, deprecated or placeholder rather than silently erased. This is a declared changed-reliance procedure, not a wired proposition-level invalidation engine. No populated wiki or host trace establishes completed repair, synchronized indexes or revised context reaching a running consumer. The useful contrast is explicit semantic ownership despite non-automatic propagation, not a stronger repair guarantee derived from the set's code-grounded label ([claim withdrawal](../../../agentic-system-analyses/retained/giodra96--project-wiki/epistemic.md#epi-rte-claim-withdraw), [reconciliation](../../../agentic-system-analyses/retained/giodra96--project-wiki/reconciliation.md#connected-routes-and-independent-convergence)).

## Comparison and consequences

Three boundaries must remain separate:

1. **What changes in the store?** Graphiti can retain a historical edge; Mem0 can replace the same ID; Hindsight can remove an entire associated observation; OpenKB can remove an association while keeping its prose. These are different dispositions, not equivalent forms of deletion.
2. **What becomes selectable later?** Mem0 maintains several local retrieval representations during update. SQLite Graph Memory requires index refresh and has route-specific graph/cache behavior. A source correction or replacement link alone does not establish that the next retrieval excludes old text or includes its correction reason.
3. **What happens to derived prose and delivered copies?** Hindsight has a further grounding-driven page-maintenance route, bounded by scheduling, ownership and failures. OpenKB cleanup does not subtract all source influence from surviving prose or exported products. Project Wiki prescribes host-led canonical correction and audit. None establishes universal revocation of conversation copies.

Multiple-source handling makes the distinction concrete. Graphiti's first-reference deletion can remove a shared edge. Hindsight removes mixed-source observations but retains surviving inputs for reconstruction. OpenKB can retain a mixed-source page after removing one source pointer. Project Wiki's exact provenance edges aid investigation without computing semantic repair. None establishes that two IDs are two independent reasons to believe the surviving claim.

The consumer boundary is not merely hypothetical: Graphiti's notebook has a separate conversation checkpoint; Mem0 coding recall keeps local retrieval snapshots and seen-ID state; OpenKB reloads retained text/tool history. Those concrete channels explain why server-side mutation cannot be assumed to repair all later inputs. They do not establish that every uninspected integration lacks correction handling ([Graphiti checkpoint](../../../agentic-system-analyses/retained/getzep--graphiti/memory.md#mem-obj-memory-saver), [Mem0 delivery state](../../../agentic-system-analyses/retained/mem0ai--mem0/memory.md#mem-obj-evidence-store), [OpenKB session history](../../../agentic-system-analyses/retained/vectifyai--openkb/memory.md#mem-obj-session-history)).

## Evidence limitations

These are frozen architectural findings, not current product guarantees. Reading relevant accepted members and their reconciliation does not make underlying inspections exhaustive. Graphiti's backend parity, Hindsight's alternate stores/full retraction executor, Mem0's hosted implementation and language/integration parity, OpenKB's PageIndex private state, Project Wiki's external host execution and SQLite Graph Memory's private pipeline remain outside the established conclusions.

No selected correction run was observed or measured here. Hindsight's convergence evaluator wires criterion and forbidden-claim checks; evaluator source is not a passing result or production repair gate ([evaluation](../../../agentic-system-analyses/retained/vectorize-io--hindsight/memory.md#mem-rte-page-evaluation)). Missing repair evidence is not proof of absence in uninspected routes. Conversely, coexisting deletion, summarization, provenance and retrieval features do not establish that they compose into a correction pipeline. No prevalence, complete-forgetting or benefit conclusion follows from these selected examples.

## Open questions and experiments

The unresolved question is whether a correction reaches each relevant representation and actual later input. The following tests would distinguish those outcomes; partial traces should identify where propagation stops rather than treating mutation success as completion.

1. **Trace one correction end to end.** Materialize facts, summaries, indexes and exports before correction. Record changed IDs, text, validity, lineage and consumer-visible payloads afterward. Separate immediate mutation from background convergence and owner-requested repair.
2. **Withdraw one of two supports.** Compare independent sources with duplicated/derived sources, reversing ingestion order. Inspect Graphiti's first-reference behavior, Hindsight's removal/reconsolidation and OpenKB's surviving multisource prose. Check support adequacy separately from survival.
3. **Delay or fail maintenance.** Query before index refresh, during pending consolidation, after scheduling/mirror-fetch failure, and before a host confirms high-impact correction. For SQLite Graph Memory, distinguish fresh MCP children from long-lived importing consumers. Measure stale delivery, not only successful writes.
4. **Keep consumers alive.** Compare same-session and fresh-session inputs after replacement under the same ID and after withdrawal. Inspect checkpoints, SDK history, seen-ID state and exported/installed artifacts. Use a backend/integration pairing with established mutation semantics; record the next model input rather than only the tool response.
5. **Check repaired meaning separately.** Assess surviving prose against remaining evidence, including omitted qualifications and correction reasons. Visibility filtering, archive retention, structural validation and semantic repair need separate outcomes. A benefit or component-effect claim would need an independently specified assessment and appropriate intervention/comparison evidence.
