## Boundary and evidence

This run analyses the Dynamic Cheatsheet repository at the reviewed commit as a complete implementation of its query-time memory and retrieval framework. The system sends a query and supplied cheatsheet or retrieved examples to a language model; its cumulative variants make a second model call to curate the cheatsheet, which the caller can pass to a later query. Retrieval variants consume supplied prior inputs, outputs, and embeddings. The repository also includes provider routing and optional code execution around generation.

Included functions are prompt construction, generation orchestration, cheatsheet extraction and update, optional retrieval over supplied embeddings, provider-client integration, and the repository's documented usage contract. The framework does not itself own durable storage across process or query boundaries: callers supply the current cheatsheet and retrieval inputs. Benchmark data, reported benchmark outcomes, and notebook results are not treated as inspected execution evidence in this boundary.

## Bounded synthesis

At reviewed commit `5cfe3c37e8e52b1d858d0f3df46e7f17c50991b9`, Dynamic Cheatsheet is a query-time memory and retrieval library. The caller supplies a question, prompt templates, any current cheatsheet, and, for retrieval, aligned prior examples and embeddings. The wrapper calls a configured model to generate an answer, then in cumulative modes asks that model to propose a cheatsheet update. The library returns the proposed text; a caller must retain and resubmit it for use in a later call. Its code therefore affords caller-mediated accumulation rather than providing durable storage itself ([runtime.md], RT-RTE-1, RT-RTE-3; [memory.md], RT-OBJ-1).

The routes differ in how they assemble context. Cumulative generation reuses a supplied cheatsheet and can pass an extracted update to later rounds in the same call. Full-history appending places all supplied prior pairs in the prompt. Retrieval-only and cumulative retrieval rank supplied examples by cosine similarity; retrieval synthesis first asks the model to form a query-specific sheet from selected examples. These selectors establish ordering in the supplied vector space, not correctness or answer quality. The embedding producer, vector provenance, and example alignment are outside the inspected boundary ([runtime.md], RT-RTE-1, RT-RTE-2, RT-RTE-3, RT-RTE-4, RT-RTE-5; [memory.md], MEM-OBJ-1, MEM-OBJ-2).

In cumulative modes, tag extraction is the content admission check: a tagged model response replaces the in-call sheet, while missing tags retain the previous value. The check does not assess truth, evidence, or intended use; an empty tagged body can also replace the sheet. For retrieval synthesis, the missing-tag fallback is the formatted retrieval view, not the prior cheatsheet supplied to the curator. These mechanisms establish string handling and routing, not epistemic acceptance ([runtime.md], RT-RTE-1, RT-RTE-2, RT-RTE-3; [memory.md], RT-RTE-1, RT-RTE-2; [reconciliation.md], RT-RTE-2).

The implementation also exposes direct provider-client paths and optional code execution. A configured text trigger can launch model-proposed Python in a local subprocess with the host process's available authority; the inspected code establishes no sandbox or approval step. A provider-native execution request is wired for supported providers, but execution and isolation belong to uninspected provider environments. These paths carry operational authority, while their actual use and effects are unobserved ([runtime.md], RT-RTE-6, RT-RTE-7, RT-RTE-8, RT-BAP-1, RT-BAP-2; [epistemic.md], EPI-OBJ-5, EPI-OBJ-6).

The evidence supports a caller-mediated reuse affordance and automatic candidate production, but not improved future capacity: no execution traces, correctness oracle, capability comparison, or causal experiment were supplied. The README's learning and benchmark claims therefore remain unverified by this run ([epistemic.md], EPI-CLM-1, EPI-CLM-2, EPI-CLM-3; [memory.md], RT-RTE-1, RT-RTE-3). The records do not establish that the system meets theory-builder conditions 1–4, is reflective, is autonomous, or is self-improving. The contents of the sheet and templates are unavailable, while the inspected routes provide no evidence-consuming criticism loop or measured improvement ([runtime.md], RT-RTE-1, RT-RTE-2, RT-RTE-3; [epistemic.md], EPI-CLM-1, EPI-CLM-2).
