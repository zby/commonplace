# instinctual-memory agentic-system analysis

## Boundary and evidence

The target is the complete `mem` product in the instinctual-memory repository: a Git-first durable memory system for AI agents. Its intended use is to turn prior agent sessions and project memory files into sourced facts, retrieve facts alongside journal events, and supply memory to agent hosts through tools, hooks, and managed project-file blocks (SRC-2, `README.md`). This qualifies as a memory/knowledge/context-engineering system. The boundary is whole-system for this repository product, rather than the enclosing Claude Code, Codex, or OpenCode runtimes.

Included functions are store selection and initialization; transcript and file ingestion; an append-only journal; rules and model-assisted consolidation; fact/entity representations; Git publication, checkpoints, controls, and recovery; search and optional reranking; validated remember/correct/forget changes; erasure and tidying; index and project-file writeback; CLI, shell, MCP and HTTP interfaces; host setup and hook entry points; and evaluation tooling. The implementation inventory is exposed in `src/lib.rs`, with the CLI entry point in `src/main.rs`; consolidation and host hook context delivery are implemented in `src/consolidate.rs` and `src/hook.rs` (SRC-1). Checked-in tests and CI definitions are source evidence about executable checks, without evidence here that those checks passed.

## Bounded synthesis

The strongest supported contribution is a wired path from prior session messages to durable fact statements and later agent context. `mem`, the product in instinctual-memory, imports source text, extracts standing assertions or instructions, retains them in Git, and returns or emits selected statements on later requests and callbacks. This establishes memory production and delivery in the inspected implementation, without establishing improved future capacity. The boundary is the repository product at commit `6acb13dc35765bf5ccfc87e445dd09c480f1c28a`; enclosing agent hosts, external providers and model internals are excluded. Source inspection supplies the evidence, including test code; no target execution or passing test result is supplied. ([MEM-RTE-1](memory.md), [RTE-4, RTE-5, CLM-1](runtime.md).)

The enclosing agent owns planning, tool choice and answers. `mem` owns memory operations exposed through CLI, MCP, loopback HTTP and a restricted memory shell. Its selected filesystem root determines the store operated on. The store's raw JSONL journal remains independently searchable alongside curated entity facts, which combine readable statements with IDs, status, source references and temporal metadata in a bare Git repository. Generated index counts summarize active statuses; they do not count verified truths or all currently eligible facts. This separation permits raw-source recall even when extraction omitted or rejected a statement. ([OBJ-1, RTE-1, RTE-2](runtime.md), [EPI-RTE-2](epistemic.md), [part-specific OBJ-1 amendment](reconciliation.md).)

Acquisition imports transcripts and files into the journal. Consolidation selects checkpoint-bounded batches, then uses narrow rules or an optional chat model to propose lasting facts. The model branch processes user/note content and checks evidence occurrence, statement shape and the returned durability flag before placement; it does not verify that the evidence entails the statement or that the source is true. Facts retain evidence references rather than model deliberation. Existing statements and retained controls govern deduplication and re-admission, while changed-file support can retire older file-derived facts. Successful publication through the domain-validated publisher checks a candidate and updates the Git ref against its expected base; that enforces publication coordination and structural validity, rather than semantic correctness. ([MEM-RTE-1](memory.md), [RTE-4, RTE-3](runtime.md), [EPI-OBJ-1, EPI-CLM-1](epistemic.md).)

Instruction preservation has a concrete source-inspected defect. In rules mode, `please never use tabs` maps to `User requested: use tabs`, because the preference template omits the matched negative qualifier. Separately, overlap-based deduplication drops words including `not`, `no` and `never`, so opposed assertions can appear equivalent to that check. These are implementation deductions, without an executed incident here. They matter particularly when remembered preferences become later instructions: source quotation alone cannot repair a changed instruction's meaning. ([RTE-4 annotation](memory.md), [RTE-4 amendment](reconciliation.md), [RTE-9](runtime.md).)

Requested search combines curated facts and journal events, with optional remote relevance judging, a cached local reranker, then lexical fallback. Project filtering occurs after the bounded fact shortlist, so unrelated facts can consume candidate slots; direct ID reads do not apply a project predicate. Project selection therefore provides retrieval scope rather than tenant isolation. Automatic host delivery uses different selectors: session start reads only the exact preference entity and emits at most twenty statements, while prompt callbacks emit at most six lexical matches after prompt and overlap gates. These callbacks emit advisory context; project writeback persists selected statements in a managed instruction block. Host incorporation and behavioral activation remain uninspected. ([RTE-1, RTE-2, RTE-5, BAP-1, BAP-2](runtime.md), [RTE-5 amendment](reconciliation.md), [MEM-OBJ-1](memory.md).)

For a scenario requiring a forgotten or expired statement to disappear from every later context, the consumer differences are decisive. Search applies temporal eligibility and fact controls. Direct entity reads select active-status facts after suppression/deletion filtering but omit search's time and audience checks; session-start delivery inherits that behavior. Writeback has its own status and fact-visibility filters, permits disputed facts, and omits controls, entity visibility and temporal eligibility. A previously written block survives subsequent store changes. Soft forget also leaves raw journal content searchable. Hard erasure extends removal to selected journal, history and intent material through successive fallible steps, with external transcripts and file copies outside its reach. These paths support local withdrawal, without a uniform all-context or whole-environment erasure guarantee. ([RTE-2, RTE-6 amendments](reconciliation.md), [RTE-3, RTE-9](runtime.md), [MEM-OBJ-1](memory.md).)

Explicit remember/correct/forget requests admit caller-proposed changes after structural checks. The shared request interface can treat a reused request ID as replay before comparing its changed payload, narrowing the low-level publisher's replay assurance. Task updates separately enforce an expected version under a lock, but write by truncating and syncing the task file; crash-safe replacement is unsupported. Tidy proposes duplicate or session-only withdrawal, with operator apply/keep decisions and retained reasons. These operations change retained material and local reliance without independently demonstrating improved reliability. ([RTE-3, RTE-9](runtime.md), [OBJ-2, RTE-8 amendments](reconciliation.md).)

For the shipped extraction and tidy methods, theory-builder condition 1—localized formulated guidance—is afforded, and condition 2—content-dependent consumption—is wired by supplying that guidance to the model and using its outputs. Conditions 3 and 4—content-directed criticism of the method and retained iteration on that criticism—are absent in those inspected paths: outcome records and withdrawal reasons do not revise the method prompts. Consequently those paths are neither reflective nor autonomous theory builders, despite computational extraction and admission. Reflection of the methods remains uninspected; retained processing outcomes alone do not establish both causal directions between self-representation and later behavior. Criticism improving future capacity, learning in that stronger sense, and self-improvement at the selected product boundary remain uninspected. Particular retained theories and inaccessible model reasoning are not classified by these method-path findings. ([RTE-4, RTE-9](runtime.md), [bounded conclusion](epistemic.md).)

Retrieval evaluation can compare lexical and reranked top-k results against operator-supplied IDs and text predicates; benchmarking can report workload latency. Both return reports, without an automatic production successor-selection route. A frozen execution showing later hosts using a retained fact would strengthen activation evidence; an appropriately controlled comparison would be needed to attribute improved capacity or ranking benefit. Negation-preserving transformation and deduplication, consistent consumer eligibility, payload-checked replay, and propagation of withdrawal to written copies would change the respective implementation assessments. ([RTE-10](runtime.md), [EPI-OBJ-3, EPI-OBJ-5, EPI-RTE-3](epistemic.md), [RTE-4, RTE-6 amendments](reconciliation.md).)
