# Meta-n synthesis

## Bounded synthesis

### From task evaluation to retained solver changes

Meta-n implements an improvement plane: a fixed model-driven operation, Ω, reads evaluated solver traces and proposes Python preprocessing and Python/bash helpers that become part of subsequent task-solving chains. Its strongest supported contribution is this trace-responsive, retained change to the process that produces answers, rather than only revision of individual answers. The inspected implementation wires proposal, evaluation, selection, persistence and later consumption. Whether those changes actually improved future task-solving capacity remains unresolved. The README's recursive-improvement and emergent-role claims are attributed design/reporting, not independently inspected campaign results ([RT-RTE-chain-admission](runtime.md#rt-rte-chain-admission), [EPI-CLM-recursive-improvement](epistemic.md#epi-clm-recursive-improvement)).

The evidence is source code and declared design from SRC-1, `https://github.com/MinnesotaNLP/Meta-n`, at commit `b7081843d3c7b0e0f418ca10aaf2ccbff856e7f8`, with cutoff 2026-10-14. The whole-system functional boundary includes the shipped CLI, native solvers, external-agent bridges, improvement search, persistence and diagnostic consumers. It is not an exhaustive audit of every algorithm. No target code, tests, model calls or benchmark campaign were executed or supplied as observed evidence. Upstream datasets, evaluator/SDK internals, live providers and the paper are not independently frozen evidence ([boundary and evidence](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)). This synthesis uses the accepted records; no additional target-source read was needed.

A representative shipped workflow begins with `meta-n --tasks <json> --use-archive`. Archive-enabled configuration is a prerequisite; the bare custom-task invocation without it is rejected before task loading or model-client construction. The operator supplies tasks, optional verification scripts, provider settings and search controls. For the fresh unseeded native case, software evaluates a depth-1 baseline, archives its scored traces, then selects parents using elite reservation and fitness/exploration sampling. An optional operator-selected seed library instead imports helper content whose upstream authorship and experience provenance remain unresolved ([RT-RTE-native-solve](runtime.md#rt-rte-native-solve), [MEM-RTE-seed-import](memory.md#mem-rte-seed-import)).

The improvement handoff gives Ω selected traces, prior injections, task descriptions and score comparisons. Code samples and truncates the view; the proposal model does not receive the whole archive or own scheduling. Ω returns parsed preprocessing, helper source and rationale. Software appends the intervention to the parent's full chain, assigns a new child identity and evaluates it under the selected solver/executor route. Native composition nests preprocessing and source-returning layers, not separately autonomous model workers at each depth. The outer layer executes the resulting source and owns optional local debug retries. Later helper names override earlier ones ([RT-RTE-chain-admission](runtime.md#rt-rte-chain-admission), [MEM-RTE-omega-context](memory.md#mem-rte-omega-context), [RT-OBJ-code-library](runtime.md#rt-obj-code-library)).

The intervention has two different kinds of force. Host Python executes preprocessing to emit additional context; the solver model interprets that prose and helper advertisements as guidance. Native prepended source or externally staged files can determine executable effects when invoked. Guidance delivery is not reliable compliance, and source staging is not proof of invocation. Retained rationale reaches later Ω requests when its layer survives selection; it is not independently accepted explanation or directly executed policy ([RT-BAP-prompt-guidance](runtime.md#rt-bap-prompt-guidance), [RT-BAP-executable-injection](runtime.md#rt-bap-executable-injection), [RT-OBJ-rationale](runtime.md#rt-obj-rationale)).

### Checks permit bounded trials, not universal endorsement

For a non-focus child with the quality gate enabled, software executes sampled tasks and compares success/score against the parent baseline. Without a protection floor, the first clearing sample permits full evaluation. With a floor, sampled regressions can veto. Missing baseline or disabled margin leaves liveness-only clearing. Gate traces can be reused during full evaluation. The gate grants continuation, not all-task non-regression, production approval or acceptance of the intervention's explanation. Fully evaluated children can remain archived even when worse; whole-candidate ranking and per-task-best promotion are separate decisions ([EPI-RTE-gate-check](epistemic.md#epi-rte-gate-check), [EPI-RTE-gate-disposition](epistemic.md#epi-rte-gate-disposition), [MEM-OBJ-trace](memory.md#mem-obj-trace)).

With within-layer refinement enabled, a failed nonempty, non-focus proposal at depth at least 2 can receive one repair attempt, provided failure traces exist. The request supplies the newest intervention and lower chain under a fixed directive to preserve the approach and fix the code. That directive is a requested diagnosis, not established causal blame. Software creates a distinct repaired candidate, filters it, re-gates it and fully evaluates it only if it clears. The rejected original is not mutated into the repair. A repair event's matched-subset score comparison differs from gate-based archive admission. Separate downstream repair can replace an intermediate layer and archive a nonempty evaluated variant even when classified non-improving ([RT-RTE-within-refine](runtime.md#rt-rte-within-refine), [RT-RTE-downstream-repair](runtime.md#rt-rte-downstream-repair), [workflow account](workflow.md#workflow-account)).

Optional Python-helper verification has narrower scope still. Only crew-only selection supplies the inspected real value harness; other selections use an explicitly unverified pass-through stub. The real criterion is full-set score above a fixed comparator and feasibility of at least 50%, under the mounted oracle/configuration. It uses the `test` split for selection, so later reporting on that split is not an untouched holdout for helper-selected chains. Failed sibling entry points can be restored through dependency closure without acquiring a new verified stamp; preprocessing and bash pass through. Adapter demotion can also separate retained admission from live deployment ([EPI-RTE-helper-check](epistemic.md#epi-rte-helper-check), [EPI-RTE-helper-disposition](epistemic.md#epi-rte-helper-disposition)).

The verifier trusts the last stdout JSON object without first rejecting nonzero process exit. Its sandbox bit is status-derived; pass plus that bit stamps helper names. Those names and downstream non-adoption bars are implemented metadata, not independently authenticated helper execution. Any value warrant remains conditional on trustworthy runner measurements and the upstream oracle. No exploit or actual helper call is established. The stronger verify-then-inject doctrine therefore cannot support a universal correctness or host-isolation guarantee ([RT-RTE-helper-verification](runtime.md#rt-rte-helper-verification), [MEM-OBJ-python-library](memory.md#mem-obj-python-library), [EPI-CLM-verified-channel](epistemic.md#epi-clm-verified-channel)).

Outcome checks must be interpreted within their actual domain. For example, inspected classification scoring derives normalized label-match fractions against supplied labels; `success` means positive score, not correctness of every prediction or truth of the reference labels. Scores can select executable variants without validating their proposed mechanism. No concrete Ω output establishes whether its claims copy, derive from or go beyond its inputs; their semantic relation remains indeterminate ([EPI-RTE-classification-check](epistemic.md#epi-rte-classification-check), [EPI-OBJ-eval-result](epistemic.md#epi-obj-eval-result), [RT-RTE-chain-admission](runtime.md#rt-rte-chain-admission)).

### Later consumers and delivery

Evaluated traces, full interventions and rationale survive in files and live objects. Checkpoints separately retain scheduling, RNG, usage and admission bars. Resume reconstructs candidates, excludes incomplete injection chains and unions saved bars, then makes source and rationale available to later selection and solving. Individual checkpoint/index replacement is atomic; the candidate set is not one multi-file transaction. Current configuration wins after a drift warning. Raw Ω sidecars remain diagnostic files but ordinary reconstruction does not restore them. Resume is therefore supported continuation, not exact replay or renewed security/value verification ([MEM-RTE-archive-resume](memory.md#mem-rte-archive-resume), [MEM-OBJ-checkpoint](memory.md#mem-obj-checkpoint)).

The proposal model's context can be smaller than the executable chain: sampling, display truncation and oldest-layer eviction change visibility, not retained capability. Section budgets and character-based estimates do not guarantee a complete request fits the provider window. Native agentic solving adds a distinct action/observation loop. Its automatic compaction replaces middle turns with an unchecked model summary while retaining the first message and recent tail. Later turns consume that summary within the task; removed turns have no established reload route there. This is a trace-fed continuation artifact, not a disk-restored agent conversation ([MEM-RTE-omega-context](memory.md#mem-rte-omega-context), [RT-RTE-agentic-loop](runtime.md#rt-rte-agentic-loop), [MEM-RTE-context-compaction](memory.md#mem-rte-context-compaction)).

External-spine solving bypasses native nested composition. Software maps interventions into context and files, checks cost headroom, obtains an environment lease, stages helpers, runs an SDK backend, extracts a solution and scores it. The SDK model/tool loop owns its internal next actions. OpenHands receives a system suffix and terminal/file-editor tools; Terminus folds injection into instruction context. Host and optional container envelopes differ. Complete copied transcripts, internal SDK memory policies and live isolation are not established. Budget admission and returned usage accounting do not provide a universal dollar ceiling: concurrent work can overshoot and opaque or killed runs can undercount ([RT-RTE-external-spine](runtime.md#rt-rte-external-spine), [RT-CLM-budget-bound](runtime.md#rt-clm-budget-bound)).

At termination, the best single chain differs from the per-task-best aggregate across lineages. Optional frozen assembly combines stored winners without new evaluation; matching native task IDs select scripts without model prompting, library prepend or retries. Its recorded mean is not a fresh combined outcome, unseen-task generalization or external-backend parity. Test readers either execute retained source or reconstruct a chain and re-solve. Post-run best-of-K reports shared-task arithmetic and advisory statistics; it does not enforce compute parity or identify causal component effects ([RT-RTE-frozen-routing](runtime.md#rt-rte-frozen-routing), [MEM-RTE-test-readback](memory.md#mem-rte-test-readback), [EPI-RTE-arm-report](epistemic.md#epi-rte-arm-report)).

Operator delivery is CLI reporting plus final artifact writing, not deployment acceptance. Soft budget halts can return aborted results; hard client budget exceptions skip finalization and leave mid-run artifacts for operator-directed resume. The Stage 2 CO-Bench launcher nevertheless skips on summary-file existence, which can suppress rerun of a mid-run artifact. Correct CLI finalization does not establish uniform launcher completion detection or automatic recovery ([WF-CLM-delivery-boundary](workflow.md#wf-clm-delivery-boundary)).

### Independent assessments

Within the bounded search/resume experiment, trace-fed artifact learning is wired: experience feeds automatic writes whose source, summaries or compiled maps have later behavior-shaping consumers. This is not evidence of model-weight training or improved future capacity. Criticism of a consumed theory improving that capacity is unestablished: no supplied claim/result/blame account and outcome comparison supports it. Provider identifiers do not pin immutable weights, and provider-side parameter changes remain uninspected ([RT-RTE-chain-admission](runtime.md#rt-rte-chain-admission), [MEM-RTE-context-compaction](memory.md#mem-rte-context-compaction), [RT-RTE-frozen-routing](runtime.md#rt-rte-frozen-routing), [RT-CMP-llm-client](runtime.md#rt-cmp-llm-client)).

The runtime's theory-builder assessment remains separate for each condition: (1) localized strategy content is **afforded** by inspectable preprocessing/helper units, with actual theory content uninspected; (2) executable content-dependent consumption is **wired**, while model reliance on prose is unobserved; (3) content-directed criticism is **claimed** through instructions, not demonstrated by generated outputs; (4) retaining revisions for later rounds is **afforded**, but iteration of actual criticism is unobserved. These findings do not establish that all four conditions occurred. Fine-grained assumptions and explanatory scope depend on unsupplied content ([RT-RTE-chain-admission](runtime.md#rt-rte-chain-admission)).

Reflection has an afforded representation-mediated feedback path: solver outcomes and retained injections can inform subsequent organization. Its actual faithfulness and exercise are unobserved. Computational proposal, comparison and continuation establish scheduling autonomy, not an autonomous theory builder; the latter remains uninspected. A reflective theory builder is likewise uninspected: the fixed Ω method texts are not revised through this route. These properties neither imply nor negate learning or self-improvement ([RT-RTE-chain-admission](runtime.md#rt-rte-chain-admission)).

Dispositional, improvement-directed self-change is **wired** at the declared boundary, with higher task score specified independently of the proposed change. Traces shape requests, retained interventions change solver organization, and live guidance/executable channels can reach later behavior. Subsequent operation causally depending on a particular change—the fourth link required for exercised self-improvement—is unestablished. Successful improvement needs separate outcomes and a suitable comparison. For repeated trials on supplied tasks, the implementation supports an experiment and continuation mechanism. For unseen-task transfer, reliable criticism or causal superiority over matched best-of-N, the same records cannot establish the result ([RT-RTE-chain-admission](runtime.md#rt-rte-chain-admission), [EPI-RTE-arm-report](epistemic.md#epi-rte-arm-report)).

A provenance-linked campaign connecting parent feedback, concrete proposals, checks, admitted source and later executions would change the exercised-operation assessment. Controlled comparisons varying the intervention at matched compute would address benefit at that comparison's scope; independent fresh tasks would address transfer. Input/output criticism and summary instances would permit content and fidelity assessment. Authenticated runner results, a genuinely unused evaluation split, and launcher completion checks based on run status rather than file existence would strengthen the respective guarantees, not automatically the other properties.
