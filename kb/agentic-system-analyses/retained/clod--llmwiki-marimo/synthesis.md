# llmwiki-marimo synthesis

## Bounded synthesis

### From documents to reusable pages

LLM Wiki is a local knowledge system for ingesting documents, browsing retained pages and answering questions from them. This account covers the shipped web and marimo applications, generation and chat services, prompts, maintenance and evaluation drivers at Git commit `0df06b0499a6242a4a5edfb1495e1d55a3e3c8b7`, with an analysis cutoff of 2026-10-18. SRC-1 supplies implementation and source-native design evidence, not an observed workload or causal experiment. External provider internals, weights and deployed user workspaces are outside the inspected evidence. The whole-system functional boundary is not an exhaustive algorithm audit ([boundary](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)).

The distinguishing progression is source acquisition → generated wiki → later retrieval and merging. Upload or scan starts a code-owned pipeline. It extracts and commits source text before requesting model-generated concepts and summaries. Existing same-slug concept bodies become input to later generation. Software then admits generated Markdown and updates references, search state and collection pages without per-generated-page human approval. A malformed extraction response can become a raw summary fallback rather than being rejected. Instructions to preserve existing content guide the model; they do not enforce a lossless merge ([RT-RTE-document-ingest](runtime.md#rt-rte-document-ingest)).

Editable Markdown is the durable knowledge product. SQLite retains source text, lexical search chunks, references and diagnostics; it is not a vector-memory design in the inspected paths. Page prose supplies interpreted context, while IDs, FTS terms, aliases and thresholds have fixed program consumers. Original sources remain a separate evidential substrate. Citation connections establish lineage, not source truth or semantic preservation through generation. Without content-level input/output evidence, generated propositions cannot be classified uniformly as faithful reshaping, entailed derivation or novel conjecture ([MEM-OBJ-source-text](memory.md#mem-obj-source-text), [MEM-OBJ-wiki-pages](memory.md#mem-obj-wiki-pages), [MEM-OBJ-document-chunks](memory.md#mem-obj-document-chunks), [EPI-OBJ-wiki-pages](epistemic.md#epi-obj-wiki-pages)). Thus the project's compilation claim is supported as retained reuse, not as demonstrated production of accepted new knowledge ([EPI-CLM-wiki-compilation](epistemic.md#epi-clm-wiki-compilation)).

### From retained state to an answer

The application dispatches the turn; a model does not schedule independent workers. In default pre-retrieval mode, code filters history and selects evidence before invoking the answer agent. Question vocabulary, aliases, blacklist, FTS, open-page identity and collection intent choose among wiki chunks, raw sources, whole overview/index bodies and dataset context. An uncovered follow-up can use a separate condenser invocation; only its rewritten question returns to the retrieval gate. Defaults of six wiki chunks or four raw chunks are count limits, not a global token budget. History removes refused exchanges, compacts advisory tables and keeps a six-message tail. Removed conversation text has no automatic reload pointer; querying current data again does not recover past conversational values ([RT-RTE-preretrieval-chat](runtime.md#rt-rte-preretrieval-chat), [memory annotations](memory.md#annotations)).

Grounding has different force at different return boundaries:

- **Strict:** PydanticAI owns the model/tool loop. The service substitutes refusal unless its inspected messages contain a substantive tool return. This predicate does not compare answer meaning with evidence; a retrieved result can be ignored and still satisfy it. Supplied-history semantics also qualify the predicate's scope ([RT-RTE-strict-chat](runtime.md#rt-rte-strict-chat)).
- **Pre-retrieval:** Scope and context selection can prevent generation. Post-processing tests tool presence only when no context was injected, and applies lexical coverage to raw-source answers, not equivalently to curated context. Open-page, collection and dataset/advisory alternatives therefore matter to any grounding claim ([RT-RTE-preretrieval-chat](runtime.md#rt-rte-preretrieval-chat)).
- **Streaming:** Reachable web and marimo dispatch emits text immediately without strict final grounding substitution. This establishes an unchecked output route, not an observed incorrect answer ([RT-RTE-streaming-chat](runtime.md#rt-rte-streaming-chat)).

Standard chat grants retrieval, not wiki writing. Separate services perform ingestion, saving and maintenance. This is a composition-time tool boundary, not an OS sandbox: the generic factory permits caller-supplied Python tools, and other application paths can invoke host subprocesses. Configured models are not immutable weight identities; requested sampling settings do not establish deterministic output ([RT-CLM-readonly-chat](runtime.md#rt-clm-readonly-chat), [RT-RTE-configure-grants](runtime.md#rt-rte-configure-grants), [RT-CMP-openai-model](runtime.md#rt-cmp-openai-model), [runtime control envelope](runtime.md#control-envelope-and-forcing-cases)).

Structured datasets add a distinct route. The finance overlay validates required metrics and attributes, admits eligible currency/amount/term combinations, computes conditional gains in Python and ranks results. Non-deterministic alternatives are separated from ranked projections. This supports arithmetic under encoded premises and a constant-rate model, not authenticated quotations or future-return predictions. A postprocessor can append the computed table, but only when its marker test does not find an existing table marker; it does not verify that an already-present model table matches ([MEM-OBJ-datasets](memory.md#mem-obj-datasets), [EPI-RTE-finance-check](epistemic.md#epi-rte-finance-check), [EPI-RTE-finance-select](epistemic.md#epi-rte-finance-select), [EPI-RTE-finance-derive](epistemic.md#epi-rte-finance-derive), [EPI-RTE-answer-format](epistemic.md#epi-rte-answer-format)).

### From an answer back into retained knowledge

The representative workflow crosses the important admission boundary: web question → displayed answer → separately requested concept draft → editable review → save. Drafting selects answered exchanges, omits refusals and unanswered questions, and merges an existing same-slug page when present. The human can edit, verify or cancel. Optional draft verification compares submitted editor text with passages retained from that conversation, without re-retrieving sources. A successful save return displays a notice and refreshes navigation; a draft or displayed answer alone is not a retained wiki page ([workflow account](workflow.md#workflow-account), [RT-RTE-chat-save](runtime.md#rt-rte-chat-save)).

Review is a normal web protocol, not an enforced server provenance condition. The save endpoint requires nonempty input and an available lock, not a prior draft or verification pass. Marimo and convenience-service paths structure and write without intermediate review. Web saving avoids another generation call, but deterministic repairs can still change the resulting page. Git history is attempted rather than required for delivery. On failure the dialog preserves editor contents for human retry; it does not roll back already-written files or derived state. Ingestion compensation cannot be assumed for this different save sequence ([RT-RTE-chat-save](runtime.md#rt-rte-chat-save), [workflow save annotation](workflow.md#annotations)).

The strongest supported learning-related contribution is this software-admitted conversation-to-page chain: recorded conversational text becomes a durable page that later retrieval or merging can consume. It establishes a wired trace-fed update on marimo/convenience paths, independently of improved capacity or factual acceptance. Human-reviewed web admission is a different mechanism. Raw trace files, reduced turn history and a saved page are not interchangeable artifacts. The accepted profile verification confirms this local positive while preserving incomplete trace-source and update coverage ([MEM-OBJ-wiki-pages](memory.md#mem-obj-wiki-pages), [MEM-OBJ-spans](memory.md#mem-obj-spans), [profile verification](profile-verification.md#verification)).

### Criticism, maintenance and the assessment it permits

Optional NLI verification scores selected checkable sentences against selected passages. Page results retain probabilities, hashes and abbreviated excerpts; current thresholds can change later classifications without new inference. These results inform readers and lint, not a universal admission or retrieval veto. Answer annotation follows display. Fresh hashes license reuse of a diagnostic, not endorsement of source assertions ([EPI-RTE-verify-check](epistemic.md#epi-rte-verify-check), [MEM-OBJ-page-verifications](memory.md#mem-obj-page-verifications), [EPI-RTE-verify-use](epistemic.md#epi-rte-verify-use)).

Maintenance preserves some explicit criticism. A shared-source, truncated page comparison can produce a possible-contradiction warning; repair retains it rather than adjudicating which claim to reject. Gap reminders can later become links on lexical coverage evidence, not a demonstrated semantic resolution. Source withdrawal removes raw access and one-to-one summaries but leaves other citing concepts stale and searchable. History restoration is conditional; a usable database snapshot preserves state that file-based reindex cannot reconstruct ([EPI-RTE-contradiction-check](epistemic.md#epi-rte-contradiction-check), [EPI-RTE-contradiction-note](epistemic.md#epi-rte-contradiction-note), [EPI-RTE-gap-note](epistemic.md#epi-rte-gap-note), [MEM-RTE-source-withdrawal](memory.md#mem-rte-source-withdrawal), [MEM-OBJ-index-snapshots](memory.md#mem-obj-index-snapshots)).

For personal source-backed browsing and reusable summaries, the implementation establishes acquisition, retention, multiple read-back selectors and explicit maintenance effects. For the stronger scenario of accepting new factual conclusions and improving future action through criticism, the evidence stops earlier. Retained warnings and update routes are a contribution, but no supplied chain establishes theory-builder condition 1's localized formulated theory, condition 2's content-dependent consumption, condition 3's blame-assigned criticism with revision or changed reliance, and condition 4's reuse of that result as separately satisfied properties. Nor is there evidence that criticism of a consumed theory improved future capacity. These are unestablished conclusions, not evidenced absences or consequences of fixed model weights ([epistemic bounded conclusion](epistemic.md#bounded-conclusion), [RT-RTE-wiki-maintenance](runtime.md#rt-rte-wiki-maintenance)).

Reflection, autonomy and self-improvement remain independent questions. The records do not establish the two causal directions needed for reflection or computational performance of every internal theory-building role. They do establish automatic substeps, despite human initiation. Retained pages and controls can affect later behavior, but no supplied evidence closes an exercised self-improvement pathway from objective-bearing evidence through update determination and live adoption to subsequent operation causally depending on the change. No controlled comparison demonstrates successful improvement ([RT-RTE-configure-grants](runtime.md#rt-rte-configure-grants), [RT-RTE-chat-save](runtime.md#rt-rte-chat-save), [epistemic bounded conclusion](epistemic.md#bounded-conclusion)).

Linked before/after content and execution traces could establish particular transformations, exercised consumption and responses to criticism. A recorded evidence-consuming acceptance criterion, intended use and scope would change the acceptance assessment. A comparison independently varying a mechanism would be needed for its causal benefit. Likewise, enforcing draft provenance or a semantic save gate would change the current admission guarantee; excluding stale derivatives from retrieval would change withdrawal's force. Existing evaluator code alone does none of these. Fixed suitability probes, human-mediated packets and frozen regression fixtures support bounded checks, while the report verification explicitly retains incomplete evaluator coverage ([RT-RTE-model-evaluation](runtime.md#rt-rte-model-evaluation), [EPI-RTE-eval-packet](epistemic.md#epi-rte-eval-packet), [EPI-RTE-corpus-freeze](epistemic.md#epi-rte-corpus-freeze), [report verification limits](report-verification.md#limits)).
