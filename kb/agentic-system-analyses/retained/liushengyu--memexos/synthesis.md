# MemexOS synthesis

## Bounded synthesis

MemexOS is a knowledge-production and retrieval system, not an enclosing answering agent. It collects sources, delegates wiki writing, conditionally checks and publishes the changes, and returns retained material to later callers. This account covers the shipped CLI, scheduled maintenance, console actions, prompts, vault instructions and evaluators at commit **bb9e9b2ac0adbca87d13a9f7600867128b5f71b9**, with an applicability cutoff of **2026-11-07**. Its sole source, SRC-1, is the frozen `liushengyu/memexos` repository. Evidence is implementation text and attributed doctrine, not target execution. No production trace, adopted performance result or causal experiment establishes successful operation or benefit. External model services, qmd internals and ordinary consuming agents' reasoning remain outside the inspected implementation ([boundary](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)).

### From collected experience to a selected draft

The system's persistent center is a filesystem and Git vault. Raw sources and derived wiki pages have different lifecycles. Captured text can enter directly, while unattended intake asks a model to admit, reject or retain uncertain candidates. Selected text scanning can veto admission; it is not a guarantee over every binary copy, capture or plugin route. Session intake is already a transformation: selected conversational and tool records become distilled snapshots before wiki compilation. Thus a file in `raw/` need not be a verbatim original or independently warranted evidence ([RT-RTE-source-admission](runtime.md#rt-rte-source-admission), [MEM-OBJ-raw](memory.md#mem-obj-raw), [MEM-RTE-session-distillation](memory.md#mem-rte-session-distillation)).

The representative workflow is `memex ingest`, chosen because one shipped caller connects selection, delegation, checking, repair and delivery. Code selects unprocessed, unheld raw paths, obtains a write lock and creates a staging branch/worktree from the vault base. It supplies the writer with source paths, classification and instructions to read the vault rules. The writer proposes wiki, index, log and inbox edits; code retains scheduling and merge authority. No routine per-edit human approval is required. Separate writer and reviewer calls exchange files and selected reports, not an inspected shared conversation ([RT-RTE-compile-publish](runtime.md#rt-rte-compile-publish), [RT-OBJ-stage](runtime.md#rt-obj-stage), [workflow account](workflow.md#workflow-account)).

Context selection is consequential at each handoff. Session rendering abbreviates tool output and removes some material; classification uses bounded digests and selected precedents; review receives a capped diff with file-reload access; repair receives rendered problems rather than the entire reviewer session. These mechanisms isolate work and restrict delivered context. They do not establish that every relevant fact reaches the next model. Files can remain available for requested reads without being present in its window. External CLI compaction remains opaque ([MEM-RTE-session-distillation](memory.md#mem-rte-session-distillation), [MEM-RTE-catalog-reuse](memory.md#mem-rte-catalog-reuse), [RT-RTE-backend-execution](runtime.md#rt-rte-backend-execution)).

### What publication accepts—and what it does not

Gate 1 checks structural properties of the staged changes, including allowed paths, selected link/source references and new-page structure. Optional sentence self-check supplies support diagnostics for selected unmarked additions; unavailable checking can proceed to review. Gate 2 asks a model for source-faithfulness, coverage, overwrite and injection judgments. Deterministic rules then decide publication eligibility over that model-produced inventory. Critical unsupported or contradicted claims and missed critical points veto; noncritical bad claims block above 5%, and must-point coverage blocks below 80%. These thresholds are not independently measured error rates over all actual claims ([EPI-RTE-gate1-check](epistemic.md#epi-rte-gate1-check), [EPI-RTE-selfcheck-check](epistemic.md#epi-rte-selfcheck-check), [EPI-RTE-review-claims](epistemic.md#epi-rte-review-claims), [EPI-RTE-review-decision](epistemic.md#epi-rte-review-decision)).

The acceptance criterion is eligibility of this changed batch for source-faithful vault publication, not truth of the underlying source. The rubric explicitly excludes source trustworthiness. Honestly marked speculation is allowed; PARTIAL judgments and some noncritical errors need not block. Review fields enforce continuation on enabled covered paths, while their reasons guide another writer. On rejection, selected claim, source, location and reason fields reach bounded rework. Exhausted repairs can hold a branch and suppress ordinary retry; review unavailability instead discards the draft and starts a cooldown. Initial writer failure, holding and merge-abort have different recovery paths ([RT-BAP-review-verdicts](runtime.md#rt-bap-review-verdicts), [MEM-OBJ-review](memory.md#mem-obj-review), [RT-RTE-compile-publish](runtime.md#rt-rte-compile-publish), [workflow account](workflow.md#workflow-account)).

This is a **conditional publication protocol**, not the public claim that nothing is published unreviewed. Gate 2 can be configured off; no review-relevant changes can pass without a model call. Catalog synchronization independently publishes material source-use metadata after Gate 1 alone. `Stage.publish` has no independent review-certificate requirement. Nor is writer isolation uniform: Codex's workspace grant is broader than the writer's named edit paths, and Gate 1 checks the diff rather than undoing prior process effects. The OpenAI-compatible adapter also has a provider-response-shaped fetch dispatch case without a local web-permission recheck; that is code-level reachability, not an observed model bypass ([RT-CLM-checked-publication](runtime.md#rt-clm-checked-publication), [EPI-RTE-catalog-sync](epistemic.md#epi-rte-catalog-sync), [RT-RTE-backend-execution](runtime.md#rt-rte-backend-execution)).

Delivery means the draft merged into the live vault. Persistence adds no epistemic warrant, and no separate post-acceptance semantic integration judgment is established by this compile path. FTS refresh is attempted and vector reindexing follows asynchronously; merge success does not guarantee fresh indexes or a multi-file reader snapshot ([EPI-RTE-wiki-retention](epistemic.md#epi-rte-wiki-retention), [RT-RTE-compile-publish](runtime.md#rt-rte-compile-publish)).

### Later use and feedback

An asking agent requests search, then optionally gets page text. Search combines available lexical/vector routes, filtering, fusion and optional reranking; it can return raw material independently of wiki approval. Get reloads requested file contents. Retained pages supply information, not an enforced answer policy: the caller owns subsequent reasoning, citation and reliance. Classification and source pointers help interpret evidence but do not certify it ([RT-RTE-search-get](runtime.md#rt-rte-search-get), [RT-BAP-retrieved-pages](runtime.md#rt-bap-retrieved-pages), [MEM-OBJ-wiki](memory.md#mem-obj-wiki)).

Read-back also occurs inside production. Code supplies pending sources to fresh compilers, URL/author-matched catalog precedents to classifiers, and retained review problems or usage summaries to repair/lint calls. Those automatic supplies differ from requested search/get. Retained state has several forces: prose supplies context and guidance; processing ledgers exclude or select work; verdict fields can veto publication; text and vectors influence retrieval ranking. FTS tokens, dense vectors and external model parameters are distinct objects, not interchangeable kinds of memory ([MEM-RTE-catalog-reuse](memory.md#mem-rte-catalog-reuse), [MEM-OBJ-ledgers](memory.md#mem-obj-ledgers), [MEM-OBJ-fts](memory.md#mem-obj-fts), [MEM-OBJ-vectors](memory.md#mem-obj-vectors)).

The strongest supported adaptation contribution is a wired trace-to-durable-change chain. Session distillation produces reusable text. Usage extraction and model diagnosis can produce feedback; confirmation with nonempty problems creates stored repair tasks; fix can publish revised wiki for later retrieval. A smaller loop persists rerank timing and uses it to set later candidate budgets. These establish automatic trace-fed writes with later consumers, not just passive log storage. They do **not** demonstrate improved future capacity, accurate diagnosis, better answers or faster retrieval ([MEM-RTE-session-distillation](memory.md#mem-rte-session-distillation), [MEM-RTE-usage-repair](memory.md#mem-rte-usage-repair), [MEM-RTE-rerank-budget](memory.md#mem-rte-rerank-budget), [profile verification](profile-verification.md#verification)).

The public evolution claim has separate, bounded outcomes. Improvement-directed self-change is implemented dispositionally: evidence can shape repairs, publication changes retained organization, and later writers/retrieval can consume it. Exercised self-improvement remains unestablished because no subsequent operation is shown to depend causally on that change; successful improvement needs additional outcome evidence. Reflection has a partial wiring witness in usage representations that can drive repairs, not an observed faithful two-way cycle. Several internal operations are automated, but whole-system autonomy is not established. Theory-builder conditions **1** (localized formulated theory), **2** (decisions dependent on its content), **3** (content-directed criticism and changed reliance/revision) and **4** (retained criticism shaping another round) remain individually unestablished here: no concrete theory instance is individuated. Neither repair wiring nor schema proposals establish these conditions, and no improvement attributable to criticism of a consumed theory is demonstrated ([EPI-CLM-evolves-itself](epistemic.md#epi-clm-evolves-itself), [RT-CLM-schema-change](runtime.md#rt-clm-schema-change)).

### Assessment relative to the work

For accumulating sources into a revisable, searchable wiki, the implementation supplies a coherent unattended workflow with explicit rejection and recovery states. For certifying every delivered claim as true, its source-relative rubric, model-selected inventory and alternate publication routes do not supply that guarantee. For demonstrated self-improvement, it supplies the update pathway but not exercised causal dependence or benefit. These are different questions, not a product ranking ([RT-RTE-compile-publish](runtime.md#rt-rte-compile-publish), [EPI-CLM-reviewed-memory](epistemic.md#epi-clm-reviewed-memory), [EPI-CLM-evolves-itself](epistemic.md#epi-clm-evolves-itself)).

The shipped evaluators could supply local evidence about retrieval ranks, answer grading, seeded reviewer errors and tool procedure. Their references and consequences differ: a model-maintained question bank is not independent source truth, and procedure matching can include stubbed effects. No adopted result establishes general quality or an automatic evaluation-driven optimizer. Paired real inputs/outputs would resolve compilation's semantic transformation; longitudinal traces with controlled contrasts could establish whether particular retained changes improve later work. Uniform review claims would additionally require covering the alternate publishers and their actual consumers, not merely renaming a pass result ([EPI-RTE-evaluation-bank](epistemic.md#epi-rte-evaluation-bank), [EPI-RTE-answer-grading](epistemic.md#epi-rte-answer-grading), [EPI-RTE-review-calibration](epistemic.md#epi-rte-review-calibration), [EPI-RTE-tooluse-scoring](epistemic.md#epi-rte-tooluse-scoring), [EPI-RTE-writer-transform](epistemic.md#epi-rte-writer-transform)).
