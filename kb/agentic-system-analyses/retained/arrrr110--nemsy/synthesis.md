# Nemsy synthesis

## Bounded synthesis

### From local material to a retained Wiki

Nemsy is a caller-directed personal knowledge assistant. It turns local documents and selected conversations into Markdown Wiki pages, then supplies retained text to later model calls. This account covers the shipped Python implementation, CLI, Web backend, browser callers, prompts, storage and evaluation definitions at commit **2338bab0aab96a91efb90a80249f33510b630260**, with cutoff **2026-11-09**. SRC-1 supplies implementation and doctrine/design evidence, not observed runs or causal experiments. The whole-system functional boundary excludes developer-assistant rules, roadmap claims and external dependency internals; no actual user Vault or service responses were supplied. See the [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register). This synthesis uses accepted members without additional source inspection.

The README's continuous-accumulation and autonomous-induction claims have a concrete partial realization: caller-triggered generation, page retention and index appending. They do not establish automatic maintenance of arbitrary existing pages. Python owns file selection, model invocation, parsing and filesystem effects. The remote model proposes text, not executable next steps. The inspected calls grant text generation rather than model-selected tools or agent delegation. The configured DeepSeek aliases and endpoint are mutable, not exact pinned model weights; provider-side state and parameter changes remain uninspected ([EPI-CLM-knowledge-accumulation](epistemic.md#epi-clm-knowledge-accumulation), [RT-CMP-deepseek](runtime.md#rt-cmp-deepseek), [runtime account](runtime.md#runtime-account)).

The representative workflow is a CLI ingest followed by a **separate human-requested query**. Ingest does not automatically initiate the query. The CLI collects sources and uses stripped-content hashes to skip unchanged input unless forced. For each pending file, it supplies source text, ancestor directory guidance, the Wiki index and ten recent other pages, or fifty with wide context, to generation. Directory batches run serially: an earlier generated page can enter a later file's context if selected. That is an implemented state dependency, not demonstrated beneficial integration ([workflow account](workflow.md#workflow-account), [RT-RTE-document-ingest](runtime.md#rt-rte-document-ingest)).

The model returns requested SUMMARY and QUESTIONS sections. Python requires SUMMARY, performs text cleanup, writes a dated source page and appends an index entry. It does not independently check source fidelity, truth, schema conformity or citation support before writing. Cleanup can remove substantive text by its position under a matched heading; it is selection and reshaping, not semantic validation. A source page can combine the document, guidance and prior Wiki content, and its requested provenance fields are not independently authenticated ([MEM-OBJ-source-page](memory.md#mem-obj-source-page), [EPI-RTE-summary-cleanup](epistemic.md#epi-rte-summary-cleanup)).

Delivery and completion are different. A missing SUMMARY yields no page, but the enclosing ingest still records the nonempty source hash, while the CLI wrapper reports a completed call. A later unchanged CLI ingest can therefore skip a source that produced no page. Force or changed input permits another attempt; neither restores an earlier version. Page, index and log writes are separate, not a transaction. These are source-predicted consequences, not observed incidents ([RT-RTE-document-ingest](runtime.md#rt-rte-document-ingest), [MEM-OBJ-ingest-log](memory.md#mem-obj-ingest-log), [workflow recovery](workflow.md#checked-rejection-and-recovery-path)).

Controls depend on the caller. CLI directory exclusions do not cover every direct-file branch; HTTP direct-file ingestion bypasses collection and does not consume its force field. Empty-file recording occurs before the CLI dry-run return. Thus neither directory exclusion nor dry-run is a universal no-write or no-ingestion guarantee ([RT-RTE-document-ingest](runtime.md#rt-rte-document-ingest)).

### From retained pages to answers and further retention

A later ordinary query receives the full Wiki index plus up to thirty recent other Markdown pages. Selection uses modification time and file count, not the question. The loader does not follow index links to recover omitted bodies and provides no model-accessible fetch tool for missing pages. Complete selected files and the unbounded index are not an input-token budget. The model interprets this window under instructions to answer only from Wiki content, cite pages and abstain when information is missing. That is a **model-interpreted policy**, not a checked answer invariant; absence from the selected window cannot establish absence from the whole Wiki ([RT-RTE-wiki-answer](runtime.md#rt-rte-wiki-answer), [MEM-OBJ-wiki-index](memory.md#mem-obj-wiki-index), [RT-CLM-wiki-grounding](runtime.md#rt-clm-wiki-grounding)).

Chat has different context lifetimes. CLI chat loads twenty recent pages once at session start; ingest or save does not refresh that snapshot. Web chat reloads twenty pages per request and accepts caller-supplied history. Positive CLI max_turns discards old message pairs without a summary; the shipped zero setting leaves history untrimmed. Browser Wiki mode omits history from that request but preserves the visible array for later Chat mode. Leaving the Chat view can instead lose its unsaved local state. The searched product paths contain no implemented cross-session raw-history or summary-cache checkpoint, despite configured directory names ([RT-RTE-conversation-chat](runtime.md#rt-rte-conversation-chat), [memory annotations](memory.md#annotations), [MEM-ABS-history-store](memory.md#mem-abs-history-store)).

Retained material has several distinct effects. Wiki prose supplies model context; ancestor guidance supplies ingestion directions. Stored hashes enforce ordinary CLI skipping, while modification times rank pages for context. Token and operation logs supply accounting or action descriptions, not acceptance of propositions. Putting Wiki prose in a chat system prefix does not enforce a distinction between reliable knowledge and embedded instructions ([RT-BAP-wiki-context](runtime.md#rt-bap-wiki-context), [MEM-OBJ-index-guidance](memory.md#mem-obj-index-guidance), [MEM-OBJ-ingest-log](memory.md#mem-obj-ingest-log), [MEM-OBJ-token-log](memory.md#mem-obj-token-log), [MEM-OBJ-operation-log](memory.md#mem-obj-operation-log)).

Optional ordinary query archive writes the answer with fixed metadata and removes its ARCHIVABLE marker. The caller's archive flag authorizes retention; the marker alone does not. HTTP query accepts but ignores archive. CLI reasoning query has a separate reachable tuple-to-string-consumer mismatch: conditional on provider completion, reasoning-plus-archive is predicted to fail when the archive helper calls replace on the tuple. Successful ordinary archive semantics therefore cannot be generalized to these alternatives ([RT-RTE-answer-archive](runtime.md#rt-rte-answer-archive), [MEM-OBJ-query-page](memory.md#mem-obj-query-page), [RT-RTE-reasoning-query](runtime.md#rt-rte-reasoning-query)).

Conversation saving is Nemsy's strongest supported trace-fed contribution. A CLI save or browser archive operation supplies selected user/assistant history to a fresh model request; code admits the rewritten insight page without review of its particular propositions. The page can subsequently reach generation through the Wiki loader. This is a wired conversation-to-durable-context pathway, independent of weight training, novelty or demonstrated improvement. It is not automatic history compaction: raw conversation is neither durably checkpointed nor replaced by the insight. Background and derivation are requested, not guaranteed, and save receives no freshly loaded Wiki despite requesting associated-knowledge links ([RT-RTE-insight-save](runtime.md#rt-rte-insight-save), [MEM-OBJ-insight-page](memory.md#mem-obj-insight-page)).

The accepted comparison distinguishes automatic Wiki provision from explicit file retrieval. Task-triggered code pushes a coarse recency-selected window without the model requesting those pages; a human choosing a file or citation pulls that retained material. Citation rendering and stem resolution make current page text inspectable but do not test whether it supports the answer. Duplicate stems, nonexistent references and changed page versions delimit that inspectability ([MEM-RTE-browser-read](memory.md#mem-rte-browser-read), [EPI-RTE-citation-display](epistemic.md#epi-rte-citation-display), [profile verification](profile-verification.md#verification)). Ancestor-guidance selection is an additional route omitted from the comparison's separate direction/signal inventory; that inventory remains incomplete, as specified below.

### Checking, maintenance and the assessment it supports

Nemsy has real but narrow checks. SUMMARY parsing gates format. Lint requests model diagnoses of contradictions, outdated views, orphans and gaps using index plus fifty recent pages, but returns advice without installing corrections or retaining a criticism-to-revision loop. Smoke definitions assert metadata, lengths, permissive answer substrings and archive-file existence; their result controls the smoke command's exit status, not normal knowledge admission. No passing execution was supplied, and test writes precede assertions without automatic rollback ([RT-RTE-wiki-lint](runtime.md#rt-rte-wiki-lint), [EPI-RTE-smoke-check](epistemic.md#epi-rte-smoke-check), [EPI-RTE-smoke-disposition](epistemic.md#epi-rte-smoke-disposition)).

For the scenario of accumulating readable summaries and revisiting recent retained material, the implemented progression is established. For exhaustive corpus answering, verified knowledge production or automatic correction, it is insufficient: selection is windowed, source warrant is unknown, and generated text acquires operational use without evidence-consuming semantic acceptance. Actual source/output pairs would be needed to distinguish faithful compression, entailed derivation and conjecture; generation alone establishes none of these at proposition level. New pages and navigation links do not by themselves establish accepted knowledge or lifecycle integration ([epistemic bounded conclusion](epistemic.md#bounded-conclusion)).

The trace-to-insight route supports durable experience-derived context, but improved capacity for future action remains unestablished. Likewise, the inspected lint and retention routes do not establish content-directed criticism followed by retained revision shaping another round; this is not evidence of an autonomous theory builder. The runtime supplies no separate conditions 1–4 assessment from which to infer a stronger result. Reflection is not established merely because lint discusses the Wiki: no installed diagnosis-mediated update is shown. Exercised self-improvement is independently unestablished: later loading is wired, but no supplied operation demonstrates that an evidence-responsive organizational change was subsequently exercised with causal dependence, or that it improved an independently specified objective ([MEM-OBJ-insight-page](memory.md#mem-obj-insight-page), [RT-RTE-wiki-lint](runtime.md#rt-rte-wiki-lint), [epistemic bounded conclusion](epistemic.md#bounded-conclusion)).

A traced save-to-later-use sequence could establish exercised retention and particular-content activation; controlled comparisons would be needed for benefit attribution. A semantic admission decision with criterion, evidence and intended scope would change the knowledge-acceptance assessment. An implemented consumer that applies, retains and reuses criticism would change the maintenance-loop assessment. None can be substituted by a confident answer, a successful counter or an archive label. The [report verification](report-verification.md#verification) accepts the bounded implementation account without asserting those stronger conclusions.
