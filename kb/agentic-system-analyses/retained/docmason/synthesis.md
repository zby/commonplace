# DocMason synthesis

## Bounded synthesis

DocMason is a repo-native knowledge application whose reasoning executor is an external host agent. Python compiles and selects evidence, persists task state, checks artifacts and governs invoked answer closure. Authored skills direct the host's semantic interpretation, enrichment and user communication. This account covers the shipped knowledge application at commit `f3970939593194a158ab7ea1d49995f06cbccc86`, with applicability cutoff 2026-10-13. Its evidence is inspected implementation and doctrine/design from SRC-1, not execution or experiment. No private corpus, generated KB, host trace or evaluation run was supplied. Host inference, model mutability, permissions and isolation remain external; ancillary release-service deployment is excluded. See the [boundary and source register](boundary.md#source-register) and [RT-CMP-host-agent](runtime.md#rt-cmp-host-agent).

### From documents to a published evidence surface

Corpus placement or the shipped sample driver supplies inputs. Sync builds staged text, structure and renders, then conservative semantic outputs and reader indexes. The retained substrate is local files; natural-language summaries and claims are distinct from symbolic identifiers, provenance mappings and ranking fields. The host can add semantic overlays for assigned units without rewriting deterministic sidecars. These layers preserve inspectable source representations rather than replacing the corpus with summaries alone ([MEM-OBJ-source-evidence](memory.md#mem-obj-source-evidence), [MEM-OBJ-knowledge-text](memory.md#mem-obj-knowledge-text), [MEM-OBJ-reader-index](memory.md#mem-obj-reader-index), [MEM-OBJ-semantic-overlay](memory.md#mem-obj-semantic-overlay)).

Normal sync admits publication when validation returns `valid` or `warnings`; unchanged state can skip it. Validation checks identity, artifact contracts, resolvable citations and nonempty support. Publication switches the current root and marks eligible interaction entries promoted. It does not independently establish that a cited passage entails a generated claim. The helper checks agreement with the copied validation report rather than performing fresh semantic validation; cooperating filesystem leases are best effort. Handled publication-bookkeeping errors have restoration paths, but arbitrary host edits and universal crash durability are not covered ([RT-RTE-sync-publish](runtime.md#rt-rte-sync-publish), [EPI-RTE-knowledge-check](epistemic.md#epi-rte-knowledge-check), [RT-OBJ-publish-pointer](runtime.md#rt-obj-publish-pointer)).

The strongest inspected derivation is narrow: a generic conservative template can state that staged evidence includes a particular snippet. That follows from the stipulated staged input, not from the truth of the snippet's business assertion. Host-authored semantic production is requested, while its entailment, conjecture and semantic acceptance remain indeterminate without actual premise/output pairs. Fingerprints withdraw stale overlays' coverage credit, not necessarily all reader access to their text ([EPI-RTE-conservative-output](epistemic.md#epi-rte-conservative-output), [RT-RTE-hybrid-refresh](runtime.md#rt-rte-hybrid-refresh), [EPI-RTE-overlay-coverage](epistemic.md#epi-rte-overlay-coverage)).

### From a question to canonical delivery

The representative workflow is a corpus question through canonical `ask` and `grounded-answer`. The host opens a governed turn with stable identities and a thin work brief. The returned answer path, support contract, scope and status bind the inner workflow. Only an `execute` handoff starts that workflow; a workflow boundary is not evidence of a separately launched agent. Missing publication can route to sync, while usable stale publication can support an answer with a freshness notice. Confirmation and shared-job waits preserve the same turn ([RT-RTE-canonical-ask](runtime.md#rt-rte-canonical-ask), [workflow account](workflow.md#workflow-account)).

The host retrieves selected published bundles, inspects relevant text, structure and renders, and drafts a separate answer Markdown file linked by the symbolic turn record. Retrieval is requested read-back, with lexical-plus-graph selection and source/domain constraints. Compact payloads and file-first inspection reduce requested context, but do not establish host-window eviction, isolated side-agent frames or a total token budget ([RT-RTE-evidence-tools](runtime.md#rt-rte-evidence-tools), [EPI-OBJ-answer](epistemic.md#epi-obj-answer), [RT-OBJ-canonical-turn](runtime.md#rt-obj-canonical-turn), [RT-BAP-canonical-skills](runtime.md#rt-bap-canonical-skills)).

Trace evaluates the exact answer file and produces consequential support diagnostics. Its grounding classifier is heuristic, not an entailment oracle: the inspected code deduction shows that adding `never` to a positively supported sentence can leave vocabulary coverage at the grounding threshold. This is a countercase to a truth-oracle interpretation, not an observed full-gate bypass. Canonical admission separately checks ownership, versions, settled jobs, support bindings and scope. Those checks govern invoked commits; host adherence to final-reply discipline remains a protocol obligation. Public evidence tools and out-of-band host replies are not universally mediated ([EPI-RTE-trace-check](epistemic.md#epi-rte-trace-check), [RT-CLM-commit-gate](runtime.md#rt-clm-commit-gate)).

Recovery separates missing-trace hydration from semantic repair. The wrapper can recover trace bindings and retry completion under its stated conditions. A repairable failure returns prepared state and a repair contract; the host performs the rewrite. The authored protocol permits one rewrite/retrace and another finalize, not an unbounded loop or a demonstrated hard retry counter. Hard-artifact gaps can authorize one narrowed, governed refresh; covered settlement requires post-refresh retrieval and trace. Final business delivery is permitted only by `completed` or `boundary`, with clean answer text separate from governance detail. Waiting and blocked states are not delivered ordinary answers ([workflow recovery](workflow.md#annotations), [RT-RTE-hybrid-refresh](runtime.md#rt-rte-hybrid-refresh), [RT-RTE-canonical-ask](runtime.md#rt-rte-canonical-ask)).

These controls suit the inspected scenario of scoped, provenance-linked work over a local corpus. They do not support the broader claim that all answers are KB-grounded or that hallucinated cross-source facts are prevented. External, mixed, model-knowledge and governed-boundary support bases are legal; provenance and closure legality have narrower warrants than factual correctness ([EPI-CLM-source-trust](epistemic.md#epi-clm-source-trust), [RT-CLM-commit-gate](runtime.md#rt-clm-commit-gate)).

### What experience changes for later work

DocMason has wired automatic trace-fed writes with later consumers. Native reconciliation retains user text, bounded assistant excerpts, attachments and derived policy metadata. Pending projections can reach current-target readers before publication, conditionally on domain and memory mode; sync can later group entries, produce semantics and publish them. External-factual queries exclude interaction records, as does workspace-corpus minimal mode. Other modes use lexical thresholds and rank priors. Labels such as `confirmed` can be fallback classifications, not corroboration. Promotion changes participation tier, not truth status ([MEM-RTE-native-capture](memory.md#mem-rte-native-capture), [MEM-RTE-interaction-promotion](memory.md#mem-rte-interaction-promotion), [EPI-RTE-pending-overlay](epistemic.md#epi-rte-pending-overlay), [MEM-OBJ-interaction-policy](memory.md#mem-obj-interaction-policy)).

This is a supported trace-learning pathway in the write-route sense: recorded sessions feed durable context and semantic artifacts that later retrieval can deliver. It does not demonstrate improved capacity for future action. Retained evidence is richer than displayed summaries but still bounded: assistant excerpts and summary fragments can omit reasons. Explicit continuation anchors reload linked task state; optional prompt hooks independently push selected advisory continuation reminders. Hook activation and resulting host behavior are unobserved ([MEM-OBJ-interaction-entry](memory.md#mem-obj-interaction-entry), [RT-RTE-host-hooks](runtime.md#rt-rte-host-hooks), [profile verification](profile-verification.md#verification)).

A second contribution is trace-derived evaluator state. Runtime review groups conversation and tool records into retained reasons and benchmark candidates. Explicit promotion derives and appends selected regression cases; later suites consume cases and baselines. Review itself forbids production mutations. Replay can use supplied answer plans and judge trials, so its existence does not establish autonomous answer generation or causal product improvement ([MEM-RTE-review-projection](memory.md#mem-rte-review-projection), [MEM-OBJ-benchmark-candidates](memory.md#mem-obj-benchmark-candidates), [RT-RTE-operator-eval](runtime.md#rt-rte-operator-eval)).

The independent higher-order findings remain unresolved, not a bundled negative. The accepted runtime does not establish theory-builder conditions 1–4 separately: localized theory content, content-dependent consumption, content-directed criticism and retained criticism shaping iteration cannot be inferred from contracts, diagnostics or candidate retention alone. Improved future capacity from criticism of a consumed theory is unestablished. Reflective and autonomous operation are also unestablished at this boundary; descriptions of runtime state and explicit maintenance do not settle those properties. For self-improvement, the review-to-regression chain supplies an improvement-directed evaluation surface, but no supplied subsequent operation establishes exercised, evidence-responsive change to production behavior. Its objective is regression assessment; candidate adoption is explicit and its request control unresolved. Core replacement and adapter projection are separate maintenance channels, not demonstrated evidence-selected successors ([RT-RTE-operator-eval](runtime.md#rt-rte-operator-eval), [RT-RTE-core-update](runtime.md#rt-rte-core-update), [RT-RTE-adapter-sync](runtime.md#rt-rte-adapter-sync), [epistemic bounded conclusion](epistemic.md#bounded-conclusion)).

Actual source-to-output lineage and host execution traces would change the assessment of authoring, activation and delivery. A proposition-sensitive semantic acceptance mechanism would change the warrant assessment beyond current artifact and lexical checks. Objective-linked comparisons tracing a retained update into subsequent behavior would permit stronger learning or self-improvement attribution. Complete reader invalidation and unit-level withdrawal paths would change the freshness and forgetting assessment. No additional source reads or new evidence were used for this synthesis.
