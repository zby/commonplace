# QwenPaw synthesis

## Bounded synthesis

### From request to action

QwenPaw is an enclosing personal-assistant runtime, not just a memory API. It assembles models, tools, workspace instructions and saved context for interactive, scheduled and protocol-mediated requests. This account covers the shipped system at commit **16b2e712d198166c9359e77055b13bf2668bf5ae**, with applicability cutoff **2026-10-15**. Its evidence is executable source and shipped doctrine from SRC-1, `https://github.com/niceirene/qwenpaw`, as registered in the [boundary](boundary.md#source-register). No target execution, supplied run trace or causal experiment establishes successful operation. Whole-system inclusion does not mean exhaustive implementation inspection; unresolved paths remain included, not absent. This synthesis uses the supplied records without additional source reads. Both independent verifications report no blockers or additional limits ([report verification](report-verification.md#verification), [profile verification](profile-verification.md#verification)).

An ordinary native request passes through workspace dispatch, lifecycle hooks and command handling before agent construction. Hooks or slash commands can answer without inference. Otherwise the builder selects the provider/model, tools, skills, prompt contributors and context manager, restores session state and constructs an AgentScope-backed agent. QwenPaw owns outer sequencing and streaming; AgentScope owns the dependency's inner ReAct algorithm. Model inference proposes answers and actions; code and optional human approval govern permitted tool execution. Completion emits response events and runs state-saving hooks, not an independent answer-quality verdict ([RT-RTE-native-turn](runtime.md#rt-rte-native-turn), [RT-CMP-active-model](runtime.md#rt-cmp-active-model)).

The console decouples a tracked task from its HTTP stream, so disconnecting is not equivalent to cancelling work. Normal session hooks restore and later save agent/mode state, while ACP ephemeral requests skip those hooks. Normal save errors are tolerated. Cancellation instead attempts a shielded best-effort snapshot and does not reproduce every normal post-response operation. Consequently, a delivered response is not a transactional persistence receipt ([RT-RTE-native-turn](runtime.md#rt-rte-native-turn), [RT-OBJ-session-state](runtime.md#rt-obj-session-state)).

Tool control is conditional. Toolkit filtering constrains exposed identities; it does not prevent an allowed shell from performing equivalent operations. Native wrapped tools consult a governor that can allow, deny, ask or provide sandbox configuration. OFF settings, approved unsandboxed retries and conversion of unavailable sandbox fallback to unsandboxed ALLOW prevent interpreting this as invariant confinement. Enforcement also depends on the external permission consumer and platform honoring their contracts ([RT-RTE-tool-governance](runtime.md#rt-rte-tool-governance)). Non-native Codex/Qoder backends bypass the native lifecycle and own their inner actions, tools and retained context. QwenPaw bridges events, session identities and supported approval callbacks; native guard guarantees do not transfer to these runtimes, which also expose bypass settings ([RT-RTE-harness-turn](runtime.md#rt-rte-harness-turn)). These distinctions qualify the attributed security claim without denying the implemented policy machinery ([RT-CLM-security-built](runtime.md#rt-clm-security-built)).

### What survives and returns to the model

Persistence has several purposes. Session JSON restores live agent state; Scroll SQLite history supports recovery of admitted messages and tool results; ReMe daily/session notes and digests supply derived memory. Edited workspace files can supply standing instructions. These are different objects and consumption paths, not interchangeable layers of one lossless store ([RT-OBJ-session-state](runtime.md#rt-obj-session-state), [MEM-OBJ-history](memory.md#mem-obj-history), [MEM-OBJ-daily-note](memory.md#mem-obj-daily-note), [MEM-OBJ-digest](memory.md#mem-obj-digest), [RT-BAP-workspace-prompt](runtime.md#rt-bap-workspace-prompt)).

With ReMe selected, reply batching, compression snapshots and commands such as `/memorize`, `/new` and `/compact` can submit selected conversation material to an asynchronous extraction job. Software/model admission, not per-note human approval, requests durable notes for later search. Tagged synthetic recall blocks are removed before extraction; this protects one provenance boundary, not all source truth. ReMe's internal fact selection and writing algorithms are external to the inspected source ([MEM-RTE-trace-extraction](memory.md#mem-rte-trace-extraction), [EPI-RTE-search-exclusion](epistemic.md#epi-rte-search-exclusion)). Dream maintenance configures merging of retained notes into digest material; Daily Paper configures external paper acquisition and analysis. Their adapter wiring is established, but semantic transformations remain dependency contracts. Dream command completion can even follow a null backend response. A completion label or bounded inbox notification is not factual acceptance ([MEM-RTE-dream-maintenance](memory.md#mem-rte-dream-maintenance), [MEM-RTE-paper-maintenance](memory.md#mem-rte-paper-maintenance), [MEM-OBJ-inbox-event](memory.md#mem-obj-inbox-event), [report verification](report-verification.md#verification)).

Later consumption can be requested or automatic. Explicit memory search returns snippets; enabled middleware instead uses the latest external user query and injects a simulated completed search interaction without a foreground model decision. Automation is skipped, and cached selection is bounded by user-turn markers. ReMe indexes daily/digest Markdown, not all raw history or every root file. Optional embeddings and reranking alter selection; reranker failure can fall back to the prior ordering, and result caps are counts rather than demonstrated token bounds. Relevance and permutation checks license ordering, not truth of the delivered facts ([MEM-RTE-memory-retrieval](memory.md#mem-rte-memory-retrieval), [MEM-CMP-embedding-model](memory.md#mem-cmp-embedding-model), [EPI-RTE-rerank-check](epistemic.md#epi-rte-rerank-check), [EPI-RTE-rerank-selection](epistemic.md#epi-rte-rerank-selection)).

The ADBPG alternative forwards user-role text to an opaque service and combines returned text with local Markdown fallback. Scheduling an add and marking message IDs do not confirm remote storage; successful fallback search does not witness a successful remote write. Backend `none` disables memory-manager machinery, not all session or context persistence ([MEM-RTE-adbpg-retention](memory.md#mem-rte-adbpg-retention), [MEM-RTE-memory-retrieval](memory.md#mem-rte-memory-retrieval)). An additional idle-triggered agent consumes cleaned saved-session text and can propose tasks. Its separate toolkit and bypass permission context prevent extending native-governor coverage to that consumer; exact recent-session selection and final delivery remain incompletely traced ([MEM-RTE-proactive-context](memory.md#mem-rte-proactive-context)).

### Continuing under context pressure

Scroll first persists live content, then preferentially folds recoverable completed-turn tool outputs or evicts older dialogue while preserving a recent raw tail. Failed persistence prevents eviction. A code-managed recovery index and model-generated continuation summary are checkpointed separately. Summary parsing, identifier, secret, duplicate and source-endpoint checks can reject a candidate, permit one repair retry or withdraw unsupported old state. They do not establish proposition-by-proposition fidelity. Bounded input previews also prevent assuming every rationale survives ([MEM-RTE-scroll-retention](memory.md#mem-rte-scroll-retention), [MEM-OBJ-continuation-summary](memory.md#mem-obj-continuation-summary), [MEM-OBJ-eviction-index](memory.md#mem-obj-eviction-index)).

Later calls receive rendered summary/index material as a user-role background message, not actual system-role instruction. Structured recall can separately retrieve archived rows by sequence, tool-call, lexical, date and scope selectors, with page/cursor guards. Pointers enable copying selected evidence back; they are not live references and do not prevent source expiry. A compatible provider-overflow path rebuilds prepared messages after one recovery attempt; another overflow propagates. Native archive/debug replay and turn-local visual projection are additional mechanisms, not proof of equivalent checkpoint restoration or lossless visual encoding ([MEM-RTE-history-recall](memory.md#mem-rte-history-recall), [RT-RTE-context-recovery](runtime.md#rt-rte-context-recovery), [MEM-RTE-archive-replay](memory.md#mem-rte-archive-replay), [MEM-RTE-visual-context](memory.md#mem-rte-visual-context)). Thus long-session continuation has explicit recovery machinery, but its semantic quality and successful use remain unobserved.

### Delegated project work and delivery

The representative multi-step workflow is foreground forked project work. A parent model supplies a task and optional restrictions; QwenPaw creates a child session and, when available, a Git worktree. The child inherits the parent's **saved session file**, potentially stale or empty, not its latest evolving window. Worktree metadata and an injected commit protocol guide the child. That protocol permits task-specified absolute paths outside the worktree, so rebinding the project directory is not general confinement ([RT-RTE-fork-worker](runtime.md#rt-rte-fork-worker), [workflow account](workflow.md#workflow-account)).

Foreground collection tests for a truthy non-usage payload, then invokes an administrative finalizer. Locks, registry/scope checks and fallback staging/commit govern finalization; a clean worktree can succeed without new changes. Successful finalization permits the foreground branch marker. None of these checks verifies the task's correctness, tests or useful product. Failure can preserve a failure marker and retained worktree, rather than automatically repairing the work ([WF-RTE-fork-finalization](workflow.md#wf-rte-fork-finalization)). Background submission advertises its branch immediately and separately arranges later completion/finalization where applicable. A branch marker therefore has path-dependent meaning. Result delivery to the parent, administrative finalization, merge into the parent's project and delivery to the original user remain distinct milestones; universal merge enforcement was not inspected ([RT-RTE-fork-worker](runtime.md#rt-rte-fork-worker)).

### Adaptation, warranted reliance and what would change the assessment

The strongest supported adaptive contribution is an implemented trace-fed artifact path: conversation/tool activity can feed durable ReMe notes or Scroll continuation state, and later invocations can consume those outputs. This is architectural trace learning, not demonstrated increased capacity. At the update consumer, traces shape derived artifacts; at the later task consumer, the resulting prose supplies context. No input/output comparison or later-action evidence demonstrates improved capacity for future action, much less a causal effect of one component ([MEM-RTE-trace-extraction](memory.md#mem-rte-trace-extraction), [MEM-RTE-scroll-retention](memory.md#mem-rte-scroll-retention), [MEM-BAP-retained-context](memory.md#mem-bap-retained-context), [profile verification](profile-verification.md#verification)).

Editable instructions and executable plugins additionally provide behavior-changing paths. Selected edited Markdown enters future system prompts; plugin installation imports and registers code in the application process before individual native tool checks. Neither structural admission establishes improvement, model training or complete rollback of prior effects ([RT-RTE-workspace-instruction](runtime.md#rt-rte-workspace-instruction), [RT-RTE-plugin-install](runtime.md#rt-rte-plugin-install)).

The theoretical properties remain independent. **Theory-builder condition 1**, a whole localized formulated theory, is not established merely by editable prose or generated notes; the records supply no identified theory instance. **Condition 2**, decisions depending on that theory's content, is not established by context delivery alone. **Condition 3**, content-directed criticism with blame and changed reliance or revision, is not established by relevance scores, summary checks or administrative finalization. **Condition 4**, retaining criticism's result to shape another round, is likewise unestablished. These are evidence limits of the inspected routes, not system-wide evidenced absences. The runtime supports request and revision affordances, not a completed theory-building account ([RT-RTE-native-turn](runtime.md#rt-rte-native-turn), [RT-RTE-workspace-instruction](runtime.md#rt-rte-workspace-instruction), [EPI-RTE-rerank-check](epistemic.md#epi-rte-rerank-check), [MEM-RTE-scroll-retention](memory.md#mem-rte-scroll-retention)).

Separately, criticism of a consumed theory improving later capacity is unestablished. Reflection is also unestablished: task-state summaries do not by themselves demonstrate a self-representation with both causal directions for an aspect of the system. Scheduled work, automatic extraction and idle initiation establish bounded computational initiative, not role-by-role autonomy of theory construction. Exercised self-improvement is not established at this revision: no objective-linked evidence chain shows an improvement-directed update to QwenPaw's own organization followed by operation causally depending on it. Instruction/plugin loading and note reuse supply possible live behavioral paths but do not close that chain or demonstrate benefit ([MEM-OBJ-continuation-summary](memory.md#mem-obj-continuation-summary), [MEM-RTE-proactive-context](memory.md#mem-rte-proactive-context), [RT-RTE-plugin-install](runtime.md#rt-rte-plugin-install), [MEM-BAP-retained-context](memory.md#mem-bap-retained-context)).

For prior-work questions, the supported assessment is selected retained context with recoverable raw evidence, not warranted factual acceptance. For delegated editing, it is separated worker execution and administrative return, not verified integration. Permission checks, relevance judgments, retention, restoration and structural summary checks have distinct domains; none supplies a universal answer oracle. Imported web text has unknown source warrant, and no evidenced accepted ampliative claim is established in the inspected routes. Uninspected evaluators prevent converting that finding into an architectural absence ([EPI-RTE-web-acquisition](epistemic.md#epi-rte-web-acquisition), [EPI-RTE-rerank-selection](epistemic.md#epi-rte-rerank-selection), [RT-RTE-tool-governance](runtime.md#rt-rte-tool-governance), [epistemic conclusion](epistemic.md#bounded-conclusion)).

Concrete evidence could change these assessments: linked extraction/summary inputs, outputs and later invocations would establish actual retained-content consumption; semantic acceptance records naming criteria, evidence and scope could establish warranted acceptance. An independent recall test must withhold the answer from the query, unlike the shipped seeded-keyword expectation. A controlled comparison could support improvement, with component attribution only where independently varied. For self-improvement, a trace would additionally need to connect objective-bearing evidence, an organizational update and subsequent dependent operation. Full dependency and merge-path inspection could resolve narrower semantic and workflow limits. Stronger confinement would require eliminating or explicitly bounding unsandboxed and alternate-backend paths, not merely another security label ([MEM-CLM-memory-evaluator](memory.md#mem-clm-memory-evaluator), [RT-RTE-tool-governance](runtime.md#rt-rte-tool-governance), [WF-RTE-fork-finalization](workflow.md#wf-rte-fork-finalization)).
