# Beever Atlas synthesis

## Bounded synthesis

### From source conversations to retained knowledge

Beever Atlas is a shipped knowledge and context system, not merely an MCP retrieval server. It acquires platform conversations and imported or pushed content, extracts facts and graph relationships, maintains summaries and wiki pages, and serves later human and model consumers. This account covers the repository at `7d791af27ef4aa19644cb385c7ca24619bc4f848`, with an applicability cutoff of 2026-10-15. SRC-1 supplies inspected implementation and attributed design claims. There is no supplied execution trace or causal experiment, and no target code was run. The whole-system boundary includes shipped producers, maintenance, admission, dashboard and bot callers, and evaluation surfaces; inspection within that boundary remains selective. External provider internals and external clients' subsequent behavior are not attributed to Atlas. See the [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The architectural distinction is a layered memory pipeline. MongoDB retains normalized messages, page/cache objects, conversation history and recovery state. Vector-backed records retain fact prose, access metadata, dense vectors, summaries and searchable past QA. Graph records retain entities and relationships. Natural-language content supplies interpreted evidence; symbolic fields select, exclude or route work; dense vectors support similarity rather than representing a local weight-training operation. These are distinct operative parts, not one uniformly authoritative memory. See [MEM-OBJ-channel-messages](memory.md#mem-obj-channel-messages), [MEM-OBJ-atomic-fact](memory.md#mem-obj-atomic-fact), [MEM-OBJ-fact-metadata](memory.md#mem-obj-fact-metadata), [MEM-OBJ-text-vector](memory.md#mem-obj-text-vector), [MEM-OBJ-graph-entity](memory.md#mem-obj-graph-entity) and [MEM-OBJ-chat-history](memory.md#mem-obj-chat-history).

Acquisition success is not extraction completion. Platform synchronization can process inline or leave pending messages for a worker. Signed push returns queued acceptance; file-import commit retains normalized messages and waits for manual sync. Signatures, payload checks and channel permissions govern acquisition, not the truth of incoming statements. Source authorship may be human, bot or mixed, and heuristic provenance matching can attach a source without authenticating the extracted proposition. See [RT-RTE-message-ingestion](runtime.md#rt-rte-message-ingestion), [MEM-CLM-import-admission](memory.md#mem-clm-import-admission) and [MEM-OBJ-fact-metadata](memory.md#mem-obj-fact-metadata).

### Coordinated extraction and its delivery boundary

Background extraction is the representative connected workflow. The worker claims pending rows, groups them by channel and delegates a batch to a system-owned working session. The processor supplies messages, job/channel identity, known entities, similarity candidates and policy settings. Code fixes the workflow: preprocessing fans out to fact and entity extraction; an explicit join precedes parallel embedding and deterministic entity validation; another join precedes persistence. Models propose content, not the pipeline topology. The joins' execution guarantee depends on ADK semantics and does not deduplicate independent retries. See [RT-RTE-message-ingestion](runtime.md#rt-rte-message-ingestion) and the [workflow account](workflow.md#workflow-account).

Admission combines model-emitted quality scores with code thresholds, structured-output recovery and deterministic reconciliation. A low score can remove a candidate; malformed output can be salvaged or replaced by an empty fact list while processing continues. This is consequential verification of representations, not independent source-truth verification. Narration rewriting can remove a reported-speech qualifier, and normalized-name or vector matching can conflate identities. The general semantic relationship between source and generated content remains indeterminate; neither fluent extraction nor a passing score establishes warranted new knowledge. See [WF-RTE-fact-admission](workflow.md#wf-rte-fact-admission), [EPI-RTE-quality-check](epistemic.md#epi-rte-quality-check), [EPI-RTE-quality-admission](epistemic.md#epi-rte-quality-admission), [EPI-RTE-narration-rewrite](epistemic.md#epi-rte-narration-rewrite) and [EPI-RTE-entity-dedup](epistemic.md#epi-rte-entity-dedup).

Recovery belongs to several owners. Processor retries start fresh sessions and restore whitelisted completed-stage artifacts from checkpoints. The worker separately finalizes successful and failed message keys and schedules backoff. Its successful terminal is retained-memory output plus a completion signal to downstream subscribers, not a verified answer or proof of a refreshed page. Cross-store persistence is not atomic: graph failure alone does not prevent final intent completion, and live scheduling of the afforded reconciler was not established. See [RT-OBJ-session-state](runtime.md#rt-obj-session-state), the [workflow recovery annotation](workflow.md#on-rt-rte-message-ingestion) and [RT-CLM-write-completion](runtime.md#rt-clm-write-completion).

### Maintaining material that later consumers can use

Derived memory has multiple successor paths. Consolidation selects active member facts, ranks them by quality and supplies at most twenty from up to fifty fetched members as cluster context. Topic/channel summaries persist for overview tools and wiki generation. This reduces retained evidence but cannot guarantee complete rationale preservation. Event-driven wiki maintenance supplies new facts and an existing page to a completion model, merges affected sections and saves. Automatic updates skip frozen pages and defer manual ones; an explicit pending-update request can temporarily enable eligible manual pages and restore their mode afterward. These gates constrain the inspected incremental writer, not every writer. See [MEM-RTE-summary-retention](memory.md#mem-rte-summary-retention), [RT-RTE-wiki-maintenance](runtime.md#rt-rte-wiki-maintenance), [RT-RTE-page-curation](runtime.md#rt-rte-page-curation) and [RT-BAP-page-curation](runtime.md#rt-bap-page-curation).

Full refresh/reorganize/rebuild is a separate route. Frozen lookup there is best effort; rebuild can wipe current state even after snapshot failure. Compiler validation can trigger corrective generation, but selected twice-failed branches still return prose. That soft admission must not be generalized to every compiler variant: report verification identifies a modular narrative gate that rejects sections when nonempty input has raw citation coverage below its tier-selected threshold, with cleaned results entering module selection. Citation presence is a representation criterion, not proof that source facts entail the narrative. See [MEM-RTE-wiki-refresh](memory.md#mem-rte-wiki-refresh), [EPI-RTE-compiler-retry](epistemic.md#epi-rte-compiler-retry) and the [report-verification limit](report-verification.md#limits).

Successful page persistence also does not establish identical fresh text at every consumer. Full compilation saves rendered cache content and seeds minimal page-store records; compatibility reads can overlay legacy render keys on newer page metadata, whereas slug-based MCP reads use the page store directly. The records do not establish that every incremental update synchronizes the compatibility rendering. See [EPI-RTE-builder-retention](epistemic.md#epi-rte-builder-retention) and [MEM-OBJ-wiki-page](memory.md#mem-obj-wiki-page).

Contradiction maintenance changes reliance rather than merely adding text. A model compares a new fact with up to ten candidates selected through its first entity tag. Confidence thresholds can supersede an old fact or flag the new one. Persisted lifecycle fields exclude old facts from guarded semantic/native-hybrid retrieval and consolidation context. Ordinary embedding/hybrid failures can instead enter BM25, which lacks the invalidation filter; later formatting and reranking do not restore it. The implemented withdrawal is therefore branch-specific, not universal, and confidence/recency does not establish acceptance of the newer proposition's truth. See [EPI-RTE-contradiction-check](epistemic.md#epi-rte-contradiction-check), [EPI-RTE-fact-supersession](epistemic.md#epi-rte-fact-supersession) and [MEM-BAP-fact-lifecycle](memory.md#mem-bap-fact-lifecycle).

### Retrieval, answer generation and effect boundaries

A dashboard question reaches an authenticated HTTP endpoint, channel/session checks, a fresh ADK session and a mode-specific QA agent. Atlas automatically supplies content from up to ten stored messages, not ten turns. The model chooses tools and completion; ADK executes the loop. Requested tools retrieve facts, summaries, pages, provenance or prior QA. Such retrieval remains pull even when code embeds and reranks the query. History injection and automatic summary, maintenance and checkpoint context are separate push operations at their respective consumers. Wiki-first use and two/four/eight call budgets are prompt instructions, not mandatory sequencing or inspected counter enforcement. See [RT-RTE-dashboard-ask](runtime.md#rt-rte-dashboard-ask), the [memory context annotation](memory.md#on-rt-rte-dashboard-ask) and [MEM-RTE-knowledge-retrieval](memory.md#mem-rte-knowledge-retrieval).

HTTP streams answer text, progress and citations, then persists history for later turns and QA search. Earlier generated answers can thus become later evidence without independent truth checking. Citation annotation supplies identifiers and excerpts when suitable registration is available; it does not test whether each answer assertion follows from them. MCP ask instead reuses principal-namespaced process-memory sessions and does not establish the same durable HTTP history or context budget. Its wrapper binds principal but not HTTP's authorized-channel set, so HTTP isolation cannot be generalized across paths. These are inspected control differences, not observed exploits. See [MEM-OBJ-chat-history](memory.md#mem-obj-chat-history), [EPI-RTE-citation-annotation](epistemic.md#epi-rte-citation-annotation), [RT-RTE-mcp-ask](runtime.md#rt-rte-mcp-ask) and [RT-CLM-channel-isolation](runtime.md#rt-clm-channel-isolation).

Tool grants also reach beyond retrieval. Configured remote catalogs enter summarize/deep agents, and wrappers POST model-supplied arguments with configured credentials. The inspected QA construction does not invoke the available untrusted-context filtering helper. A textual safety note therefore does not establish removal of write/egress capabilities. Exact deployed grants and remote behavior are unavailable. Model assignments can separately change future provider routing through authenticated configuration, compatibility checks and an optional force override; non-fatal reload prevents an unconditional next-call guarantee. Neither mechanism establishes autonomous source modification or local model training. See [RT-RTE-outbound-tools](runtime.md#rt-rte-outbound-tools), [RT-CLM-untrusted-tools](runtime.md#rt-clm-untrusted-tools) and [RT-RTE-model-assignment](runtime.md#rt-rte-model-assignment).
