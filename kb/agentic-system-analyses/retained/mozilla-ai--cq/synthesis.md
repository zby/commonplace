# CQ synthesis

## Bounded synthesis

### From task experience to shared advice

CQ is a knowledge-sharing system for agents, not their enclosing runtime. This analysis covers its shipped prompts, integrations, clients, stores, remote admission and review, maintenance and source-level evaluators at commit **5765494a3840e5f5a7223c42101f41e85cb9d898**, with an applicability cutoff of **2026-10-14**. SRC-1 is the frozen repository. Evidence is inspected implementation and doctrine/design; no target execution, observed session, test result or causal experiment was supplied. External hosts, model services and the live deployment are outside that evidence boundary. See [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The operational division is clear: the host agent chooses what to ask, reasons about candidates and decides how to act; CQ selects, transports and persists advice. Its five MCP operations are query, propose, confirm, flag and status. CLI and SDK routes expose related operations; the shipped Pi adapter maps use to shell commands. SQLite is the default local store, with alternative or injected stores and an optional remote service. CQ returns knowledge, not a completed application task, and does not mediate the host's other tools or model calls. [RT-RTE-knowledge-query](runtime.md#rt-rte-knowledge-query), [RT-RTE-host-installation](runtime.md#rt-rte-host-installation), [RT-CMP-host-model](runtime.md#rt-cmp-host-model).

A retained lesson consists of natural-language summary, detail and action, accompanied by symbolic tags, identifiers and evidence metadata. Detail can retain an explanation, but source references, raw task traces and checking rationale are not required. Caller content enters with unknown source warrant. Serialization, structural validation and later retrieval do not independently validate its claims. Arbitrary extension JSON has no established uniform meaning or application consumer. [MEM-OBJ-insight](memory.md#mem-obj-insight), [MEM-OBJ-selection-metadata](memory.md#mem-obj-selection-metadata), [MEM-OBJ-extensions](memory.md#mem-obj-extensions).

The skill requests querying before unfamiliar work and proposing stabilized discoveries during work. Retrospective reflection is a backstop: the foreground agent is asked to summarize selected session experience and draft shareable candidates. A conflicting skill subsection describes server extraction, but the dedicated command, MCP registration and Python stub support agent-led extraction, not that server endpoint. Candidate production and its semantic relation to the session remain unobserved. [RT-RTE-session-reflection](runtime.md#rt-rte-session-reflection), [EPI-CLM-reflection-server](epistemic.md#epi-clm-reflection-server).

### Permission, retention and remote eligibility

The representative workflow is interactive reflection with a configured remote store. Its requested progression is summary → candidate selection → safety screening → user approve/edit/skip → query for close matches → proposal or feedback → inline results and final counts/IDs. There is no delegated sub-agent: a later reviewer is another admission principal. The near-match query is limited retrieval, not a novelty certificate. Individual proposal errors are to be reported while the batch continues, not rolled back transactionally. These handoffs are supported by instructions and implementation, not an executed workflow. See [workflow account](workflow.md#workflow-account) and [RT-RTE-session-reflection](runtime.md#rt-rte-session-reflection).

Three decisions must remain separate. Interactive user approval selects content under the instructed procedure. Software validates fields and credentials before persistence. Remote review subsequently controls eligibility for ordinary remote retrieval. The requested vulnerabilities, impact, bias and edge-case screen can prompt criticism and sanitization, but its result is not required by proposal handlers. Headless rules permit clean or appropriately caveated proposals without a user; direct APIs also do not attest approval. For presented hard findings, the interactive procedure defaults to sanitized content but lets the user explicitly choose the original. Consequently neither human approval nor removal of hazardous content is a universal software invariant. [RT-CLM-proposal-approval](runtime.md#rt-clm-proposal-approval), [RT-RTE-knowledge-proposal](runtime.md#rt-rte-knowledge-proposal), [EPI-CLM-guardrails-layer](epistemic.md#epi-clm-guardrails-layer), [workflow account](workflow.md#workflow-account).

Successful remote proposals receive server identities and pending review state. A browser affords inspection and approve/reject/skip; it shows the retained lesson and selected metrics, not the originating conversation or safety-screen provenance. JWT authentication establishes a caller, not human presence or independent review; a shipped seed script approves through the same APIs. The pending check precedes an unconditional status write, so it does not establish atomic single-winner review. Ordinary server queries enforce approved status, including on the semantic selector. That gate does not establish factual acceptance or PRIVATE-tier confidentiality: public query filters status rather than ownership or tier. Rejection retains the payload for review readers while excluding ordinary retrieval; skip changes browser-local selection only. [RT-RTE-remote-review](runtime.md#rt-rte-remote-review), [RT-CLM-approved-query](runtime.md#rt-clm-approved-query), [workflow account](workflow.md#workflow-account).

Local retention follows a different path. Go proposal failures involving transport, server errors or 401/403 can fall back locally, where content is immediately queryable without remote review. Python supports caught per-call failures after destination resolution, but exhausted discovery failures become an uncaught DiscoveryError before insertion. Thus outage retention is route-dependent. Later Go drain, explicitly invoked or started in the background at MCP startup, re-proposes LOCAL units and deletes successfully posted local copies. The remote successor has a new identity and awaits review. Transfer omits old evidence, flags and supersession links; Python also omits extensions. This is best-effort transfer, not faithful replication, exactly-once publication or uninterrupted availability. [RT-RTE-knowledge-proposal](runtime.md#rt-rte-knowledge-proposal), [RT-RTE-local-drain](runtime.md#rt-rte-local-drain), [MEM-OBJ-flags](memory.md#mem-obj-flags), [MEM-OBJ-extensions](memory.md#mem-obj-extensions).

### Delivery, checking and future selection

Queries are principally requested memory reads. SQLite gathers domain-or-full-text candidates and ranks relevance times confidence; ordinary server queries rank approved domain matches. Go merges local first, deduplicates by ID with local winning, then truncates without a global rerank. A small limit can therefore exclude every remote candidate. Defaults and clamps bound item counts, not the host's token window. MCP query drops nonfatal warning/source metadata that SDK or CLI consumers can receive, weakening the host's ability to diagnose incomplete remote retrieval. Retrieved action text remains advice; CQ does not execute it. [RT-RTE-knowledge-query](runtime.md#rt-rte-knowledge-query), [RT-BAP-knowledge-guidance](runtime.md#rt-bap-knowledge-guidance).

Optional semantic retrieval uses retained numerical vectors, first limiting approved domain matches by distance, then ranking by **(0.8 × relevance + 0.2 × (1 − normalized distance)) × confidence**. Distance still affects final ordering. Provider identity, compatibility and quality are unresolved; similarity adds no truth warrant. Wrapped provider errors can bypass the intended SQL fallback, and embedding failure can block writes or feedback updates. [MEM-OBJ-knowledge-vectors](memory.md#mem-obj-knowledge-vectors), [RT-CMP-token-embedding](runtime.md#rt-cmp-token-embedding), [epistemic selection ledger](epistemic.md#authority-route-ledger).

The skill requests verification against current documentation, tool output or experience before reliance and feedback. The API consumes a caller's assertion rather than requiring that evidence. Confirmation raises confidence; supported flags lower it and retain an objection, without rewriting the insight or revoking review approval. Initial confirmation counts are admission defaults, not independent successful use. A sole matching flagged unit can remain deliverable even at zero confidence. Go-local duplicate flags can retain a reference; server and Python Client duplicate requests lack the required reference and fail before updating. Feedback therefore supplies wired future ranking influence, not calibrated correctness or guaranteed protection. [RT-RTE-knowledge-feedback](runtime.md#rt-rte-knowledge-feedback), [MEM-OBJ-selection-metadata](memory.md#mem-obj-selection-metadata), [MEM-OBJ-flags](memory.md#mem-obj-flags), [EPI-OBJ-evidence](epistemic.md#epi-obj-evidence), [EPI-CLM-flag-protection](epistemic.md#epi-clm-flag-protection).

For a task needing reusable starting-point advice, the inspected loop supports persistence, later selection and requested host checking. For a task needing accepted factual knowledge, reliable novelty detection, confidentiality or guaranteed withdrawal of wrong advice, those mechanisms alone are insufficient. Permission to submit, approved status and confidence do not establish evidence-consuming truth acceptance against a named criterion and intended scope. The inspected retention and indexing routes consequently do not establish lifecycle integration after such acceptance. The declared automatic PII, factual and staleness guardrail suite remains doctrine on the selected paths, not an implemented evaluator suite established by this analysis. [RT-CLM-approved-query](runtime.md#rt-clm-approved-query), [EPI-CLM-guardrails-layer](epistemic.md#epi-clm-guardrails-layer), [epistemic bounded conclusion](epistemic.md#bounded-conclusion).

### Experience-responsive capacity and its unresolved effects

The strongest supported experience-responsive contributions are persistent feedback that can change later advice ranking and the automatic Cursor failure-event → clipped retained record → later stop reminder chain. Under the memory comparison's trace-learning definition, the latter qualifies as wired trace-fed context production without needing a diagnosis or demonstrated improvement. It selects the latest conversation-keyed failure, bounds input/error text, emits it and clears it; session start sweeps old files. This is not automatic lesson admission. Discovery caches separately route HTTP calls using retained endpoint metadata. Neither these mechanisms nor reflection's requested summary implement host turn eviction, compaction checkpoints or isolated worker frames. [RT-RTE-knowledge-feedback](runtime.md#rt-rte-knowledge-feedback), [RT-OBJ-failure-record](runtime.md#rt-obj-failure-record), [RT-RTE-failure-reminder](runtime.md#rt-rte-failure-reminder), [MEM-RTE-discovery-resolution](memory.md#mem-rte-discovery-resolution), [profile verification](profile-verification.md#verification).

The independent property conclusions remain bounded:

- **Theory-builder conditions 1–4:** localized candidate theory, content-dependent consumption, content-directed criticism and iteration are each uninspected for actual reflection reasoning. Requested extraction or stored advice does not establish any of them. [RT-RTE-session-reflection](runtime.md#rt-rte-session-reflection).
- **Learning from criticism of consumed theory:** future ranking capacity is wired, but no comparison establishes improved future action capacity, or attributes it to criticism of what a consumed theory says. Score arithmetic does not evaluate a prose objection's argument. [EPI-OBJ-evidence](epistemic.md#epi-obj-evidence), [epistemic bounded conclusion](epistemic.md#bounded-conclusion).
- **Reflection:** agent-led examination of session experience is afforded; exercised reflection remains uninspected. The source-native command name is not proof of the full reflective property. [RT-RTE-session-reflection](runtime.md#rt-rte-session-reflection).
- **Autonomy:** deterministic storage and score updates are wired; whole-loop autonomy is not established. External hosts own reasoning and action, and the selected interactive path requires per-content user decisions. [RT-CMP-host-model](runtime.md#rt-cmp-host-model), [RT-RTE-session-reflection](runtime.md#rt-rte-session-reflection).
- **Self-improvement:** over subsequent advice-consuming tasks at this boundary, no exercised improvement-directed self-change is established. Retained rank changes can reach future selection, but no trace shows subsequent behavior causally depending on them, and no independently assessed outcome establishes improvement. Static prompt installation is not experience-driven self-patching. [RT-RTE-knowledge-feedback](runtime.md#rt-rte-knowledge-feedback), [RT-RTE-host-installation](runtime.md#rt-rte-host-installation), [epistemic bounded conclusion](epistemic.md#bounded-conclusion).

A linked session/candidate/review/later-use trace would change the assessment of operation and consumption. Recorded challenged claims, blame placement, changed reliance or revision, and reuse in another round would bear separately on theory building. An independently specified objective and controlled later-outcome comparison would bear on improvement and attribution. Implemented approval attestations, tier-aware access predicates, atomic review transitions, evidence-requiring acceptance, withdrawal rules or identity/history-preserving transfer would change the relevant architectural assessment; they would still require their own execution evidence. These resolving conditions follow the limits of the cited proposal, review, query, drain and feedback records, not a product ranking or adoption recommendation.
