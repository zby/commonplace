### Runtime and downstream delivery

I traced CLI registration and add-time drift selection through Engine construction, lazy loading, source iteration, preparation, batching and metadata updates in SRC-1 `crates/semquery/src/main.rs`, `crates/semquery/src/engine.rs`, `crates/semquery-indexer/src/indexer.rs` and `crates/semquery-storage/src/sqlite.rs`. [RT-RTE-index-admission](runtime.md#rt-rte-index-admission) correctly separates user initiation from automatic content admission. Registration precedes model loading; five-file transaction commits, deletion sweeps and baseline updates do not form a whole-run transaction. [RT-CLM-transaction-scope](runtime.md#rt-clm-transaction-scope) preserves that distinction and does not infer same-connection caller isolation from individual mutex acquisitions. The all-source wrapper recalculates drift within successive source passes; its early baseline update supports the report's qualification of all-collection reembedding. Search/ask do not invoke a freshness barrier.

I traced both recall branches, error propagation, fusion, optional reranking, chunk lookup, path resolution and final assembly in SRC-1 `crates/semquery-retrieve/src/retriever.rs` and `crates/semquery-retrieve/src/fusion.rs`. [RT-RTE-hybrid-search](runtime.md#rt-rte-hybrid-search) is supported: either recall error stops the pipeline; rank fusion ignores raw score magnitudes; an injected absent reranker preserves fused ordering, whereas an unfilled configured cell errors. Empty queries terminate in Retriever only after ordinary Engine loading. These are selection mechanisms, not factual evaluators.

For [RT-RTE-answer-generation](runtime.md#rt-rte-answer-generation), I followed direct synthesis and streaming synthesis through SRC-1 `crates/semquery-synth/src/synthesizer.rs`, `crates/semquery-synth/src/prompt.rs`, `crates/semquery-synth/src/citation.rs`, `crates/semquery-model/src/gguf.rs`, Engine forwarding and CLI output. Five-hit retrieval precedes generation; no hits return an empty answer. Both concrete GGUF completion methods allocate fresh contexts and keep only a suffix of over-budget formatted input. Query strings have no total prompt-token admission bound here, so over-budget reachability is not inferred from a dead branch alone. The pre-truncation marker set remains unchanged. Both synthesis variants return raw text; metadata filtering does not scrub displayed markers or test sentence support. [RT-CLM-citation-filter](runtime.md#rt-clm-citation-filter) and [RT-BAP-prompt-influence](runtime.md#rt-bap-prompt-influence) correctly bound enforcement to metadata and describe natural-language grounding as a request.

The [workflow account](workflow.md#workflow-account) faithfully follows this shipped path rather than inventing agent delegation. Token callbacks precede citation checking; ignored send failures do not cancel active inference. The current-thread callback uses best-effort sends, while the ordinary CLI has a multithreaded runtime. The report preserves that condition instead of alleging routine CLI token loss. Text mode does not replace printed deltas with terminal text; JSON prefers the terminal answer and has a buffered fallback; Engine's collecting ask requires a terminal answer. Error propagation, possible partial display and caller-driven reinvocation are correctly distinguished from durable recovery and successful delivery.
