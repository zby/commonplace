# Agentic Local Brain synthesis

## Bounded synthesis

### From collection request to retained knowledge

Agentic Local Brain is a personal knowledge application, not the enclosing desktop-agent runtime. This analysis covers its shipped collection, retention, mining, retrieval, wiki and maintenance paths at commit `41ea0cb104686eb0d39f32c94c2b84d37cdff0e7`, with an applicability cutoff of 2026-10-12. SRC-1 supplies inspected implementation and shipped design/instructions. No installation, user store, model-output specimen, execution trace or causal experiment was supplied; no target code was executed. The boundary is whole-system for the knowledge application, but the detailed inventories remain partial. External agent tools, provider internals and the repository's development-agent workflow are not attributed to it ([boundary and evidence](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)).

The application retains selected files, webpages, papers, emails, bookmarks and notes, derives search and organizational state, and returns documents or generated answers. Click console aliases and FastAPI handlers initiate separate application-owned pipelines. Python owns stage scheduling and effects; models propose metadata, retrieval inputs, scores or prose. The inspected retrieval/mining roots have no application model-tool dispatcher. Explicit search/update subprocesses and an external host's tools are different capabilities ([RT-RTE-file-admission](runtime.md#rt-rte-file-admission), [RT-RTE-chat-query](runtime.md#rt-rte-chat-query), [RT-RTE-mining-run](runtime.md#rt-rte-mining-run), [RT-ABS-tool-dispatch](runtime.md#rt-abs-tool-dispatch)).

File admission writes Markdown, optionally extracts missing tags/summary, saves SQLite metadata, and attempts chunk/vector indexing into Chroma and SQLite. Caller-supplied values can override extraction; generated missing fields are admitted automatically, not reviewed per result. These writes are staged, not a cross-store transaction: collection can report success despite indexing failure. Direct notes are a distinct branch, indexing their input text rather than reloading the saved file ([RT-RTE-file-admission](runtime.md#rt-rte-file-admission), [MEM-RTE-note-admission](memory.md#mem-rte-note-admission)). Successful SQLite insertion also attempts background mining with the summary as content, so admission need not finish indexing before mining starts. This verifier-established connection qualifies the reports' unresolved worker invocation account; it does not establish successful execution ([report-verification limits](report-verification.md#limits)).

The representative multi-step workflow is the skill's restricted-webpage recovery. An external agent first attempts webpage collection; after failure, it is instructed to fetch through its own tools, save temporary Markdown, and invoke file collection. If automation fails, it asks the user for content. The application then owns file admission. The second handoff carries a path/title, not the original browser session or necessarily a structured original URL. Duplicate checking on the temporary path is not article-level deduplication. Application status output marks completion, possibly without semantic indexing; host-to-user delivery and successful later retrieval remain unobserved ([workflow account](workflow.md#workflow-account), [RT-RTE-host-fallback](runtime.md#rt-rte-host-fallback), [RT-RTE-file-admission](runtime.md#rt-rte-file-admission)).

### From retained representations to derived products

The memory architecture has several independently consumed representations. Markdown supports file search/mining; SQLite supports metadata, entities, document vectors, relations and topics; Chroma supports chunk similarity search. Dense vectors are derived numerical representations, not updated model weights. Entity descriptions and typed relations are candidate assertions; source links and short contexts preserve associations without validating those assertions ([MEM-OBJ-knowledge](memory.md#mem-obj-knowledge), [MEM-OBJ-chunks](memory.md#mem-obj-chunks), [MEM-OBJ-entities](memory.md#mem-obj-entities), [MEM-OBJ-document-embeddings](memory.md#mem-obj-document-embeddings)).

Mining uses separate web, CLI and per-document drivers. Web full-mode confirmation is a caller acknowledgement on that route, not universal human approval or a cross-process lock. The worker covers entities, embeddings and relations, not the batch topic/wiki stages. Numerical thresholds admit represented similarities and associations; updating a retained topic centroid can change subsequent classification. Neither numerical validity nor a rebuild establishes semantic correctness or improvement ([RT-RTE-mining-run](runtime.md#rt-rte-mining-run), [EPI-RTE-numeric-selection](epistemic.md#epi-rte-numeric-selection), [MEM-OBJ-topic-clusters](memory.md#mem-obj-topic-clusters)).

Wiki compilation generates durable Markdown and article metadata for later human browsing. Topic articles use bounded selected sources; stored source IDs can outnumber sources actually delivered to the model. Parsing is not factual verification, and parse failure can retain a raw-response prefix. Entity cards are an additional thresholded compile-all path using descriptions, topic titles and mention contexts, with empty source-document lists. The topic article account therefore does not characterize every wiki product ([RT-RTE-wiki-compile](runtime.md#rt-rte-wiki-compile), [MEM-OBJ-wiki-articles](memory.md#mem-obj-wiki-articles), [EPI-RTE-structural-checks](epistemic.md#epi-rte-structural-checks), [report-verification limits](report-verification.md#limits)).

### From a later question to selected context and answer

Enhanced web chat loads applicable session history, expands the question, combines semantic/graph/keyword candidates, fuses by document ID, reranks, enriches and constructs context before generation. Unavailable components can degrade. Returned source metadata does not establish full source delivery. Hierarchical construction truncates/omits material; a separately afforded flat-builder branch concatenates chunks without enforcing its supplied budget. The ordinary web dependency supplies the hierarchical builder, so this distinction is not evidence that flat formatting necessarily disables its budgeting. Neither branch establishes a whole-message tokenizer cap ([RT-RTE-chat-query](runtime.md#rt-rte-chat-query), [MEM-CLM-budget-scope](memory.md#mem-clm-budget-scope), [report-verification conflict disposition](report-verification.md#relations-correction-answers-and-conflict-dispositions)).

CLI and legacy HTTP RAG use another route with progressive fallbacks, including keyword search without the semantic branch's tags. Graph/keyword alternatives likewise prevent treating tags as demonstrated end-to-end isolation. Enhanced result-cache hits precede session work, and the cache key omits options. Empty retrieval and failed turn saves prevent a universal conversation-retention guarantee ([RT-RTE-legacy-query](runtime.md#rt-rte-legacy-query), [RT-RTE-chat-query](runtime.md#rt-rte-chat-query)).

On applicable successful writes, prior conversational text feeds future expansion/answer generation, and newly generated assistant prose is retained for subsequent model context. This is a wired trace-fed durable-text update, not merely unused logging. The verified profile recognizes this positive separately from improvement: it requires neither a continuation summary nor parameter training. Session matching and recent-turn/character filtering select supplied history; saved source dictionaries are not included by that formatter. Reading events instead feed a transient weighted recommendation profile and conditional recent-view score boosts. Those events can shape later selection, but the profile itself is not durably written ([MEM-OBJ-rag-conversations](memory.md#mem-obj-rag-conversations), [MEM-BAP-retained-context](memory.md#mem-bap-retained-context), [MEM-RTE-history-selection](memory.md#mem-rte-history-selection), [profile-verification](profile-verification.md#verification)).

These are distinct consumption operations: requested knowledge/article/recommendation returns fulfill a request, while automatically supplied session history and recent-view influence supply context inside a requested chain. No unsolicited scheduler is needed for that latter distinction. All ten comparison axes remain partial; local positive witnesses do not classify opaque providers or untraced alternatives ([profile-verification](profile-verification.md#verification)).

### Reliance, correction and improvement assessment

For collecting and revisiting personal material, the inspected architecture supports staged retention, multiple retrieval surfaces and durable synthesis for browsing. For factual reliance, its checks support narrower conclusions. Type/endpoint/count/parse checks establish structural admissibility; deterministic sentence selection reshapes existing statements; similarity/count computations concern represented inputs. Generated summaries, articles and answers have indeterminate semantic relations without output/source comparisons. The citation prompt requests contextual answers but does not validate them. Numeric answer confidence uses retrieval scores, source count and stage labels, not answer assertions, and is advisory rather than a factual veto ([EPI-RTE-structural-checks](epistemic.md#epi-rte-structural-checks), [EPI-RTE-extractive-summary](epistemic.md#epi-rte-extractive-summary), [EPI-RTE-numeric-selection](epistemic.md#epi-rte-numeric-selection), [RT-CLM-context-answer](runtime.md#rt-clm-context-answer), [EPI-OBJ-answer-confidence](epistemic.md#epi-obj-answer-confidence)).

No evidence-consuming source-domain acceptance decision is established for those inspected generation paths. Retention and later use therefore do not establish accepted new knowledge or post-acceptance integration. This is not a system-complete absence of evaluators: remaining test/data drivers and consumers are incompletely inspected ([epistemic bounded conclusion](epistemic.md#bounded-conclusion), [report-verification omission account](report-verification.md#omission-questions-and-stopping-decision)).

For correction and withdrawal, representations can diverge. HTTP metadata editing does not demonstrate file rewriting/reembedding; deletion removes SQLite state first, then attempts vector and optional file removal. Wiki prose, prior turns, free-standing entity claims, files and archives can survive. Exact-title cleanup is a separate limited-listing SQLite-only disposition, not semantic equivalence testing. Wiki recompilation detects changed source-ID sets or force, not arbitrary same-ID text edits, narrowing the README's broader currentness claim ([RT-RTE-item-update](runtime.md#rt-rte-item-update), [MEM-RTE-item-withdrawal](memory.md#mem-rte-item-withdrawal), [EPI-RTE-title-cleanup](epistemic.md#epi-rte-title-cleanup), [EPI-RTE-category-recompilation](epistemic.md#epi-rte-category-recompilation), [EPI-CLM-staleness-tracking](epistemic.md#epi-clm-staleness-tracking)).

The strongest supported learning-related contribution is durable conversation-derived context plus history/centroid-driven selection capacity. Improved capacity for future action is not demonstrated: there is no outcome comparison. No particular formulated theory is established from inaccessible generated output, so theory-builder condition 1 (localized theory), condition 2 (content-dependent consumption), condition 3 (content-directed criticism), and condition 4 (retained criticism shaping iteration) are each unestablished for these paths, not evidenced absent. In particular, stored prose, scores and recompiled products do not establish criticism of a consumed theory improving future capacity ([RT-RTE-wiki-compile](runtime.md#rt-rte-wiki-compile), [epistemic bounded conclusion](epistemic.md#bounded-conclusion), [profile-verification](profile-verification.md#verification)).

Reflection and autonomous theory building are independently unestablished, not disproved by those theory gaps. Automatic internal stage scheduling is wired, while host-assisted recovery relies on an excluded host. Neither fact settles whether all operations of a theory-building loop are computational or whether a self-representation has the required two causal directions. Self-improvement is likewise not established at this revision: retained context and centroid changes can reach later behavior, but no independently specified improvement objective/evidence-responsive update and subsequent exercised causal dependence are established. Operator-triggered release installation is maintenance, not a quality-based successor comparison ([RT-RTE-host-fallback](runtime.md#rt-rte-host-fallback), [EPI-RTE-numeric-selection](epistemic.md#epi-rte-numeric-selection), [RT-RTE-product-update](runtime.md#rt-rte-product-update), [epistemic bounded conclusion](epistemic.md#bounded-conclusion)).

The assessment would change with inspectable source/output comparisons and consequential factual acceptance decisions; restart/read-back traces across substrates; edit/deletion/recompilation traces; or objective-defined before/after comparisons tracing retained updates to subsequent behavior. Content-version-based wiki invalidation and coordinated cross-store edit/withdrawal mechanisms would alter the current correction envelope if implemented and verified. Provider version pins and exercised caller traces would resolve different provenance and activation questions, not by themselves prove quality or improvement.
