# Cognee synthesis

## Bounded synthesis

Cognee is a memory platform that acquires content, processes it into graph and vector representations, and supplies retained material to later answer and maintenance computations. Its public claim includes retaining project context and distilling session lessons for reuse across runs. The inspected implementation supports that architecture, including a model-mediated lesson acceptance route; it does not demonstrate factual reliability or improved future performance. See [EPI-CLM-durable-lessons](epistemic.md#epi-clm-durable-lessons).

This account uses SRC-1, the Cognee repository at commit `f154b32a9e544dac73e7ddf2010327cf9988edcd`, with an applicability cutoff of 2026-10-14. The [boundary](boundary.md#boundary-and-evidence) is **complete artifact, partial loop**: the repository is pinned, but not every shipped producer, maintainer and consumer is traced. Evidence consists of inspected implementation and doctrine/design, not target executions or causal comparisons. External model and database internals, separately distributed plugins, Cloud and arbitrary enclosing applications are excluded implementations. Shipped callers remain included; the Company Brain driver provides a separate saved-memory recall invocation, but no supplied execution proves its success. Evidence identities and layers are in the [Source register](boundary.md#source-register). This synthesis adds no source reads.

### Acquisition and retention

The ordinary local permanent-memory request supplies content to `remember`, which resolves user and writable dataset scope, calls `add`, then runs `cognify`. Code fixes the task progression; models perform selected extraction and summarization, rather than choosing the pipeline's next task. Generated nodes, edges and embeddings cross graph/vector storage interfaces. Blocking errors can propagate; background processing reports through a running result. Remote configuration delegates under a separate server contract. See [RT-RTE-permanent-memory](runtime.md#rt-rte-permanent-memory).

Retention is not a single state transition. Session remember first writes cache data; optional automatic improvement is a separately scheduled continuation. Its failure does not undo the session write. Typed QA, trace and feedback branches return after their own writes, while typed SkillRuns are graph-backed. A successful session-storage result therefore does not establish permanent graph publication. Automatic maintenance depends on configuration, host admission and debounce; the host callback fails open and explicit `improve` bypasses it. Process-local claims limit overlapping maintenance, not cross-worker contention or eventual processing. See [RT-RTE-session-improve](runtime.md#rt-rte-session-improve), [MEM-RTE-typed-admission](memory.md#mem-rte-typed-admission), [RT-CLM-auto-admission](runtime.md#rt-clm-auto-admission) and [RT-CLM-improve-coordination](runtime.md#rt-clm-improve-coordination).

The retained products have distinct roles. Graph prose supplies content; graph identifiers and provenance govern traversal and cleanup; numerical indexes support retrieval. Session records retain question/answer text, sanitized host traces, feedback and derived guidance. Skills separate deployed procedure text, discovery/scope metadata, run summaries and proposed revisions. Sharing storage does not make these interchangeable. Neither dense retained representations nor scalar feedback weights establish provider-weight training. See [MEM-OBJ-graph-content](memory.md#mem-obj-graph-content), [MEM-OBJ-graph-structure](memory.md#mem-obj-graph-structure), [MEM-OBJ-vector-index](memory.md#mem-obj-vector-index), [MEM-OBJ-session-agent-trace](memory.md#mem-obj-session-agent-trace) and [MEM-OBJ-skill-run](memory.md#mem-obj-skill-run).

### Maintenance, checking and admission

Session turns can generate guidance candidates and ratings. Deterministic gates reject invalid, oversized, low-confidence or duplicate guidance. Later ranking uses content, confidence, helpfulness and recency; default guidance budgets fit whole content into 400 characters per section and 1,200 characters overall, not a total conversation-token bound. Trace promotion separately converts QA or trace text into graph content and extracts active agent-profile lessons. Oldest-pending graph persistence and newest-at-most-40 lesson extraction have different coverage; an extraction watermark can advance past older unexamined backlog. Agent-profile storage also does not imply injection into the inspected agentic guidance block, which defaults to QA profile. See [MEM-RTE-session-guidance](memory.md#mem-rte-session-guidance) and [MEM-RTE-trace-promotion](memory.md#mem-rte-trace-promotion).

Distillation adds a substantive acceptance architecture. Gated entries and bounded QA timelines reach a curator, which proposes durable lessons. A writer judges support, novelty and durability against resolved member entries, retrieved prior lessons and a glossary. Code grants publication eligibility only to nonfailed, accepted, nonblank statements. Accepted text and optional `why_learned` prose become documents, then enter `add` and `cognify` for graph organization and later reuse. Checking, admission, retention and integration are separate functions. See [MEM-RTE-session-distillation](memory.md#mem-rte-session-distillation), [EPI-RTE-lesson-check](epistemic.md#epi-rte-lesson-check), [EPI-RTE-lesson-admission](epistemic.md#epi-rte-lesson-admission), [EPI-RTE-lesson-retention](epistemic.md#epi-rte-lesson-retention) and [EPI-RTE-lesson-integration](epistemic.md#epi-rte-lesson-integration).

That acceptance licenses a model judgment for graph reuse, not independent corroboration. The writer lacks the original QA transcript, unresolved member IDs are omitted, and novelty/glossary lookup failures produce empty results. No actual input/output and decision instance establishes whether a generated lesson preserves, entails or extends its evidence. Imported source warrant remains unknown. Publication can survive a later failed model call; failed calls leave inputs retryable, whereas successful rejection or empty proposals can advance the watermark. See [EPI-RTE-lesson-curation](epistemic.md#epi-rte-lesson-curation), [EPI-RTE-lesson-check](epistemic.md#epi-rte-lesson-check) and [EPI-RTE-distillation-recovery](epistemic.md#epi-rte-distillation-recovery).

Other maintenance changes reliance without establishing truth. Feedback and preference updates alter ranking state or durable preference text. Optional “truth subspace” geometry uses accepted-learning embeddings to rerank chunks; matching integer epochs suppress some stale coordinates but cannot exclude a documented abandoned-basis/reused-epoch countercase. Optional global summaries compress child content for a later query prelude. Contradiction checks retain model warning edges without vetoing ingestion; temporal supersession records current-by-recency policy, not empirical verification of the latest assertion. Their later reader policies remain unresolved. See [MEM-RTE-ranking-maintenance](memory.md#mem-rte-ranking-maintenance), [MEM-RTE-truth-maintenance](memory.md#mem-rte-truth-maintenance), [MEM-RTE-summary-readback](memory.md#mem-rte-summary-readback), [EPI-RTE-contradiction-annotation](epistemic.md#epi-rte-contradiction-annotation) and [EPI-RTE-temporal-supersession](epistemic.md#epi-rte-temporal-supersession).

### Later consumption and a representative workflow

Recall returns selected session, graph or other lane results. Caller-pinned search types override automatic routing; session success can short-circuit graph work in auto-fallthrough mode. Without a usable LLM, the default graph path chooses chunks rather than generated completion. The decorator offers another route: it selects recent trace feedback and graph context within a 4,000-character envelope, invokes the wrapped function, then attempts trace persistence. Only structured-output gateway calls within its active frame automatically receive that memory. The host still owns its actions, and the decorator's graph selection must not be assumed embedding-based merely because an index exists. See [RT-RTE-recall-dispatch](runtime.md#rt-rte-recall-dispatch), [RT-RTE-decorated-agent](runtime.md#rt-rte-decorated-agent), its memory annotation, and [profile verification](profile-verification.md#verification).

The representative multi-step workflow is explicit agentic completion over one dataset, not default recall. Code prepares graph context, optional history/guidance, a skill catalog and a filtered tool manifest. The model chooses successive AgentStep actions or a final answer. Requested `load_skill` selects from the active map and supplies procedure text; a 12,000-character body cap is followed by an 8,000-character tool-result cap, so full stored procedure delivery is not guaranteed. Tool-scope and dataset-permission checks precede in-process handler invocation; they do not sandbox its effects. See [RT-RTE-agentic-tools](runtime.md#rt-rte-agentic-tools), [RT-OBJ-agent-step](runtime.md#rt-obj-agent-step) and [WF-RTE-skill-loading](workflow.md#wf-rte-skill-loading).

Caught scope, permission and invocation failures become error text for the model's next decision. Other exceptions can escape; previous tool effects are not rolled back. A nonblank final answer wins immediately. Iterative exhaustion or no actionable step causes an additional best-effort completion, beyond the turn bound. SkillRun and QA recording are best effort and selective, not complete replay. The inherited evidence-append call is a no-op, not final-answer validation. Delivery means returning the answer list, not verified task success or host adoption. This is a supported possible progression, not an observed run; a request may use no tools. See the [workflow account](workflow.md#workflow-account) and [MEM-OBJ-skill-run](memory.md#mem-obj-skill-run).

### Adaptation and independent property assessments

The strongest supported adaptive contribution is implemented trace-fed production of later-consumed guidance, lessons and ranking state. Recorded turns and host feedback can shape durable updates without updating model weights. This establishes update wiring, not improved capacity for future action. Skill revision adds failure-selected drafting, retained old/new procedures and rationale, and caller-selected installation into future skill delivery. Installation checks identity, not performance improvement or stale-base consistency. The report verifier also found a shipped model-feedback demo that writes a scored SkillRun and automatically applies a proposal; the inventory therefore must not imply that all callers use neutral scores or that application is necessarily human-controlled. No demo execution or subsequent revised-skill use is supplied. See [MEM-RTE-trace-promotion](memory.md#mem-rte-trace-promotion), [MEM-RTE-session-distillation](memory.md#mem-rte-session-distillation), [MEM-RTE-ranking-maintenance](memory.md#mem-rte-ranking-maintenance), [RT-RTE-skill-revision](runtime.md#rt-rte-skill-revision) and [report verification](report-verification.md#limits).

For the inspected proposal mechanism, [RT-RTE-skill-revision](runtime.md#rt-rte-skill-revision) supports separate conclusions, not a ladder:

| Property | Supported status and boundary |
| --- | --- |
| Theory-builder condition 1: localized formulation | **Afforded** at whole-procedure granularity; no supplied procedure instance establishes a formulated theory or separately revisable assumptions. |
| Condition 2: decisions depend on theory content | **Afforded** through progressive guidance delivery; actual content-dependent decisions are unobserved. |
| Condition 3: content-directed criticism | **Uninspected**; failure scores and requested revisions do not establish a stated challenged claim, result and placement of blame. The additional demo requests missing-instruction criticism but supplies no performed instance. |
| Condition 4: criticism shapes another round | **Afforded** through retained/applied guidance and future run evidence; actual criticism retention and consequential reuse are unobserved. |
| Learning from criticism of a consumed theory | **Uninspected**; no capacity improvement or attribution evidence is supplied. |
| Reflection | **Afforded**: stored guidance and run outcomes represent selected operation and can mediate revision; actual bidirectional operation is unobserved. |
| Reflective theory builder | **Uninspected**; all four conditions are not demonstrated for criticism of method text against its own operation. |
| Autonomous theory builder | **Uninspected**; the core apply caller's role is unresolved and the additional automatic demo does not establish every internal theory-building role. |
| Self-improvement | **Afforded**, within the skill-guided retriever across revision and a possible later invocation, with better skill task performance as the independent objective. Failure evidence can shape replacement and later instruction supply, but subsequent behavior causally depending on that change is unobserved. Successful improvement is not established. |

These unresolved properties do not negate the positive update mechanisms. Offline golden-answer evaluation is implemented separately, but no inspected linkage makes its scores a production lesson or skill-install acceptance gate. No controlled comparison identifies either an overall improvement or a component effect. See [MEM-CLM-evaluation-boundary](memory.md#mem-clm-evaluation-boundary) and [EPI-RTE-benchmark-evaluation](epistemic.md#epi-rte-benchmark-evaluation).

### Scenario-relative assessment

For cross-invocation memory supply, Cognee has source-supported production and later-consumer routes, including shipped callers. For evidence-sensitive lesson reuse, it adds explicit model judgment with publication force, but incomplete evidence views and unobserved fidelity limit the warrant. For bounded tool work, it owns action dispatch and iteration policy, not arbitrary host execution or isolated effects. For comprehensive withdrawal, it follows recorded dependency chains rather than all semantic consequences: traces without graph IDs, append-only alternatives and unresolved derived-state retraction prevent universal erasure. See [MEM-RTE-memory-withdrawal](memory.md#mem-rte-memory-withdrawal).

Assessment would change with linked production/update/consumer traces, actual lesson decision pairs, complete score-producer and apply-driver coverage, and controlled future-task comparisons. Exact basis identity checked per truth-coordinate would address the epoch countercase; complete derivative dependency and backend deletion tracing would strengthen withdrawal conclusions. These are named evidence or system changes, not inferred benefits or adoption recommendations.
