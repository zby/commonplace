# CocoIndex report verification

## Verification

The reports support a bounded implementation account of incremental indexing, retained computation, shipped search consumers and model-assisted extraction. They do not establish observed operation, factual acceptance of extracted claims or improved agent performance. I read all five submitted members, the boundary, their types and the record contract. Correction-answer files were empty; the structural report returned `none`. There is no structural failure to route. I independently checked source behavior rather than accepting the analysts' validation statements as semantic verification. SRC-1 HEAD equals the reviewed revision and the checkout is clean; no target program, test, provider or database was executed.

### Runtime and workflow

I checked every runtime declaration and its load-bearing source passages: both model components, the component memo object, all six routes and the extraction instruction path. Direct reads of SRC-1 `examples/text_embedding/main.py`, `examples/manuals_llm_extraction/main.py`, `python/cocoindex/_internal/app.py`, `python/cocoindex/cli.py`, `rust/sdk/cocoindex/src/app.rs` and `rust/core/src/engine/app.rs` support the invocation owners, separate update/query calls and SDK option forwarding in the [runtime account](runtime.md#runtime-account). The producer declares a vector index despite stale comments; the query really orders distance and limits returned rows. The manual function awaits conversion and extraction before declaration; the workflow does not splice the unrelated text query into manual delivery.

The preview submit branch in SRC-1 `rust/core/src/engine/execution.rs` returns before normal sink application. It also rejects pending child-provider actions. This supports the branch-bounded guarantee of [RT-RTE-preview-update](runtime.md#rt-rte-preview-update), not universal preview success or a no-effects sandbox. Drop installs a raising error handler, drains captured live controllers with ignored timeout results, deletes the root and then clears per-app storage. Ordinary root cleanup has different error handling. The qualifications in [RT-RTE-drop-app](runtime.md#rt-rte-drop-app) are necessary and supported. SRC-1 `python/cocoindex/connectors/localfs/_source.py` starts observation before scanning, marks ready, processes changes and rescans; readiness is not termination. SRC-1 `rust/core/src/engine/admission.rs` supports token loans and the unbounded `None` case, not a total-process resource cap.

SRC-1 `python/cocoindex/ops/sentence_transformers.py` and `python/cocoindex/_internal/runner.py` support inference, the configuration-based memo key, smaller-batch requests, optional callable serialization and broken-pool restart. Neither subprocess placement nor a model alias establishes isolation or exact weights. The manual's CPU converter option is distinct from its GPU runner placement. The [workflow account and annotation](workflow.md#workflow-account) accurately distinguish shape admission, a new row declaration, conditional SQL delivery and unobserved success. PostgreSQL dispatch and both awaited upsert implementations support that distinction. No workflow records require supersession.
