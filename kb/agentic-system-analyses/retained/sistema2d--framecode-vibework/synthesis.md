# FrameCode-VibeWork synthesis

## Bounded synthesis

FrameCode-VibeWork (FCVW) organizes AI-assisted project changes around minimum context, a plan, scoped execution, evidence and a version record. It is a Markdown governance and memory system, not an enclosing agent runtime. This account covers the whole shipped FCVW system at Git commit `847cdcedc02d08531961c8367f4e2ddb2dc392f1`, with applicability cutoff 2026-11-08. SRC-1 is the sole frozen source. Python supports implementation findings; policies and skills support doctrine/design findings. No host/model execution trace, consuming-project QA run or causal experiment was supplied, and the analysis did not execute the target. The external host, model, application and user approvals remain dependencies rather than FCVW implementations. See the [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

### Entering a governed change

A user asks an external host agent or human to change a project. That host owns the next step: read the entry point, classify session and event impacts, load applicable policies, create or resume a plan, implement, validate and close out. FCVW supplies the work contract, not an inference loop or filesystem sandbox. Plans retain scope, acceptance, risk, regression checks and rollback. Read-only work and narrowly specified trivial prose changes have no-plan alternatives; the representative workflow here uses the standard plan path. [RT-RTE-governed-change](runtime.md#rt-rte-governed-change).

Optional Python routing unions supplied session requirements, explicit events, file-derived events and active-plan `context_files`. It returns mandatory paths, reasons and reading ranges; it does not deliver all mandatory bodies. Complementary lexical retrieval can rank copied Markdown chunks and expand one graph hop. A versioned-change invocation requires event and file declarations, but application semantic impacts remain caller-owned. Empty selectors and omitted semantic facts can under-route: valid syntax does not establish complete task context. [RT-RTE-context-delivery](runtime.md#rt-rte-context-delivery).

Context control is selective loading, not management of the host's full window. Skills load on demand; section reads omit unrequested bodies; archive links allow later reload. With the optional context budget, selection receives complete chunks and skips oversized candidates. Without it, ordinary excerpts are sliced at 1,200 characters. The estimate covers the serialized optional-result array, not mandatory documents, actual tokenizer usage or existing host turns. FCVW does not evict those turns or allocate isolated worker contexts. [RT-CLM-context-controls](runtime.md#rt-clm-context-controls), [RT-RTE-mcp-checks](runtime.md#rt-rte-mcp-checks), [MEM-RTE-session-handoff](memory.md#mem-rte-session-handoff).

### Executing, reviewing and delivering

The representative multi-step workflow connects one active plan to independent work packages and main-agent review. Delegation requires current authority, real host tools, non-overlapping ownership and a reason to expect time or review-quality benefit. Otherwise one executor or sequential packages suffice. Each handoff names exact files, required skill, preserved behavior, evidence and rollback. FCVW prescribes collision checks and soft locks but does not enforce worker filesystem ownership or context isolation. The main agent reviews every return; a worker's success assertion cannot close the plan. [RT-RTE-work-packages](runtime.md#rt-rte-work-packages), [workflow package annotation](workflow.md#on-rt-rte-work-packages).

Review tests preservation as well as the requested feature. Insufficient blast-radius evidence, pending regression results or undocumented failing checks block prescribed completion. A failing or unavailable check can be handled only with an explicit limitation, residual risk, owner and decision; bypass additionally requires named authority and bounded follow-up. Recovery belongs to the host: split, reduce, defer, obtain required approval or perform authorized rework. Confirmed regressions should lead to a strengthened replay or guardrail, not merely another note. Delivery means scoped changes, decided acceptance, reproducible evidence, final regression dispositions, a changelog/release record and consistent plan status/directory. It is not demonstrated deployment or a mandatory commit/push. [Workflow account](workflow.md#workflow-account), [workflow change annotation](workflow.md#on-rt-rte-governed-change).

Optional hooks strengthen only selected host paths. When enabled by the automation contract and environment, pre-edit can deny recognized edit-tool calls lacking an active/closing plan. It does not match edits to plan scope; shell edits, unrecognized tools and exempt paths are outside that dispatch. Stop can request repairs, but recursion, failures and timeouts include fail-open branches. These are host-honored protocol controls, not universal edit or completion barriers. MCP separately confines direct resolved file arguments within its root and caps section content, but that guarantee does not cover arbitrary host tools or other FCVW interfaces. Route references can flag out-of-root paths without reading them. [RT-RTE-hook-lifecycle](runtime.md#rt-rte-hook-lifecycle), [RT-RTE-mcp-checks](runtime.md#rt-rte-mcp-checks).

### Retaining work and bringing it back

FCVW separates raw imports, historical evidence, reusable wiki understanding and current canonical project state. The curator asks the host to promote only reusable, sourced, nonduplicate knowledge, preferably by updating an existing page. Source review may confirm, update, supersede, invalidate or defer. These are content-based admission instructions, not evidence that a particular proposition was accepted. Retention and lifecycle linking remain distinct from acceptance. Without paired inputs, outputs and decisions, generated prose cannot be classified as an accepted new inference merely because it is called a synthesis. [MEM-OBJ-wiki](memory.md#mem-obj-wiki), [EPI-RTE-wiki-review](epistemic.md#epi-rte-wiki-review), [EPI-RTE-wiki-integrate](epistemic.md#epi-rte-wiki-integrate).

The continuity mechanism is a bounded host-authored session handoff from actual workspace, plan, decisions, validation and risks. A later host selects a relevant handoff by scope/date/unique ID, verifies it against disk and follows links. Rotation archives older sessions while preserving evidence; it does not implement transcript eviction or automatic deletion. The model-host branch can admit summaries without separate human approval per item. This supports a prescribed trace-fed durable-artifact route, not an observed automatic FCVW transcript service or improved capacity. [MEM-OBJ-session](memory.md#mem-obj-session), [MEM-RTE-session-handoff](memory.md#mem-rte-session-handoff), [RT-RTE-asset-admission](runtime.md#rt-rte-asset-admission), [profile verification](profile-verification.md#verification).

Python builds disposable JSONL text indexes and typed graph/review state from files. Later requested retrieval and MCP section calls can return retained bodies; queue calls return plan identities, derived metadata and recommendations, while routes return references and digest calls return fingerprints. Non-writing tools can therefore consume memory without authoring it. The opt-in SessionStart hook instead pushes all sorted in-progress plan names and up to five pending names into additional context. This is coarse plan-identity supply, not targeted wiki selection or handoff-body loading. [MEM-RTE-index-build](memory.md#mem-rte-index-build), [MEM-OBJ-knowledge-graph](memory.md#mem-obj-knowledge-graph), [RT-RTE-mcp-checks](runtime.md#rt-rte-mcp-checks), [RT-RTE-hook-lifecycle](runtime.md#rt-rte-hook-lifecycle).

The trust policy is stronger than retrieval's own enforcement. Explicit authority and retrieval-scope metadata precede builder defaults. A separate validator can flag incompatible authority, but no mandatory validation-before-index chain is established. Retrieval does not rehash live sources; obsolete, superseded, contradictory and archived records are downweighted rather than universally withdrawn. Graph expansion may return only one target chunk, and ordinary slicing can omit conditions or rationale. These are reachable implementation countercases, not demonstrated malicious deployment. [RT-CLM-context-controls](runtime.md#rt-clm-context-controls), [memory delivery annotation](memory.md#on-rt-rte-context-delivery), [EPI-RTE-evidence-check](epistemic.md#epi-rte-evidence-check).

### Checking evidence and changing future behavior

Deterministic checks establish narrower facts than semantic warrant. Source digests and direct declared dependencies identify review candidates, not changed truth or automatic revocation. Evidence metadata checks establish selected consistency/reference predicates; optional method guarding, URL non-fetching and local reference existence do not authenticate a claim or test execution. A review report has no automatic canonical-mutation authority. [EPI-RTE-source-review](epistemic.md#epi-rte-source-review), [EPI-RTE-evidence-check](epistemic.md#epi-rte-evidence-check), [MEM-RTE-source-review](memory.md#mem-rte-source-review).

Product QA adds a distinct stronger admission protocol. Approved expectations require approved requirements, criteria, decisions or owner confirmation; code/live behavior alone cannot approve intent. The host is instructed to observe selected application cases and ask the user about every expected/actual divergence before dependent action. The checker binds declared runs to selected parsed contract hashes and rejects incomplete or failed declared results. It cannot attest live execution, evidence truth, hidden coverage or consultation authenticity. A clear decision gate does not turn a failed test into a pass, and hashing does not cover unencoded behavior. [MEM-OBJ-product-contract](memory.md#mem-obj-product-contract), [MEM-OBJ-qa-run](memory.md#mem-obj-qa-run), [EPI-RTE-live-qa](epistemic.md#epi-rte-live-qa), [EPI-RTE-qa-check](epistemic.md#epi-rte-qa-check), [EPI-RTE-divergence-decision](epistemic.md#epi-rte-divergence-decision).

For framework maintenance, the strongest supported contribution is an evidence-responsive method-revision procedure: diagnose failure/drift, patch the smallest behavior-changing section, replay the exposing task and retain updated guidance. Its theory-builder conditions remain separate: (1) localized revisable method content is afforded; (2) decisions depending on its content are claimed; (3) content-directed criticism and revision are requested, not shown performed with blame assigned to a particular theory; (4) retention for later rounds is afforded, not observed iteration. Criticism improving future capacity remains uninspected. A host-mediated reflective pathway is afforded because representations of operating failures can inform rule changes; exercised reflection is not established. Autonomous theory building remains uninspected, rather than disproved by the external user role. [RT-RTE-asset-admission](runtime.md#rt-rte-asset-admission).

Self-improvement is likewise a dispositional host-mediated pathway at the boundary of FCVW skill/profile maintenance across sessions, with the independent objective of reducing evidenced failure, drift or cost. Retained revisions can enter later instruction paths, but subsequent operation causally depending on them is unestablished. Thus neither exercised nor successful self-improvement is demonstrated. Release upgrade implements a separate machinery-replacement path with dry run, apply/conflict/prune controls and backups; it is not evidence-driven semantic improvement or atomic rollback. [RT-RTE-asset-admission](runtime.md#rt-rte-asset-admission), [RT-BAP-policy-consumption](runtime.md#rt-bap-policy-consumption), [RT-RTE-framework-upgrade](runtime.md#rt-rte-framework-upgrade).

For a project seeking auditable continuity, the supported contribution is the explicit chain from scoped work to evidence, handoff and later checking, with executable selection and consistency support. For a scenario requiring universal write mediation, authenticated QA or demonstrated learning benefit, the present records do not establish those properties. The retrieval benchmark compares optional selection with a baseline against authored/caller labels, without executing a model; the local driver consumes test/status/byte-snapshot evidence, not downstream task-quality measurements. Actual configured-host traces, authenticated case evidence, paired revision/replay records and subsequent revision-dependent operation would change these assessments. Mandatory validator admission before indexing, live-source freshness checks or broader host interception would change the corresponding implementation guarantees. [EPI-RTE-retrieval-benchmark](epistemic.md#epi-rte-retrieval-benchmark), [RT-RTE-local-checks](runtime.md#rt-rte-local-checks), [report verification](report-verification.md#verification).
