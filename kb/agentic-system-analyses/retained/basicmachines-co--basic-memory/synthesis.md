# Basic Memory synthesis

## Bounded synthesis

Basic Memory is a persistent knowledge engine with shipped assistant integrations, not the enclosing assistant's general-purpose runtime. It accepts Markdown notes, maintains derived access structures, and supplies selected retained content through tools and host callbacks. This account covers the canonical repository at `a72751c5d626380dedeed30f55f7a80ba3dc710d`, with an applicability cutoff of 2026-10-16. Its evidence is inspected implementation and doctrine/design from SRC-1, not target execution, production sessions or causal experiments. The boundary is **complete artifact, partial loop**: the artifact includes first-party callers and instructions, but their material routes are not exhaustively traced. See [boundary and evidence](boundary.md#boundary-and-evidence) and the [Source register](boundary.md#source-register).

### From a caller's proposal to accepted and published state

An enclosing user or assistant chooses a note operation. MCP `write_note`, also reachable through a CLI wrapper, resolves the project and passes a typed request to the knowledge API. Deterministic service code identifies the exact path owner and accepts or refuses the mutation in a database transaction. The caller still owns the next reasoning step. Server instructions ask assistants to obtain consent before creating notes; this is model-facing guidance, not a service requirement for per-content human approval. Enabled host capture can write automatically ([RT-RTE-note-write](runtime.md#rt-rte-note-write), [RT-BAP-server-instructions](runtime.md#rt-bap-server-instructions)).

Replacement policy is conditional. An occupied path can be refused when overwrite is false; overwrite can be unconditional or checksum-conditioned. A collaboration-relay branch can supersede a mismatching revision under specified previous-source/storage-head conditions. Direct CRUD and filesystem paths do not inherit every path-addressed tool guard. Thus checksums provide scoped revision control, not a universal stale-write rejection guarantee ([RT-RTE-note-write](runtime.md#rt-rte-note-write)).

Acceptance, file publication and retrieval readiness are different completion points. Production local materialization queues an accepted snapshot, checks versions and existing bytes, publishes status, indexes successful writes and schedules vector work separately. Per-note queue serialization is process-local. Graceful shutdown drains work; startup recovery can re-drive pending, writing or failed rows. Neither this protocol nor its separate file check and write proves crash durability, cross-process serialization or atomic compare-and-swap against arbitrary filesystem writers ([RT-RTE-note-materialization](runtime.md#rt-rte-note-materialization)).

The retained body, synchronization metadata and published graph serve different consumers. Structured note reload can return accepted entity content before every derived representation agrees; its resource fallback tests for missing content, not an empty body. Parsed graph generations concern publication consistency, not factual warrant. This distinction matters when a caller needs the accepted text rather than a search-ready projection ([MEM-OBJ-markdown-content](memory.md#mem-obj-markdown-content), [MEM-OBJ-sync-state](memory.md#mem-obj-sync-state), [MEM-OBJ-graph-publication](memory.md#mem-obj-graph-publication), [MEM-RTE-note-reload](memory.md#mem-rte-note-reload)).

### From retained material to a later working context

Requested graph context selects indexed knowledge by identifier or search, traverses relations and applies page/related-result bounds. Compact mode omits observations and source prose; explicit note reads can retrieve bodies, metadata or line slices. Omitted material remains reachable through further calls. These are controls over particular returns, not a total assistant context budget or host compaction mechanism ([RT-RTE-context-build](runtime.md#rt-rte-context-build), [MEM-RTE-note-reload](memory.md#mem-rte-note-reload)).

The representative multi-step workflow is Pi working-thread continuation. With direct capture selected, valid configuration, project mapping and workspace trust enable automatic callbacks. After the assistant settles, fixed code extracts current-branch user/assistant text, requires user content and sufficient text, formats an extractive checkpoint, then invokes the CLI with Markdown on stdin. Tool-role results and hidden/nontext blocks are not a complete evidentiary transcript in this branch. Default session/branch-derived titles permit checkpoint replacement; explicit titles change that overwrite behavior. The host still performs the user's task ([RT-RTE-pi-checkpoint](runtime.md#rt-rte-pi-checkpoint), [EPI-OBJ-capture-draft](epistemic.md#epi-obj-capture-draft), [workflow account](workflow.md#workflow-account)).

On a later eligible agent start, prompt/timeframe/project-filtered search selects up to five checkpoints, each with an excerpt clipped to 500 characters, for a displayed host message. The wrapper tells the assistant to treat recall as reference data, not instructions; model interpretation is not mechanically separated by that warning. Automatic operations and model-tool capture have trust predicates that the human capture command does not share. Those predicates are not an all-write approval gate or a sandbox ([RT-RTE-pi-checkpoint](runtime.md#rt-rte-pi-checkpoint), [RT-BAP-recall-data](runtime.md#rt-bap-recall-data)).

Delivery remains weaker than verified continuation. The subprocess helper checks exit status and JSON syntax, not a successful-write discriminant; a capture notification therefore does not independently certify admission or completed publication. Capture failure warns without immediate retry. Recall consumes its automatic attempt before searching, so failure need not retry until a new session or explicit command. The supported endpoint is a context handoff, not demonstrated use or task success ([workflow delivery account](workflow.md#verification-rejection-recovery-and-delivery)).

Other hosts materially differ. Python hook capture separates raw lifecycle metadata from authored checkpoints and emits bounded session briefs. Its archive sweep parses, moves and age-prunes metadata; it does not promote that metadata into knowledge. Tau instead asks an external host model to fold public session text and a prior handoff into a new durable handoff. Pending/confirmed receipts and identity/digest checks support uncertain-write reconciliation rather than blind retry. Tau requests rationale preservation and later reads prior handoffs, but fidelity remains unobserved. Hermes uses extractive first/last-turn summaries and query prefetch. OpenClaw caches task/recent-activity recall and returns it through `systemPromptAddition`; that placement does not turn reference content into standing instructions, and child-note creation does not establish child read-back ([RT-RTE-hook-checkpoint](runtime.md#rt-rte-hook-checkpoint), [MEM-RTE-trace-archive](memory.md#mem-rte-trace-archive), [MEM-RTE-tau-handoff](memory.md#mem-rte-tau-handoff), [MEM-RTE-hermes-continuity](memory.md#mem-rte-hermes-continuity), [MEM-RTE-openclaw-context](memory.md#mem-rte-openclaw-context)).

These routes establish useful architectural capacity for continuing selected work across context boundaries. They do not substantiate literal universal recall: capture omissions, clipping, query selection, failure handling and host dependence remain consequential. Deletion also removes accepted/search/vector state without revoking already copied host context. Archive-first lifecycle guidance is not a universal deletion prohibition ([EPI-CLM-never-forgets](epistemic.md#epi-clm-never-forgets), [MEM-RTE-note-withdrawal](memory.md#mem-rte-note-withdrawal)).

### What checking and retained experience establish

Automatic Pi, hook, Tau and Hermes writes connect recorded conversational experience to durable context with later consumers. This supports the memory comparison's local wired trace-learning findings: here that term means an automatic trace-fed durable-context route, not improved capacity for future action. Tau additionally consumes its previous handoff during the next durable update. The unresolved question is whether these mechanisms improve later action, preserve the needed qualifications, or merely supply more context. No comparison in this evidence measures that benefit ([RT-RTE-pi-checkpoint](runtime.md#rt-rte-pi-checkpoint), [RT-RTE-hook-checkpoint](runtime.md#rt-rte-hook-checkpoint), [MEM-RTE-tau-handoff](memory.md#mem-rte-tau-handoff), [MEM-RTE-hermes-continuity](memory.md#mem-rte-hermes-continuity), [profile verification](profile-verification.md#verification)).

Basic Memory also implements narrow, genuine checking. Schema inference derives counts and proportions over supplied note representations and proposes field rules; frequency does not warrant the underlying assertions or compel schema adoption. Schema validation reports mode-relative structural conformity: warning-mode pass can coexist with a missing required field. Drift reports compare declared fields with observed usage. These responses are not factual acceptance certificates or inspected core write vetoes ([EPI-RTE-schema-inference](epistemic.md#epi-rte-schema-inference), [EPI-RTE-schema-validation](epistemic.md#epi-rte-schema-validation), [EPI-RTE-schema-drift](epistemic.md#epi-rte-schema-drift)).

Research and reflection instructions prescribe more than storage. Research calls for current sources, uncertainty and user approval to save. Reflection calls for full-note review, durability selection, source links and preserving unresolved disagreements. They remain doctrine-only routes rather than observed evidence-consuming acceptance or installed autonomous recurrence. The benchmark separately generates answers from selected context and judges gold-fact coverage/noncontradiction or appropriate abstention. Verdicts affect metric accounting and can be rejudged; extra assertions are allowed unless contradictory. This is neither a comprehensive hallucination audit nor a production note-revision loop ([EPI-RTE-research-note](epistemic.md#epi-rte-research-note), [EPI-RTE-reflect-notes](epistemic.md#epi-rte-reflect-notes), [EPI-RTE-qa-answer](epistemic.md#epi-rte-qa-answer), [EPI-RTE-qa-judge](epistemic.md#epi-rte-qa-judge)).

The independent properties remain separate. No actual formulated theory route is established for assessing theory-builder conditions: localized theory content (condition 1), decision dependence on that content (2), content-directed criticism with blame and changed reliance (3), and retained criticism shaping another round (4) are each unestablished here, not evidenced absent system-wide. Nor is criticism of a consumed theory shown to improve future-action capacity. Reflection instructions and their operation records do not establish a bidirectional reflective system. Automatic callbacks establish local computational control, not autonomy over every internal theory-building operation. For self-improvement, retained context can reach later behavior, but the record establishes neither objective-responsive determination of an improvement-directed organizational update nor subsequent operation causally depending on that change. Exercised self-improvement and successful improvement are therefore unestablished at this boundary; this does not negate the wired continuation mechanisms ([EPI-RTE-reflect-notes](epistemic.md#epi-rte-reflect-notes), [RT-RTE-pi-checkpoint](runtime.md#rt-rte-pi-checkpoint), [MEM-RTE-tau-handoff](memory.md#mem-rte-tau-handoff)).

Embedding adapters request inference, not parameter training, and configurable model names are not immutable weight identities. Their opaque provider behavior is a separate uncertainty from learning through retained prose ([RT-CMP-fastembed-provider](runtime.md#rt-cmp-fastembed-provider), [RT-CMP-openai-provider](runtime.md#rt-cmp-openai-provider), [RT-CMP-litellm-provider](runtime.md#rt-cmp-litellm-provider)).

For a checkpoint-continuation scenario, the supported result is a connected capture–retain–select–deliver architecture. For structurally checking notes, it is a mode-relative diagnostic capacity. For factual knowledge acceptance or improved future action, the evidence stops earlier. A traced successful-write check plus read-after-write confirmation would strengthen the Pi delivery contract; captured later use would establish activation. An objective-defined comparison with and without the continuity mechanism could assess benefit at that treatment level. Component attribution would require separate variation of the component. An evidence-consuming factual acceptance trace or an objective-responsive update followed by causally dependent operation would change the epistemic or self-improvement assessment, respectively. No source checkout reads or new evidence were added for this synthesis.
