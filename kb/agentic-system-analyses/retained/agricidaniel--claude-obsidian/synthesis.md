# claude-obsidian synthesis

## Bounded synthesis

### From a preservation request to a knowledge proposal

claude-obsidian is a local-first Agent Skills package for building and maintaining a user-owned Obsidian knowledge vault. Its architectural split is between model-facing procedures that select and assess content, and Python code that admits and persists submitted changes. It is not the enclosing agent scheduler. This account covers the shipped production, maintenance, admission and later-consumption paths at commit `32ac5a02c4e082e4a5628ca810776375e134708e`, with applicability cutoff 2026-10-13. The evidence is inspected implementation and doctrine/design from SRC-1, not a live vault or executed workflow. External hosts, model services, extraction implementations and Obsidian rendering are outside the source set. The whole-system boundary does not mean exhaustive inspection of every branch. See [the boundary](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The declared promise is source-cited, compounding knowledge construction, not unconditional factual correctness. Shipped persistence and consumption pathways support the construction claim; they do not establish compounding quality. [RT-CLM-product-promise](runtime.md#rt-clm-product-promise) retains that distinction.

Save begins with conversation content explicitly selected by the user. The foreground agent reads orientation and relevant pages, looks for an existing note and proposes a small create or replacement. The resulting prose, navigation, log and hot context are durable artifacts, not an unattended transcript dump. Conversation assertions cannot alone make a claim accepted. Ingest instead starts from captured source material and asks whether canonical compilation adds durable synthesis, navigation or reusable value. Source retention can therefore end without a canonical paraphrase. See [RT-RTE-save-apply](runtime.md#rt-rte-save-apply), [MEM-OBJ-wiki-pages](memory.md#mem-obj-wiki-pages) and [EPI-RTE-evidence-assessment](epistemic.md#epi-rte-evidence-assessment).

A representative multi-step workflow is bounded batch Ingest with one local source per worker. Delegation is optional. The parent supplies the vault root, source identity/path and bounded discovery scope. The worker returns proposed content, current target hashes, evidence locators, contradictions and unfinished work. Missing or ambiguous inputs stop the assignment; turn-budget pressure calls for a verified partial packet with a resumable next step. The parent resolves overlaps and owns one shared transaction. A worker packet is an intermediate return, not delivery of an ingested vault. Actual worker isolation and read-only permissions belong to the host: the declared worker tool surface includes Bash. See [RT-RTE-ingest-drafts](runtime.md#rt-rte-ingest-drafts) and [the workflow account](workflow.md#workflow-account).

This arrangement keeps source discovery in a requested separate context while copied proposals cross back to the parent. It does not remove the parent's accumulated turns. Later page reads reload retained content, not live references into a worker window. Host eviction and compaction remain uninspected.

### From proposed claims to admitted bytes

Provenance separates source records, claim assessments and the legacy ingestion manifest. Source records describe identity, freshness and support eligibility; raw payloads preserve evidence bytes. Claim records hold prose and evidence relationships. The manifest tracks processing identity and generated pages rather than warrant. A captured payload or successful processing label does not establish source truth. See [MEM-OBJ-source-ledger](memory.md#mem-obj-source-ledger), [MEM-OBJ-claim-ledger](memory.md#mem-obj-claim-ledger) and [MEM-OBJ-manifest](memory.md#mem-obj-manifest).

The provenance gate has computational force, but a restricted license. Accepted claims require fresh active non-synthetic support and review chronology; high-risk claims require two independent source groups. Fresh contradictory evidence requires contested assessment or nonempty adjudication notes. The program checks these declared fields, not whether the passages entail the claim or the notes resolve the contradiction. Moreover, prospective validation runs when a provenance ledger is written; prose-only edits do not trigger that gate. Thus the software can veto malformed acceptance metadata without establishing semantic acceptance. See [EPI-RTE-ledger-check](epistemic.md#epi-rte-ledger-check) and [EPI-RTE-ledger-disposition](epistemic.md#epi-rte-ledger-disposition).

The host is instructed to assess evidence and seek review. CLI inspect produces a vault-bound plan digest; CLI apply requires that digest. The core checks supplied approval and current declared preconditions under the mutation lock, journals originals and performs confined per-file replacements. The digest binds planned effects, not the identity or judgment of a human reviewer. Only declared preconditions protect previously read non-write inputs. Per-file atomicity does not give simultaneous visibility of a whole batch. On drift the parent must reread and rebuild; journal restoration refuses to overwrite unrelated external changes and can remain rollback-failed. Final delivery is the apply result's operation ID and exact changed paths. See [RT-RTE-save-apply](runtime.md#rt-rte-save-apply), [RT-BAP-plan-enforcement](runtime.md#rt-bap-plan-enforcement) and [the workflow recovery account](workflow.md#application-rejection-and-recovery).

Reviewed admission is not universal. The shipped callable capture route invokes the core without a plan approval argument, while retaining create-only raw payload constraints. Derived retrieval caches have their own automatic admission. These alternatives defeat a blanket human-review guarantee, not the local controls on the reviewed CLI branch. See [RT-RTE-direct-capture](runtime.md#rt-rte-direct-capture) and [RT-RTE-optional-rerank](runtime.md#rt-rte-optional-rerank).

### From retained material to a later answer

Later Query starts from hot/index orientation, then requests relevant candidates and reads current pages and provenance before answering. Hot context is orientation, not independent evidence. Indexed retrieval filters known stale index/chunk/page mismatches and deduplicates pages; its default final budget is five pages from twenty BM25 chunk candidates. Unavailable or degraded retrieval calls for read-only fallback search, not an automatic rebuild. Candidate selection is implemented; evidence-grounded answering and refusal remain requested model behavior. See [RT-RTE-vault-query](runtime.md#rt-rte-vault-query), [MEM-OBJ-hot](memory.md#mem-obj-hot) and [MEM-BAP-vault-evidence](memory.md#mem-bap-vault-evidence).

The prescribed Query branch uses `--no-rerank` and requests no mutation. Direct default retrieval may instead invoke Ollama, rerank with dense vectors and persist an embedding cache outside the canonical transaction journal. Unusable embeddings produce a whole-set no-op fallback. Ranking consumes contextualized chunk text, whereas displayed snippets show only capped raw excerpts. Neither ranking nor a snippet supplies a complete warrant. Synthetic prefixes copy selected opening text and may truncate qualifications; optional model prefixes have no established semantic relation without input/output instances. Egress-enabled prefix generation can fall back from Anthropic to a Claude subprocess and then synthetic text. See [MEM-OBJ-chunks](memory.md#mem-obj-chunks), [RT-RTE-optional-rerank](runtime.md#rt-rte-optional-rerank), [RT-RTE-prefix-generation](runtime.md#rt-rte-prefix-generation) and [EPI-RTE-synthetic-prefix](epistemic.md#epi-rte-synthetic-prefix).

A separate lifecycle route supplies retained context without a current query. After environment opt-in and applicable vault consent, SessionStart emits at most 32 KiB from the fixed hot file, including on resume or compact. This is coarse availability/consent/budget selection, not targeted relevance. The Save authoring target of 500 words is a different control. Stop emits bounded journal warnings; it neither captures a transcript nor performs recovery. The package emits bytes, while the external host delivers them and the model determines their influence. A non-instruction envelope does not establish injection resistance. See [RT-RTE-session-context](runtime.md#rt-rte-session-context).

### Maintenance and the limits of improvement

The strongest supported contribution toward future work is explicit retention and reuse: selected reasoning can become vault prose, admitted revisions can reach later queries, and code can reuse or rebuild derived access structures. That is not demonstrated improved capacity. Chunk maintenance withdraws the BM25 index before changes, prunes surplus chunks and can leave indexed retrieval unavailable after failure. Tiling reuses vectors and deletes orphan entries; its overlap bands are heuristic, with uncalibrated seeds, not permission to merge meanings. Log folds request additive extractive summaries without upgrading evidence or changing hot context. Research preserves a dossier even when the separately reviewed canonical merge is rejected. See [MEM-RTE-chunk-maintenance](memory.md#mem-rte-chunk-maintenance), [MEM-RTE-tiling-diagnosis](memory.md#mem-rte-tiling-diagnosis), [MEM-RTE-log-fold](memory.md#mem-rte-log-fold) and [EPI-RTE-canonical-integration](epistemic.md#epi-rte-canonical-integration).

Diagnostics and admission remain separate. Lint does not auto-repair. Optional checkpoint lint can block a Git checkpoint without undoing prior note retention, and callers can skip it. Product verification supplies executable checks and explicitly pending manual gates, not an automatic promotion scheduler. Mode changes affect future filing through explicit configuration rather than evaluation-fed learned policy. See [EPI-RTE-checkpoint-gate](epistemic.md#epi-rte-checkpoint-gate), [RT-RTE-review-machinery](runtime.md#rt-rte-review-machinery) and [MEM-BAP-filing-config](memory.md#mem-bap-filing-config).

For a bounded source-ingestion scenario, this architecture offers a connected proposal-to-delivery procedure with deterministic stale-plan rejection and recovery. For a vault-question scenario, it offers candidate retrieval plus requested current-support assessment. For unsolicited continuity, it offers consent-gated copied orientation. None of these source-supported mechanisms establishes successful synthesis, trustworthy downstream withdrawal or improved answers in operation.

Learning, reflection, autonomy and self-improvement are separate questions. The runtime supports retained guidance, explicit configuration and review machinery, but supplies no theory account establishing conditions 1–4: a complete localized theory, content-dependent consumption, content-directed criticism with revision or changed reliance, and retained criticism shaping a next round are not established as a theory-building chain. This is not evidence that every condition is absent. Nor does the account establish that criticism of a consumed theory improved future-action capacity. Reflective self-representation with both causal directions, computation performing every internal theory-building role, and exercised evidence-responsive self-change are independently unestablished. Product gates and note revision alone close none of those claims. For the declared package boundary, no update-to-later-operation comparison establishes exercised self-improvement or successful improvement. The accepted memory assessment likewise establishes neither a qualifying automatic trace-fed behavior-shaping chain nor a bounded system-wide negative. See [RT-RTE-review-machinery](runtime.md#rt-rte-review-machinery), [EPI-RTE-evidence-assessment](epistemic.md#epi-rte-evidence-assessment), [the epistemic conclusion](epistemic.md#bounded-conclusion) and [profile verification](profile-verification.md#verification).

An inspectable source-to-packet-to-apply-to-query trace would change the assessment of exercised delivery and reliance. Checks of actual source/claim pairs would test semantic acceptance; controlled outcome comparisons would test benefit at the varied mechanism's level. Explicit withdrawal handling with downstream tests would strengthen retraction conclusions. A retained criticism/update trace and subsequent operation depending on that update would be needed for exercised self-improvement attribution. More source inspection alone cannot supply those observations or causal comparisons.
