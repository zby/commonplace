## Bounded conclusion

AIDE2's strongest documented epistemic route is measurement followed by scoped operational selection. Public execution feedback guides inner search. Private scores averaged across tasks/runs decide whether a proposed harness becomes incumbent. Acceptance uses a named criterion—better aggregate grade—for a named use—subsequent task optimization at fixed budgets—on a fixed selection benchmark. The consequential path is grade to fixed selector to retained incumbent code to later editing and execution, not an unconditional endorsement of the harness's explanations ([RT-RTE-harness-admission](runtime.md#rt-rte-harness-admission), [RT-BAP-incumbent-code](runtime.md#rt-bap-incumbent-code)). The authors report that it operated; the implementation and raw exercised path are uninspected.

Measured propositions are new evidence about outcomes, but no checked implementation or warranted-premise derivation is available. Arithmetic aggregation is specified, not verified. The capture does not individuate a produced accepted ampliative explanatory claim: code generation creates operational candidates, and absent rationales prevent determining whether any accompanying proposition is imported, entailed or non-entailed. No general claim-production negative follows.

Reviewer interpretation and summaries carry an unresolved semantic edge. Their names do not establish faithful reshaping. Selected deduplicated error lines have a narrower non-ampliative role: they preserve selected occurrence text while losing context and multiplicity. They may influence later model generation without being accepted causal diagnoses ([EPI-RTE-reviewer-extraction](#epi-rte-reviewer-extraction), [EPI-OBJ-candidate-summary](#epi-obj-candidate-summary), [EPI-OBJ-error-signatures](#epi-obj-error-signatures)). External task code enters as a starting artifact; source warrant for any factual claims in that code is unknown, not acquired merely by having a codebase. The reported trace-fed memory and retained harness rules can change future action independently of model-weight updates.

The robustness reminder is advisory. The short-code guard checks the length of generated task-solution code and re-prompts the inner generator; it does not admit outer harness successors ([MEM-OBJ-candidate-code](memory.md#mem-obj-candidate-code)). Length is only a proxy, not semantic acceptance. The penalty reportedly changes no selection. The scorer patch repairs failure propagation but does not certify evaluator integrity. Each retains its distinct force and limit ([RT-RTE-robustness-controls](runtime.md#rt-rte-robustness-controls)). No cleanup, claim withdrawal, false-acceptance rollback or claim-level integration protocol can be verified from this capture.

Reported held-out gains and reduced proxy/downstream divergence support bounded whole-harness outcomes, not component explanations. They are not evidence that the summary, reminder or error memory caused the gains. Harness-level learning and improvement are reported separately from theory-building, reflection and autonomy: numerical selection alone supplies no formulated content-directed criticism. Full method content and consumer dependence remain unavailable. Fixed model descriptions do not rule out learning through retained code, but provide no weight-learning evidence. The ignition comparison does not establish superior self-improver efficiency or acceleration ([RT-CLM-harness-improvement](runtime.md#rt-clm-harness-improvement), [EPI-RTE-heldout-comparison](#epi-rte-heldout-comparison), [RT-RTE-ignition-test](runtime.md#rt-rte-ignition-test)).
