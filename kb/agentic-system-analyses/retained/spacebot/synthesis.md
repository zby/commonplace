# Spacebot synthesis

## Bounded synthesis

Spacebot is an enclosing runtime for persistent conversational, delegated and background agent work. It owns message admission, model context, tool grants, worker supervision, retained state and outbound routing. This account covers its shipped functional loop at commit `5c2ee47b397e09c956dc15000ea576ecd28e92bb`, with an analysis cutoff of 2026-10-14. The evidence is source implementation and doctrine/design from SRC-1, not execution: no target tests, model calls, deployment traces or causal experiments were supplied or run. Whole-system scope does not mean exhaustive file inspection. Provider internals, external OpenCode and remote services are outside the frozen implementation boundary ([boundary](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)).

### From request to delegated effects

An inbound message is resolved to an agent and conversation channel. Code constructs the context, selects model routing and exposes tools; the channel model chooses its next action within those grants. Effects can include replies, task changes, filesystem work, subprocesses and remote calls. Branches receive copied conversation context and return conclusions. Built-in workers receive their own preambles, tools, task context and clean or forked history. Required skills supply full procedure bodies; suggested skills supply hints. Neither delivery path proves obedience ([RT-RTE-channel-turn](runtime.md#rt-rte-channel-turn), [RT-RTE-delegated-work](runtime.md#rt-rte-delegated-work), [RT-CLM-required-skills](runtime.md#rt-clm-required-skills)).

The representative workflow is task-bound, noninteractive built-in worker execution. It exposes three different admission decisions. First, spawning checks authoritative task status, live attempts and required-skill availability, then claims an attempt. Ready or InProgress can proceed; PendingApproval, Backlog and terminal tasks cannot. Second, dispatch attempts to commit a terminal outcome before emitting its normal completion event. The receiving channel rereads that durable result and checks versions, kind and owner before queuing it. Third, the result retriggers the channel model, which decides what to relay through permitted outbound paths. These checks establish execution permission and lifecycle consistency, not satisfaction of the user's requirements ([RT-RTE-delegated-work](runtime.md#rt-rte-delegated-work), [WF-RTE-completion-admission](workflow.md#wf-rte-completion-admission)).

Recovery is local rather than universal. A timeout can preserve available partial output; terminal commits have bounded retries; some retrigger failures retain pending results. Exhausted commits can suppress notification, other queue failures can drop pending results, and a model can skip relay. Completion, queue acceptance, outbound routing and actual user receipt are different milestones. No workflow execution or delivery receipt establishes their reliability here ([workflow account](workflow.md#workflow-account)).

Tool topology is not global containment. Direct channels and autonomy Act can expose execution tools outside workers. Task approval applies to task-bound execution, not every unbound, reference-only or direct action. OpenCode is started without Spacebot's sandbox wrapper, and its permission events receive automatic allowance rather than human veto. Configured sandboxing can fall back to unsandboxed subprocess execution. These are implemented scope limits, not observed exploits ([RT-CLM-role-grants](runtime.md#rt-clm-role-grants), [RT-RTE-opencode-work](runtime.md#rt-rte-opencode-work)).

### What survives and reaches later work

Spacebot retains distinct surfaces: typed claim text and selectors in per-agent SQLite, association graphs, dense retrieval indexes, temporal event narratives, durable conversation text, chronicle checkpoints, filesystem procedures and identity text, and instance-wide wiki versions. These parts do not have interchangeable authority. Prose informs models; fixed code interprets selectors and lifecycle state ([MEM-OBJ-memory](memory.md#mem-obj-memory), [MEM-OBJ-memory-metadata](memory.md#mem-obj-memory-metadata), [MEM-OBJ-retrieval-index](memory.md#mem-obj-retrieval-index), [MEM-OBJ-wiki-page](memory.md#mem-obj-wiki-page), [MEM-BAP-memory-selectors](memory.md#mem-bap-memory-selectors)).

Automatic context is a limited view. Global memory rendering selects first lines under fixed type, importance, recency and budget rules. Participant context separately matches human keys; temporal context supplies budgeted narratives and event tails. Explicit recall uses hybrid or metadata selection and returns deeper content to eligible consumers. In standard channel operation a branch mediates raw memory recall; direct and other configured processes can recall themselves. Requested recall and unsolicited context supply are separate routes ([MEM-RTE-context-supply](memory.md#mem-rte-context-supply), [MEM-RTE-memory-recall](memory.md#mem-rte-memory-recall)).

Context reduction also changes what remains recoverable. Rolling compaction leaves a session-live summary and recent tail. Chronicles retain durable summaries or explicit unsummarized coverage markers, then trim selected prefixes. Branches and workers keep private context out of the parent and return selective results. Durable conversation expansion reconstructs text, not original tool-call structures. A stored checkpoint or identifier therefore does not preserve the entire former model window. Failure markers and emergency cuts must not be counted as successful semantic summaries ([RT-RTE-context-control](runtime.md#rt-rte-context-control), [MEM-OBJ-conversation-log](memory.md#mem-obj-conversation-log), [MEM-RTE-chronicle-retention](memory.md#mem-rte-chronicle-retention)).

### Retention checks do not supply a truth oracle

Conversation persistence and file ingestion ask models to select useful statements. Save handlers validate structure and pipeline outcomes. The terminal contract compares reported IDs with successful saves and governs process completion; it does not check truth or extraction completeness. Model-produced statements may preserve, distort or extend their inputs; no actual input/output comparison establishes which occurred ([MEM-RTE-memory-admission](memory.md#mem-rte-memory-admission), [MEM-RTE-file-ingestion](memory.md#mem-rte-file-ingestion), [EPI-RTE-completion-contract](epistemic.md#epi-rte-completion-contract), [EPI-RTE-memory-extraction](epistemic.md#epi-rte-memory-extraction)).

Maintenance changes later reliance without necessarily judging propositions. Write-time consolidation advice arrives after saving; explicit batches replace survivors and withdraw absorbed rows. SQL commitment precedes warn-only vector upkeep. Similarity associations and contradiction weights alter ranking, not truth adjudication. Forgetting excludes ordinary retrieval but does not retract copied prompts or derived procedures. Wiki versioning preserves edits; its verification instruction is not an enforced evidence gate ([MEM-RTE-memory-curation](memory.md#mem-rte-memory-curation), [EPI-RTE-memory-selection](epistemic.md#epi-rte-memory-selection), [EPI-RTE-wiki-mutation](epistemic.md#epi-rte-wiki-mutation)).

Two source deductions show why deterministic processing alone cannot guarantee preserved meaning. First-line rendering can omit a necessary condition on a later line. Substring-based merging or byte clipping can suppress distinct content. These are code-supported counterexamples to general guarantees, not observed incidents. Accordingly, public claims of staleness-free context and write-time duplicate merging support narrower conclusions: a current store view and an advisory consolidation path, not current truth, complete content or unconditional merge-on-save ([EPI-RTE-memory-render](epistemic.md#epi-rte-memory-render), [EPI-RTE-memory-maintenance](epistemic.md#epi-rte-memory-maintenance), [EPI-CLM-memory-context](epistemic.md#epi-clm-memory-context), [EPI-CLM-write-consolidation](epistemic.md#epi-clm-write-consolidation)).

### Retained adaptation, reflection and autonomous work

The strongest supported improvement-related contribution is a wired, trace-fed procedure-change path. Eligible persistence branches can inspect conversation and worker records, decide whether a reusable lesson exists, write or patch skill files, reload them and supply procedures to later processes. The objective is reusable procedure improvement that avoids repeated procedural errors. Model abstention and structural/origin checks can reject changes, but there is no enforced procedural-correctness oracle. Agent-origin pin/read protections apply to that mutation protocol; User-origin, installation, API and generic file/shell paths have different controls ([RT-RTE-skill-change](runtime.md#rt-rte-skill-change), [RT-BAP-skill-instruction](runtime.md#rt-bap-skill-instruction)).

Conversation extraction, temporal synthesis and continuation summarization likewise wire automatic trace-fed retained outputs to later consumers. This is a supported adaptation capacity, including non-parametric changes, not demonstrated improved future capacity. Retaining summaries or procedures does not by itself show that criticism of a consumed theory improved future action ([MEM-RTE-temporal-synthesis](memory.md#mem-rte-temporal-synthesis), [MEM-RTE-chronicle-retention](memory.md#mem-rte-chronicle-retention), [RT-RTE-skill-change](runtime.md#rt-rte-skill-change)).

The procedure route's independent assessments are:

- **Theory-builder condition 1, localized content:** afforded architecturally through whole procedure bodies and replacement; particular formulated theory content is uninspected.
- **Condition 2, content-dependent consumption:** operation uninspected. Instruction supply is wired, but dependent decisions are not observed.
- **Condition 3, content-directed criticism:** claimed in reflection guidance. Formulated criticism with blame placement is not demonstrated.
- **Condition 4, iteration:** operation uninspected. Reload permits another round, but no retained criticism is shown shaping it.
- **Reflection:** the architecture wires records of its own operation into a writer that can change later instructions. Exercise and quality of both causal directions remain unobserved.
- **Self-improvement:** improvement-directed self-change capacity is supported at the skill surface across sessions. No supplied run closes the four links from objective-bearing evidence to a particular update, accepted self-change, live consumption and causally dependent behavior. Exercised or successful self-improvement is not established.

These conclusions follow the separate assessments in [RT-RTE-skill-change](runtime.md#rt-rte-skill-change), not an inference from one property to another. Autonomous operation has its own wired route: a supervisor admits resident-channel epochs under the lesser of agent level and instance ceiling, pause and scheduling/wake conditions, then supplies briefings and level-dependent tools. This supports autonomous work capacity, not observed useful work, reliable criticism or an autonomous theory builder ([RT-RTE-autonomy-epoch](runtime.md#rt-rte-autonomy-epoch)).

For persistent conversational assistance, the supported architectural contribution is continuity through selective context and delegated work. For task delivery, permission and durable-result consistency are stronger than semantic verification or receipt guarantees. For procedure improvement, source wiring supports a candidate self-change mechanism, while the public claim that use makes the system better remains untested. The shipped behavioral fixtures evaluate first-action routing with a four-of-five threshold, not final task correctness or the effect of a changed procedure ([EPI-CLM-better-use](epistemic.md#epi-clm-better-use), [EPI-RTE-behavioral-fixtures](epistemic.md#epi-rte-behavioral-fixtures)).

A retained before/after procedure, its source evidence and criticism, subsequent prompt consumption and dependent task outcomes would materially change the learning assessment. An intervention varying that procedure against an appropriate comparison would support attribution at that level. Failure/restart traces and delivery receipts would change the workflow assessment. Implemented semantic acceptance, derivative withdrawal or deployment-wide containment would alter different conclusions and would require their own route evidence. No single missing evaluator or trace decides all these properties.
