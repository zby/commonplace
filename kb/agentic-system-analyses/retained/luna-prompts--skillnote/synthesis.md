# SkillNote synthesis

## Bounded synthesis

SkillNote is a self-hosted procedural registry: authors retain reusable skill descriptions and bodies, and shipped adapters make them available to external agents. Its strongest supported feedback contribution is narrower than its improvement claims: retained usage and comments can change the order and membership of a later candidate response without rewriting a procedure. Whether that improves future task capacity remains unresolved. The claims that agents learn repeated patterns and that the registry improves over time are doctrine, not demonstrated outcomes. See [EPI-CLM-pattern-learning](epistemic.md#epi-clm-pattern-learning), [EPI-CLM-registry-improves](epistemic.md#epi-clm-registry-improves) and [MEM-RTE-feedback-catalog](memory.md#mem-rte-feedback-catalog).

The evidence is SRC-1, the SkillNote repository at commit `7ea2fc7a8435af64d1c080d8765c0eabba1121ea`, with an applicability cutoff of 2026-10-14. The whole-system boundary includes browser authoring, backend state, imports and archives, CLI maintenance, host hooks, OpenClaw instructions, MCP, the claude.ai connector and feedback. It is code-grounded but selectively inspected. External hosts, their models and context semantics, remote source/package bytes and deployed state are not frozen. No target execution, host transcript, actual skill corpus or causal experiment was supplied. Thus implementation and policy can be characterized, but successful operation and benefit cannot. See the [boundary and Source register](boundary.md#boundary-and-evidence).

### From a convention to retained guidance

The representative workflow turns a persistent convention into a reviewed registry skill, then distributes it to a configured Claude Code project. An explicit user request starts authoring; for unsolicited creation, the skill-push prompt requires permission before drafting. An optional inherited-model skill-creator role can draft and check trigger quality, brevity and examples. Its availability does not establish a mandatory specialist launch, fixed handoff or isolated child return. The foreground author checks slug existence, offers collection choices, shows a complete preview and requests approval before POST or PATCH. Invalid collection names are surfaced for user correction; a slug collision directs the author toward PATCH. The delivered authoring result is committed registry content and a viewing link, not a completed later task. See the [workflow account](workflow.md#workflow-account) and [RT-RTE-registry-write](runtime.md#rt-rte-registry-write).

User review and backend admission are different gates. Review is a host-followed natural-language policy, with trigger suitability as a named criterion; it is not observed truth acceptance. Backend schema, collection and conflict checks can reject structurally invalid writes, but receive no required approval receipt or independent task oracle. Direct callers, imports, archives and connector policies have other admission paths. Moreover, report verification found a separate synchronous prompt-watch hook that retains pending sentence drafts automatically and emits authoring pointers. No automatic later draft-adoption chain was established. Consequently, the approval policy cannot be generalized to every draft or registry write. See [RT-RTE-registry-write](runtime.md#rt-rte-registry-write), [EPI-OBJ-skill-push](epistemic.md#epi-obj-skill-push) and the [report-verification limits](report-verification.md#limits).

Current skill rows hold natural-language descriptions and instructions alongside symbolic IDs, collections and source fields. Saving creates a content snapshot; restore creates another snapshot, while set-latest reselects an existing one. History omits extra frontmatter and origin fields and does not require an edit rationale. Published ZIPs are independent retained products, not interchangeable with Markdown snapshots. Browser-local fallback can survive an API error without registry admission. Reverse import can stage a non-current body, automatically adopt it under policy, or expose a resolution choice; rejecting staged content can delete its bytes while preserving an audit identifier. These distinctions determine what can be restored, distributed or inspected later. See [MEM-OBJ-skill](memory.md#mem-obj-skill), [MEM-OBJ-content-version](memory.md#mem-obj-content-version), [MEM-OBJ-skill-version](memory.md#mem-obj-skill-version) and [MEM-RTE-inbound-resolution](memory.md#mem-rte-inbound-resolution).

### From retention to a later agent

SkillNote owns database, HTTP, archive and file operations, not the enclosing task loop. For Claude Code, hooks fetch collection-filtered current rows and write transformed SKILL.md files plus a manifest into project discovery paths. Collection matching selects content before host discovery; wildcard supply is untargeted. Codex has a related handler with its own project lock and stdout policy. MCP instead exposes current rows as named tools and returns requested instruction text. CLI add and update install selected active archives, or generated current bundles for never-published skills, through agent adapters. Checksum and archive-entry checks constrain bytes and extraction, not procedure correctness or the agent's subsequent actions. The browser connector uses queued operations and a logged-in browser session for remote delivery, with best-effort group retirement. See [RT-RTE-project-sync](runtime.md#rt-rte-project-sync), [RT-RTE-mcp-delivery](runtime.md#rt-rte-mcp-delivery), [RT-RTE-bundle-install](runtime.md#rt-rte-bundle-install), [MEM-RTE-install-maintenance](memory.md#mem-rte-install-maintenance) and [RT-RTE-browser-sync](runtime.md#rt-rte-browser-sync).

At the eventual task consumer, prose is guidance interpreted under an external host's instruction hierarchy, not a SkillNote-enforced task invariant. The host chooses what to read and do. OpenClaw's shipped instructions request description-first matching, ordinarily at most three matches and never more than five loaded bodies. These are policy body-count limits, not enforced token budgets. User consent attaches its sidecar to AGENTS. Subagent and compaction hooks supply pointers or catalog reminders rather than a retained task-reasoning summary; model-visible PostCompact delivery remains unresolved. Neither the context-bundle resolver docstring nor the optional authoring specialist establishes an executed isolated work frame. See [RT-BAP-host-instructions](runtime.md#rt-bap-host-instructions), [RT-CMP-host-model](runtime.md#rt-cmp-host-model), [RT-RTE-openclaw-use](runtime.md#rt-rte-openclaw-use) and [RT-RTE-context-hooks](runtime.md#rt-rte-context-hooks).

### Feedback changes availability, not warrant

Completion prompts ask the host for ratings and outcomes. Code checks score ranges and some references; it does not independently verify task success. Comments, ratings and usage events have separate stores and consumers. Rated agent comments also create rating rows, but deleting a comment does not retract that fan-out in the inspected handler. The watcher extracts skill-file reads from host logs into analytics and retains replay state; a read is not proof of application, and those call events are not the usage-event store counted by the context bundle. See [RT-RTE-feedback-report](runtime.md#rt-rte-feedback-report), [EPI-RTE-comment-check](epistemic.md#epi-rte-comment-check), [MEM-OBJ-comment](memory.md#mem-obj-comment), [EPI-RTE-rating-admission](epistemic.md#epi-rte-rating-admission) and [MEM-RTE-trace-reporting](memory.md#mem-rte-trace-reporting).

On a context-bundle request, the server takes an alphabetic window of four times the requested size, orders it by 30-day usage, comment-rating mean and name, then truncates it. The request's task summary does not enter this ranking. Any deprecation warning or low mean yields needs_review; no warning or rating can still yield healthy. These labels classify stored reports, not semantic correctness, and do not withdraw a skill. Only the latest comment's first 200 characters are delivered. Arithmetic conclusions concern retained rows, whose outcome truth remains unchecked. A deployed resolver consumer and successful task matching are unestablished. An additional prompted large-catalog consumer uses analytics top-skills, whose call-count and SkillRating aggregates differ from the bundle's Comment means; the bundle is therefore not the only feedback surface. See [EPI-RTE-bundle-metadata](epistemic.md#epi-rte-bundle-metadata), [EPI-RTE-bundle-selection](epistemic.md#epi-rte-bundle-selection), [MEM-RTE-feedback-catalog](memory.md#mem-rte-feedback-catalog) and the [report-verification limits](report-verification.md#limits).

Feedback-dependent selection is implemented capacity. It does not establish accepted new truth, automatic procedure correction, weight learning or improved future-action capacity. The bundle is recomputed rather than retained as a durable derived procedure. Unknown evaluation consumers and caller/payload production prevent a complete negative about trace learning. Separately, reliable reflection and autonomous content criticism remain unestablished. The runtime supplies no condition-by-condition theory-builder assessment: storage and delivery do not establish consumption of a formulated theory, content-directed criticism or iteration, and no corpus resolves which skill contents qualify as theories. Conditions 1–4 therefore cannot be affirmed collectively or treated as collectively absent. Nor is there evidence that criticism of a consumed theory improved future capacity. See the [epistemic bounded conclusion](epistemic.md#bounded-conclusion), [MEM-OBJ-content-version](memory.md#mem-obj-content-version) and [profile verification](profile-verification.md#verification).

The OpenClaw adapter has an automatic update route, but unequal version strings and installation are not an improvement experiment. No independently assessed objective or subsequent operation causally dependent on an evidence-shaped organizational change is established. Exercised self-improvement and successful improvement therefore remain unestablished independently of feedback ranking, reflection and autonomy. See [RT-RTE-adapter-update](runtime.md#rt-rte-adapter-update).

### Maintenance and scenario-relative assessment

For the scenario of retaining a reviewed team convention and making it discoverable in later configured projects, the source supports persistence, collection scoping and delivery machinery. It does not support assured host application. For the scenario of withdrawing a harmful procedure everywhere, controls are narrower: disabled archives block covered downloads, but current-row MCP and cached copies can remain available. CLI update can skip a withdrawn release without deleting its installation. Sync guards preserve caches on some empty or failed responses, while the interactive picker can independently delete managed files. Neither uniform freshness nor universal revocation follows. Git re-import can change metadata without replacing a same-source body, and refresh apply is a stub. See [RT-RTE-bundle-install](runtime.md#rt-rte-bundle-install), [MEM-RTE-install-maintenance](memory.md#mem-rte-install-maintenance), [RT-RTE-project-sync](runtime.md#rt-rte-project-sync), [RT-RTE-source-import](runtime.md#rt-rte-source-import) and the [report-verification limits](report-verification.md#limits).

The assessment would change with linked authoring, approval, synchronization and host-use traces identifying the actual consumed versions; complete cleanup and feedback-consumer tracing; and comparisons that independently vary feedback or revised guidance against a declared task objective. Demonstrating content-directed criticism requires the challenged claim, evidence, blame placement and resulting revision or changed reliance, followed into a next round. Demonstrating improvement requires evidence of better future capacity at the comparison's actual scope, not merely saved feedback or a replaced file. These additions would address the gaps in [RT-RTE-registry-write](runtime.md#rt-rte-registry-write), [RT-BAP-host-instructions](runtime.md#rt-bap-host-instructions), [EPI-RTE-bundle-selection](epistemic.md#epi-rte-bundle-selection) and [RT-RTE-adapter-update](runtime.md#rt-rte-adapter-update).
