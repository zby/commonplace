# Qiju synthesis

## Bounded synthesis

### From a session to a retained account

Qiju is a local session-record system for coding agents, not an agent orchestrator. It supplies a Python CLI and portable log, search and review skills for external hosts such as Claude Code, Codex, Kiro and Cursor. This analysis covers the whole shipped record loop, including those instructions, at SRC-1 commit `a5ea9db29262ce7ec514cdc1dc5c5d017a6a3f89`, with cutoff 2026-11-08. Its evidence is inspected implementation and doctrine/design. No actual store, host trace or causal experiment was supplied. Host orchestration, model internals, permissions and skill discovery remain external; source wiring is not observed handoff success ([boundary](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)).

The representative workflow is a requested checkpoint followed by a later history question. It is supported by connected capture and retrieval paths, not by joining unrelated capabilities or by an execution trace. The user supplies the checkpoint scope. The foreground host composes JSON through a temporary file and invokes log; Qiju then owns deterministic admission and persistence. The installed instructions ask for completed work, agreed next steps, rejected and undecided alternatives, artifact anchors and reasons not recoverable from files. This can preserve process knowledge that a code snapshot alone would omit, but it preserves a selected account rather than automatically acquiring the original conversation ([workflow account](workflow.md#workflow-account), [RT-RTE-record-capture](runtime.md#rt-rte-record-capture), [MEM-OBJ-body-md](memory.md#mem-obj-body-md)).

Capture normalizes metadata, repairs malformed or missing timestamps, redacts six named fields, checks schema and appends absent short/long copies under a shared home lock. A conflicting explicit project is rejected when a valid authoritative marker exists; markerless explicit projects and environment-root selection remain supported alternatives. Project selection is routing, not authenticated access control. The host/caller owns correction and retry after rejection. Staging cleanup follows successful capture and can refuse deletion with a warning without retracting the returned record ID ([RT-RTE-record-capture](runtime.md#rt-rte-record-capture)).

These checks admit structurally valid history, not verified historical truth. Schema validation consumes types and metadata, not evidence that an action or agreement occurred. A user asking for a checkpoint does not approve each sentence, and the source label `manual` does not establish human authorship. Installed guidance nevertheless asks the host to privilege records as verified history. Artifact anchors and explicit decision statuses make checking possible and constrain requested composition, but no inspected factual-acceptance step closes that gap ([EPI-RTE-shape-check](epistemic.md#epi-rte-shape-check), [EPI-RTE-shape-admission](epistemic.md#epi-rte-shape-admission), [EPI-CLM-verified-history](epistemic.md#epi-clm-verified-history), [RT-BAP-host-guidance](runtime.md#rt-bap-host-guidance)).

### Persistence and later selection

Record bodies, plans, descriptors and metadata share local JSONL and monthly Parquet files. Their effects differ: bodies supply interpreted history; next steps supply potential directions; timestamps, project names and IDs drive fixed filtering, ordering and copy-admission rules. Optional caller fields can survive capture without their meaning or provenance becoming known ([MEM-OBJ-body-md](memory.md#mem-obj-body-md), [MEM-OBJ-next-steps](memory.md#mem-obj-next-steps), [MEM-OBJ-search-descriptors](memory.md#mem-obj-search-descriptors), [MEM-OBJ-address-metadata](memory.md#mem-obj-address-metadata)).

Retention is not semantic distillation. Explicit maintenance removes old short copies, sweeps stale staging and moves eligible long records into archives; archived history remains a normal retrieval input. Row-count and ID-set checks guard archive replacement, not every field's semantic equivalence. Sequential short/long appends are not one transaction. Retrying the same explicit ID can fill a missing tier, but existing copies are skipped without payload comparison, and an archived ID returns immediately. Short rotation does not check that a surviving copy exists after an earlier partial append. Thus the source supports preservation mechanisms, not universal losslessness or tested recovery ([RT-RTE-store-maintenance](runtime.md#rt-rte-store-maintenance), [RT-RTE-record-capture](runtime.md#rt-rte-record-capture), [memory maintenance annotation](memory.md#annotations), [RT-CLM-lossless-records](runtime.md#rt-clm-lossless-records)).

On a later question, the host requests search with scope, dates, metadata, tags or literal/regex terms. Keyword matching is deterministic OR matching, not semantic relevance ranking. The skill recommends a small candidate manifest followed by exact-ID hydration. This can keep bodies outside the model window until selected, while preserving an explicit reload address. It is not enforced: default search returns full records and show can be invoked directly. Limits and projections shape output, not a measured token budget or an indexed-performance guarantee. Qiju neither evicts accumulated host turns nor creates an isolated worker context ([RT-RTE-record-retrieval](runtime.md#rt-rte-record-retrieval)).

What reaches the host matters. Summary supplies stored title and locators, not a generated narrative summary or retained reasons. Full show can return reasons; actions omits them and the exact ID. The actions renderer deduplicates strings and prints unchecked tasks without consulting later body text for completion. It therefore establishes that an item appeared in selected plans, not that it remains open. Time/project checks, widened fallback and recovery of incomplete IDs are requested host conduct, not final-answer gates. Qiju delivers CLI data; the host owns the history answer or resumed action, with no supplied acknowledgement of correct downstream use ([MEM-BAP-record-history](memory.md#mem-bap-record-history), [EPI-RTE-action-rollup](epistemic.md#epi-rte-action-rollup), [workflow account](workflow.md#workflow-account)).

### From history to proposed method changes

The strongest supported experience-based contribution is the checkpoint route itself: the requested host computation selects session experience into a durable account, software admits it without per-content human approval, and later retrieval can supply that account as context. This supports an afforded trace-fed behavior-shaping route, including conversational session material. It does not show faithful extraction, exercised learning or improved future capacity. Generic caller and legacy inputs remain unresolved alternatives, and tool use alone does not establish tool-trace or trajectory inputs ([RT-RTE-record-capture](runtime.md#rt-rte-record-capture), [MEM-OBJ-body-md](memory.md#mem-obj-body-md), [MEM-BAP-record-history](memory.md#mem-bap-record-history), [profile verification](profile-verification.md#verification)).

A separate retrospective procedure asks the external host to inspect recent summaries, hydrate relevant records, diagnose recurring or high-impact mistakes and propose targeted skill wording. It cautions against invented details and misplaced blame. It affords evidence-sensitive method criticism, not just a log display. Application requires an explicit user request under the instruction policy; Qiju does not enforce that permission through a CLI veto. Recommendations have no wired durable queue, actual edits and later loading are not supplied, and direct init/update replaces skills from bundled package text independently of retrospective findings. Backups do not prove that local lessons remain active ([RT-RTE-skill-review](runtime.md#rt-rte-skill-review), [RT-RTE-skill-install](runtime.md#rt-rte-skill-install), [EPI-CLM-review-improvement](epistemic.md#epi-clm-review-improvement)).

The runtime separates the relevant properties rather than assigning a grade:

- **Theory-builder condition 1, localized content:** afforded at whole-guidance/proposed-wording granularity; actual reviewed theory content is uninspected.
- **Condition 2, consumption:** claimed; requested decisions depend on guidance's failings, but actual dependence is not observed.
- **Condition 3, content-directed criticism:** afforded by requests to identify unclear, missing or counterproductive instructions and distinguish alternative causes; actual claim-specific criticism and changed reliance are not supplied.
- **Condition 4, iteration:** uninspected; no retained criticism shown to shape a next round. The conditions therefore do not establish a functioning theory builder.
- **Improved future capacity from criticism of consumed guidance:** uninspected, not established by retained history, recommendations or edits alone.
- **Reflection:** afforded for the host-plus-guidance pathway, in which operation records can represent mistakes and guide changes affecting later work; actual bidirectional use is unobserved.
- **Autonomous theory building:** uninspected; full computational performance of the internal operations is not evidenced, while application expressly requires user authorization.
- **Self-improvement:** the host-plus-installed-guidance pathway affords improvement-directed proposals toward preventing repeated mistakes and unclear instructions across sessions. Evidence shaping an actual admitted update, that update entering live authority, and later operation causally depending on it remain unestablished. Neither exercised self-improvement nor successful improvement is demonstrated.

These are the separate findings of [RT-RTE-skill-review](runtime.md#rt-rte-skill-review); the afforded checkpoint trace-fed route does not upgrade any of them.

### Scenario-relative assessment

For a deliberately recorded checkpoint and a later question with useful scope or search terms, Qiju implements addressable local history with optional delayed body loading. For recovering an unrecorded decision, establishing that a plan is still pending, or treating a retrieved narrative as factually accepted, those mechanisms do not supply the missing evidence. For preventing recurring mistakes, it supplies a structured review-and-proposal procedure, not demonstrated beneficial adaptation ([RT-RTE-record-retrieval](runtime.md#rt-rte-record-retrieval), [EPI-RTE-action-rollup](epistemic.md#epi-rte-action-rollup), [EPI-CLM-verified-history](epistemic.md#epi-clm-verified-history), [RT-RTE-skill-review](runtime.md#rt-rte-skill-review)).

Linked capture/retrieval traces would change the assessment of exercised handoff and rationale receipt. An evidence-consuming historical check would change the warrant assessment. A retained critique, authorized edit and later behavior trace would address iteration and live use; objective-based outcome comparisons would be needed separately for benefit, with attribution no finer than the intervention compared. Transactional persistence or verified surviving-copy controls would change the preservation assessment. None of those changes follows from source inspection alone.
