# Synthadoc synthesis

## Bounded synthesis

### From source documents to retained pages

Synthadoc is a knowledge system that compiles source documents into a local Markdown wiki, maintains the wiki and supplies retained content to later questions and external consumers. This account covers its shipped server, CLI, browser and Obsidian clients, MCP integration, maintenance instructions and exported-bundle consumer at Git revision `b80d9388a3013e8051baf2854c7250942c46e91a`, with an applicability cutoff of 2026-10-15. The whole-system boundary is functional scope, not a claim that every file or alternative received exhaustive inspection. SRC-1 supplies code and attributed design only: no target execution, production corpus, provenance-linked run trace or causal experiment was adopted. External providers and enclosing hosts are not Synthadoc's inspected implementation. See [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

There is no single universal agent loop. Python owns a queue-driven compilation pipeline, returning answer computations and a separate model-directed maintenance loop. An ordinary ingest request returns a job ID. A worker later extracts source text, clips and sanitizes it, obtains model analysis, retrieves up to five old-page snippets and obtains a create/update/flag/skip proposal. Python dispatches the proposal into page or candidate writes, provenance, audit and index changes. A queued result is therefore not yet a completed wiki, and a persisted draft is not yet eligible for ordinary search ([RT-RTE-source-ingest](runtime.md#rt-rte-source-ingest)).

The persistent knowledge product is readable page prose, distinct from parsed lifecycle and provenance fields. Extracted sidecars precede ingest sanitization and clipping; they are not necessarily verbatim originals because extraction may already transform content. SQLite retains chat, snapshots, cached computations and answers; stored numerical page vectors rerank lexical candidates rather than constitute model-weight training. These parts have different consumers and authority ([MEM-OBJ-page-content](memory.md#mem-obj-page-content), [MEM-OBJ-page-metadata](memory.md#mem-obj-page-metadata), [MEM-OBJ-source-sidecars](memory.md#mem-obj-source-sidecars), [MEM-OBJ-search-vectors](memory.md#mem-obj-search-vectors), [MEM-BAP-retained-content](memory.md#mem-bap-retained-content)).

Admission is route-specific. Optional staging can retain proposed pages for promotion or discard, but defaults to off; existing-page force paths bypass it and flagging writes directly. Candidate promotion moves a file and may leave it draft. Automatic lint can activate drafts or model-reconciled pages; direct MCP replacement can preserve an already-active state. Thus neither staging nor active status establishes universal human review. This matters because the ingest prompt asks the model to treat active pages as human-reviewed authority ([RT-RTE-candidate-admission](runtime.md#rt-rte-candidate-admission), [EPI-RTE-lifecycle-admission](epistemic.md#epi-rte-lifecycle-admission), [RT-RTE-lint-repair](runtime.md#rt-rte-lint-repair), [RT-RTE-client-write](runtime.md#rt-rte-client-write), [EPI-CLM-active-review](epistemic.md#epi-clm-active-review)).

### Checks change permissions without supplying one truth guarantee

Synthadoc has consequential checks, but their domains differ. Structural citation lint checks marker shape, source membership and available line counts. Annotation itself can accept structurally screened model text or fall back to an unannotated original; it does not guarantee every claim is cited or that the prose is unchanged. Adversarial lint asks a model to criticize a truncated page without complete raw-source evidence. An optional positive warning threshold can demote active/stale pages and block automatic resolution, but unchanged cached pages skip demotion reapplication. Empty warnings can also follow parsing or provider failures. These are real reporting and restriction mechanisms, not reliable proofs of factual correctness ([EPI-RTE-citation-annotation](epistemic.md#epi-rte-citation-annotation), [EPI-RTE-structural-citations](epistemic.md#epi-rte-structural-citations), [EPI-RTE-adversarial-review](epistemic.md#epi-rte-adversarial-review), [EPI-RTE-warning-gate](epistemic.md#epi-rte-warning-gate)).

Semantic citation auditing does compare an extracted claim fragment with cited sidecar lines against a support criterion. Its fallible model verdicts and short reasons feed later review displays, stale-only audit selection and CLI exit status. They do not automatically demote or rewrite the page, certify the source's truth or accept all of the page's claims. Freshness keys use source-ingestion timestamps rather than exact body identity. This supports scoped evidence-consuming assessment, not the public promise of invariant claim-level warrant ([EPI-RTE-faithfulness-audit](epistemic.md#epi-rte-faithfulness-audit), [MEM-OBJ-faithfulness-cache](memory.md#mem-obj-faithfulness-cache), [EPI-CLM-citation-coverage](epistemic.md#epi-clm-citation-coverage)). Without actual input/output comparisons, general compilation and answering remain semantically indeterminate: neither checked derivation nor novel conjecture is established merely by calling them synthesis. The inspected routes do not establish acceptance and subsequent integration of a produced ampliative claim; this is not a system-complete negative about unassessed routes ([epistemic bounded conclusion](epistemic.md#bounded-conclusion)).

### Later questions receive selected memory, not the entire wiki

Ordinary query retrieves active/stale pages through BM25 and optional vector reranking, then budgets text for model synthesis. Streaming and blocking constructors differ in routing delivery. Help or live context can replace wiki context. The initial citation list can include retrieved pages omitted or truncated before synthesis, so a citation identifier is not verified answer support. Cached answers can bypass new synthesis, with keys that omit session/history ([RT-RTE-wiki-query](runtime.md#rt-rte-wiki-query), [MEM-OBJ-response-cache](memory.md#mem-obj-response-cache)).

Local session queries automatically reload a recent raw tail. Older turns may be summarized and retained, but that summary is not supplied to synthesis in the inspected handler. Character budgets and question-relative language filtering further remove turns; raw-tail selection and trimming are not an exhaustive eviction inventory. Separate model calls isolate selected inputs and return values rather than inherit all preceding text. Omitted files remain reachable through explicit reads, not by automatic dereferencing of slugs ([MEM-RTE-session-context](memory.md#mem-rte-session-context), [report verification limit](report-verification.md#limits)).

Other consumers have different eligibility and budgets. Context packs return first-120-word excerpts; cross-wiki retrieval requires active pages and merges budgeted peer results; default OKF export includes active and contradicted pages. The shipped bundle consumer loads sorted, type-filtered exported files under a character cap, not live question-relative retrieval. Exports are separate snapshots. Requested knowledge delivery coexists with automatic history and standing purpose/control supply; automatic ranking within a requested return is not itself unsolicited memory delivery ([RT-RTE-context-export](runtime.md#rt-rte-context-export), [MEM-RTE-cross-wiki](memory.md#mem-rte-cross-wiki), [MEM-RTE-scaffold-guidance](memory.md#mem-rte-scaffold-guidance), [MEM-RTE-session-context](memory.md#mem-rte-session-context)).

### Representative maintenance: structural repair with scoped veto and recovery

The content-health resolver provides one connected workflow from request to persistent edit and streamed delivery. Python pre-discovers flagged active pages; the model receives slugs, fixed guidance and tool results, reads page bodies and proposes repairs. Registered replacement calls require a successful prior read, membership when the discovery set is nonempty, and accepted client confirmation. The gate resets per call. Confirmation is an enforced protocol on that path, not authenticated human authorship or approval bound to exact replacement bytes ([WF-RTE-content-health](workflow.md#wf-rte-content-health), [RT-CLM-confirm-scope](runtime.md#rt-clm-confirm-scope)).

The helper snapshots the old body, replaces it, retains fix metadata and rescans structural heuristics. Remaining issues update metadata but do not veto the write. Dismissal is a separate ungated metadata operation. Later rollback reloads the fix record and snapshot, with positional fallback if stable-ID resolution fails. Parse retries and tool budgets bound the loop; budget exhaustion does not undo prior effects. Plain text ends the loop and leads to streamed completion, without an independent reconciliation of the claimed result against every discovered task. This establishes implemented delegation, veto, compensating recovery and delivery—not successful factual preservation or completed corpus repair ([WF-RTE-content-health](workflow.md#wf-rte-content-health), [MEM-RTE-health-history](memory.md#mem-rte-health-history)).

This registry is not a system-wide effect boundary. Coding-tool providers have a distinct execution path and can launch a child agent with permission skipping; imported Python skills and configured shell hooks are further executors. Local page-root checks do not sandbox their effects. Schedules trigger commands rather than supply independent semantic decisions ([RT-RTE-provider-delegation](runtime.md#rt-rte-provider-delegation), [RT-RTE-extension-loading](runtime.md#rt-rte-extension-loading), [RT-CLM-effect-boundary](runtime.md#rt-clm-effect-boundary), [RT-RTE-scheduled-operation](runtime.md#rt-rte-scheduled-operation)).

### Assessment relative to retained knowledge and future action

For compiling a revisable corpus and returning selected retained content, the records establish connected implementation paths, including optional review, differentiated checks and explicit recovery. For maintaining factual accuracy, complete source-linked answers or comprehensive withdrawal, those paths do not establish the stronger guarantees: operational admission exceeds demonstrated factual acceptance, selectors omit material and masking does not erase every retained copy. These distinctions qualify the public accuracy-through-self-optimization claim without turning the system into a single epistemic grade ([EPI-CLM-accuracy-optimization](epistemic.md#epi-clm-accuracy-optimization), [MEM-RTE-sensitive-mask](memory.md#mem-rte-sensitive-mask)).

The strongest supported trace contribution is imported-session compilation: filtered recorded user/assistant turns can feed automatic durable wiki writes with later eligible answer consumers. That is wired trace learning in the write-route sense, not measured improvement. Tool results and thinking blocks are excluded; neither verified operational experience nor autonomous ingestion of every interaction follows. Stored overflow summaries do not establish a second semantic learning chain ([MEM-RTE-session-ingest](memory.md#mem-rte-session-ingest), [MEM-RTE-session-context](memory.md#mem-rte-session-context)).

Improved capacity for future action, including improvement caused by criticism of a consumed theory, remains unestablished. Theory-builder conditions remain separate unresolved questions: **1**, page and guidance text are localized, but formulated explanatory-theory content is not established by their labels; **2**, delivery and dispatch do not demonstrate decisions depending on such a theory's content; **3**, warning production and state changes do not establish the required theory-directed criticism and placement of blame; **4**, retained warnings and later consumers do not independently establish iterative theory criticism. Reflection, autonomous theory-building and reflective theory-building are likewise unestablished, not evidenced absent. Automatic proposals, state transitions and tool choice establish local computational control, not autonomy of every internal operation ([epistemic bounded conclusion](epistemic.md#bounded-conclusion), [RT-BAP-workflow-guidance](runtime.md#rt-bap-workflow-guidance)).

For self-improvement, the assessed boundary is wiki maintenance across later invocations and the independent objective is accurate retained content. Warning evidence can determine lifecycle changes that reach subsequent search eligibility: this is an implemented improvement-directed self-change pathway. No observed subsequent operation establishes causal dependence on that change, and no outcome comparison establishes success. Product revision alone neither proves nor disproves self-improvement; broader guidance-revision routes remain incompletely assessed. The AquaFlow evaluator supplies substring-coverage scores, not semantic correctness or component attribution ([EPI-RTE-warning-gate](epistemic.md#epi-rte-warning-gate), [EPI-RTE-answer-evaluation](epistemic.md#epi-rte-answer-evaluation), [epistemic bounded conclusion](epistemic.md#bounded-conclusion)).

The assessment would change with provenance-linked source/page/answer instances, check and disposition traces, and later consumer traces showing what survived selection and influenced action. A controlled comparison with a semantic accuracy criterion could establish benefit at the varied system level; component attribution requires independently varying that component. Exact-content approval binding, content-sensitive audit keys or coordinated invalidation could strengthen specific guarantees, but would require new implementation evidence and, for operational claims, exercised traces. No source reads were added during this synthesis.
