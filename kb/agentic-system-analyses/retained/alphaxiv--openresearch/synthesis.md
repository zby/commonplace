# OpenResearch synthesis

## Bounded synthesis

OpenResearch is a local research workspace that coordinates installed coding agents, experiment branches, asynchronous compute and retained evidence. This account covers the repository's shipped software at commit `2c45ff3183b494aac4001bd44eefbe57a3c249ae`, with an applicability cutoff of 2026-10-20. The whole-system boundary includes the desktop/UI callers, standalone CLI, host, adapters, instructions and state consumers. Its evidence is SRC-1 implementation and doctrine/design, not a newly executed workflow or causal experiment. External harness internals, model services and compute-provider implementations are outside the inspected implementation boundary. Included but unassessed paths remain coverage limits, not exclusions or evidence of absent behavior ([boundary](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)).

The shipped assignment spans ideation, literature review, hypothesis formulation, experiment execution and artifacts. The discriminating architecture is the division of responsibility: OpenResearch owns session admission, persistence and process supervision; the nested coding agent owns semantic decisions; the project's program supplies measurements; the foreground model is instructed to judge what those measurements support. Tools enabling that assignment do not establish successful science ([RT-CLM-research-assistance](runtime.md#rt-clm-research-assistance), [EPI-CLM-results-evidence](epistemic.md#epi-clm-results-evidence)).

### From a project request to an executable experiment

A UI/API message reaches ChatHost, which starts or durably queues the turn and dispatches the selected harness. In the inspected Claude path, a private Git worktree, rendered project playbook and skill folders prepare the session. Native context is resumed where available; missing native context can instead receive a lossy ORX transcript snapshot. The model then chooses tools and text. On return, normalized events and assistant output are persisted and presented to the UI. Startup reconciles unfinished turns and resumes queues; these are implemented continuity mechanisms, not proof of exactly-once external effects ([RT-RTE-chat-turn](runtime.md#rt-rte-chat-turn)).

The playbook supplies natural-language directions and changing orientation facts, including experiment/run counts, rather than full research evidence. For Claude, rewriting its file each turn does not establish that a resident child rereads it: appended system guidance enters at spawn/respawn. Optional model names do not pin immutable weights, and provider parameter changes remain uninspected ([RT-OBJ-playbook](runtime.md#rt-obj-playbook), [RT-BAP-playbook-injection](runtime.md#rt-bap-playbook-injection), [RT-CMP-claude-model](runtime.md#rt-cmp-claude-model), [RT-CMP-codex-model](runtime.md#rt-cmp-codex-model)).

Permissions are route-specific. Claude bridge requests receive token/busy-turn checks and mode-dependent allow, deny or human review. Codex Plan uses a different policy mapping, including workspace-write. A separate shipped operator-shell endpoint runs Bash without consulting model permission mode. This is a reachable human mutation path, not a demonstrated model exploit. Neither Plan nor a private worktree is a system-wide read-only or OS-sandbox guarantee; bridge enforcement also depends on native runtime cooperation ([RT-RTE-permission-review](runtime.md#rt-rte-permission-review), [RT-RTE-user-shell](runtime.md#rt-rte-user-shell)).

For literature work, discovery and paper commands import attributed external material. Ranking and source identifiers help locate candidates, not certify their claims. The default alphaXiv report is not original text suitable for quotation; instructions request reading original evidence. OpenAlex token-position reconstruction preserves reading order only under its stated input assumptions. Neither import nor this reshaping establishes new accepted scientific knowledge ([EPI-RTE-literature-import](epistemic.md#epi-rte-literature-import), [EPI-RTE-abstract-reshape](epistemic.md#epi-rte-abstract-reshape)).

For execution, the agent/user proposes research code and a run command. `orx exp run` selects the experiment branch's committed tip, creates a content-addressed source archive, validates launch settings and reserves a run. The default concurrent-run guard can be deliberately relaxed with `--force`; source selection still applies. The inspected local controller extracts the snapshot and launches the command with configured environment, while detached supervision maintains status and mirrors logs. Standalone dispatch also reaches this submission path. The snapshot binds recorded code, not data, dependencies, secrets or services; arbitrary shell commands do not inherit this compute contract ([RT-OBJ-source-snapshot](runtime.md#rt-obj-source-snapshot), [RT-RTE-experiment-run](runtime.md#rt-rte-experiment-run)).

### From completion to an evidence-bearing answer

A representative source-supported workflow is a locally configured request to run and summarize an experiment: inspect baseline, create hypothesis-relevant child branches, commit, submit, await completion, inspect evidence and return a cited explanation. It is a scenario reconstructed from connected shipped responsibilities, not an observed session. Compute delegation is to a controller/process, not another reasoning agent ([workflow account](workflow.md#workflow-account)).

Submission returns a run identity, not a measured answer. A prior explicit wake subscription can later cause the host to claim an idle session and start a hidden turn. That turn receives run/status text and directions to inspect evidence, not full measurements. Waiting likewise supplies a completion signal; instructions require rereading run states to reconcile other completions ([RT-RTE-run-wakeup](runtime.md#rt-rte-run-wakeup), [workflow account](workflow.md#workflow-account)).

The log command returns a full-file locator and a short tail: at most 500 characters derived from a 2048-byte suffix. The next evidence step is an explicit targeted file read. Preview omission cannot establish that a metric is absent from the log. The instructed reporting check asks for variant/effective configuration, final metrics and summary, long-run trajectory and supporting citation lines. This is semantic guidance to the model, not a software gate preventing unsupported reports. No recorded evidence-consuming acceptance event was established ([MEM-RTE-log-retrieval](memory.md#mem-rte-log-retrieval), [EPI-RTE-results-check](epistemic.md#epi-rte-results-check), [WF-RTE-result-handoff](workflow.md#wf-rte-result-handoff)).

The instructed next-step policy distinguishes repair, refill, promote and stop. An unintended failure normally leaves the question unanswered, but an OOM may answer a memory hypothesis. Answered nodes should remain frozen and changes should branch; repeated unanswered repairs require user escalation. These are requested model judgments, not enforced scientific counters or an expected-answer oracle. Carrying a winning branch forward can support local optimization without establishing an explanation of why it won or transfer beyond the comparison ([EPI-RTE-winner-promotion](epistemic.md#epi-rte-winner-promotion), [workflow account](workflow.md#workflow-account)).

Reports become project artifacts immediately on filesystem write. Descriptions likewise retain caller text without scientific approval. Tree moves change comparison organization without rebasing branch code; archive flags hide or restore nodes rather than refuting their claims. The chart helper does enforce numerical/schema conditions before its own new write, but fabricated finite values can pass and arbitrary writers bypass it. Thus structural validation, retention and scientific acceptance have distinct domains; none establishes post-acceptance knowledge integration here ([MEM-RTE-artifact-access](memory.md#mem-rte-artifact-access), [EPI-RTE-description-store](epistemic.md#epi-rte-description-store), [EPI-RTE-tree-organize](epistemic.md#epi-rte-tree-organize), [EPI-RTE-chart-render](epistemic.md#epi-rte-chart-render)).

### What persists and can change later work

OpenResearch's strongest supported trace-fed contribution is retained continuation context. Fallback compaction automatically turns recorded work and prior bootstrap material into a summary, persists it, clears the native session ID and supplies that seed to a later ordinary turn without native context. Persisted selected-path ACP/legacy side-chat seeds provide another continuation path. These implemented trace-fed writes can shape later work; they do not demonstrate improved capacity for future action ([MEM-RTE-chat-compaction](memory.md#mem-rte-chat-compaction), [MEM-RTE-branch-context](memory.md#mem-rte-branch-context), [MEM-BAP-bootstrap-injection](memory.md#mem-bap-bootstrap-injection), [profile verification](profile-verification.md#verification)).

Three stores must remain distinct: ORX transcript rows, native session payloads and bootstrap prose. Fallback compaction consumes an all-branch, newest-32-KiB flattened snapshot plus earlier seed; full tool bodies have already been omitted. Side-chat preparation instead selects a fixed parent active path. Native compaction preserves a native session through provider-specific mechanisms whose contents and budgets remain opaque. Keeping transcripts does not guarantee their full return to a model window, and requesting preservation of reasons does not guarantee that reasons survive ([MEM-OBJ-chat-messages](memory.md#mem-obj-chat-messages), [MEM-OBJ-native-session](memory.md#mem-obj-native-session), [MEM-OBJ-bootstrap-context](memory.md#mem-obj-bootstrap-context), [MEM-RTE-chat-compaction](memory.md#mem-rte-chat-compaction)).

Ordinary composition supplies retained goals, gated bootstrap and selected recent shell exchanges; slash-selected skills enter as instructions, while shell output and selected excerpts are labeled untrusted data. `prepared_input` bypasses ordinary composition. Side chats have separate conversational state but share a worktree; documented independent chats instead have no automatic result return. Neither establishes a universal native-subagent isolation contract ([MEM-RTE-turn-context](memory.md#mem-rte-turn-context), [MEM-RTE-branch-context](memory.md#mem-rte-branch-context), [MEM-CLM-independent-chat](memory.md#mem-clm-independent-chat)).

Reusable skill upload admits structurally valid content and distributes managed copies for later use; it does not certify quality or guarantee immediate resident-harness reload. Verification also found persisted model screening of native catalog entries and machine-wide `compute/CUSTOM.md` guidance outside the detailed analyst inventories. Uploads bypass that catalog screening; custom compute guidance has implemented revision-checked replacement but only instructed later retrieval. These omissions prevent a complete instruction/adaptation inventory, not the supported summary and upload findings ([RT-RTE-skill-upload](runtime.md#rt-rte-skill-upload), [report verification limits](report-verification.md#limits)).

Theory-building properties remain separate. In the assessed experiment-policy route, condition 1, localized theory content, is **afforded** by whole descriptions/code; condition 2, content-dependent consumption, is **claimed**; condition 3, content-directed criticism assigning blame and changing reliance, is **uninspected**; condition 4, iteration shaped by the result, is **claimed**. Winner selection alone supplies no formulated criticism. Whether criticism improved future capacity is unestablished. Reflection on OpenResearch's own operation and autonomous computational performance of every internal theory-building role are also unestablished, not inferred absent. At this boundary, no exercised self-improvement pathway is established: research-code optimization concerns an external product, summary delivery does not prove later causal dependence or improvement-directed self-change, and skill/release update paths alone do not close those links. These limits coexist with implemented retained-context updates ([EPI-RTE-winner-promotion](epistemic.md#epi-rte-winner-promotion), [MEM-RTE-chat-compaction](memory.md#mem-rte-chat-compaction), [RT-RTE-skill-upload](runtime.md#rt-rte-skill-upload), [RT-RTE-release-update](runtime.md#rt-rte-release-update)).

For the local experiment scenario, the supported result is a connected architecture for committed-code execution, asynchronous continuation and evidence-oriented reporting instructions. Exercised reliability, scientific acceptance and improved research capacity remain unresolved. Traces linking source, measurements, actual checks, dispositions and subsequent decisions would change the operation assessment. Controlled comparisons would be needed for benefit or component attribution. An enforced claim-admission mechanism would change the reporting guarantee; traced evidence-responsive updates to OpenResearch's own organization, followed by causally dependent operation, would change the self-improvement assessment.
