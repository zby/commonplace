# oh-my-pi synthesis

## Bounded synthesis

### From request to controlled effects

oh-my-pi is an enclosing coding-agent runtime: its CLI constructs sessions, dispatches model inference, executes admitted tools and returns results to the caller. This account concerns the repository at **2431e8a8716a4da73ae327a412f6d54c22f681e5**, with an applicability cutoff of **2026-10-14**. SRC-1 supplies implementation and declared design, not execution traces or causal experiments. The boundary is **complete artifact, partial loop**: the artifact is pinned, but not every shipped producer, evaluator, driver and later consumer was traced. External provider weights, deployed services and installed third-party implementations are excluded. See [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register). The accepted [report verification](report-verification.md#verification) and [profile verification](profile-verification.md#verification) declare no remaining blockers or publication limits; that does not remove the records' coverage and evidential qualifications. This synthesis used the supplied members without source reads.

An ordinary headless request passes through print mode, AgentSession and the core Agent loop. The caller supplies the problem; the model proposes text and tool requests; code owns scheduling, runnable identities, argument checks and execution. Tool results feed subsequent model steps. Steering and stop-boundary queues can extend the turn; exhausted queues or termination controls end it. Strict MCP readiness can prevent prompt dispatch. Extension context hooks and provider transformations intervene before inference, so accumulated history is not necessarily the delivered provider context. These are implemented routes, not observed successful work ([RT-RTE-session-turn](runtime.md#rt-rte-session-turn), [RT-OBJ-system-prompt](runtime.md#rt-obj-system-prompt), [RT-CLM-coding-agent](runtime.md#rt-clm-coding-agent)).

The main effect boundary is execution admission, not acceptance of a correct solution. Revised requests are revalidated; wrapped tools resolve approval against effective parameters; denial or human rejection stops that invocation. A human veto is conditional on policy requiring and obtaining approval, not implied by starting a session. Shell command approval is not per-system-call confinement. Nor is the wrapper universal: Cursor native mutations have a separate live-grant/write-policy gate and reject prompt-required mutations on a channel that cannot ask approval. Optional speculative local reads require early authorization and later resource/evidence revalidation. Extension modules and factories execute during loading, outside ordinary tool-request mediation; their host guard is not an operating-system sandbox. These distinct owners prevent attributing one enforcement guarantee to all effects ([RT-RTE-tool-dispatch](runtime.md#rt-rte-tool-dispatch), [RT-RTE-cursor-exec](runtime.md#rt-rte-cursor-exec), [RT-RTE-speculative-read](runtime.md#rt-rte-speculative-read), [RT-RTE-extension-load](runtime.md#rt-rte-extension-load)). Retry and dispatch recovery do not establish rollback of arbitrary file or remote mutations.

### Delegation separates working conversations, not all effects

The representative workflow is a **blocking, non-isolated child coding task with structured completion enabled**. It was selected because the task tool, facade and executor form a connected shipped path, not because an observed usage distribution makes it typical. The foreground model proposes delegation; the task facade passes an assignment and selected resources; the executor constructs another AgentSession. Batch context is forwarded only when batch mode is enabled. The forwarded context-file list excludes files named `agents.md`, without ruling out other instruction-discovery paths. A child receives selected instructions and context, not a transparent copy of the entire parent conversation ([workflow account](workflow.md#workflow-account), [RT-RTE-task-spawn](runtime.md#rt-rte-task-spawn)).

Completion has two consequential boundaries. The executor uses bounded reminders when structured work stops without a yield, and waits for owner background work. Newly delivered results can invalidate an earlier yield; failure to refresh it can produce a failed return with salvage output. Separately, finalization checks the selected output schema and mode. Strict policy can reject format failure; permissive policy can still reject, while some explicitly overridden submissions can return with a warning. Neither pending-work settlement nor schema validity tests the semantic correctness of the child's patch ([WF-RTE-completion-barrier](workflow.md#wf-rte-completion-barrier), [WF-RTE-output-finalization](workflow.md#wf-rte-output-finalization)).

Finalized output can be written untruncated to an artifact before the executor bounds the returned text. The model-facing task envelope adds status and another preview budget. Temporary artifact cleanup can remove the target of a rendered pointer. Thus neither a completion marker nor an `agent://` pointer proves full reasoning transfer, durable retrieval or accepted work. The parent regains next-step ownership through the tool result; caller delivery belongs to the foreground session's eventual output. In the selected non-isolated path, result failure does not undo child edits. Separate conversations can also share parent-backed Hindsight or Mnemopi banks through explicit operations, while automatic child recall/retention is suppressed ([WF-RTE-result-delivery](workflow.md#wf-rte-result-delivery), [RT-RTE-session-turn](runtime.md#rt-rte-session-turn), [RT-RTE-task-spawn](runtime.md#rt-rte-task-spawn), [MEM-RTE-hindsight-retention](memory.md#mem-rte-hindsight-retention), [MEM-RTE-mnemopi-retention](memory.md#mem-rte-mnemopi-retention)).

### Later turns receive selected retained material

Session retention is not simply replay of the visible transcript. Reconstruction selects a branch and its latest reset/checkpoint, combines retained and later turns, inserts valid notes and filters unsafe turns. Text summaries, opaque provider replay payloads and image-encoded archives are distinct checkpoint parts. A readable summary cannot establish what an opaque payload contains; archive delivery has byte budgets distinct from display rendering. A whole-replacement notebook has branch ownership and size checks, and the latest valid revision can survive removal of older active turns. Explicit full-branch history access can recover details, but a path in context requires a subsequent tool request rather than automatic dereferencing ([MEM-RTE-context-rebuild](memory.md#mem-rte-context-rebuild), [MEM-OBJ-compaction-summary](memory.md#mem-obj-compaction-summary), [MEM-OBJ-provider-payload](memory.md#mem-obj-provider-payload), [MEM-OBJ-snapcompact-archive](memory.md#mem-obj-snapcompact-archive), [MEM-RTE-notebook-update](memory.md#mem-rte-notebook-update), [MEM-RTE-artifact-read](memory.md#mem-rte-artifact-read)).

Backend memory has several different progressions:

- **Local memory** starts eligible rollout extraction and project consolidation for enabled, persisted top-level sessions. Schema checks, secret redaction and nonempty fields admit model-derived outputs. The published summary is automatically budgeted into guidance; detailed memory and generated procedures are explicitly readable. Scripts are published code text, not established executed capabilities; template/example form and consumers remain unresolved. Learned bullets have separate explicit admission, deduplication and a 100-bullet cap. The summary takes injection budget first, so lessons can receive no space. A snapshot can remain frozen after conversation starts ([MEM-RTE-local-consolidation](memory.md#mem-rte-local-consolidation), [MEM-OBJ-memory-summary](memory.md#mem-obj-memory-summary), [MEM-OBJ-local-scripts](memory.md#mem-obj-local-scripts), [MEM-OBJ-local-templates](memory.md#mem-obj-local-templates), [MEM-OBJ-local-examples](memory.md#mem-obj-local-examples), [MEM-RTE-local-lessons](memory.md#mem-rte-local-lessons)).
- **Mnemopi and Hindsight** compose first-turn queries from the prompt/recent history and configured scopes, budget the returned material, then persist delivered recall for reuse. This supplies context without a foreground recall call. Explicit recall/reflect and full-row reads are demand paths. Mnemopi can announce changes to tracked previews without rewriting historical recall; Hindsight reuses text without that ID comparison. Hindsight also supplies a separate stable mental-model cache with generation/deadline-controlled publication, not first-turn recall persistence. Service retention requests do not prove upstream durability or transformation ([MEM-RTE-backend-recall](memory.md#mem-rte-backend-recall), [MEM-OBJ-recall-entry](memory.md#mem-obj-recall-entry), [MEM-OBJ-mental-models](memory.md#mem-obj-mental-models), [MEM-RTE-hindsight-retention](memory.md#mem-rte-hindsight-retention)).
- **Sharpshooter** extracts decision deltas from committed top-level user turns and bounded referent context, queues admitted deltas, then consolidates project files for budgeted instruction supply. Evidence strings must occur in the triggering prompt. This checks occurrence, not whether the proposed interpretation follows. Final replacement files have separate structural/redaction gates; optional rationale can reach consolidation without surviving every final sentence or delivery budget. Sequential renames do not provide multi-file atomic rollback ([MEM-RTE-decision-memory](memory.md#mem-rte-decision-memory), [MEM-OBJ-decision-deltas](memory.md#mem-obj-decision-deltas), [MEM-OBJ-project-decisions](memory.md#mem-obj-project-decisions)).

These mechanisms distinguish retention, selection and authority. Local memory asks the model to treat guidance as heuristics subordinate to current evidence; project decisions ask it to follow them unless overridden. Both are natural-language influence, not enforced compliance. Retained identifiers, scopes and ownership tokens can instead enforce software eligibility at their particular consumers. Deletion and withdrawal are also consumer-relative: Mnemopi facts are read-only through memory_edit, update/forget require working rows, and retirement differs from deletion. Historical prompt copies can remain after live-store changes; Hindsight clear does not clear the upstream bank ([MEM-BAP-memory-guidance](memory.md#mem-bap-memory-guidance), [MEM-RTE-memory-edit](memory.md#mem-rte-memory-edit), [MEM-RTE-backend-recall](memory.md#mem-rte-backend-recall), [MEM-RTE-hindsight-retention](memory.md#mem-rte-hindsight-retention)).

### Trace-fed revision is implemented; benefit and theory criticism are separate

The strongest supported learning-related contribution is **conditional automatic trace-to-durable-guidance wiring**. Local rollout consolidation produces later memory/procedure supply; Sharpshooter produces later decision instructions; private auto-learn capture can produce durable lessons or managed skills. This is more than raw logging, but is not evidence that future capacity improved. No before/after capacity comparison or causal intervention was supplied ([MEM-RTE-local-consolidation](memory.md#mem-rte-local-consolidation), [MEM-RTE-decision-memory](memory.md#mem-rte-decision-memory), [MEM-RTE-autolearn-capture](memory.md#mem-rte-autolearn-capture)).

Private capture requires a top-level controller, enabled settings including autoContinue, sufficient tool activity, a non-aborted eligible stop outside plan/goal diversion, and available model/tools. It copies history into a detached agent restricted to `learn` and `manage_skill`. The model may elect no write. The synthetic capture instruction expressly does not represent a user answer or approval. Managed mutation checks name, content, byte limits and filesystem constraints; discovery gives enabled authored skills precedence. An invocation builder can read a selected retained body, but complete dispatch and compliance remain unobserved. Description sanitization can erase meaning, such as removing the comparison operator in `a<b`, so normalization does not warrant universal semantic preservation ([EPI-RTE-capture-turn](epistemic.md#epi-rte-capture-turn), [EPI-RTE-skill-mutation](epistemic.md#epi-rte-skill-mutation), [EPI-RTE-skill-readback](epistemic.md#epi-rte-skill-readback), [EPI-RTE-description-sanitize](epistemic.md#epi-rte-description-sanitize), [EPI-CLM-managed-library](epistemic.md#epi-clm-managed-library)).

For these selected session/capture paths, theory-builder conditions remain independently unestablished: **1**, no supplied formulated theory instance; **2**, no demonstrated decision dependence on what such a theory says; **3**, no established content-directed criticism with resulting revision or changed reliance; **4**, no established retained criticism result shaping a next round. Delivered procedural text and a requested usefulness judgment do not close those gaps. Whether criticism of a consumed theory improved future capacity is likewise unestablished, not disproved. Reflection is not established: the account does not close both directions between a selected system aspect, its self-representation and representation-mediated changes. Computation owns many scheduling and update operations, but this does not establish an autonomous theory builder performing every internal theory operation. These limits concern the inspected routes, not a system-wide absence or a claim about inaccessible model processing ([epistemic bounded conclusion](epistemic.md#bounded-conclusion), [EPI-RTE-capture-turn](epistemic.md#epi-rte-capture-turn), [RT-CMP-agent-model](runtime.md#rt-cmp-agent-model)).

Self-improvement has a supported partial pathway: the capture objective requests genuinely reusable material; operating traces can shape proposals; admitted files can supply later instructions. The unresolved links are whether objective-bearing evidence actually determined a useful update, whether subsequent operation exercised its authority path, and whether behavior causally depended on it. Consequently this boundary supports conditional improvement-directed self-change machinery, not exercised or successful self-improvement. Improvement of an external coding work product would not settle that question. Reflection, autonomy and future-capacity improvement remain separate properties ([MEM-RTE-autolearn-capture](memory.md#mem-rte-autolearn-capture), [EPI-RTE-capture-turn](epistemic.md#epi-rte-capture-turn), [EPI-RTE-skill-mutation](epistemic.md#epi-rte-skill-mutation), [EPI-RTE-skill-readback](epistemic.md#epi-rte-skill-readback)).

Checking is heterogeneous rather than a single answer oracle. The exposed eval judgment helper returns typed model assessments over caller-selected questions to an awaiting cell. It supplies no generic mandatory product disposition without a particular consequential cell consumer. Format checks, policy checks, evidence occurrence and model judgments each license narrower conclusions than truth or procedural efficacy. Generic generated-content relations remain indeterminate without actual propositions and premises; persistence and use do not establish accepted knowledge ([EPI-RTE-eval-judgment](epistemic.md#epi-rte-eval-judgment), [EPI-CMP-judge-chain](epistemic.md#epi-cmp-judge-chain), [epistemic bounded conclusion](epistemic.md#bounded-conclusion)).

### Scenario-relative assessment and what would change it

For a delegated coding request, the inspected architecture supports separate child work, scheduling/format rejection and bounded status-bearing return. It does not certify the patch or reverse non-isolated effects. For continuation across long sessions, it supports checkpoint/notebook reconstruction and explicit recovery, without establishing fidelity of opaque or image history. For cross-session reuse, it supports backend-specific automatic guidance and explicit retrieval, but preservation of prompt bytes can delay visibility of changed memory. These are different operating scenarios, not a product ranking.

A trace linking request, effective gates, child work, finalization and actual parent delivery would establish bounded operation. Consumer-side captures of reconstructed provider messages would clarify which retained bytes survive transformation. Recorded memory production and later action dependence would strengthen reuse claims; independent update/no-update comparisons against a specified future-task objective would test benefit at the level varied. Actual stated theories, targeted criticism, revised reliance and retained next-round use would change the theory-builder assessment. Particular eval-cell disposition traces, semantic acceptance criteria, complete skill dispatch, and traced core/vector/withdrawal alternatives would change their local authority and coverage conclusions. The current records establish none of those stronger findings merely from available code.
