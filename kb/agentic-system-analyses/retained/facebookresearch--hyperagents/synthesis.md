# Hyperagents synthesis

## Bounded synthesis

Hyperagents implements an improvement plane: a host driver generates code-modified agents, evaluates them, retains their lineage and results, and selects code for another generation. Its consequential output can change the editor and tools that produce future agents, not only task answers. This account covers the whole shipped framework at Git commit `59a68f672dfb92c74aeb7e61535d776fb36e172d`, with an applicability cutoff of 2026-10-14. SRC-1 supplies inspected implementation and declared design only. No target execution, experiment logs or causal comparison was frozen; the paper, blog and external dependency implementations are outside this evidence. Thus the account establishes implemented pathways, not successful runs or measured gains ([boundary and evidence](boundary.md#boundary-and-evidence); [RT-RTE-generation-cycle](runtime.md#rt-rte-generation-cycle)).

### From a generation request to executable change

An operator chooses domains, budget and modes. The host owns scheduling, generation identities, root preparation and resume. It reconstructs a selected parent by replaying ordered saved patches into a writable repository, then launches the inherited editor. The initial editor starts a fresh conversation and asks a provider model to modify the codebase. Python parses textual tool calls, dispatches registered tools and limits their count; the model chooses edits. Generated descendants can change task code, editor code, tools and optional selector or ensemble logic. Provider inference does not itself update the provider model's weights ([RT-RTE-editor-admission](runtime.md#rt-rte-editor-admission), [RT-RTE-model-tools](runtime.md#rt-rte-model-tools), [RT-CMP-provider-models](runtime.md#rt-cmp-provider-models)).

The archive has two importantly different effects. First, saved diffs become executable code through later replay and Python imports. This is stronger than advisory historical context. Second, previous evaluations and logs can become model-readable evidence. Normal delivery copies a filename-filtered archive view, removing current-generation, validation/test-named and repository-copy material. The initial editor accepts an evaluation path but does not insert it or its contents into the prompt; historical evidence use requires discovery and a tool read. Parent-only `no_archive` copying is unpruned, while optional selector/ensemble wrappers receive a full archive. These are different visibility policies, not proof that held-out information is semantically isolated ([RT-BAP-code-replay](runtime.md#rt-bap-code-replay), [MEM-RTE-archive-delivery](memory.md#mem-rte-archive-delivery), [RT-RTE-optional-consumers](runtime.md#rt-rte-optional-consumers)).

Context control also operates inside each invocation. Initial editor and task conversations start empty. Task workers return predictions while logs persist separately. File-view results can be clipped, with disk contents still available for another range request. The model helper accumulates turns; its output-context retry is not a demonstrated summarization mechanism. Fresh task frames therefore limit conversational carryover without making execution a pure return-only boundary: filesystem effects and imported code can escape it ([MEM-OBJ-chat-history](memory.md#mem-obj-chat-history); [memory annotations](memory.md#annotations)).

### From edited code to scores and another parent

The representative workflow is one paper-review generation. After editing, the runner attempts to restore `domains/` and saves a diff. A nonempty diff and successful imports admit an evaluation attempt, not an improved or trustworthy agent. The harness creates a fresh task agent for each paper, supplies paper text without its outcome label, and saves predictions. The report normalizes strings and measures agreement with dataset labels. Positive staged scores for every selected domain allow fuller evaluation unless staging is skipped. Full evaluation extends existing prediction tables; it does not necessarily rerun completed rows ([RT-RTE-task-evaluation](runtime.md#rt-rte-task-evaluation), [MEM-RTE-prediction-reuse](memory.md#mem-rte-prediction-reuse); [workflow account](workflow.md#workflow-account)).

These checks have bounded targets. Label agreement supports a conditional statistic over supplied rows, not independent truth of the labels. Proof grading delegates judgment to an external grader before a fixed points conversion; it is not inspected formal verification. BALROG checks actions and summarizes environment progress. Genesis evaluates trained policies through fitness metrics. Polyglot attempts patch tests but has a logger-call defect on its nonempty-patch path. None of these outcomes by itself explains why an editor change works or licenses transfer ([EPI-RTE-label-scoring](epistemic.md#epi-rte-label-scoring), [EPI-RTE-proof-grading](epistemic.md#epi-rte-proof-grading), [EPI-RTE-outcome-summary](epistemic.md#epi-rte-outcome-summary), [RT-RTE-domain-effects](runtime.md#rt-rte-domain-effects)).

On normal return to the outer loop, a generation is archived even when it is ineligible. Separate flags and scores govern successor selection. Starting-node exceptions, first-node fallback and eligibility's `meta_patch_files is not None` alternative prevent a universal successful-evaluation prerequisite; the CLI's empty-list default also satisfies that alternative. Parent selection chooses an exploration lineage, not necessarily an agent better than its parent. Failure can invalidate parent or selector reuse without deleting its retained history ([RT-OBJ-metadata](runtime.md#rt-obj-metadata), [RT-RTE-parent-selection](runtime.md#rt-rte-parent-selection), [RT-BAP-selector-flags](runtime.md#rt-bap-selector-flags)).

Optional consumers alter this progression. Editable selection runs code from the latest eligible selector source, which need not be the task-performance parent; exceptions disable that source and trigger bounded retries. The initial ensemble selects an archived agent using the requested split's score and returns its saved prediction, rather than making a new task-model call. Validation/test-score-conditioned selection cannot establish unseen-split generalization ([RT-RTE-optional-consumers](runtime.md#rt-rte-optional-consumers)).

Delivery is a directory containing available diffs, logs, predictions, reports and metadata, plus a lineage that can be replayed later—not a deployed winning agent. Cleanup is best effort; outer plotting and selection are outside the local generation exception handler. Docker's writable mount and host networking, post-edit domain restoration and mutable dependencies do not establish adversarial containment or evaluator integrity ([workflow delivery](workflow.md#delivery-and-next-round-authority), [RT-RTE-editor-admission](runtime.md#rt-rte-editor-admission), [RT-CLM-bash-description](runtime.md#rt-clm-bash-description)).

### Learning and improvement: positive pathways, separate unresolved properties

The strongest supported trace-fed contributions are explicit, consequential update routes. In optional DGM mode, selected failed-case reports and interaction or episode traces feed model diagnosis; extracted implementation/problem fields reach a later coding agent and can lead to retained executable changes. Genesis separately wires rollout-fed numerical policy training to saved checkpoints and later action inference. These are implemented trace-fed behavior-shaping routes. Ordinary archive-informed editing remains an affordance because copied evidence is not automatically consumed. No comparison establishes improved future capacity from any of these routes ([MEM-RTE-dgm-diagnosis](memory.md#mem-rte-dgm-diagnosis), [RT-CMP-policy-runner](runtime.md#rt-cmp-policy-runner), [MEM-RTE-archive-delivery](memory.md#mem-rte-archive-delivery)).

The records do not establish a theory-builder assessment for the system. Condition 1, localized formulated theory, is not established merely by an executable patch or opaque parameters. Condition 2, decisions depending on that theory's content, is not established by archive availability. Condition 3, criticism identifying a challenged claim, result and placement of blame, is not established by scores or the diagnosis label. Condition 4, retaining criticism's result to shape another round, is not established merely by replaying code. These are separate unresolved findings, not evidenced absences; the DGM route and opaque model processing prevent a universal negative. Improved capacity specifically caused by criticism of a consumed theory is likewise unestablished ([RT-RTE-editor-admission](runtime.md#rt-rte-editor-admission), [MEM-RTE-dgm-diagnosis](memory.md#mem-rte-dgm-diagnosis); [epistemic conclusion](epistemic.md#bounded-conclusion)).

Reflection is not established by editing one's generating machinery alone: the accepted account does not establish the required self-representation and both causal directions. Computational scheduling and automatic per-change admission are implemented, but they do not establish an autonomous theory builder when its theory operations remain unresolved. These qualifications do not erase the supported automatic edit, evaluation and replay mechanisms ([RT-RTE-generation-cycle](runtime.md#rt-rte-generation-cycle), [RT-RTE-editor-admission](runtime.md#rt-rte-editor-admission)).

Self-improvement has a stronger architectural finding: within later generations of the same host run, an independently specified task-performance objective and a live change-to-own-machinery channel support **dispositional improvement-directed self-change**. Exercised evidence-responsive self-improvement remains unestablished because no trace shows objective-relevant evidence determining the actual update or subsequent operation causally depending on it. Successful improvement requires separate outcome evidence. There was no treatment/comparison here, so no system-level gain or component effect can be attributed ([RT-CLM-recursive-improvement](runtime.md#rt-clm-recursive-improvement)).

For bounded benchmark search, the architecture connects executable variation, outcome measurement and lineage reuse. For an account of warranted mechanism discovery or demonstrated future-capacity improvement, its evidence stops earlier. A revision-linked trace showing selected evidence, update determination, replay and dependent later behavior would change the exercised-self-improvement assessment. Comparable before/after outcomes would address benefit; attributing a component effect would require independently varying that component. Reliable recovery claims also require repairing the identified branches and observing them, while stronger evaluation-integrity claims require controls beyond mutable path conventions ([RT-CLM-recursive-improvement](runtime.md#rt-clm-recursive-improvement); [report verification](report-verification.md#limits)).
