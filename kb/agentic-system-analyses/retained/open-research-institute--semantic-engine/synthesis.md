# Semantic Engine synthesis

## Bounded synthesis

### From selected sources to retained retrieval state

Semantic Engine is an operator-driven document memory pipeline, not an autonomous agent runtime. This account covers its shipped ingestion, storage, embedding, retrieval, visualization and export responsibilities at commit `7e2481671cad01f0b4c89f2a1877d6733d7e552c`, with an analysis cutoff of 2026-10-17. SRC-1 supplies inspected implementation and declared design only. No target code, tests, services or model calls were executed, and no execution trace or causal experiment was supplied. The whole-system boundary describes functional source coverage, not a demonstrated integrated deployment ([boundary](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)).

The declared work is ingesting, embedding and visualizing documents and their relationships. Its most concrete connected workflow is the CLI quickstart: a human selects an archive corpus, downloads it, loads documents, embeds chunks and separately submits a query. Files and database rows connect the steps; the operator owns cross-command continuation and recovery. Fixed scripts choose the next computational steps. Models return numerical embeddings rather than selecting tools or delegating reasoning. Terminal document output completes this workflow, not reviewer acceptance or answer generation ([RT-CLM-pipeline-purpose](runtime.md#rt-clm-pipeline-purpose), [workflow account](workflow.md#workflow-account)).

Downloaded archive files are raw input, not automatically the searchable corpus. Existing local files are skipped without a refresh check. The archive loader filters retweets and replies to others, joins surviving self-threads and drops orphan replies. The alternate RSS loader converts HTML to titled Markdown under different field checks; archive filtering does not govern RSS. Both automatically admit rows after human source selection, rather than obtaining per-item approval. Fresh IDs and stored hashes do not prevent duplicate reimports. Separate root and chunk insertions lack a spanning driver transaction, so interrupted ingestion need not leave a complete searchable population ([MEM-OBJ-archives](memory.md#mem-obj-archives), [RT-RTE-ingest-documents](runtime.md#rt-rte-ingest-documents)).

The dataset-selected SQLite file separates full root text, chunk text and offsets, provenance metadata, and dense chunk vectors. Segmentation preserves an ordered text collection but need not preserve a complete assertion in each fragment; its 512-JavaScript-string-unit size is not a model-token guarantee. Metadata preserves associations rather than verified trust: RSS author and date fallbacks can substitute feed labels and ingestion time. These distinctions matter because chunks become model inputs while roots and labels become human-facing output ([MEM-OBJ-docs-content](memory.md#mem-obj-docs-content), [MEM-OBJ-chunks-content](memory.md#mem-obj-chunks-content), [MEM-OBJ-docs-metadata](memory.md#mem-obj-docs-metadata), [EPI-RTE-split-text](epistemic.md#epi-rte-split-text), [EPI-RTE-source-reshaping](epistemic.md#epi-rte-source-reshaping)).

### Derivation, later selection and maintenance

The embedding driver reads null-vector chunks, sends their text to the configured LMStudio model and constructs ID-keyed updates. Admission checks for a nonempty returned array, not correspondence, dimensions or semantic quality. A failed batch advances to the next batch; a fresh invocation can revisit still-null rows. Non-null selection is therefore neither eventual completion nor freshness checking. The external model has no immutable weights identity recorded with each vector. Changing the configured model does not invalidate older vectors ([RT-RTE-embed-chunks](runtime.md#rt-rte-embed-chunks), [RT-CMP-lmstudio](runtime.md#rt-cmp-lmstudio)).

The strongest supported durable contribution is the implemented path from imported text to retained numerical ranking inputs: later query selection depends on those values. That is not a provider-weight update or demonstrated learning benefit. Even successful vector normalization remains unobserved: the schema declares F32 blobs, while the update constructs JSON-stringified CASE values without the adapter's ordinary conversion expression ([MEM-OBJ-chunks-embedding](memory.md#mem-obj-chunks-embedding), [RT-BAP-vector-ranking](runtime.md#rt-bap-vector-ranking)).

A query sends only its current text to LMStudio. SQL then ranks non-null stored chunk vectors by cosine similarity, takes at most fifty candidates for the ten-root limit, deduplicates parent IDs and reloads full roots for printing. Repeated chunks from a few roots can consume the window, so ten distinct results and the globally best ten roots are not guaranteed. This is requested read-back to a terminal user, not unsolicited context injection or retrieval into a generative answer model. The quickstart's “RAG” label establishes no missing generation stage ([RT-RTE-query-documents](runtime.md#rt-rte-query-documents), [EPI-CLM-rag-quickstart](epistemic.md#epi-clm-rag-quickstart)).

The operator can clear all non-null vectors in a dataset. That removes retrieval eligibility and enables recomputation without removing roots, chunks or provenance. It keeps no former vector version and does not synchronize derived map or Atlas copies. This is explicit maintenance, not evidence-responsive factual retraction or automatic model-version migration ([RT-RTE-clear-embeddings](runtime.md#rt-rte-clear-embeddings)).

### What the other outputs and checks establish

Canvas projects vectors through PCA and affords a GeoJSON/map consumer, but its fixed database path, string-vector assumptions, missing null exclusion and generated/requested filename mismatch prevent claiming a connected current-schema route. Joined content columns also leave displayed text identity ambiguous. Atlas export has independent initialization and obsolete-schema obstacles, plus ID and array-shape qualifications. It explicitly requests topic modeling; neither its output nor its remote acceptance and later consumers are available. These alternatives remain in scope without being joined into the terminal workflow ([MEM-RTE-canvas-display](memory.md#mem-rte-canvas-display), [MEM-RTE-atlas-export](memory.md#mem-rte-atlas-export), [EPI-RTE-atlas-topics](epistemic.md#epi-rte-atlas-topics)).

The separate Knowledge Gate page sends two current texts to OpenAI and displays their cosine similarity; it does not gate corpus admission. Equal-length and nonzero-magnitude guards enforce limited arithmetic preconditions, not factual truth or semantic equivalence. Authored chunker tests concern fixture behavior, not retrieval relevance, and have no inspected ingestion-acceptance consumer. Optional clustering groups copied content; its processor call is commented out, and SSE diagnostics do not select an accepted factual explanation ([RT-RTE-compare-texts](runtime.md#rt-rte-compare-texts), [EPI-RTE-cosine-guards](epistemic.md#epi-rte-cosine-guards), [EPI-RTE-chunk-tests](epistemic.md#epi-rte-chunk-tests), [EPI-RTE-cluster-items](epistemic.md#epi-rte-cluster-items)).
