# OKF synthesis

## Bounded synthesis

### From a task to selected project knowledge

OKF is an agent-operated knowledge ecosystem, not an enclosing model runtime. It gives project explanations a durable home in Markdown, supplies retrieval and structural checks, and asks an external agent to keep the content current. This account covers the four shipped gems, skills, plugin and Pro installation templates at commit `cfb7ffac7fef37d56e97b5b7dd8fe97ffc648c7c`, with an applicability cutoff of 2026-11-08. SRC-1 is the sole registered source. The evidence is inspected implementation and authored doctrine/design, not supplied session traces, passing test executions or causal experiments. The host conversation loop, model internals and optional backend internals are outside inspected implementation; see the [boundary](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

A user brings a task to an agent in a project with an OKF bundle. The skill routes intent to a playbook. Consume requests directory shape, a relevant branch index and recent history, then only the concept bodies the task needs; pointed questions transfer to search. The CLI parses visible Markdown and returns maps, matches or selected bodies. The external agent chooses subsequent steps, interprets the content and delivers the task answer. There is no OKF-owned answer oracle or terminal-answer evaluator in this route. The knowledge side and the host's task-answer side therefore have separate delivery boundaries: [RT-RTE-skill-work](runtime.md#rt-rte-skill-work), [RT-CMP-agent](runtime.md#rt-cmp-agent), [WF-RTE-maintenance-closeout](workflow.md#wf-rte-maintenance-closeout).

The durable corpus separates concept prose from provenance and lifecycle fields, authored indexes, and update logs. Pro adds a work board, daily journal, retained counter snapshots and friction events. Natural-language explanations guide agents and humans; symbolic fields separately control filters, counts and admissibility checks. A source reference records an origin claim, not proof that the source supports the prose. The body and its metadata thus have different consumers and warrants: [MEM-OBJ-concept-body](memory.md#mem-obj-concept-body), [MEM-OBJ-concept-metadata](memory.md#mem-obj-concept-metadata), [MEM-OBJ-index](memory.md#mem-obj-index), [MEM-OBJ-log](memory.md#mem-obj-log).

MCP supplies shipped tools, resources and prompts for later consumption. Requested searches filter and project results; exact-id concept reads return original Markdown. A host can request a resource attachment without the model deciding to fetch it. Browser and TUI support human consumption and registry management. These are concrete retrieval interfaces, not proof that delivered content changed an agent's behavior: [RT-RTE-mcp-retrieve](runtime.md#rt-rte-mcp-retrieve), [RT-RTE-registry-manage](runtime.md#rt-rte-registry-manage), [MEM-BAP-retained-knowledge](memory.md#mem-bap-retained-knowledge).

Selection keeps material out before it enters context; it does not establish control over the host's accumulated conversation. MCP row projections and log cuts, filtered hook feedback and computed opening state are distinct supply controls. The log byte bound is per file's content and scales with the requested limit; it does not bound the complete response, full concept reads, resource reads or host window. Cache eviction removes Ruby residency, not already delivered turns. Live body bytes also do not guarantee fresh selection metadata: path/mtime/size fingerprints can miss preserving edits, reserved-log reads can fall back to a loaded snapshot, and browser structural views are boot snapshots. SafeRead's containment checks do not cover hardlinks or the resolve/open race. These are implementation qualifications, not observed stale or escaping executions: [RT-RTE-mcp-retrieve](runtime.md#rt-rte-mcp-retrieve), [RT-CLM-live-bodies](runtime.md#rt-clm-live-bodies).

### From a discovery to maintained files

The representative multi-step workflow is connected by an explicit handoff: a durable discovery during consume triggers maintain. The same agent finds affected concepts, updates bodies and attribution, repairs enumerations and links, and appends a dated log entry. It then checks the index, runs validate and lint, and judges loose concepts and tags. This is procedural delegation to commands, not an evidenced handoff to another model worker. Validate can reject conformance with exit 1; lint is advisory by default unless a failure threshold is selected. Direct edits already persist before these checks. Recovery is agent correction and rechecking, not automatic rollback: [RT-RTE-skill-work](runtime.md#rt-rte-skill-work), [WF-RTE-maintenance-closeout](workflow.md#wf-rte-maintenance-closeout).

Acquisition and maintenance have several forms. Produce requests distillation from code, documents or human knowledge; document adoption requests preservation of existing bodies, with permitted relocation-link edits. That adoption branch must not stand for every migration mode: the report verification identifies a spelling-migration mode that moves citations into metadata and deletes their old body section. The transformation inventory is consequently incomplete. Correction and deprecation can preserve superseded reasoning for later readers, but distillation alone does not establish a novel claim, semantic preservation or evidence-consuming acceptance: [MEM-OBJ-concept-body](memory.md#mem-obj-concept-body), [EPI-RTE-semantic-disposition](epistemic.md#epi-rte-semantic-disposition), [report-verification limits](report-verification.md#limits).

There are several different write controls, not one universal approval gate:

- Library Writer validates a materialized temporary bundle before locked promotion, with attempted backup restoration on failed overwrite. This protects that publication route, not arbitrary host file edits: [RT-RTE-publish-bundle](runtime.md#rt-rte-publish-bundle).
- The base plugin supplies filtered post-edit findings and exits zero. It can be disabled and cannot undo the edit: [RT-RTE-curation-feedback](runtime.md#rt-rte-curation-feedback).
- Installed Pro hooks request asks or blocks for recognized host events; Stop, staged-tree pre-commit and CI are separate later doors. Enforcement depends on setup and the host honoring the protocol. Shell recognition is heuristic, external write tools are not enclosed by the named matchers, and an empty object event can supply no target. Whether real edit events can reach that last branch is unresolved, not a demonstrated bypass: [RT-RTE-pro-gates](runtime.md#rt-rte-pro-gates).
- Pro's mechanical writers construct constrained board/journal/closure changes and check declared line-multiset deltas. Conservation does not establish prose truth, line placement, concurrent-update safety or multi-file transactionality. Interrupted writes can require repair: [RT-RTE-pro-writes](runtime.md#rt-rte-pro-writes).

### What checks license, and what later sessions receive

OKF implements useful deductions within parsed structural domains: field membership, links, declared expiry, trust classification and snapshot agreement. These are not semantic source checks. Keyed attribution joins labels; it does not show that a cited source supports a sentence. A human-prefixed verification mapping yields a human-reviewed tier without binding that declaration to current body bytes or freshness. The tier matters operationally: optional search filters select membership, and Pro pairing treats human review as discharging a reference-reading obligation. Full concept reads have no universal human-review prerequisite. The intended owner decision is actual review, but neither a permission ask nor recorded metadata authenticates that review: [EPI-RTE-structural-check](epistemic.md#epi-rte-structural-check), [EPI-RTE-trust-tier](epistemic.md#epi-rte-trust-tier), [EPI-RTE-read-pairing](epistemic.md#epi-rte-read-pairing), [EPI-RTE-semantic-review](epistemic.md#epi-rte-semantic-review).

Pro's eligible Write feedback searches a few filename terms and presents bounded collision snippets, including deprecated hits. It asks the agent to compare claims, correct/deprecate a loser or retain a linked unresolved board obligation. It neither detects semantic contradiction nor automatically accepts a winner; Edit does not take this Write-only branch. The prescribed semantic disposition has meaningful intended consequences for later reliance, but no operated evidence-consuming acceptance and subsequent integration chain is supplied: [MEM-RTE-reconcile-search](memory.md#mem-rte-reconcile-search), [EPI-RTE-semantic-disposition](epistemic.md#epi-rte-semantic-disposition).

Later context also arrives without an explicit request for those retained parts. SessionStart selects the latest dated Snapshot alongside cheap live state and selected friction cues. The historical snapshot is labeled not live; its command computes a line that the caller must append. Friction automatically records raw instrumented intent, not necessarily completed actions, and later supplies a count/report rather than a durable revised method. This supports cross-session state feedback, not demonstrated lesson extraction or improved prioritization: [MEM-RTE-snapshot-context](memory.md#mem-rte-snapshot-context), [MEM-RTE-friction-feedback](memory.md#mem-rte-friction-feedback), [MEM-BAP-state-context](memory.md#mem-bap-state-context). The [profile verification](profile-verification.md#verification) preserves the distinction between these supported paths and unresolved trace-learning/source classifications; neither a positive learning value nor a system-wide negative follows.

Attested Computation is a separate offered protocol. A consumer binds permitted parameters to sanctioned code, an independent deterministic attester compares the executed artifact and displayed value against authoritative receipt data, and a display gate is supposed to refuse failure. The inspected CLI/MCP surfaces expose contracts and inventories, not this complete execution/check/display chain. Even a conforming attestation would license artifact/value fidelity for that call, not the sanctioned definition's real-world correctness. Arbitrary payload meaning and concrete executor/attester behavior remain unresolved: [MEM-OBJ-references](memory.md#mem-obj-references), [EPI-OBJ-computation](epistemic.md#epi-obj-computation), [EPI-RTE-run-attestation](epistemic.md#epi-rte-run-attestation), [EPI-RTE-display-gate](epistemic.md#epi-rte-display-gate).

### Adaptation and scenario-relative assessment

The strongest supported adaptation contribution is an inspectable way to propose and retain changes to retrieval layout or instruction organization, supported by explicit principles and requested before/after checks. Refine reserves execution approval to the user; the separate instruction-restructuring skill does not impose that same approval rule. This is a policy-level pathway, not an observed improvement comparison. Governance installation can change instruction/hook files, and extension discovery can load capability code in-process; neither installation nor a naming check establishes trace-responsive improvement or sandboxing: [RT-RTE-refine-proposal](runtime.md#rt-rte-refine-proposal), [RT-RTE-governance-install](runtime.md#rt-rte-governance-install), [RT-RTE-extension-load](runtime.md#rt-rte-extension-load).

For the structural principles assessed in the runtime record, theory-builder condition 1 is wired: localized explanatory units exist. Condition 2 is claimed: the playbook requests decisions governed by their content, without observed consumption. Conditions 3 and 4 are uninspected: diagnosis under unchanged principles is not evidenced content-directed criticism of those principles, and no retained criticism-to-next-round chain is shown. Criticism of a consumed theory improving future capacity is therefore unestablished, independently of the useful revision pathway. Reflection is unestablished because both causal directions through a bounded self-representation are not shown. Autonomous theory building is unestablished; actual role execution and host internals are not frozen, and refine retains human approval. Exercised self-improvement is also unestablished: no evidence-shaped organizational update is traced into subsequent operation causally depending on it. These are separate findings, not a combined negative judgment about OKF or its external agent: [RT-RTE-refine-proposal](runtime.md#rt-rte-refine-proposal).

For a task needing navigable, editable project explanations, the evidence supports durable retention, selective later access and differentiated structural/work-state controls. For a task requiring authenticated source review, automatic semantic reconciliation or demonstrated cross-session improvement, those same routes are insufficient evidence. Paired source/concept and review records could establish semantic preservation or accepted claims; configured-host traces could establish actual gate reachability and delivery; retained-update/later-consumer traces plus an appropriate comparison could establish improvement at the level varied. Concrete executor/attester receipts would change the computation assessment, and backend implementation evidence would resolve the opaque alternative. None of these missing observations negates the implemented paths already described.
