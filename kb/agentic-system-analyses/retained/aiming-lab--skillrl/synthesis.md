# SkillRL synthesis

## Bounded synthesis

### From experience to two behavior-changing products

SkillRL implements automatic experience-fed changes to both a textual skill bank and an agent's numerical policy. The strongest supported contribution is the connected architecture: failure-responsive rules can enter later training prompts, while reward-bearing rollouts feed parameter updates. Whether those changes improve future action remains unestablished. This account uses executable source, declared design and attributed benefit claims from SRC-1, `https://github.com/aiming-lab/SkillRL`, at commit `4d984d455b9b02f0bad283cbe9ab3d66a7e5b89d`, with an applicability cutoff of 2026-10-14. No target execution, provider call, supplied execution trace or controlled comparison supports it. See the [boundary](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The functional boundary is the whole SkillRL builder or improvement plane: offline experience processing, bank generation, selection and prompt delivery, environment interaction, policy fitting, validation, dynamic skill admission and persistence. It includes shipped training drivers and environment managers, but is not an audit of every feature of the bundled training framework. External model weights, services, rollout provenance and the external supervised fine-tuning trainer are not frozen. The product is a configured training run with artifacts and metrics, not a general-purpose deployed assistant.

The reusable skill library contains natural-language principles and mistakes, organized by general and task-specific categories. Symbolic IDs, category keys and ordering control selection and admission; optional dense vectors support ranking. Their roles differ from the numerical actor weights that determine generation. Storing these parts together does not give them the same authority. The bank text supplies model-interpreted directions, not executor permissions. See [MEM-OBJ-skill-content](memory.md#mem-obj-skill-content), [MEM-OBJ-skill-metadata](memory.md#mem-obj-skill-metadata), [MEM-OBJ-retrieval-index](memory.md#mem-obj-retrieval-index) and [RT-BAP-policy-parameters](runtime.md#rt-bap-policy-parameters).

Offline production has two material routes. The original ALFWorld generator extracts bounded patterns from supplied memories, requests model-generated skills and overwrites a JSON bank. A newer data pipeline cleans supplied rollout dumps, generates derived experiences, aggregates skills, then inserts generated reasoning around recorded successful actions and emits training pairs. The latter produces data for external fitting; it does not independently replay actions or verify the generated explanations. Aggregation does not preserve explicit individual-trace links in each resulting skill. See [RT-RTE-offline-production](runtime.md#rt-rte-offline-production), [MEM-RTE-trace-abstraction](memory.md#mem-rte-trace-abstraction) and [RT-RTE-sft-production](runtime.md#rt-rte-sft-production).

### A representative run: action, fitting, failure feedback and later delivery

The shipped ALFWorld skills driver is representative because it enables both policy training and dynamic bank updates. An operator chooses model, bank, data, environment and resources. The Ray-based runner creates separate training and validation managers, policy workers, reward machinery and a trajectory collector. Code schedules the outer run; the policy chooses action text within episodes; simulator workers execute projected commands. These workers are not independently prompted specialist agents. The [workflow account](workflow.md#workflow-account) traces this sequence, supported by [RT-RTE-environment-rollout](runtime.md#rt-rte-environment-rollout) and [RT-RTE-policy-update](runtime.md#rt-rte-policy-update).

At reset, the manager selects and caches skills. **Selection is not first-call delivery:** the initial ALFWorld prompt omits skills, and later delivery requires a noninitial observation with positive history length. Each policy call receives a rebuilt user message containing current observation, a recent history suffix and, on that branch, selected skill text. The episode buffer retains older entries in host memory until reset, but this path exposes no policy-controlled arbitrary-history reload tool. It trims by code rule rather than generating a continuation summary. See [RT-RTE-environment-rollout](runtime.md#rt-rte-environment-rollout) and [MEM-OBJ-episode-history](memory.md#mem-obj-episode-history).

The default template selector places all dynamic general skills before static ones, so the requested six slots are not a hard cap. Optional embedding selection can instead omit dynamic rules. General rendering drops applicability conditions; mistake rendering drops explicit reasons. Thus a producer's qualification need not reach the action consumer. The alternate experience selector has manager consumers and similarity-based examples, but its budgets are approximate and its skill-bearing branch does not enforce the advertised token limit. See [MEM-OBJ-skill-content](memory.md#mem-obj-skill-content), [RT-BAP-skill-conditioning](runtime.md#rt-bap-skill-conditioning) and [MEM-RTE-experience-selection](memory.md#mem-rte-experience-selection).

The collector submits decoded action text through projection to the simulator. ALFWorld projection flags formatting problems but does not enforce membership in the listed admissible actions; malformed text can still reach execution. Simulator success supplies bounded outcome feedback, not a corrective-action oracle or proof that a selected rule works. The collector stops at all-done or its configured step bound, subject to backend calls returning, and emits active-step rows with episode statistics. Those rows are not individually complete conversations. See [RT-RTE-environment-rollout](runtime.md#rt-rte-environment-rollout) and [RT-OBJ-trajectory-batch](runtime.md#rt-obj-trajectory-batch).

In the selected driver, actor fitting precedes scheduled validation. Reward and advantage computations feed numerical optimization. Nonfinite-gradient checks can skip an update; they are not a quality test or held-out successor-policy veto. Some configurations accept supplied reward scores rather than simulator-derived episode rewards. See [RT-RTE-policy-update](runtime.md#rt-rte-policy-update).

The driver enables dynamic updates while leaving the training-source flag unset, selecting validation-driven admission. A task success rate below 0.4 triggers failure collection, but the low-success labels do not restrict the collected failures to those categories. Validation deduplicates outputs by the first occurrence of a trajectory identifier before reconstruction; this aligns counts without establishing a full failed conversation. The updater receives at most five examples, their last five parsed steps, observation prefixes of 200 characters and existing skill titles—not existing principles. The alternative training-driven route uses periodically selected training rows without that trajectory deduplication and disables validation-driven updates. See [RT-RTE-validation-admission](runtime.md#rt-rte-validation-admission) and [RT-RTE-training-admission](runtime.md#rt-rte-training-admission).

A distinct remote model proposes new rules. Software parses a JSON array, requires ID/title/principle keys, reassigns IDs and caps proposals before appending them to the training bank and saving a step-labelled file. Requested applicability is not required by the parser. No per-content human approval or comparative candidate-effectiveness test intervenes on this chain. Structural rejection is real, but it does not establish semantic novelty, correct diagnosis or accepted knowledge. The updater's history retains counts and IDs, not originating criticism and evidence. See [EPI-RTE-proposal-check](epistemic.md#epi-rte-proposal-check) and the two admission records.

At a subsequent training reset, the changed bank becomes eligible for selection and later positive-history delivery. Validation writes only the training bank, but its failures can therefore shape subsequent training: separate managers do not establish causal isolation. Actual model dependence on the added rules remains unobserved. Final delivery consists of metrics, actor/optional critic and loader checkpoints, and separately saved skill JSON. Checkpoint resume does not reload the dynamic bank; coupled recovery requires a separately chosen matching bank. Provider-call exceptions can return no proposals, while missing credentials during construction and bank-save failures are not covered by that catch. See the [workflow account](workflow.md#workflow-account), [RT-RTE-validation-admission](runtime.md#rt-rte-validation-admission) and [RT-RTE-policy-update](runtime.md#rt-rte-policy-update).

### What checks license—and what they do not

Other paths qualify any uniform account. Online Search selection expects `task_specific_skills`, while shipped Search banks use `query_type_skills`; query-type instructions are lost on that online path, although general rules and mistakes remain possible and offline distillation supports the Search key. Search retrieval imports passages with unknown source warrant. Its terminal scorer measures normalized reference agreement over answer tags extracted from combined history, not independently verified world truth or reasoning validity. WebShop can replace observations longer than 13,000 characters with a no-history template, dropping history and selected skills for that invocation. See [MEM-CLM-search-category](memory.md#mem-clm-search-category), [EPI-RTE-search-import](epistemic.md#epi-rte-search-import), [EPI-RTE-answer-check](epistemic.md#epi-rte-answer-check) and [report verification](report-verification.md#limits).

For the traced dynamic skill routes, outcome evidence triggers generation; it does not verify the candidate rule. Operational admission, retention and use are not an evidence-consuming acceptance decision against a named effectiveness criterion. These paths therefore retain behavior-shaping candidates, not established accepted ampliative knowledge. Without generated instances, the semantic relation between failures and new rules remains indeterminate: requests for new rules do not prove either faithful compression or conjectural novelty. See [EPI-RTE-proposal-check](epistemic.md#epi-rte-proposal-check) and [RT-RTE-validation-admission](runtime.md#rt-rte-validation-admission). Unassessed alternatives prevent extending this into a system-wide absence of other checks.

### Independent capacity assessments and conditions for change

The localized rule representation is inspectable and editable at whole-principle granularity. On the traced proposal/consumption pathway, the four theory-builder conditions remain separate:

| Condition | Supported assessment |
|---|---|
| 1. Localized formulation | Wired: natural-language principles state guidance in identifiable entries. |
| 2. Content-dependent consumption | Delivery is wired; actual decisions depending on what those principles say are uninspected. |
| 3. Content-directed criticism | Uninspected beyond the bounded prompt/parser account. Title-only hints and failure excerpts do not establish a challenged claim, placement of blame and resulting revision or changed reliance. |
| 4. Criticism-shaped iteration | Repeated additions are wired; keeping a criticism's result so it shapes a next round is uninspected. Counts and IDs do not establish retained criticism. |

These assessments come from [EPI-RTE-proposal-check](epistemic.md#epi-rte-proposal-check), with content and consumer evidence in [MEM-OBJ-skill-content](memory.md#mem-obj-skill-content) and [RT-BAP-skill-conditioning](runtime.md#rt-bap-skill-conditioning). Criticism of a consumed theory improving future action is not established; neither the necessary criticism nor improved capacity is evidenced. This does not negate the implemented trace-fed update routes.

Reflection is wired at a limited aspect: selected task behavior can update its representation in failure-derived instructions, and representation-mediated prompt operations can affect later behavior. Accuracy and exercised influence remain unobserved. Computational proposal and admission are autonomous within the operator-started route, while launch and configuration remain human contributions. Autonomous theory building is unestablished because criticism and criticism-shaped iteration remain unestablished. See [EPI-RTE-proposal-check](epistemic.md#epi-rte-proposal-check).

For self-improvement, the bank pathway supports **improvement-directed self-change capacity** over later training episodes, with benchmark task success as an independently specified objective. Evidence-responsive proposals can change the system's own bank and enter a live advisory channel. The unestablished link is subsequent operation causally depending on that change. Exercised self-improvement and successful improvement therefore remain unestablished. Reward-driven fitting is a separate wired adaptation route, not a substitute witness for skill-specific effects. See [RT-RTE-validation-admission](runtime.md#rt-rte-validation-admission), [RT-RTE-training-admission](runtime.md#rt-rte-training-admission), [RT-BAP-skill-conditioning](runtime.md#rt-bap-skill-conditioning) and the assessments in [EPI-RTE-proposal-check](epistemic.md#epi-rte-proposal-check).

For bounded training with automatic guidance accumulation, the architecture supports successive writes and later consumers. For verified transferable skills, faithful trajectory explanations or exact instruction/policy recovery, its evidence is insufficient. A trace linking failure, admitted rule, final prompt and content-dependent later action would establish exercised parts of the bank pathway. A controlled comparison independently varying bank changes while holding policy fitting and other inputs fixed could establish a skill effect; new-task comparisons would be needed for transfer. Full-principle criticism with retained blame/revision and a next-round consumer would alter the theory-builder assessment. Coupled bank/checkpoint restoration and tested recovery would alter the recovery assessment. The README's reuse, recursive-evolution and 10–20% compression/utility claims remain attributed claims rather than measured conclusions: [RT-CLM-reusable-patterns](runtime.md#rt-clm-reusable-patterns), [EPI-CLM-recursive-evolution](epistemic.md#epi-clm-recursive-evolution), [EPI-CLM-context-efficiency](epistemic.md#epi-clm-context-efficiency).
