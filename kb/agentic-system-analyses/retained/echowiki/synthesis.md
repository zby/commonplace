# EchoWiki synthesis

## Bounded synthesis

### From source admission to a compilation request

EchoWiki is a knowledge-compilation system for Obsidian: incoming notes or voice transcripts become summaries, concept pages and entity pages in a linked Markdown wiki. This account covers the whole shipped production and later-consumption loop at commit `11446997423e88177dba62d6a3d5c1e8b4886c62`, with cutoff 2026-10-14. SRC-1 supplies implementation and doctrine/design, not execution traces or experiments. No target code, tests or provider calls were executed. The plugin, CLI, shared compiler, storage adapters, prompts and maintenance paths are included; Obsidian internals, remote providers and private vault state are not inspectable evidence here ([boundary](boundary.md#boundary-and-evidence), [source register](boundary.md#source-register)).

The representative workflow begins with a supported raw text file detected by the plugin watcher. With watch mode and require-approval enabled, a one-second per-path debounce leads to a persisted queue. The human can preview, approve or reject the path. Approval authorizes compilation of the file's current contents, not a frozen preview or a generated-page diff. Rejecting removes the queue item, not the source. Manual active-file compilation and CLI invocation bypass this watcher gate. Voice capture is another acquisition route: audio is saved before transcription, and nonempty returned text is saved as raw Markdown for possible later compilation. Neither microphone permission nor source approval certifies transcript or output accuracy ([RT-RTE-watcher-approval](runtime.md#rt-rte-watcher-approval), [RT-RTE-voice-ingest](runtime.md#rt-rte-voice-ingest), [workflow](workflow.md#workflow-account)).

### Code sequences the work; models choose content and page tasks

The plugin calls the shared compiler in-process with vault-backed storage; the CLI uses filesystem storage. Code owns the finite progression, while a configured chat model supplies a summary, create/update/related selections and page bodies. These are service calls, not independently scheduled agents or a model-controlled tool loop. Exported file/page/image helpers do not establish a shipped query agent. Human browsing of the resulting index and links belongs to Obsidian ([RT-RTE-document-compile](runtime.md#rt-rte-document-compile), [EPI-RTE-helper-access](epistemic.md#epi-rte-helper-access)).

Each compilation reloads stored `AGENTS.md` or a fallback and delivers it as system-role guidance. Full source text enters the summary call. Planning then receives that source, the draft summary and all eligible concept/entity briefs. Briefs use descriptions, legacy briefs or flattened 150-character body previews; entity briefs also include type and source count. The planning model selects tasks. Only update tasks receive their selected prior page body, without frontmatter. Thus retained descriptions can steer target selection before full old content reaches generation ([RT-OBJ-agents](runtime.md#rt-obj-agents), [RT-BAP-compiler-instructions](runtime.md#rt-bap-compiler-instructions), [MEM-RTE-retained-selection](memory.md#mem-rte-retained-selection)).

Concept and entity generation use separate concurrent pools. Each task receives an explicit message array rather than a growing conversation. Sibling results and the full planning response stay out of that task's context; only returned results reach writers. This isolates task output but does not bound total input: every task still receives the full source, all briefs enter planning, and no aggregate token budget or long-document split is enforced. Cross-invocation continuity comes from page reloads, not saved dialogue or conversation checkpoints ([RT-RTE-document-compile](runtime.md#rt-rte-document-compile), [MEM-RTE-retained-selection](memory.md#mem-rte-retained-selection)).

### Admission permits retention, not factual endorsement

Code filters plan shapes, names and entity types, checks related-page existence and rejects empty generation results. Malformed page JSON can fall back to raw text. Link cleanup tests a whitelist containing existing and planned targets; a failed planned page can therefore leave an admitted link without an eventual target. These checks constrain task eligibility and markup, not truth or claim support ([EPI-RTE-plan-check](epistemic.md#epi-rte-plan-check), [EPI-RTE-plan-dispose](epistemic.md#epi-rte-plan-dispose), [EPI-RTE-link-check](epistemic.md#epi-rte-link-check), [EPI-RTE-link-reshape](epistemic.md#epi-rte-link-reshape)).

The compiler writes entities, optionally rewrites the summary, writes concepts, adds related/reciprocal links, updates the index and appends the ingest log. Summary rewriting receives target names, not the final generated page bodies, so it cannot be treated as an implemented semantic comparison with those pages. Full-body replacement has no independent conflict gate: preserving manually edited meaning is requested from the model, not enforced. A create task can address an existing filename without having received the old body. Entity writers nevertheless use actual existence for metadata handling; concept metadata handling follows the plan branch. The semantic-loss warning does not imply identical metadata loss in both branches ([EPI-RTE-summary-rewrite](epistemic.md#epi-rte-summary-rewrite), [RT-CLM-conflict-policy](runtime.md#rt-clm-conflict-policy), [MEM-OBJ-entities](memory.md#mem-obj-entities), [MEM-RTE-page-maintenance](memory.md#mem-rte-page-maintenance)).

Sources and counts are association metadata, not corroboration. Summary `full_text` pointers name source copies that this short-document loop does not write; concept/entity source fields point to summaries. Retention therefore supplies navigation and context without a claim-level evidence recovery guarantee. Imported source warrant remains unknown. Without actual source/output pairs, generated content cannot be classified as faithfully preserved, entailed from warranted premises or demonstrably novel. Within the inspected shipped paths, no evidence-consuming factual acceptance decision, post-acceptance integration or refutation-directed withdrawal was found ([MEM-OBJ-page-metadata](memory.md#mem-obj-page-metadata), [MEM-OBJ-sources](memory.md#mem-obj-sources), [EPI-RTE-source-lineage](epistemic.md#epi-rte-source-lineage), [EPI-RTE-page-generate](epistemic.md#epi-rte-page-generate), [EPI-ABS-quality-gate](epistemic.md#epi-abs-quality-gate)).

### Delivery and later reuse

Persistent wiki writes and resolved caller completion constitute the shipped delivery criterion, not successful generation of every planned page. Individual task failures are skipped; malformed/empty plans and failed summary rewrites have fallbacks. Later storage failures can leave earlier writes intact. Re-running recomputes from current source/wiki rather than resuming a checkpoint, and different input paths are not serialized against shared page/index/log targets. In a non-overlapping approval, a thrown failure normally leaves the queued path for retry. An overlapping approval can instead return through the in-flight guard and remove that item before the active compile finishes or fails. Queue disappearance and modal completion notices alone are not universal delivery witnesses ([RT-RTE-document-compile](runtime.md#rt-rte-document-compile), [workflow](workflow.md#workflow-account), [report-verification limits](report-verification.md#limits)).

The strongest supported contribution to future work is durable context reuse: automatically admitted concept/entity descriptions and selected bodies reach later planning and rewriting. The compiler supplies this context automatically at the model-consumer boundary, although a new compilation triggers the chain. Requested raw-file reads and documented human browsing are separate request-fulfillment operations. Local memory combines prose with code-interpreted paths, links and metadata; previews compress retained representations and replacements revise entries. These mechanisms establish wiring, not observed response dependence or improved capacity ([MEM-RTE-retained-selection](memory.md#mem-rte-retained-selection), [RT-BAP-retained-pages](runtime.md#rt-bap-retained-pages), [MEM-OBJ-index](memory.md#mem-obj-index), [profile verification](profile-verification.md#verification)).

Learning as improved capacity remains unestablished: there is no measured improvement comparison. The operation log has no inspected consumer that extracts future guidance, while generic notes/transcripts have unresolved activity-trace origin; neither a positive trace-learning route nor a system-wide negative follows. Operator instruction edits can change later prompt supply, but the compiler does not revise its own instructions. Reflection about its own operation and autonomous theory building are not established by these paths; automated sequencing is a narrower supported property. The records do not establish formulated content-directed criticism retained into another round. No improvement objective, evidence-responsive organizational update and subsequent causally dependent operation is demonstrated, so exercised self-improvement is not established. This does not exclude retained pages from behavior-determining state merely because they are outputs, or infer absent reasoning inside opaque providers ([MEM-ABS-feedback-consumer](memory.md#mem-abs-feedback-consumer), [MEM-OBJ-raw](memory.md#mem-obj-raw), [RT-RTE-instruction-settings](runtime.md#rt-rte-instruction-settings), [epistemic conclusion](epistemic.md#bounded-conclusion), [RT-CMP-llm-model](runtime.md#rt-cmp-llm-model)).

For repeated note ingestion and wiki navigation, the implementation establishes a concrete retained-context and maintenance path. For trustworthy cross-document knowledge production, reliable human-edit preservation or complete-page delivery, its structural gates and prompt policies establish narrower guarantees. Source/output traces with recorded acceptance decisions would change the knowledge assessment; overlap/failure traces and transaction/conflict controls would change the recovery assessment; independently specified objectives, retained evidence-driven changes and controlled later comparisons would change the learning/self-improvement assessment. None is supplied by the current evidence ([EPI-CLM-cross-synthesis](epistemic.md#epi-clm-cross-synthesis), [EPI-ABS-quality-gate](epistemic.md#epi-abs-quality-gate), [RT-RTE-document-compile](runtime.md#rt-rte-document-compile)).
