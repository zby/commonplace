# Synto synthesis

## Bounded synthesis

Synto is a staged knowledge-production and consumption application. It turns source notes into linked wiki articles and portable packs, then supplies retained content to question-answering models, people and external agents. Python owns stage progression; configurable fast and heavy model endpoints propose analysis, articles and answers. It is not, on the inspected central route, a general model-controlled tool loop. This account covers the shipped lifecycle in `https://github.com/kytmanov/synto` at commit `91ac6a3681df0552b6c9baef159439c7ebd780c9`, with an analysis cutoff of 2026-10-15. SRC-1 supplies implementation and doctrine/design evidence only. No target code, tests, providers or examples were executed, and no user vault, execution trace or measured comparison was supplied. A whole-system functional boundary does not imply exhaustive inspection of every helper or observed successful operation ([boundary](boundary.md#boundary-and-evidence), [RT-RTE-pipeline-run](runtime.md#rt-rte-pipeline-run)).

### From sources to reusable candidates

An operator supplies Markdown or imports documents. Synto can archive originals, extract source segments and retain canonical raw text. Fast-model analysis produces summaries, concepts and source relationships; heavy-model compilation combines selected source bodies into concept drafts. Markdown and SQLite retain different parts of this state. Original text, derived prose and symbolic status, identity and hash fields are not interchangeable: prose informs a model, while fixed-rule metadata can decide eligibility or block a write ([MEM-OBJ-source-documents](memory.md#mem-obj-source-documents), [MEM-OBJ-raw-notes](memory.md#mem-obj-raw-notes), [RT-RTE-pipeline-run](runtime.md#rt-rte-pipeline-run)).

Each inference call receives reconstructed, bounded context rather than a shared agent conversation. Ingestion removes media/OCR noise from model input and selects concept hints. Compilation gathers budgeted source text, title hints, conventions, bounded existing-article text and recent rejection feedback. Sources remain on disk, but a title in the model window does not automatically reload them. Overflow recovery progressively reduces source and existing-text budgets and marks a successful fallback draft degraded. This can restore a writing path without preserving full-source coverage. Typed chunk checkpoints support interrupted ingestion; an exact-key response cache can substitute a prior output before inference. Neither establishes retention of private model reasoning. On the inspected OpenAI-compatible adapter, generation options are omitted from the cache key, so changed options need not cause fresh inference ([RT-RTE-pipeline-run](runtime.md#rt-rte-pipeline-run), [MEM-RTE-checkpoint-resume](memory.md#mem-rte-checkpoint-resume), [MEM-RTE-response-reuse](memory.md#mem-rte-response-reuse)).

### Admission, criticism and delivery

The representative workflow is coherent but source-reconstructed: run analysis and compilation, review a retained draft, optionally reject and recompile, then publish. Models generate content; the Python coordinator schedules stages and the human reviewer supplies the manual admission decision. Review offers editing, staging, publication, deferral and rejection, but initial display is limited to 3,000 characters and direct publication is the default single-draft action. Staging as verified is optional. Automatic approval is a separate supported branch, not evidence that human review occurred ([WF-RTE-interactive-review](workflow.md#wf-rte-interactive-review), [RT-RTE-draft-publication](runtime.md#rt-rte-draft-publication)).

The strongest supported experience-fed contribution is durable rejection guidance. With nonempty feedback, rejection retains the reason and rejected body; a later compiler supplies up to three recent feedback strings to the writer. The rejected body supports human diffs rather than being included through that prompt path. Automatic feedback-conditioned rewriting can produce a durable article available to later answering or export. This supports the verified local trace-learning finding: experience feeds an automatic behavior-shaping write. It does **not** demonstrate improved future capacity. Empty-feedback rejection can still delete a draft and reset bound compilation state without preserving a rejection record. Feedback-bearing rejections accumulate toward a cap of five; unblocking preserves history. A subsequent compilation invocation is needed, rather than rejection immediately launching a correcting agent ([MEM-OBJ-rejections](memory.md#mem-obj-rejections), [RT-BAP-rejection-guidance](runtime.md#rt-bap-rejection-guidance), [WF-RTE-interactive-review](workflow.md#wf-rte-interactive-review), [profile verification](profile-verification.md#verification)).

Publication writes the destination, updates database state and only then removes the draft. That order is not a transaction across filesystem and SQLite. The optional confidence threshold uses source count and the best source's structural-quality label, not article-level truth assessment. Lint is not a universal publication veto; on the non-auto-approval branch it precedes technical retries without a final rerun. Source summary pages are published directly, and saved synthesis has its own admission path. Consequently, draft review is neither universal knowledge admission nor universal factual acceptance ([RT-RTE-draft-publication](runtime.md#rt-rte-draft-publication), [EPI-RTE-confidence-score](epistemic.md#epi-rte-confidence-score), [MEM-OBJ-source-summaries](memory.md#mem-obj-source-summaries), [MEM-RTE-synthesis-save](memory.md#mem-rte-synthesis-save), [workflow ordering](workflow.md#annotations)).

Identity curation has a different, deterministic effect. Blessed aliases guide canonicalization, while retained denials can veto later reattachment. A JSON seed preserves selected identity decisions across database rebuilding. Merge, split and retirement can change source allocation and later routing, but semantic correctness is not established by successful mutation. Recovery horizons differ: Git undo need not reverse database state, unmerge does not restore every ledger, and clean preserves selected identity state rather than the entire prior knowledge system ([MEM-OBJ-concept-entities](memory.md#mem-obj-concept-entities), [RT-RTE-concept-curation](runtime.md#rt-rte-concept-curation), [MEM-RTE-identity-rebuild](memory.md#mem-rte-identity-rebuild), [EPI-RTE-state-recovery](epistemic.md#epi-rte-state-recovery)).

### Later consumption and its authority

A question triggers a fast-model page selection from the Markdown catalogue, followed by loading resolved pages and a heavy-model answer. Alias expansion and optional graph neighbors can broaden selection; delivered bodies are capped at 8,000 characters per page. Selected names can exceed bodies actually loaded. Grounding instructions request an answer from wiki content but do not check entailment. Saving ordinary Q&A creates a file without automatically enumerating the queries tree into that catalogue. Such files remain accessible through filesystem/export paths and recursive title resolution when a matching title is supplied. Synthesis has explicit later catalogue admission, limited to the newest 25 entries, and guards against direct synthesis-source chaining and overwriting detected manual edits. Those guards do not validate answer truth or establish universal prevention of indirect derivative reuse ([RT-RTE-query-answer](runtime.md#rt-rte-query-answer), [EPI-RTE-answer-retention](epistemic.md#epi-rte-answer-retention), [MEM-OBJ-index](memory.md#mem-obj-index), [EPI-RTE-synthesis-guard](epistemic.md#epi-rte-synthesis-guard)).

MCP offers both synthesized answering and primitive article/source access. Stored source passages can reach later client invocations without a knowledge write; this is read-back, not proof of downstream model use. Article visibility and source-license gating are separate controls. The answer loader's source-summary exception and general routing index prevent treating ordinary article visibility as all-channel confidentiality. License grandfathering can be cached for the process lifetime. Export is different again: packs can include raw notes, drafts, summaries, Q&A and synthesis independently of MCP article policy. Generated agent instructions request read-only and source-checking behavior, but actual loading and compliance belong to the external host. Re-export refreshes managed trees, not previously distributed copies ([MEM-RTE-source-passages](memory.md#mem-rte-source-passages), [RT-RTE-mcp-answer](runtime.md#rt-rte-mcp-answer), [RT-RTE-pack-export](runtime.md#rt-rte-pack-export), [RT-BAP-pack-guidance](runtime.md#rt-bap-pack-guidance)).

### What the checks and feedback establish

Synto has consequential checks, not merely unchecked generation: schema parsing, selected lexical candidate filters, relation endpoint resolution, overwrite and chain guards, structural lint and evaluation. Their licenses remain local. Chunk-wide concept attribution with code-assigned confidence 1.0 is not paragraph entailment. A relation evidence string is not a verified quotation. The offline evaluator's citation coverage checks nonempty source metadata rather than proposition-level support. The comparison advisor additionally checks expected pages, answer substrings and refusal behavior and can recommend switching configuration; it leaves installation to the human. Skipped offline term recall must not be generalized to no answer-content checking anywhere. No supplied comparison demonstrates semantic accuracy or causal model benefit ([EPI-RTE-candidate-filter](epistemic.md#epi-rte-candidate-filter), [EPI-RTE-occurrence-lineage](epistemic.md#epi-rte-occurrence-lineage), [EPI-RTE-offline-evaluation](epistemic.md#epi-rte-offline-evaluation), [RT-RTE-compare-eval](runtime.md#rt-rte-compare-eval), [report verification](report-verification.md#limits)).

The resulting assessment is scenario-relative. For source-to-wiki organization and later bounded context delivery, inspected wiring supports acquisition, consolidation, revision, identity constraints and reuse. For factual knowledge production, generated candidates and operational publication do not establish evidence-consuming acceptance against a named factual criterion. Without candidate/input instances, the semantic relation of model-generated assertions remains indeterminate: neither entailed derivation nor accepted ampliative knowledge is established. The source-native word “synthesis” does not resolve that distinction ([EPI-CLM-wiki-synthesis](epistemic.md#epi-clm-wiki-synthesis), [EPI-OBJ-query-answer](epistemic.md#epi-obj-query-answer), [EPI-RTE-answer-retention](epistemic.md#epi-rte-answer-retention)).

The properties of learning, theory building, reflection, autonomy and self-improvement remain separate. The feedback path supports durable experience-fed revision, while improved capacity from criticism of a consumed theory remains unestablished. The reports do not establish theory-builder condition 1's formulated theory instance, condition 2's content-dependent theory consumption, condition 3's challenged claim/result/blame placement, or condition 4's iteration of that criticism result. A delivered reason and later revision request alone establish none of those conditions. Reflection on Synto's own method is not established by article criticism. Python's automatic stage progression does not establish autonomous theory building, since the documented criticism branch uses human judgment. These are bounded evidential non-conclusions, not system-complete absences ([RT-BAP-rejection-guidance](runtime.md#rt-bap-rejection-guidance), [RT-RTE-draft-publication](runtime.md#rt-rte-draft-publication), [WF-RTE-interactive-review](workflow.md#wf-rte-interactive-review)).

For self-improvement at this shipped lifecycle boundary, retained articles can affect later system behavior; their being outputs does not exclude them from consideration. However, no concrete objective-bearing criticism/update episode and subsequent operation establishes exercised self-improvement, and no outcome comparison establishes successful improvement. Comparison reports are not automatically installed production changes. A provenance-linked rejection, revised article, actual later consumption and independently specified outcome comparison would change the feedback assessment. Candidate/source pairs and evidence-consuming review decisions would change the factual-acceptance assessment. Host-consumption traces and injected-store contracts would resolve different questions, not substitute for those comparisons ([RT-BAP-rejection-guidance](runtime.md#rt-bap-rejection-guidance), [RT-RTE-query-answer](runtime.md#rt-rte-query-answer), [RT-RTE-compare-eval](runtime.md#rt-rte-compare-eval), [MEM-OBJ-rag-embeddings](memory.md#mem-obj-rag-embeddings)).
