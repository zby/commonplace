# Ars Contexta synthesis

## Bounded synthesis

### Derive an operating vault

Ars Contexta is a Claude Code plugin that derives a domain-specific Markdown knowledge vault and supplies procedures for operating it. It is not an enclosing model runtime. This analysis covers the shipped builder, processing and maintenance procedures, retained-state consumers and hook implementations at commit `2acfd5cc4473c4d06c46be63df748e77e00e2746`, with an applicability cutoff of 2026-10-12. Its sole source is SRC-1. Shell implementations make the overall account code-grounded, but most semantic decisions and delegation are specified in model-facing instructions. No target execution, installed vault, session trace or causal experiment was supplied. Source-native reports are attributed reported operation, not independently observed results. Claude Code, model providers and optional qmd/MCP search implementations are outside the inspected implementation. See the [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

Setup elicits needs, derives dimensions and vocabulary using bundled methodology, presents a proposal, then requests generation of folders, configuration, context, templates, skills and hooks. It persists derivation reasons before generation and rereads them after possible context compaction. This is a specified checkpoint of design decisions, not an implementation of the host's compactor. Generated project context and separately loaded skills supply standing directions through host loading and model interpretation. Setup's transformed-copy procedure conflicts with inheritance language elsewhere; installed skill selection and automatic plugin-update reach remain unresolved. [RT-RTE-setup-generation](runtime.md#rt-rte-setup-generation), [MEM-OBJ-derivation](memory.md#mem-obj-derivation), [RT-OBJ-claude-md](runtime.md#rt-obj-claude-md), [RT-BAP-context-instructions](runtime.md#rt-bap-context-instructions), [RT-CLM-generation-paths](runtime.md#rt-clm-generation-paths).

### Process a source through persistent handoffs

The representative workflow is `/pipeline [source-file]`, because its wrapper explicitly joins source admission, extraction, note creation, connection updates, verification and archive/report delivery. Seed checks existence and duplicates, requests a decision on possible reprocessing, establishes an archive and extract-task file, and writes queue state. Queue identifiers and phase fields select work; task files retain source references, extraction reasons and phase findings for later workers. These are different memory functions. [RT-RTE-source-processing](runtime.md#rt-rte-source-processing), [RT-OBJ-queue](runtime.md#rt-obj-queue), [MEM-OBJ-task-files](memory.md#mem-obj-task-files).

The first delegation edge is conditional: seed's extract-entry templates omit `batch` and `current_phase`, while pipeline requests batch/type-filtered extraction and ralph filters and dispatches on those fields. The inspected procedures specify no repair rule. This is an instruction mismatch, not an observed failure; downstream extraction requires an eligible entry. Reduce then proposes findings and requires approval before creation, including in handoff mode, while the driver requests workers in `dontAsk` mode. Neither initiating pipeline nor that mode establishes that per-content approval occurred. [WF-CLM-extract-selection](workflow.md#wf-clm-extract-selection), [EPI-RTE-reduce-admission](epistemic.md#epi-rte-reduce-admission).

For eligible claim work, serial ralph's lead reads the queue, selects the first pending entry, supplies a phase prompt and task pointer, requests a Task worker, evaluates its return, advances state and rereads the queue. Workers create notes, add connections and topic-map membership, revise older notes and verify quality. Selected sibling titles supplement their own file reads; the titles do not supply all sibling arguments. Fresh context is a requested host protocol, not demonstrated isolation. Pipeline passes a pending-claim count, but serial iterations advance phases, so that count does not ensure completion of whole claims. Parallel ralph instead assigns remaining phases and queue completion to full-claim workers, up to five at once. Waiting for all returns, including errors, before cross-connect does not establish successful claims or transactional shared writes. [RT-RTE-source-processing](runtime.md#rt-rte-source-processing), [RT-RTE-parallel-claims](runtime.md#rt-rte-parallel-claims).

Verification predicts content from title and description before reading the body, then checks prediction fidelity, schema and graph health; unavailable semantic retrieval can be deferred. Its failure rule holds a task at verify when the prediction score is below three or a FAIL-level issue remains. Ralph nevertheless permits continuation and completion without a handoff. Done state therefore cannot certify successful verification, much less factual truth. A later cross-connect repairs missing sibling/backward links. The outer wrapper forbids archiving pending tasks and otherwise requests archival of detailed task files, a summary and a final report listing notes, counts and paths. Failed processing or archiving can leave substantive edits in place; resumption is specified, not automatic rollback. [EPI-RTE-verify-check](epistemic.md#epi-rte-verify-check), [EPI-RTE-verify-disposition](epistemic.md#epi-rte-verify-disposition), [RT-CLM-completion-gate](runtime.md#rt-clm-completion-gate), [workflow account](workflow.md#workflow-account).

### Reuse and revise retained content

The vault retains natural-language claims and reasons alongside symbolic navigation and scheduling metadata. Reflect/reweave request full note and task reads, follow curated topic links, and use semantic or keyword candidates. Reflect requires articulated relationships and traversal utility; it flags standalone synthesis opportunities rather than creating those notes. Map-opening prose can still change. Reweave compares old claims with newer vault evidence and records original claim, new evidence and revised position. Interactive revision requires approval; handoff revision applies directly, while merge/delete judgments remain human-controlled. This is content-directed criticism as specified, not merely storage or backlink creation. [MEM-OBJ-notes](memory.md#mem-obj-notes), [MEM-OBJ-topic-maps](memory.md#mem-obj-topic-maps), [MEM-RTE-note-maintenance](memory.md#mem-rte-note-maintenance), [EPI-RTE-reflect-use](epistemic.md#epi-rte-reflect-use), [EPI-RTE-reweave-revision](epistemic.md#epi-rte-reweave-revision).

Sources and query/backlink lineage support attribution, not authenticated truth. Learn files provider findings and themed synthesis for later reduce consumption; its provenance fields differ from reduce's preservation vocabulary. Without concrete input/output pairs, note expansion, map arguments and revisions do not establish semantic preservation, warranted deduction or accepted ampliative knowledge. Approval for inclusion, linking, retention and later use are not substitutes for a recorded evidence-consuming truth-acceptance decision for a named use and scope. No such accepted instance is established in the inspected routes; incompletely assessed alternatives prevent a system-wide absence claim. [MEM-RTE-research-intake](memory.md#mem-rte-research-intake), [MEM-OBJ-inbox](memory.md#mem-obj-inbox), [EPI-RTE-reduce-content](epistemic.md#epi-rte-reduce-content), [epistemic bounded conclusion](epistemic.md#bounded-conclusion).

SessionStart provides a narrower automatic read-back channel. The registered plugin prints existing goals and, under identity-file existence, full self files; five recent operational-methodology files contribute only their first three lines. The generated template instead selects titles and gates self files differently. Neither recent-note channel delivers complete directives and reasons, and full-file delivery has no hard token ceiling. Plugin tracking may replace current-session JSON before displaying purported previous context. Generated Stop capture writes lifecycle ID/time/status, not the substantive Markdown required by session mining. Manual/model summaries, reminders and task handoffs remain alternative continuity paths. [RT-RTE-session-orientation](runtime.md#rt-rte-session-orientation), [MEM-RTE-generated-orientation](memory.md#mem-rte-generated-orientation), [MEM-OBJ-session-log](memory.md#mem-obj-session-log), [MEM-CLM-transcript-gap](memory.md#mem-clm-transcript-gap).

The deterministic layer is advisory about content. Registered PostToolUse validation matches Write, not Edit or Bash, checks limited paths and text-field presence after the effect, and exits zero. Async Git persistence stages all pending changes and tolerates commit failure; it is neither semantic endorsement nor guaranteed recovery. Config flags do gate particular callback effects, but that is not universal write enforcement. The kernel evaluator separately computes bounded structural predicates and samples links; it does not supply a factual answer oracle. [RT-RTE-write-hooks](runtime.md#rt-rte-write-hooks), [EPI-RTE-hook-shape](epistemic.md#epi-rte-hook-shape), [EPI-RTE-kernel-check](epistemic.md#epi-rte-kernel-check), [EPI-CLM-write-enforcement](epistemic.md#epi-clm-write-enforcement).

### Let operational evidence change future guidance

The strongest supported improvement-related contribution is a specified path from operational evidence to durable, criticizable guidance. Remember converts explicit corrections, confirmed contextual interpretations or mined session evidence into scoped directives and observations. Reasons persist for full-body consumers such as ask and rethink, though not in title/header-only orientation. Mining specifies model admission without a per-finding confirmation gate; contextual confirmation is not universal. Next retains recommendation activity and uses recent history to avoid repeated suggestions, while workers retain phase findings for later workers. These are claimed automatic trace-fed durable update/consumer paths, not measured improvements in future capacity. The independently checked memory comparison retains partial coverage on all ten axes, including unresolved numerical, initialization and history alternatives. [MEM-RTE-friction-retention](memory.md#mem-rte-friction-retention), [MEM-RTE-local-guidance](memory.md#mem-rte-local-guidance), [MEM-RTE-work-selection](memory.md#mem-rte-work-selection), [MEM-OBJ-next-log](memory.md#mem-obj-next-log), [MEM-OBJ-task-files](memory.md#mem-obj-task-files), [profile verification](profile-verification.md#verification).

Rethink and architect specify criticism of the generated system's own operating assumptions: quote the assumption, compare operational evidence, propose a literal successor with expected benefit and risks, obtain human approval, then retain changes, reasons and resolution references. Refactor and upgrade offer related but distinct replacement paths; upgrade copies old skills for manual rollback, whereas refactor's archive-labelled step does not establish equivalent backups. [RT-RTE-architecture-evolution](runtime.md#rt-rte-architecture-evolution), [MEM-RTE-config-refactor](memory.md#mem-rte-config-refactor), [RT-RTE-skill-upgrade](runtime.md#rt-rte-skill-upgrade).

For that method-criticism route, theory-builder conditions are separately **claimed**: (1) localized quoted assumption content; (2) content-dependent proposals; (3) challenged placement and resulting revision; (4) retained successors intended to shape later rounds. Their performance is unobserved. Reflection and reflective theory building are also **claimed** for this route: operation is represented in method/configuration texts, and evidence-responsive representation changes are intended to affect future behavior. Autonomous theory building is not established: human selection/veto is an internal admission operation. Whether criticism of a consumed theory improved capacity for future action remains **uninspected**, independently of those architectural claims. Domain-note criticism has its own claimed conditions 1–4; the analysts disagree whether reflection there is inapplicable or uninspected, so no common domain-route reflection label is assigned. [RT-RTE-architecture-evolution](runtime.md#rt-rte-architecture-evolution), [MEM-RTE-note-maintenance](memory.md#mem-rte-note-maintenance), [EPI-RTE-reweave-revision](epistemic.md#epi-rte-reweave-revision).

Across future sessions of the generated operating system, the independent objective is reducing named operational friction or quality failures. The method route supports a claimed, dormant improvement-directed self-change design, not exercised or successful self-improvement. None of the four causal links is demonstrated: objective-bearing evidence shaping the update, the update changing live organization, that organization entering later behavioral authority, and subsequent operation causally depending on it. In particular, persisted or loaded instruction successors do not prove changed behavior or benefit. The scientific-method and hypothesis-test analogies do not supply missing causal comparisons. [RT-RTE-architecture-evolution](runtime.md#rt-rte-architecture-evolution), [EPI-CLM-scientific-method](epistemic.md#epi-clm-scientific-method), [EPI-CLM-hypothesis-test](epistemic.md#epi-clm-hypothesis-test).

For a scenario requiring inspectable reasons and resumable model work, the specified derivation/task checkpoints and content-criticism procedures are the supported contribution. For unattended source-to-verified-note delivery, automatic substantive continuity or evidence of improved future behavior, the same records leave central edges unresolved. Assessment would change with consistent seed/filter and phase-count contracts, an explicit failure-aware completion rule, deployed skill/hook artifacts, transcript-to-mining provenance, and traces connecting retained successors to later action. Outcome comparisons against the stated objective would be needed for successful improvement, with attribution no finer than the varied treatment.
