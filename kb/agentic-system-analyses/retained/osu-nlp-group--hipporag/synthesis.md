# HippoRAG synthesis

## Bounded synthesis

### From documents to retained search state

HippoRAG is a document-memory system, not the enclosing agent that decides which arbitrary tools to use. This account covers its shipped Python library and callers, optional Model Context Protocol (MCP) service, plugin and maintenance skills at commit `d5c8329422e0a0b834a15874545cb6a74b4f9b26`, with an applicability cutoff of 2026-10-16. The evidence is inspected implementation and attributed doctrine/design from SRC-1, the frozen HippoRAG repository. There is no registered execution trace or causal experiment. The whole-system functional boundary includes shipped maintenance and consumption paths; it does not imply exhaustive inspection of every adapter or external service. See [boundary](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The strongest supported contribution is a wired path from new documents to durable, later-searchable state, including a shipped caller that reopens an index before consuming it. Original passages remain separate from the model-derived representation that selects them. This establishes a cross-instance memory mechanism, not observed successful reuse or improved answer quality. The public claim of recognizing connections has an operational counterpart in derived graph links and retrieval, without establishing reliable recognition or a biological equivalence: [RT-RTE-index-state](runtime.md#rt-rte-index-state), [MEM-OBJ-passage-text](memory.md#mem-obj-passage-text), [EPI-CLM-memory-connections](epistemic.md#epi-clm-memory-connections).

A caller supplies strings or provenance-bearing chunks. Default preprocessing leaves each document intact. Online extraction performs named-entity recognition and then relation-triple generation. Code parses and filters structures, normalizes strings, encodes passages/entities/facts and constructs source-aware graph edges, including similarity-based entity links. The extraction, QA and embedding roles can use configured services or injected components; the inspected orchestration does not update their parameters, but it also does not enforce immutable weight identities. See [EPI-RTE-openie-generation](epistemic.md#epi-rte-openie-generation), [RT-CMP-extraction-llm](runtime.md#rt-cmp-extraction-llm), [RT-CMP-qa-llm](runtime.md#rt-cmp-qa-llm), [RT-CMP-embedding-model](runtime.md#rt-cmp-embedding-model).

Structural admission is not acceptance of relation truth. Parsing, triple arity and duplicate removal permit indexing without testing whether a relation follows from its passage. Normalization can also collapse distinctions: the recorded implementation deduction maps both C++ and C# to `c`. Original passages survive, so this is a risk to search identity rather than universal destruction of source meaning. The semantic relation between actual extraction outputs and inputs remains indeterminate without paired evidence: [EPI-RTE-triple-check](epistemic.md#epi-rte-triple-check), [EPI-RTE-triple-admission](epistemic.md#epi-rte-triple-admission), [EPI-RTE-text-normalization](epistemic.md#epi-rte-text-normalization).

### Reuse, refresh and withdrawal

Default persistence combines Parquet text/vector stores, JSON extraction/provenance state and a pickled graph. The extraction state retains source passages and extracted structures, not the full response metadata or a justification for each relation. A manifest and preparation checks can veto incompatible recorded configurations or inconsistent store/graph identities. These are bounded compatibility checks, not truth certificates or a transaction across all writes: passage persistence precedes extraction and later graph construction. See [MEM-OBJ-openie-state](memory.md#mem-obj-openie-state), [MEM-OBJ-graph-state](memory.md#mem-obj-graph-state), [RT-CLM-state-compatibility](runtime.md#rt-clm-state-compatibility).

Passage identity is a content hash; `source_id` is current caller-supplied metadata. Repeated identical text can replace that metadata without new extraction or embedding. Two sources containing identical text therefore do not acquire independent ownership of the same passage. Deletion removes selected source contributions and unreferenced derivatives while retaining facts supported by surviving chunks. Refresh by delete then index is not atomic replacement. Separately, the inspected SQLite response cache can replay raw model outputs for matching requests and is not erased by document deletion. Withdrawal from the searchable index is consequently not secure forgetting: [MEM-OBJ-chunk-metadata](memory.md#mem-obj-chunk-metadata), [RT-RTE-index-state](runtime.md#rt-rte-index-state), [MEM-RTE-response-reuse](memory.md#mem-rte-response-reuse).

### From a question to an answer

On the ordinary route, query embeddings select candidate facts, a generative model judges their relevance, and code remaps generated selections to candidate strings. Candidate membership is constrained, but nearest-string matching with cutoff zero does not guarantee faithful model intent, relevance or truth. Selected facts seed personalized PageRank over an undirected graph projection alongside dense passage weights. Empty or failed filtering instead selects dense retrieval. The library, not a general model dispatcher, owns this progression: [EPI-RTE-fact-check](epistemic.md#epi-rte-fact-check), [EPI-RTE-fact-selection](epistemic.md#epi-rte-fact-selection), [RT-RTE-retrieve-answer](runtime.md#rt-rte-retrieve-answer).

QA receives selected original passage text, the question and static guidance—not the whole graph, source metadata or extraction rationale. Context selection is primarily count-bounded, not an aggregate token guarantee. The memory account records defaults of five linked candidates, 200 retrieved passages and five QA passages; default preprocessing itself imposes no passage splitting. Material outside the prompt remains reachable through further retrieval, not through dereferenceable pointers in the model window. This is requested retrieval, not independently established unsolicited memory injection. See [memory core ideas](memory.md#core-ideas), [MEM-OBJ-passage-text](memory.md#mem-obj-passage-text), [RT-RTE-retrieve-answer](runtime.md#rt-rte-retrieve-answer), [profile verification](profile-verification.md#verification).

The returned answer is model text, with delimiter-based parsing rather than a semantic correctness gate. “Grounded” therefore denotes passage-conditioned generation here, not demonstrated entailment. Optional benchmark evaluation compares answers to supplied aliases using normalized exact match and token F1, and passages to exact document strings using recall. Scores are logged or returned; the inspected driver does not use them to accept claims or revise the pipeline. Host guidance asks an agent to check server answers against passages, but actual checking is unobserved: [EPI-CLM-grounded-answer](epistemic.md#epi-clm-grounded-answer), [EPI-RTE-metric-evaluation](epistemic.md#epi-rte-metric-evaluation), [EPI-RTE-host-check](epistemic.md#epi-rte-host-check).

Material alternatives qualify this map. Direct dense retrieval and the separate StandardRAG baseline bypass graph filtering; supplied query solutions can bypass retrieval. IRCoT uses generated thoughts as further queries, merges passage scores and stops on an answer marker or step limit. Those thoughts are current-call state, not demonstrated durable method revision. vLLM offline extraction saves state then deliberately requires a later online build; Transformers-offline participates in indexing and has different parsing/error behavior. Neither inherits every online rejection guarantee. See [RT-RTE-standard-rag](runtime.md#rt-rte-standard-rag), [RT-OBJ-query-solution](runtime.md#rt-obj-query-solution), [RT-RTE-ircot-retrieval](runtime.md#rt-rte-ircot-retrieval), [RT-RTE-offline-extraction](runtime.md#rt-rte-offline-extraction).

### Host-directed folder ingestion

The representative multi-step workflow is the shipped folder-indexing skill. The host selects files, excludes unsuitable material, prepares roughly 100–400-word passages, presents a plan and seeks confirmation above about 50 passages. Refresh first deletes by source ID; batches then submit prepared texts and provenance, and the host is instructed to report counts and skipped-file reasons. This is a connected prescribed workflow, not an observed host session. Confirmation and chunking are host-interpreted policy, not server-enforced approval or token limits. The skill's one-extraction-call/no-retrieval-LLM guidance is not universal: online extraction has two stages and ordinary filtering is model-backed. See [WF-RTE-folder-indexing](workflow.md#wf-rte-folder-indexing), [EPI-CLM-call-guidance](epistemic.md#epi-clm-call-guidance).

The MCP service serializes individual operations on one instance, returns typed counts/results and converts failures into tool errors. The host retains responsibility for subsequent batches, recovery and final reporting. Counts are not per-file or semantic audits; a successful delete followed by failed replacement can leave old content unavailable. Read-only launch omits index/delete tool registration, but does not prevent every filesystem/cache write or coordinate independent processes. See [RT-RTE-mcp-tools](runtime.md#rt-rte-mcp-tools), [WF-RTE-folder-indexing](workflow.md#wf-rte-folder-indexing).

### What the evidence changes—and does not

For a scenario requiring persistent document acquisition and later passage selection, the supported result is a concrete implementation with reload consumers, explicit withdrawal and alternate retrieval routes. For a scenario requiring verified factual admission, atomic refresh, secure erasure or demonstrated answer improvement, those mechanisms do not establish the required conclusion. No product ranking follows from this distinction.

Durable document additions can change what later retrieval can access. Whether this improves capacity for future action remains unestablished; no criticism-to-revision-to-later-benefit comparison is recorded. In particular, criticism of a consumed theory is not shown to improve future capacity. The runtime supplies no formulated-theory assessment establishing theory-builder conditions 1–4, and these conditions cannot be inferred from triples, relevance judgments or benchmark scores. Reflection is independently unestablished: retained source/configuration state does not by itself evidence both causal directions of a self-representation. Internal library sequencing is wired, but autonomous theory building and autonomous ownership of the host-directed workflow are not established. See [RT-RTE-index-state](runtime.md#rt-rte-index-state), [EPI-RTE-metric-evaluation](epistemic.md#epi-rte-metric-evaluation), [epistemic bounded conclusion](epistemic.md#bounded-conclusion), [WF-RTE-folder-indexing](workflow.md#wf-rte-folder-indexing).

The same positive memory contribution does not establish self-improvement at this boundary. No objective-bearing evaluation is shown determining a durable method update that later operation exercises; neither retaining new documents nor loading static prompts closes that pathway. This is not a system-wide absence claim. Trace-fed learning also remains unresolved because arbitrary admitted documents lack a recorded trace-origin inventory, raw response replay alone establishes no qualifying derived update, and alternative caches remain uninspected. See [RT-RTE-index-state](runtime.md#rt-rte-index-state), [MEM-RTE-response-reuse](memory.md#mem-rte-response-reuse), [profile verification](profile-verification.md#verification).

Paired passage/extraction/answer traces with semantic adjudication would change the factual-fidelity assessment. Controlled comparisons varying the graph/filter or a retained revision would change the benefit and attribution assessment. A recorded evaluation-driven update with a later consuming execution would be needed to establish the currently missing self-improvement links. Crash interventions, cache inspection and multi-process traces would separately change recovery, erasure and concurrency conclusions. These are different missing warrants, not one epistemic grade. No target-source reads were added for this synthesis.
