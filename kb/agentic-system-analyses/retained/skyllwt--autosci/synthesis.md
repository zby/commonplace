# AutoSci synthesis

## Bounded synthesis

### From sources to retained research context

AutoSci supplies research procedures for an external coding agent and Python helpers for selected deterministic operations. It is not the enclosing agent runtime. This account covers the shipped system at Git revision `f5c2fe009c6683b6aa5b668de759a0610c938aaf`, with an applicability cutoff of 2026-10-15. SRC-1 supplies implementation and doctrine/design evidence, not an observed research episode or causal experiment. The boundary includes active skills and setup, wiki tools, browser writers, scheduled intake and optional Hiera execution. Other branches, provider internals, deployed host permissions and advertised paper results are not established by this review. See the [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The principal progression is literature intake, retained wiki construction, later question answering or ideation, experiment planning and evaluation, then possible paper production. A user invokes `/ingest` with a paper. The agent interprets sources, chooses entities and merges, and writes Markdown pages; helpers admit typed graph edges and build derived navigation and context. Pages mix natural-language scientific content with symbolically consumed identifiers, statuses and links. Ingest does not require per-page human acceptance. Source interpretation and retention do not establish source truth or accepted new science. Foundations seeding is a separate admission route: it can use Wikipedia or visibly marked model fallback and skips existing foundation pages. See [RT-RTE-knowledge-cycle](runtime.md#rt-rte-knowledge-cycle), [MEM-OBJ-wiki-pages](memory.md#mem-obj-wiki-pages) and [MEM-RTE-foundation-seeding](memory.md#mem-rte-foundation-seeding).

Later `/ask` requests load a brief, gaps and index, then instruct the agent to choose at most 15 relevant full pages and synthesize a cited answer. Persisting that answer as wiki content requires a crystallization flag or confirmation; basic answering still permits audit writes and missing-context repair. The compiler and the model have different selection responsibilities. Code extracts and ranks summaries under purpose-specific section budgets and a default global 8,000-character bound; model relevance judgment chooses full pages under an instruction-level page cap. Neither bound guarantees token fit. Each compilation replaces the same brief, regardless of purpose. An ordinary general brief omits experiment and stale-entity sections because both have zero allocation; other purposes can include them. Originals remain reachable, but the brief can omit qualifications and evidence text. See [MEM-RTE-context-compilation](memory.md#mem-rte-context-compilation), [RT-OBJ-context-brief](runtime.md#rt-obj-context-brief) and [RT-BAP-retained-context](runtime.md#rt-bap-retained-context).

This context is not a single interchangeable graph. Semantic edges carry asserted relations and evidence; bibliographic citations record citation lineage, not endorsement; browser graph views also include live frontmatter projections that compiler connectivity does not use. First-occurrence semantic-edge deduplication can discard later evidence without judging its merit. These differences matter when interpreting a displayed relationship or a highly ranked summary. See [MEM-OBJ-edges](memory.md#mem-obj-edges), [MEM-OBJ-citations](memory.md#mem-obj-citations) and [EPI-RTE-edge-dedup](epistemic.md#epi-rte-edge-dedup).

### Initialization, alternate writers and recovery

The representative multi-agent workflow is `/init` through parallel `/ingest` and parent fan-in. The parent prepares a source manifest and intended common base commit; workers receive one relative source path and INIT MODE restrictions in separate worktrees. Workers are instructed to withhold incomplete commits. The parent merges successful committed branches in manifest order, handles semantic conflicts, rebuilds shared aids and runs deterministic lint repair. Known paper failures can be checkpointed and skipped; an empty success branch must instead stop for repair. Stash restoration failures retain recovery metadata. This is intended partial delivery with explicit failures, not whole-request atomicity. See [RT-RTE-parallel-ingest](runtime.md#rt-rte-parallel-ingest) and the [workflow account](workflow.md#workflow-account).

The shipped staging recipe does not establish that this intended payload flow works. Generated raw sources, wiki entities/graph and checkpoints are ignored, while parent and worker staging is unforced. A relative pathname does not copy a source into a worktree; a nonempty commit may contain tracked index/log changes without the new paper payload. Rebuild and lint cannot recover files never transported. Successful Git fan-in therefore establishes transport only for content actually committed, not complete initialized-wiki delivery. Task framing and conditional committed-artifact persistence remain supported; neither an observed failed run nor universal failure is asserted. The [report verification](report-verification.md#limits) preserves this source dependency failure separately from unobserved agent compliance.

Scheduled intake provides another admission path: CI can select papers and invoke ingest without per-paper approval. Its compatible-model alternative is inform-only. CI attempts commit/push, but unforced staging against the same ignore rules leaves new payload retention conditional. Intake also automatically supplies selected recent wiki previews and audit-tail context to recommendation; this coarse automatic supply differs from requested `/ask` retrieval. See [RT-RTE-daily-intake](runtime.md#rt-rte-daily-intake) and its [memory annotation](memory.md#on-rt-rte-daily-intake).

Browser PATCH and direct metadata CLI calls can change retained fields without a skill identity or experiment verdict. Writer ownership is explicitly policy, not enforced authorization. Helper shape checks, atomic single-file replacement and selected linked-worktree rebuild guards have narrower guarantees than the full workflow. Deterministic lint repairs reverse links and defaults, not scientific truth; the initialization lint invocation uses the initial issue count for its exit status rather than certifying a clean repaired state. Reset is scoped deletion, leaving possible projected edges, root manifests and sidecars; raw-source deletion does not automatically retract derived claims. See [RT-RTE-browser-write](runtime.md#rt-rte-browser-write), [RT-CLM-writer-contract](runtime.md#rt-clm-writer-contract), [MEM-RTE-memory-maintenance](memory.md#mem-rte-memory-maintenance) and the [workflow account](workflow.md#workflow-account).

### From experiments to changed reliance

Research orchestration is primarily model-interpreted. `/research` coordinates ideation, design, execution, later collection, evaluation and optional writing, with progress Markdown supporting later sessions. Interactive gates can stop idea selection or continuation; auto mode delegates those choices. The inspected stage body specifies ending the session and manual collection, so automatic monitoring/resumption is not uniformly established. A sanity run precedes the normal deployment approval gate; even the instructions do not support “no execution before approval.” See [RT-RTE-research-verdict](runtime.md#rt-rte-research-verdict).

The strongest scientific-acceptance design separates three functions. First, a model reviewer and foreground agent assess a localized hypothesis against experiment and sibling results, including methodological criticism. Second, a verdict licenses changed reliance, with confirmation unless auto: supported results may validate an idea only in the main-experiment, single-hypothesis case; partial and inconclusive outcomes do not advance its lifecycle; rejection requests a concrete failure reason. Third, supported claims are connected to evidence edges and context, while other branches retain rejection or inconclusive evidence without thereby accepting it. These are specified procedures, not supplied accepted-claim instances. Reviewer agreement is not calibrated certainty, and the foreground reads the reviewer verdict before forming its own. A stored status cannot authenticate this history because alternate writers can bypass it. See [EPI-RTE-verdict-check](epistemic.md#epi-rte-verdict-check), [EPI-RTE-verdict-disposition](epistemic.md#epi-rte-verdict-disposition), [EPI-RTE-verdict-integrate](epistemic.md#epi-rte-verdict-integrate) and [EPI-CLM-verdict-certainty](epistemic.md#epi-clm-verdict-certainty).

AutoSci's strongest supported feedback contribution is retained negative guidance: experimental results can become failure reasons, persist in idea pages, enter bounded summaries and guide later ideation away from the same failure. Filter eliminations, pilot failures and formal rejections retain different evidential force; they are not interchangeable refutations. Automatic outcome-to-guidance updates and later consumption are afforded, while summarization is implemented. Full verdict reasoning is not uniformly persisted or delivered. Whether criticism actually improved future action remains uninspected. See [MEM-RTE-negative-memory](memory.md#mem-rte-negative-memory) and [RT-BAP-retained-context](runtime.md#rt-bap-retained-context).

For scientific theory building, the runtime assesses the four conditions independently: localized hypothesis content is **afforded**; content-dependent consumption, content-directed criticism with changed reliance, and retention shaping another round are each **claimed**. None is an observed theory-building episode. Page/section addressability is supported at the procedure level, not formal dependency tracking. Improved capacity for future action is uninspected independently of those conditions. Reflection on AutoSci's own method is not established by criticism of an external scientific hypothesis. Full autonomous theory building remains uninspected; automatic selections and gate bypasses establish narrower delegated control, not computation performing every internal role. Exercised self-improvement is likewise unestablished at this boundary and across later research sessions: retained guidance affords a future behavior path, but no subsequent operation demonstrates causal dependence on the update or improvement. These are separate unresolved properties, not a single negative grade. See [RT-RTE-research-verdict](runtime.md#rt-rte-research-verdict) and [EPI-RTE-verdict-check](epistemic.md#epi-rte-verdict-check).

### Optional bounded search

Hiera adds executable candidate admission, frozen contract/snapshot checks, budget reservations, local or remote evaluation and receipts. Approval is local state available to a caller, not authenticated proof of human review. A successful receipt requires execution/result conditions and a finite score, not scientific confirmation. Later ledger replay uses scores, bout history and reservations to rank work, avoid duplicate spending and constrain continuation. `loop` re-evaluates selected existing candidates; `tune` separately creates immutable configuration children. This is wired outcome-sensitive execution, with no observed performance gain or content-directed theory criticism implied. See [RT-RTE-hiera-search](runtime.md#rt-rte-hiera-search), [MEM-RTE-ledger-replay](memory.md#mem-rte-ledger-replay) and [EPI-RTE-hiera-select](epistemic.md#epi-rte-hiera-select).

The object called experience is a computed count dictionary; inspected reporting callers expose its timestamp-bearing revision rather than a durable full snapshot driving scheduling. The operative feedback path is the ledger. Finalization reports `wiki_writeback: none`, and formal confirmation must return to the normal workflow. Digests and a working directory are not an OS sandbox for arbitrary candidate code. See [MEM-OBJ-experience](memory.md#mem-obj-experience), [EPI-RTE-hiera-summary](epistemic.md#epi-rte-hiera-summary) and [RT-CLM-sidecar-confirmation](runtime.md#rt-clm-sidecar-confirmation).

For a question-answering scenario, the evidence supports persistent, bounded context preparation plus instructed source-page selection, not demonstrated answer accuracy. For initialization, it supports a coordinated protocol with a known transport dependency failure. For iterative research, it supports explicit evidence-sensitive verdict and failure-reuse procedures, not observed accepted new science or improved capacity. For exploratory search, it supports executable integrity, accounting and feedback-directed continuation, not evaluator validity or secure isolation. Payload-inclusive tracking/transfer with an inspectable delivery trace would change the initialization assessment; linked source-to-verdict-to-later-action traces would establish exercised research and feedback use; independently varied comparisons would be needed to attribute gains to retained guidance or a reviewer component. See [RT-RTE-knowledge-cycle](runtime.md#rt-rte-knowledge-cycle), [RT-RTE-parallel-ingest](runtime.md#rt-rte-parallel-ingest), [MEM-RTE-negative-memory](memory.md#mem-rte-negative-memory) and [RT-RTE-hiera-search](runtime.md#rt-rte-hiera-search).
