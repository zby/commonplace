# MemPalace synthesis

## Bounded synthesis

### From host activity to retained memory

MemPalace is a memory and context-supply system with shipped host adapters and a delegated-task coordination plane. It does not own the enclosing agent's answer generation. This account covers its repository at commit **1392e1810c3ca67776bd7fe3e198788a96dbd6d1**, with an applicability cutoff of **2026-10-14**. The whole-system boundary includes capture, maintenance, shipped instructions, later consumers and evaluators; it does not imply exhaustive implementation inspection. SRC-1 supplies code and doctrine/design. No host session, live palace, executed test, benchmark rerun or causal experiment was supplied or produced. The evidence establishes implementation paths and attributed intent, not their observed exercise or benefit. See [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The ordinary traced path starts with an initialized Hermes host session. A completed-turn callback supplies user and assistant text to a bounded queue. A background worker classifies its filing location and upserts a drawer: retained text organized by wing and room. Software admits each exchange without per-content human approval. The host must invoke the lifecycle callbacks; backend initialization can leave the adapter inactive. Queue saturation drops turns, filing errors are logged rather than durably retried, and shutdown waits only five seconds. This is best-effort capture, not a confirmed lossless save. [RT-RTE-hermes-capture](runtime.md#rt-rte-hermes-capture).

CLI imports and transcript hooks are alternatives, not the same capture guarantee. Hooks schedule a daemon job or detached CLI process; submission does not confirm final persistence. Once daemon submission is attempted, its error branch does not replay locally because double-mining is possible. Downstream filing normalizes and chunks source content. General extraction rejects segments by marker scores and thresholds; normalization can spell-correct user text. Message sweep has its own cursor and IDs and can overlap file mining. Thus exact retention of an admitted representation must not be confused with byte-preservation of every original input. [RT-RTE-hook-ingest](runtime.md#rt-rte-hook-ingest), [MEM-RTE-source-filing](memory.md#mem-rte-source-filing).

Several retained parts perform different jobs. Drawer words provide recallable content; symbolic metadata filters and reconstructs chunks; dense embeddings influence candidate selection. Separate closet lines are reduced topic/quote/summary locators pointing to drawers, not complete transcripts. Optional LLM regeneration groups retained drawers by source and automatically admits parsed locator output after an operator starts the job. Its input and packing caps omit material; parsing does not verify quote fidelity or factual accuracy. Embedding and generation clients do not establish an in-use weight-training step, while exact model versions and provider-internal changes remain branch-specific uncertainties. [MEM-OBJ-drawer-text](memory.md#mem-obj-drawer-text), [MEM-OBJ-drawer-metadata](memory.md#mem-obj-drawer-metadata), [MEM-OBJ-drawer-vectors](memory.md#mem-obj-drawer-vectors), [MEM-OBJ-closet-lines](memory.md#mem-obj-closet-lines), [MEM-RTE-closet-regeneration](memory.md#mem-rte-closet-regeneration), [runtime components](runtime.md#components).

### Admission, revision and later reliance

Admission is not one universal approval gate. Interactive setup lets humans edit people/projects; `--yes` bypasses review, and topics pass through automatically. Explicit tools structurally validate caller content, but caller identity alone does not establish human authorship or approval. MCP dispatch can veto operations by read-only and runtime-state checks. This is a server-owned request boundary: direct CLI/API/callback writes do not inherit it, and permitted recovery can touch disk. Hub forwarding refuses local replay of classified mutations after eligible remote failures; it does not guarantee exactly-once execution. [RT-RTE-init-detection](runtime.md#rt-rte-init-detection), [RT-RTE-mcp-dispatch](runtime.md#rt-rte-mcp-dispatch), [RT-CLM-readonly-boundary](runtime.md#rt-clm-readonly-boundary), [RT-RTE-hub-fallback](runtime.md#rt-rte-hub-fallback).

Checkpoint saving adds a consequential similarity check: nearest-hit comparisons can mark an item duplicate, and the checkpoint consumer then skips it. Dedup errors instead allow filing. Embedding closeness is not semantic equivalence; a near match may contain a correction. Explicit update/delete provides a separate revision route and purges affected source closets after content changes. Neither storage visibility checks nor replacement certify the proposition's truth. [EPI-RTE-duplicate-check](epistemic.md#epi-rte-duplicate-check), [EPI-RTE-checkpoint-disposition](epistemic.md#epi-rte-checkpoint-disposition), [EPI-RTE-drawer-revision](epistemic.md#epi-rte-drawer-revision).

Temporal facts have a distinct lifecycle. SQLite relationship rows carry validity intervals and optional provenance. Caller-requested invalidation ends eligibility while preserving history; supersession transactionally closes old rows and inserts or reuses a successor. A reused open successor does **not** have its start aligned to the requested boundary. If it starts later, an as-of query at that boundary can exclude both old and successor rows despite successful supersession. This is an implementation deduction, not an observed failure. Temporal grouping and default confidence do not independently endorse a relationship. [MEM-OBJ-kg-triples](memory.md#mem-obj-kg-triples), [MEM-RTE-temporal-facts](memory.md#mem-rte-temporal-facts).

### Selection into a later invocation

Requested search is a pull route: query embeddings, filters and lexical/closet scoring select retained material for MCP text or a host context return. Closet-assisted hydration can choose a best passage plus neighboring chunks and truncate it rather than return the whole logical drawer. Direct logical drawer GET is the fuller read alternative. A search miss therefore does not prove stored absence, and a hit need not contain every relevant qualification. The external host/agent owns interpretation and answer generation. [RT-RTE-palace-recall](runtime.md#rt-rte-palace-recall), [memory read-back annotation](memory.md#annotations), [RT-BAP-agent-context](runtime.md#rt-bap-agent-context).

Independent startup supply is different. DSH registers agent-local prompt providers; Hermes exposes identity and cached wake-up material. The startup selector reads full identity text and selects weighted/recent snippets within a candidate window of up to 2,000 filings: at most 15 drawers, each capped at 200 characters, with an approximately 3,200-character L1 content budget. The identity file is not token-capped; headings and backend scan limits prevent a universal total-token or globally highest-importance guarantee. DSH's first assembly waits only within its time budget. Disposal removes registrations, not content already consumed elsewhere. Host compaction and child-agent context remain host-owned; Hermes's pre-compression callback is a no-op. [MEM-RTE-wake-context](memory.md#mem-rte-wake-context), [RT-RTE-palace-recall](runtime.md#rt-rte-palace-recall).

For session continuity, silent Python hooks retain short prefixes from recent eligible user messages, not assistant reasoning or a complete session summary. Later diary reads select recent physical rows, which may be chunks. Prompted summaries and imported daily files have different, partly unresolved authorship and completion controls. DSH does not relay the non-silent hook's request for model-authored saving, so checkpoint completion is not equivalent across hosts. [MEM-RTE-diary-checkpoint](memory.md#mem-rte-diary-checkpoint), [report verification limits](report-verification.md#limits).

Media search returns descriptors, paths and availability, not automatically original bytes. Tunnels support explicit navigation and persist traversal counters, but counter display does not establish default semantic-ranking influence. Explicit maintenance changes future stored eligibility without proving synchronous withdrawal from existing host prompts, backups or replicas. These differences matter when the scenario requires payload consumption, learned navigation or complete forgetting rather than reference delivery. [MEM-RTE-media-index](memory.md#mem-rte-media-index), [MEM-RTE-tunnel-traversal](memory.md#mem-rte-tunnel-traversal), [MEM-RTE-memory-maintenance](memory.md#mem-rte-memory-maintenance).

### Delegated work and its delivery boundary

The representative multi-step workflow is a coding task through the logstream. Shipped instructions connect normalized task approval, creation, handoff, worker claim, patch return and requester review. Approval of the exact task is doctrine, not enforced by the constructor. The portable default is a pasteable pointer requiring the worker to reload the persisted goal, definition of done and delivery instructions. An event alone does not wake a non-monitoring agent. Acknowledgments are linked append-only reports, not exclusive execution locks. [WF-RTE-task-create](workflow.md#wf-rte-task-create), [WF-RTE-event-ack](workflow.md#wf-rte-event-ack), [RT-BAP-task-handoff](runtime.md#rt-bap-task-handoff).

Optional controlled launch checks addressed identity, branch, resolved base commit and clean workspace before starting Codex or Claude. A mismatch rejects launch; the instructed recovery is a corrected superseding request, not automatic workspace repair. The external runner owns execution and permissions. Patch submission stores an artifact and ready event, even allowing format warnings; it does not apply the patch. Requester hash checking, explicit application, task-specific verification and applied/failed acknowledgment are downstream policy. Filing a searchable outcome drawer is prescribed, not automatic. No successful instance or acceptance trace was observed. [RT-RTE-task-launch](runtime.md#rt-rte-task-launch), [RT-RTE-patch-delivery](runtime.md#rt-rte-patch-delivery), [WF-CLM-review-closure](workflow.md#wf-clm-review-closure), [workflow account](workflow.md#workflow-account).

### Assessment and evidence that would change it

The strongest supported learning-related contribution is **automatic trace-fed production of durable continuity and retrieval artifacts**. Session-prefix checkpoints and session-fed extracted segments/closet locators have later context or ranking consumers. This is wired trace learning, distinct from raw-log retention and from demonstrated improved capacity for future action. The unresolved question is whether these transformations make later work better rather than merely different. No before/after capacity comparison or component intervention was supplied. Other properties remain separate. For the inspected capture, setup and task paths, a formulated-theory loop meeting conditions 1–4 is not established: localized operational guidance is inspectable, but theory-dependent decisions, content-directed criticism with blame and revision, and retention shaping another criticism round are not demonstrated as a connected theory route. This is not a whole-system absence claim. Criticism of a consumed theory improving future capacity is independently unestablished. Traversal self-recording and organization auditing support narrower self-state mechanisms, not a demonstrated reflective theory builder. Autonomous queueing and selection are implemented, but a fully autonomous theory builder is not established, and workflow review remains assigned to a requester.
