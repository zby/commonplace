# Cludebot synthesis

## Bounded synthesis

### From interaction to retained experience

Cludebot, called Clude in its documentation, ships a memory system together with chat, bot/service consumers, maintenance workers, SDK/MCP entry points and local storage alternatives. This account concerns repository `https://github.com/sebbsssss/cludebot` at commit `cecf234f10397b1e21dec2ff65ded864982f3564`, with cutoff 2026-10-15. SRC-1 supplies inspected implementation and doctrine/design, not independently observed execution or causal experiments. The whole-system boundary includes shipped producers and consumers; it does not mean every included path was audited. The [Source register](boundary.md#source-register) and [coverage inventory](memory.md#coverage-inventory) define that distinction. No new source reads were made for synthesis.

The source's claim to process memory beyond storage and retrieval has concrete implementation support: maintenance can generate new retained text, change retrieval weights and add graph links. Whether those operations produce accurate beliefs or better action is a separate question ([RT-CLM-cognitive-memory](runtime.md#rt-clm-cognitive-memory)).

An authenticated chat turn illustrates the ordinary progression. Code authenticates the principal, checks conversation ownership, recalls owner-scoped memories and loads conversation history. A character-estimate fitter retains the base prompt, selects history and fits a prefix of recalled memories. The provider model generates answer text; this handler supplies no arbitrary-tool loop. Selected memories reach it as dated summaries and bounded content snippets, not the full store or an automatically traversed evidence graph. After streaming, separate writes persist assistant text, accounting and, for sufficiently long inputs, an episodic exchange. A delivered answer is therefore not a receipt for durable memory, completed enrichment or billing ([RT-RTE-chat-turn](runtime.md#rt-rte-chat-turn), [RT-OBJ-memory-context](runtime.md#rt-obj-memory-context)).

Two conditions materially bound this context mechanism. History is fetched ascending with a 50-row limit, so backward fitting need not include the current/latest turn of a long conversation. Character estimates and minimum reserves do not enforce a strict provider-token budget. Omitted text can remain in storage without remaining visible to the model. Guest chat is a separate nonpersistent route, not this memory loop ([RT-RTE-chat-turn](runtime.md#rt-rte-chat-turn), [RT-RTE-guest-chat](runtime.md#rt-rte-guest-chat)).

Other writes admit caller text, packs, document extracts and task findings. Software/model admission is not per-content human approval. Schema, length, duplicate and citation checks do not authenticate a claim's truth or original author. The generic pack handler's effective owner scope remains unresolved; a separately owner-scoped Cortex handler does not repair it ([RT-RTE-memory-entry](runtime.md#rt-rte-memory-entry), [RT-RTE-pack-import](runtime.md#rt-rte-pack-import), [MEM-RTE-upload-extraction](memory.md#mem-rte-upload-extraction), [WF-RTE-store-finding](workflow.md#wf-rte-store-finding)).

### Maintenance changes both content and future selection

Retained prose and retrieval state have different jobs. PostgreSQL rows hold exchanges, summaries and generated text; vectors, lexical indexes, links, importance, decay and access state affect selection. PostgreSQL recall reinforces access/links, whereas JSON local recall also raises importance. SQLite has another store and dream queue. These alternatives are not equivalent deployments of one invariant algorithm ([MEM-OBJ-memories](memory.md#mem-obj-memories), [MEM-OBJ-retrieval-state](memory.md#mem-obj-retrieval-state), [MEM-OBJ-local-store](memory.md#mem-obj-local-store), [MEM-OBJ-sqlite-store](memory.md#mem-obj-sqlite-store)).

Main dreams sequence consolidation, compaction, self-reflection, contradiction handling and other phases. Old episodic summaries can become semantic takeaways with evidence IDs and links; originals are marked, not deleted. Self-model text is explicitly reloaded into later reflection. Journal continuity likewise supplies prior journal summaries to later generation. These are real retained-input-to-derived-artifact-to-later-consumer chains, even though shortened summaries can lose reasons. The compaction hash pointer is independently generated from the stored product's hash and is not established as a valid pointer ([RT-RTE-dream-cycle](runtime.md#rt-rte-dream-cycle), [MEM-RTE-dream-compaction](memory.md#mem-rte-dream-compaction), [EPI-RTE-self-reflection](epistemic.md#epi-rte-self-reflection), [MEM-RTE-journal-continuity](memory.md#mem-rte-journal-continuity)).

Contradiction handling stores a model-proposed resolution and downweights an original. Crucially, code chooses that original by importance and age, not by interpreting which claim the model judged wrong. Citation parsing and cop-out rejection do not test evidential support. Thus changed reliance is wired, but accurate belief correction and evidence-consuming epistemic acceptance are not established. Without actual outputs, whether generated claims preserve, entail or extend their inputs also remains unresolved ([MEM-RTE-belief-revision](memory.md#mem-rte-belief-revision), [EPI-RTE-self-reflection](epistemic.md#epi-rte-self-reflection)).

Hosted dreams instead produce bounded sets of semantic insights and procedural rules from owner-scoped episodes; they omit the main phase set and explicit evidence-ID mapping in their writes. This factual reduction supports consolidation, notwithstanding the profile's conservative route inventory. Local SQLite dreams persist generated queue results, not automatically adopted recallable memories in the inspected completion sink. A later adoption consumer remains unestablished, rather than proved absent ([MEM-RTE-hosted-dream](memory.md#mem-rte-hosted-dream), [MEM-RTE-local-dream](memory.md#mem-rte-local-dream), [profile verification limits](profile-verification.md#limits)).

### Later context can become behavioral guidance

The strongest improvement-related contribution is the wired outcome-to-guidance pathway. Social action/outcome records feed feature-level rates; thresholds trigger caution or reinforcement rules, and positive same-feature actions can raise existing strategy importance. A distinct response service independently selects procedural rows and presents them with an explicit instruction to follow the strategies. This changes durable behavior-shaping material and connects it to later model input. It is stronger than merely logging outcomes, but feature matching does not show that a strategy was used or caused success. Stored rates are not causal justification ([EPI-RTE-action-learning](epistemic.md#epi-rte-action-learning), [MEM-RTE-strategy-refinement](memory.md#mem-rte-strategy-refinement), [MEM-BAP-procedural-guidance](memory.md#mem-bap-procedural-guidance)).

This pathway supports dispositional, improvement-directed self-change at the shipped action-learning/shared-response boundary. Its objective is better future social-action outcomes, represented by engagement proxies, not merely producing another rule. Exercised self-improvement remains uninspected: no subsequent operation is shown causally depending on an updated rule. Successful improvement and learning as improved capacity for future action remain unestablished without an appropriate comparison. Wired trace learning here means automatic experience-fed production of durable material with later consumers; it does not supply that missing benefit evidence ([EPI-RTE-action-learning](epistemic.md#epi-rte-action-learning), [MEM-RTE-response-memory](memory.md#mem-rte-response-memory)).

The theory-builder conditions remain separate. For belief revision, condition 1, formulation of a localized whole belief, is afforded; condition 2, decisions depending on its content, is uninspected. Condition 3, content-directed criticism identifying claim, result, blame and revision, is afforded by the request but not observed. Condition 4, retained criticism shaping a next round, is uninspected. Action-learning outputs do not establish actual theory content or any of these exercised conditions. Row IDs permit whole-entry addressing, not demonstrated assumption-level revision. No full theory-builder or autonomous theory-builder conclusion follows ([MEM-RTE-belief-revision](memory.md#mem-rte-belief-revision), [EPI-RTE-action-learning](epistemic.md#epi-rte-action-learning)).

Reflection has a positive architectural result independently: behavior-related summaries can update a self-model, and self-model text feeds later generation contexts. Those directions are wired; exercised reflective dependence and accurate introspection remain unobserved. Computational scheduling, generation and admission establish local automatic operations, not role-complete autonomy of a theory-building process. Neither reflection nor automation establishes that criticism of a consumed theory improved future capacity ([EPI-RTE-self-reflection](epistemic.md#epi-rte-self-reflection), [RT-RTE-dream-cycle](runtime.md#rt-rte-dream-cycle)).

Checks do exist, but their licenses differ. Confidence scoring uses retrieval counts, scores, diversity and dispersion; filtering can remove selected evidence, while hedging remains advisory. It does not evaluate semantic support, and later-added strategies are outside the main result's confidence assessment. Pack signatures concern bytes and keys, not truth. Benchmark reference-answer judging and optional criticism/revision concern benchmark answers, not production dream admission; permissive critic fallback and failure-only rejudging bound what reported scores mean ([EPI-RTE-confidence-check](epistemic.md#epi-rte-confidence-check), [EPI-RTE-confidence-consumption](epistemic.md#epi-rte-confidence-consumption), [EPI-RTE-pack-verification](epistemic.md#epi-rte-pack-verification), [EPI-RTE-benchmark-checks](epistemic.md#epi-rte-benchmark-checks)).

### A task workflow and its delivery boundary

The representative multi-step workflow is an owner-assigned dashboard research task. The caller supplies assignment and problem; a task-local Anthropic loop chooses tools, receives tool text, can store findings and can declare completion. This is one model/tool loop, not automatic decomposition into sub-agents. Its recall wrapper returns summaries through a selector whose inspected implementation ignores query text: issuing different queries does not establish topical investigation through the general hybrid pipeline ([RT-RTE-dashboard-task](runtime.md#rt-rte-dashboard-task), [workflow account](workflow.md#workflow-account), [MEM-RTE-recall-selection](memory.md#mem-rte-recall-selection)).

Unknown tools are rejected; ordinary tool failures return text for model-chosen recovery. Advertised schemas do not form an execution-time per-agent allowlist, and the timer race does not cancel losing work. Owner retry starts fresh task messages, without automatically replaying prior logs or retracting stored findings. Completion can follow a completion tool, end-turn text or iteration exhaustion without independent correctness acceptance. Delivery is attempted persistence into owner-readable task metadata, not observed owner receipt or accepted research quality ([RT-RTE-dashboard-task](runtime.md#rt-rte-dashboard-task), [WF-RTE-store-finding](workflow.md#wf-rte-store-finding), [workflow account](workflow.md#workflow-account)).

For repeated memory-enabled conversations, the source supports retention, bounded context reconstruction and automatic derived guidance. For query-driven dashboard research, strict effect deadlines, verified belief revision or portable withdrawal, the narrower mechanisms above prevent stronger guarantees. Deletion, revocation, contradiction downweighting and compaction are different operations; none establishes erasure of derivatives or already delivered text. Ordinary patches also lack demonstrated index/encryption coherence across modes ([MEM-RTE-memory-withdrawal](memory.md#mem-rte-memory-withdrawal)).

The assessment would change with linked traces showing source experience, admitted update, exact later prompt and content-dependent action; comparison designs would then need to isolate the changed guidance to support benefit attribution. Actual claim/criticism/revision artifacts retained into subsequent rounds would resolve theory-condition questions. Implementation changes enforcing dispatch grants, cancelling effects, preserving latest-turn context, validating semantic support and propagating withdrawal would change the corresponding architectural guarantees. These are conclusion-specific evidence or system changes, not a product ranking or adoption recommendation.
