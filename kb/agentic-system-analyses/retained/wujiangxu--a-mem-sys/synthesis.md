# A-MEM synthesis

## Bounded synthesis

### From caller content to organized memory

A-MEM is a synchronous Python memory library, not a complete task-solving agent. This account covers its shipped library, model adapters, prompts, README callers and tests at commit `f303dfc71e07bdc787f4bc135d4cea328ae30e99`, with an analysis cutoff of 2026-10-16. SRC-1 provides inspected implementation, declared design and attributed results, but no observed execution or causal experiment. The whole-system boundary is relative to this memory system; external services, dependency internals and the separate paper-reproduction project are not frozen evidence ([boundary](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)). No target tests, examples or services were run.

The strongest supported contribution is **automatic organization of retained content that can shape later memory processing**. A caller submits text through `add_note`. When keywords or tags are missing, or context has its default value, the library asks a configured model for semantic metadata and fills those fields. Complete caller metadata bypasses that analysis, not subsequent evolution in a populated store. The library keeps original content alongside the descriptions and embeds an enhanced concatenation of content, context, keywords and tags. Thus generated descriptions can affect later selection without changing model parameters ([RT-RTE-note-admission](runtime.md#rt-rte-note-admission), [MEM-OBJ-memory-content](memory.md#mem-obj-memory-content), [MEM-OBJ-semantic-metadata](memory.md#mem-obj-semantic-metadata), [MEM-OBJ-chroma-snapshot](memory.md#mem-obj-chroma-snapshot)).

Python owns progression and effects. The inference backend is OpenAI, Ollama, SGLang or OpenRouter; Chroma and its configured sentence-transformer supply embedding and nearest-neighbor operations. These are separately assembled model requests, not an accumulating conversation or an open-ended tool loop. The inspected library does not update inference or embedding parameters, and exact model artifacts are not pinned. Provider-side changes and retention remain uninspected ([RT-CMP-openai](runtime.md#rt-cmp-openai), [RT-CMP-ollama](runtime.md#rt-cmp-ollama), [RT-CMP-sglang](runtime.md#rt-cmp-sglang), [RT-CMP-open-router](runtime.md#rt-cmp-open-router), [RT-CMP-sentence-transformer](runtime.md#rt-cmp-sentence-transformer)).

### Retained neighbors influence subsequent writes

On a later addition with available neighbors, code queries by the new note's content and supplies up to five retained Chroma snapshots to an evolution model. The supplied parts include IDs, content, context, keywords, tags and timestamps. There is no local token or character cap on those five records. Unselected notes remain available to later searches. This is automatic context delivery to the model during ingestion; the model neither initiates retrieval nor schedules maintenance ([RT-RTE-neighbor-evolution](runtime.md#rt-rte-neighbor-evolution), [RT-BAP-neighbor-context](runtime.md#rt-bap-neighbor-context), [memory annotation](memory.md#on-rt-rte-neighbor-evolution)).

The model decides whether to evolve and proposes fixed actions. `strengthen` appends links to the new note and replaces its tags; `update_neighbor` replaces selected existing neighbors' context and tags. Python interprets these fields through fixed dispatch rather than executing model text as code. This constraint is local to evolution: direct CRUD, live-object mutation and retriever access are alternatives. Suggested link values lack the existence checks applied to neighbor writes. Requested JSON schemas and local parsing do not guarantee semantic correctness or complete schema compliance ([EPI-RTE-evolution-judgment](epistemic.md#epi-rte-evolution-judgment), [EPI-RTE-evolution-disposition](epistemic.md#epi-rte-evolution-disposition), [RT-RTE-direct-mutation](runtime.md#rt-rte-direct-mutation)).

The retained organization has several distinct effects: descriptions supply model context and caller reference material; enhanced documents influence similarity ranking; symbolic links select additional candidates. None of these establishes factual warrant or observed reliance. Applied fields persist within the initialized system, but automatic evolution does not retain its criticism or rationale. Usage/history fields exist without automatic count increments, access refreshes or evolution-history appends in the searched production paths ([MEM-OBJ-note-links](memory.md#mem-obj-note-links), [MEM-ABS-usage-feedback](memory.md#mem-abs-usage-feedback), [RT-BAP-neighbor-context](runtime.md#rt-bap-neighbor-context), [RT-BAP-caller-results](runtime.md#rt-bap-caller-results)).

### Storage, maintenance and delivery do not share one consistency guarantee

The representative shipped workflow adds related neural-network notes, reads them and calls `search_agentic`. It establishes a connected source-supported sequence, not successful execution. The caller owns the requests; model handoffs return to synchronous Python control; completion is a note ID or returned result list, not a delivered task answer ([workflow account](workflow.md#workflow-account)).

Live objects and Chroma metadata are different read representations. `read` returns a mutable object. `search` uses Chroma-selected IDs but returns live fields. Evolution's neighbor input and `search_agentic` direct hits instead use Chroma metadata. Neighbor evolution immediately changes only live objects, so a later model request can receive older context than an ID read. Threshold-triggered or explicit consolidation re-adds every live note through a get-or-create collection; it does not explicitly reset, delete or upsert existing entries. Successful refresh is therefore unresolved, not an enforced repair guarantee ([RT-RTE-memory-retrieval](runtime.md#rt-rte-memory-retrieval), [MEM-RTE-index-consolidation](memory.md#mem-rte-index-consolidation)).

Two further transformations affect delivery. `search_agentic` appends linked live notes after direct results and finally truncates to `k`; when direct results fill the budget, appended links do not reach the caller. Metadata conversion also interprets numeric-looking and JSON-looking strings without field-specific typing. The accepted implementation deduction shows that text `0012` can become numeric `12` in metadata-backed results while map-backed reads preserve the original. This is a conditional lexical-lineage defect, not an observed round trip or universal factual error ([RT-RTE-memory-retrieval](runtime.md#rt-rte-memory-retrieval), [EPI-RTE-metadata-conversion](epistemic.md#epi-rte-metadata-conversion)).

Failure handling permits degraded continuation. Declined or handled failed evolution does not reject ingestion; earlier mutations can survive an exception. Some adapters return parseable empty values after provider failure. Map and collection operations have no route-wide transaction, and search can return an empty list for either failure or no results. The caller must decide how to recover from escaping errors. A successful-looking ID or nonempty result does not certify relationship quality ([EPI-RTE-metadata-parsing](epistemic.md#epi-rte-metadata-parsing), [RT-RTE-note-admission](runtime.md#rt-rte-note-admission), [workflow account](workflow.md#workflow-account)).

Direct `update` replaces supplied attributes and rewrites the retriever entry without regenerating metadata or invoking evolution, contrary to the README's add-or-update claim. Caller deletion removes entries, but does not retain withdrawal history, repair surviving links or revoke delivered copies. New construction starts an empty map and attempts a collection reset; there is no established shipped save/load route. These facts distinguish instance-local accumulation from cross-session restoration ([RT-RTE-direct-mutation](runtime.md#rt-rte-direct-mutation), [EPI-CLM-update-evolution](epistemic.md#epi-clm-update-evolution), [MEM-OBJ-note-links](memory.md#mem-obj-note-links), [RT-RTE-note-admission](runtime.md#rt-rte-note-admission)).

### What changes, and what the evidence does not establish

For caller-controlled, same-instance organization, A-MEM wires semantic description, retained-neighbor selection and automatic revision into one usable API progression. Whether this improves future task capacity remains unresolved at this boundary. No component intervention or inspectable benchmark supports attribution of superior retrieval to metadata, links or evolution; the README's six-model comparison remains an attributed claim ([RT-CLM-memory-organization](runtime.md#rt-clm-memory-organization), [EPI-CLM-retrieval-accuracy](epistemic.md#epi-clm-retrieval-accuracy)). For scenarios requiring fresh metadata on every read, validated factual memory or restoration in a new instance, the inspected mechanisms do not establish those guarantees.

The checks have narrower domains than truth acceptance. Parsing checks syntax, dispatch bounds actions, similarity selects relevance, and shipped tests check selected structural/API properties. None records an evidence-consuming acceptance of a truth claim against a criterion for a stated use and scope in the searched library consumers. Retention and linking therefore do not establish accepted knowledge production. Actual model outputs are also needed to distinguish faithful reshaping, derivation and added interpretation; the accepted records leave that relation indeterminate ([EPI-RTE-test-evaluation](epistemic.md#epi-rte-test-evaluation), [EPI-ABS-evidence-acceptance](epistemic.md#epi-abs-evidence-acceptance), [EPI-RTE-metadata-generation](epistemic.md#epi-rte-metadata-generation)).

The independent learning and theory-related conclusions remain bounded:

- **Learning:** organization changes and later-consumer wiring are supported; improved capacity for future action, including improvement through criticism of a consumed theory, is not demonstrated. Unknown caller provenance also prevents deciding whether the automatic writes are trace-fed learning. Lack of observed improvement is not itself the missing trace-origin fact ([RT-RTE-neighbor-evolution](runtime.md#rt-rte-neighbor-evolution), [MEM-OBJ-memory-content](memory.md#mem-obj-memory-content), [MEM-ABS-usage-feedback](memory.md#mem-abs-usage-feedback)).
- **Theory-builder conditions 1–4:** no positive condition is established for a formulated-theory route. The records identify descriptions and fixed evolution guidance, not an established localized explanatory theory (condition 1); context delivery does not establish dependence on such a theory's content (condition 2); the accessible route does not expose content-directed criticism with blame and revision (condition 3); retained edits do not establish iteration of that criticism (condition 4). These are not claims about inaccessible model reasoning ([runtime account](runtime.md#runtime-account), [EPI-RTE-evolution-judgment](epistemic.md#epi-rte-evolution-judgment), [EPI-RTE-evolution-disposition](epistemic.md#epi-rte-evolution-disposition)).
- **Reflection and autonomy:** automatic metadata decisions are wired, but a self-representation with both causal directions required for reflection is not established. Caller-owned scheduling and fixed internal model decisions do not establish autonomous theory building or a complete autonomous task agent ([runtime account](runtime.md#runtime-account), [workflow account](workflow.md#workflow-account)).
- **Self-improvement:** retained organizational changes can enter later ranking/context paths. That is a positive change-and-consumption pathway, not an exercised self-improvement result. No supplied subsequent operation establishes causal dependence on the change, nor does outcome evidence establish successful improvement toward retrieval accuracy ([RT-BAP-neighbor-context](runtime.md#rt-bap-neighbor-context), [MEM-OBJ-chroma-snapshot](memory.md#mem-obj-chroma-snapshot), [EPI-CLM-retrieval-accuracy](epistemic.md#epi-clm-retrieval-accuracy)).

An inspectable ingestion-to-later-consumption trace would establish operation where only wiring is known. Recorded input provenance would resolve trace-fed classifications. A frozen dependency round trip or explicit replacement mechanism could resolve refresh behavior; field-specific serialization could address lexical preservation. A benchmark that independently varies metadata, links or evolution would support correspondingly bounded component attribution. Truth-acceptance conclusions would require an operative evidence-consuming acceptance route, not merely stronger formatting checks.
