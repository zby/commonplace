# Agent Skills for Context Engineering synthesis

## Bounded synthesis

### From packaged guidance to a host invocation

Agent Skills for Context Engineering is an instruction corpus with a research maintenance plane and shipped context-management examples, not one enclosing agent runtime. This analysis covers its Git artifact at commit `9ff0c99108b36d3b886defd825d8ac1f47dba374`, with cutoff 2026-10-19. SRC-1 supplies implementation and doctrine/design evidence. The boundary is **complete artifact, partial loop**: material shipped paths remain unassessed, and external hosts, providers and private deployment state are not frozen. No target program or provider was executed during the analysis. Repository-contained optimizer samples were inspected by report verification, but their complete generating run was not established. See the [boundary and evidence](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register) and [report verification](report-verification.md#verification).

The ordinary consumption path installs a skill directory or plugin. Manifests expose the skill directories; an external host selects and loads relevant content. The stated policy loads names and descriptions first, then the activated body. Packaging is inspectable, but the manifest does not implement that loader. Once supplied, a skill body gives natural-language behavioral guidance rather than a symbolic permission gate. Neither loading compliance nor improved task performance is established. [RT-RTE-skill-delivery](runtime.md#rt-rte-skill-delivery), [RT-OBJ-skill-body](runtime.md#rt-obj-skill-body), [RT-BAP-skill-instruction](runtime.md#rt-bap-skill-instruction).

### From queued research to reviewable changes

The representative maintenance workflow turns external research into a reviewable skill change. A repeated Python step selects queued or active work under configured budgets, initializes run files, later fetches source bytes, and then parks the run. Its persistent queues and run state choose subsequent work; the scheduler does not itself perform source evaluation. The handoff supplies source pointers, captured evidence where fetched, an evaluation draft, proposal scaffold and recorded state. Fetch/state failures are parked or quarantined and logged. Substantive judgment and drafting remain the responsibility of an external human or agent. [RT-RTE-research-step](runtime.md#rt-rte-research-step), [workflow account](workflow.md#workflow-account).

The prescribed evaluator applies source-suitability gates, records evidence and scores, rejects failed gates, and prepares mechanism and skill proposals. These criteria concern suitability for the research pipeline, not the truth of every imported assertion. The reports disagree whether this external review route is `claimed` or `afforded`; they agree that no implemented semantic judge or observed review was established. Deterministic validation separately checks recorded rubric arithmetic and run-file readiness. Correct arithmetic cannot establish honest scoring or sound evidence. [WF-RTE-source-triage](workflow.md#wf-rte-source-triage), [EPI-RTE-source-review](epistemic.md#epi-rte-source-review), [EPI-RTE-rubric-arithmetic](epistemic.md#epi-rte-rubric-arithmetic).

Novelty checking gives research memory a concrete software consumer. It compares selected proposal text with accepted/candidate mechanism entries and corpus documents using token overlap. Its report can influence active-run readiness, which requires a rationale for a non-pass result. This is lexical comparison, not semantic novelty acceptance. Promotion then projects mechanism fields and evidence IDs into a registry and retains reviewer/rationale events separately. Later novelty checking reads the registry, not rejected-ledger rationale. Retaining rejection reasons therefore does not establish rejection-aware avoidance of rediscovery. [EPI-RTE-novelty-check](epistemic.md#epi-rte-novelty-check), [EPI-RTE-run-readiness](epistemic.md#epi-rte-run-readiness), [MEM-OBJ-registry](memory.md#mem-obj-registry).

Promotion is a bounded default-path protocol, not an authenticated human approval invariant. A nonempty reviewer string is required; accepted/candidate admission normally consumes readiness. However, `--allow-unready` bypasses failed readiness, and a supported close-then-promote sequence invokes weaker closed-state checks. The inspected code establishes these routes, not their execution. Multiple appends are not transactional. CLI state labels also do not enforce the whole ordered research procedure: recording PR readiness need not run validation first. Registry admission neither edits published skill bodies nor installs them. The protocol's delivered result is reviewable repository changes with summary, test plan and risks; push/merge approval and interruption summaries are instructions, not credential isolation or demonstrated successor delivery. [RT-RTE-mechanism-promotion](runtime.md#rt-rte-mechanism-promotion), [RT-CLM-maintenance-guarantees](runtime.md#rt-clm-maintenance-guarantees), [workflow account](workflow.md#workflow-account).

### From retained context to later use

The shipped examples establish several different strengths of reuse. The digital-brain helper reloads ideas, bookmarks and posts, selects bounded subsets, and prints a draft scaffold. It neither generates a finished post nor persists the scaffold. Its evidence heading does not check source reliability, freshness or archive status. By contrast, file offload, plan reload, observation masking and context trimming are mostly caller-invoked capabilities: a path or returned compact reference does not prove that a later model reloads it, or remove text already present in the host window. [RT-RTE-idea-draft](runtime.md#rt-rte-idea-draft), [MEM-RTE-file-offload](memory.md#mem-rte-file-offload), [MEM-RTE-plan-reload](memory.md#mem-rte-plan-reload), [MEM-RTE-context-selection](memory.md#mem-rte-context-selection).

The vector/graph helper is illustrative rather than a demonstrated durable semantic memory service. It stores process-local state and ranks synthetic hash-seeded random vectors. Integrated query filtering differs from entity/graph access, its integrated time-filter argument is unused, and its consolidation method is empty. Those are local implementation findings, not corpus-wide absences. CAS materialization and public export provide separate byte-integrity/access and field-projection mechanisms; their production consumers and complete withdrawal enforcement remain unresolved. [MEM-RTE-memory-access](memory.md#mem-rte-memory-access), [MEM-OBJ-vector-store](memory.md#mem-obj-vector-store), [MEM-ABS-helper-consolidation](memory.md#mem-abs-helper-consolidation), [MEM-OBJ-artifact-body](memory.md#mem-obj-artifact-body), [MEM-OBJ-public-projection](memory.md#mem-obj-public-projection).

Working-context controls likewise have different owners. The router constructs description-only prompts at its caller boundary, without establishing every SDK-internal exclusion. The optimizer uses separate capture, analysis, rewrite and generation requests; selected formatted values cross those boundaries rather than a shared accumulated conversation. Other helpers trim, summarize or mask caller-supplied content with approximate budgets. They do not establish a universal hard token ceiling or installed compaction hook. Mirrored context edits, latent KV transfer and opaque compression remain described alternatives, not verified target-host operation. [RT-RTE-router-benchmark](runtime.md#rt-rte-router-benchmark), [RT-RTE-prompt-optimization](runtime.md#rt-rte-prompt-optimization), [MEM-RTE-context-selection](memory.md#mem-rte-context-selection), [MEM-CLM-context-protocols](memory.md#mem-clm-context-protocols).

### From traces to revised instructions

The strongest supported improvement-related contribution is a wired trace-to-instruction update. The optimizer captures activity, requests model diagnosis, rewrites the current system prompt and, on continuation, supplies selected text to the next capture. It can save durable prompt artifacts; a separate generation command later consumes final text and summary to produce a skill. This exceeds raw logging: activity feeds automatic behavior-shaping writes and a later consumer. Requested artifact consumption and automatic whole-prompt successor supply are distinct operations. The latter uses coarse continuation/selection bookkeeping, not passage-level relevance matching. This supports the memory comparison's trace-learning route, independently of demonstrated capacity gain. [RT-RTE-prompt-optimization](runtime.md#rt-rte-prompt-optimization), [MEM-OBJ-final-prompt](memory.md#mem-obj-final-prompt), [MEM-OBJ-generated-skill](memory.md#mem-obj-generated-skill), [profile verification](profile-verification.md#verification).

The unresolved question is whether those revisions improve later action. Capture's success flag can mean only that no tool calls remain; analyzer scores can include parser fallback numbers; tool results may be mocks. The loop can associate a trace's score with a subsequently generated prompt, so final reported improvement is not an independent test of that final prompt. Analyzer tool-result inputs are truncated, saved trace displays are more lossy, and separate artifact generation reconstructs no iterations. Retaining analysis beside a prompt does not establish that the successor receives its reasons. [EPI-RTE-trace-analysis](epistemic.md#epi-rte-trace-analysis), [MEM-OBJ-reasoning-trace](memory.md#mem-obj-reasoning-trace), [MEM-OBJ-final-prompt](memory.md#mem-obj-final-prompt), [MEM-OBJ-generated-skill](memory.md#mem-obj-generated-skill).

For this prompt-controlled optimizer boundary and within-run horizon, the runtime assesses theory-builder conditions independently: **1, localized theory content: uninspected; 2, decisions depending on its assertions: afforded, not observed; 3, claim-specific criticism and blame: uninspected; 4, iteration of qualifying criticism: uninspected.** Editable prompt/Markdown content is addressable, but that does not establish a qualifying theory-building episode. Committed samples contain candidate instructions and criticism reports; their presence must not be mistaken for either absence of such content or proof of its complete generating route. Criticism of a consumed theory improving future capacity remains unestablished. [RT-RTE-prompt-optimization](runtime.md#rt-rte-prompt-optimization), [report-verification limits](report-verification.md#limits).

Reflection is separately **afforded**: trace representations can feed changes to later prompt-controlled behavior, while fidelity and exercise remain unobserved. Reflective theory building and autonomous theory building remain **uninspected**; automated orchestration does not establish that computation performs every qualifying operation. Learning as improved future capacity remains **uninspected**. Evidence-responsive self-change has a wired successor instruction path, but subsequent operation causally depending on a particular revision is unobserved; exercised self-improvement is therefore unestablished, and successful improvement needs separate outcome evidence. These are independent findings, not a combined negative. [RT-RTE-prompt-optimization](runtime.md#rt-rte-prompt-optimization), [epistemic bounded conclusion](epistemic.md#bounded-conclusion).

### Scenario-relative assessment and change conditions

For preparing auditable, reviewable research changes, the inspected files connect acquisition, external judgment, lexical comparison, structural checks and retained proposals. They do not establish an autonomously completed publication loop. For routing among skill descriptions, the benchmark implements agreement with fixture primary labels, not skill-body effectiveness; its effectiveness runner has no execution stage. For trace-fed prompt adaptation, update and retention are wired, but independent task correctness and transfer remain unestablished. No ranking among products follows. [RT-RTE-research-step](runtime.md#rt-rte-research-step), [RT-RTE-router-benchmark](runtime.md#rt-rte-router-benchmark), [RT-ABS-effectiveness-executor](runtime.md#rt-abs-effectiveness-executor), [RT-RTE-prompt-optimization](runtime.md#rt-rte-prompt-optimization).

A provenance-linked research instance showing evidence review, rejection/acceptance, skill edits and actual handoff would change the workflow's operation assessment. Authenticated approval plus gates covering overrides and closed-state paths would change the promotion guarantee. Linked optimizer iterations showing the tested input prompt, specific diagnosis, chosen revision and causally dependent successor behavior would address exercised self-change; independent outcome comparisons would address capacity gain, with attribution bounded to what was varied. An implemented effectiveness executor and inspected result provenance would change the current body-effectiveness evidence gap. These are resolution conditions, not claims that the target already supplies them. No additional source files were read for this synthesis.
