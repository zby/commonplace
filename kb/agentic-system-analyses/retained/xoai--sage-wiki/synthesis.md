# Sage-wiki synthesis

## Bounded synthesis

### From sources to retained knowledge

Sage-wiki is a knowledge-state producer and consumer for humans and external agents. It retains documents and agent-supplied knowledge, compiles wiki articles and graph representations, and selects retained material for later searches and answers. Go code owns progression; models supply candidate content and some judgments, not the next action in an autonomous tool loop. This analysis covers the whole shipped knowledge-state loop at commit `d3ef3a1346405c82eac01b4d7c493c94c1c59169`, with an applicability cutoff of 2026-10-15. Its sole source, SRC-1, supplies inspected implementation and attributed design. No execution trace, target test or causal experiment establishes operation, accuracy or benefit. External providers, services and enclosing agents remain outside the frozen repository; included but uninspected alternatives remain uncertainties, not absences. See the [boundary](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The runtime has several entrances. CLI, embedded Go, MCP, REST and UI callers reach overlapping but nonidentical operations. Source capture can persist supplied bytes without a model. MCP capture instead asks a model to extract items and admits structurally valid results, falling back to raw text on extraction failure. Direct article/summary writes bypass compiler generation and answer-output trust. Caller identity does not establish human authorship or per-content approval. These differences prevent treating compilation as a universal knowledge-admission gate. See [RT-RTE-capture-source](runtime.md#rt-rte-capture-source), [RT-RTE-capture-knowledge](runtime.md#rt-rte-capture-knowledge) and [RT-RTE-write-article](runtime.md#rt-rte-write-article).

Standard tier-3 compilation is the representative multi-step workflow. Code diffs sources, claims queued work, summarizes successful inputs, extracts concepts, selects article inputs and prepares articles. Independent completions receive different selections rather than a shared conversation: concept extraction sees at most 1,000 bytes of each summary; article writing rereads selected source sections and an existing article. Preparations can run concurrently, while effects are applied sequentially. Hash-matching persisted summaries can be reused after interruption. The [workflow account](workflow.md#workflow-account) and [RT-RTE-compile-sources](runtime.md#rt-rte-compile-sources) establish these handoffs and their recovery limits.

Delivery means retained files, attempted derived indexes/graph updates, manifest finalization and returned counts/errors—not universal success. Article files are atomically written before later index and manifest effects, which do not form one transaction. Conditional post-publication scoring can trigger one fresh rewrite; a still-low article can remain published. A failed rewrite after deletion can leave the original file absent, and pass completion can coexist with individual errors. Resumability therefore does not guarantee rollback or automatic repair of each failed article. See the [workflow annotation](workflow.md#annotations), [EPI-RTE-quality-score](epistemic.md#epi-rte-quality-score) and [EPI-RTE-quality-rewrite](epistemic.md#epi-rte-quality-rewrite).

The retained representations have distinct jobs. Summaries support extraction and resume; articles supply prose and later updates; entries/chunks and dense vectors support retrieval; manifest and queue state preserve lineage and scheduling. Ontology definitions, typed relations and temporal state support traversal and graph answering. Alias decisions preserve applied identities and rejected pairs that constrain later resolution. Community summaries support a separate answer route. Prose, symbolic controls and numerical similarity representations must not be conflated with provider weights or a complete claim-by-claim justification. See [MEM-OBJ-summaries](memory.md#mem-obj-summaries), [MEM-OBJ-articles](memory.md#mem-obj-articles), [MEM-OBJ-entries](memory.md#mem-obj-entries), [MEM-OBJ-vectors](memory.md#mem-obj-vectors), [MEM-OBJ-manifest](memory.md#mem-obj-manifest), [RT-OBJ-compile-items](runtime.md#rt-obj-compile-items) and [MEM-RTE-resolve-aliases](memory.md#mem-rte-resolve-aliases).

### From retained state to answers and reuse

Requested search and explicit file reads can serve external agents without native answer generation. Truncated search displays can point to a full read. Within compilation, code also automatically supplies saved summaries, existing articles and relevant source sections to later completions. Thus request-led external retrieval coexists with automatic internal read-back; it does not establish unsolicited injection into a host agent's conversation. Generated host instructions prescribe search before work and capture afterward, but writing those instructions establishes only an affordance conditional on host loading and precedence. Internal prompt overrides have a separately wired completion-consumer path. See [RT-RTE-search-wiki](runtime.md#rt-rte-search-wiki), [MEM-OBJ-summaries](memory.md#mem-obj-summaries), [MEM-OBJ-articles](memory.md#mem-obj-articles), [RT-OBJ-prompts](runtime.md#rt-obj-prompts) and [RT-BAP-generated-skill](runtime.md#rt-bap-generated-skill).

Three native answer routes consume different evidence:

- **Document Q&A** retrieves identities, rereads permitted article prefixes, adds graph-related material, synthesizes an answer and attempts filing. Per-article truncation and approximate byte-based budgets govern context. Returned chunk IDs can include material omitted from final context; fallback-neighbor content can lack a returned source path. Metadata is therefore not a complete snapshot of what synthesis saw. See [RT-RTE-query-answer](runtime.md#rt-rte-query-answer) and its [memory annotation](memory.md#annotations).
- **Local graph Q&A** selects hybrid-search seeds and a bounded subgraph, optionally at a historical time, then requests an answer with edge citations. Code filters citation integers, not semantic support for the prose. Its inspected handler does not file the answer. See [MEM-RTE-graph-query](memory.md#mem-rte-graph-query).
- **Global Q&A** selects cached community summaries, maps the question over each, discards empty or model-declared irrelevant partials, then reduces the survivors. Citations identify community origins, not verified support for each final claim. Communities must be enabled; global mode rejects historical `as_of` requests and does not use document-answer filing. See [MEM-RTE-global-query](memory.md#mem-rte-global-query) and [MEM-OBJ-communities](memory.md#mem-obj-communities).

For native document Q&A, returning an answer and admitting it to future retrieval are different events. The strongest inspected evidence-consuming acceptance is conditional automatic promotion for future answer reuse. A model-derived passage-support score must reach its configured threshold; confirmation count must pass its threshold; chunk-set distance must exceed 0.3 or confirmations reach twice the count threshold. These are proxy criteria, not independent verification of source truth. Agreement can come from embeddings or a model; distinct chunk identities do not prove independent sources. Grounding loads currently recorded source files, skips unreadable paths and assigns a score of one when no claims are extracted. See [EPI-RTE-answer-agreement](epistemic.md#epi-rte-answer-agreement), [EPI-RTE-grounding-check](epistemic.md#epi-rte-grounding-check) and [EPI-RTE-verify-promote](epistemic.md#epi-rte-verify-promote).

Promotion can move/index an accepted answer for later reuse, but this is not universal quarantine. Unrestricted filing admits directly; explicit caller promotion has different grounds; non-output articles pass the shared output predicate; known-path file reads bypass it. Automatic hooks can write confirmed state before post-transaction promotion, unlike the explicit promotion function's final state write. Source changes and rejection can withdraw later retrieval eligibility, not retract already delivered answers or guarantee erasure. See [RT-RTE-admit-output](runtime.md#rt-rte-admit-output), [RT-CLM-review-order](runtime.md#rt-clm-review-order), [MEM-OBJ-pending-outputs](memory.md#mem-obj-pending-outputs) and [EPI-RTE-output-withdrawal](epistemic.md#epi-rte-output-withdrawal).

Other checks have narrower licenses. Source-count gating counts declared paths, not independent support. Triple admission checks quoted-span occurrence in a compiled summary, not relation entailment or original-source truth. Functional temporal supersession depends on configured predicates and model confidence; ambiguous and other conflicts can remain live. Consequently the design claims of graph-only grounding, quarantine until verification and contradiction-free default answers exceed what the inspected controls universally enforce. Direct ontology admission further bypasses compiler-specific graph gates, as the [report verification limit](report-verification.md#limits) records. See [EPI-RTE-source-count](epistemic.md#epi-rte-source-count), [EPI-RTE-span-check](epistemic.md#epi-rte-span-check), [EPI-RTE-edge-supersession](epistemic.md#epi-rte-edge-supersession), [EPI-CLM-graph-grounding](epistemic.md#epi-clm-graph-grounding), [EPI-CLM-output-quarantine](epistemic.md#epi-clm-output-quarantine) and [EPI-CLM-edge-contradictions](epistemic.md#epi-clm-edge-contradictions).

### Trace-fed change and assessment

The strongest supported trace-fed contribution is a wired session-to-ontology chain: scribing filters recorded user/assistant turns, automatically extracts durable definitions/relations, and later explicit ontology traversal can return them. Tool records and thinking are removed. This is a concrete retained update with a later consumer, not demonstrated improved capacity. Pathless entities need not enter article-based Q&A. Separately, the learning-entry table implements storage, deduplication, recall and pruning, but bounded caller searches and the unfilled article-template field do not establish native lesson-to-article delivery. See [RT-RTE-scribe-session](runtime.md#rt-rte-scribe-session), its [memory annotation](memory.md#annotations), [MEM-OBJ-entities](memory.md#mem-obj-entities) and [MEM-OBJ-learnings](memory.md#mem-obj-learnings).

Quality-triggered rewriting is also a supported local response to evaluation. It can replace content later consumed by the system, but supplies no content-directed criticism identifying a challenged theory and placing blame. The accepted records assess no actual formulated theory instance: condition 1 (localized theory), condition 2 (decisions depending on its content), condition 3 (content-directed criticism) and condition 4 (a next round shaped by that criticism) are not individually established. Opaque provider processing is not evidence that these are absent. Improved future capacity through criticism of a consumed theory, reflection, and autonomous theory building likewise remain unestablished independently; software-owned pipeline progression alone settles none of them. See [EPI-RTE-quality-rewrite](epistemic.md#epi-rte-quality-rewrite), [RT-CMP-llm-client](runtime.md#rt-cmp-llm-client) and the [epistemic bounded conclusion](epistemic.md#bounded-conclusion).

At this frozen boundary, the article-rewrite route supports at most a dispositional improvement-directed pathway: quality evidence can select an update, retained replacement prose can enter later synthesis, but no subsequent operation is shown to causally depend on that change. Exercised self-improvement and successful improvement are therefore not attributed. Pack installation and prompt changes offer separate means to alter future behavior, not proof of evidence-responsive improvement. See [EPI-RTE-quality-rewrite](epistemic.md#epi-rte-quality-rewrite) and [RT-RTE-apply-pack](runtime.md#rt-rte-apply-pack).

For a scenario requiring persistent multi-representation knowledge and later retrieval, the source establishes concrete production, maintenance and consumer routes. For one requiring certified factual knowledge, complete provenance, guaranteed recovery or demonstrated autonomous improvement, it does not establish the required guarantees. The shipped LOCOMO evaluator uses a separate answerer and reference-answer judge over retrieval; its existence is not a native-Q&A result or a causal comparison. Traces connecting retained updates to later decisions would strengthen activation findings; controlled comparisons would be needed for benefit attribution. Complete context/dependency capture, edge-aware cache invalidation, semantic support checks and audited alternate admissions would change particular provenance, freshness and warrant conclusions. See [EPI-RTE-benchmark-judge](epistemic.md#epi-rte-benchmark-judge), [MEM-OBJ-communities](memory.md#mem-obj-communities) and [RT-RTE-query-answer](runtime.md#rt-rte-query-answer).
