# Siftly synthesis

## Bounded synthesis

### Acquire content and start application-controlled work

Siftly is a self-hosted bookmark knowledge system, not an enclosing general-purpose agent runtime. It imports X bookmarks and likes, retains source content and generated annotations, and exposes them through browsing, search, a JSON CLI and exports. This account covers its shipped application, browser drivers, model adapters, SQLite state, maintenance and consumers at commit **b25daa45b858f4be096b5c368671c34db4407d8e**, with an applicability cutoff of **2026-10-18**. The sole source, SRC-1, supplies implementation and attributed design claims; no execution trace or causal experiment was supplied. Remote providers, external CLI internals and actual user databases are not frozen evidence. The whole-system boundary therefore supports a shipped-path account, not observed deployment success or dependency guarantees. See the [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The representative workflow starts when a user uploads JSON. The import endpoint parses records, skips existing tweet IDs and persists bookmarks and media. It returns counts and a job ID; it does not itself launch enrichment. The browser's next step starts or attaches to categorization when there is imported work. Its ordinary empty-body request selects the collection's unfinished bookmarks, not precisely the newest import's IDs. Direct file and bookmarklet imports can persist without starting that browser-owned continuation. Other ingress routes have their own triggering conditions. These distinctions matter when judging whether a successful import also produced searchable annotations ([RT-RTE-import-content](runtime.md#rt-rte-import-content); [workflow account](workflow.md#workflow-account)).

### Transform content and admit annotations

After the processing request, server code owns progression. It returns before the background task finishes, backfills entities, runs five bookmark workers and drains category batches of up to 25. Workers analyze untagged media, enrich missing semantic tags and queue bookmarks for categorization. SQLite effects persist, but progress, pending work and stop flags have process lifetime. This is asynchronous application orchestration, not a model selecting its own next application action or a durable executor reconstructing interrupted work ([RT-RTE-enrich-categorize](runtime.md#rt-rte-enrich-categorize), [RT-OBJ-categorization-state](runtime.md#rt-obj-categorization-state)).

Backend choice depends on the stage, not just the configured provider. Text processing prefers Codex on the OpenAI branch or available Claude on the other branch, then SDK fallback. A MiniMax configuration can consequently use Claude for text stages. Vision prefers an available SDK client; SDK failure does not itself activate CLI vision fallback. SDK vision receives fetched image bytes, whereas CLI vision receives a URL in text, with image access unresolved. Siftly controls the requests and parses returns, not external CLI tools, internal conversations or sandboxing ([RT-RTE-model-dispatch](runtime.md#rt-rte-model-dispatch)).

Retained content has several distinct meanings. Raw imported JSON is source material, not a Siftly execution log. Deterministic extraction normalizes selected fields; model vision and semantic enrichment supply descriptions, OCR, tags and associations. Membership links organize the collection. Empty markers and timestamps select future work. Natural-language content is interpreted by models or readers; IDs, slugs and markers have fixed code-level effects. JSON serialization does not make the content a symbolic reasoning system ([MEM-OBJ-raw-json](memory.md#mem-obj-raw-json), [MEM-OBJ-entities](memory.md#mem-obj-entities), [MEM-OBJ-image-tags](memory.md#mem-obj-image-tags), [MEM-OBJ-semantic-tags](memory.md#mem-obj-semantic-tags), [MEM-OBJ-bookmark-category](memory.md#mem-obj-bookmark-category)).

Ordinary annotation admission is automatic. JSON parsing checks syntax; category filtering checks allowed slugs; confidence clamping checks a numeric range. These checks do not verify image correspondence, topical correctness or calibrated confidence. Category writes resolve returned tweet IDs against existing database rows, not current-batch membership; the requested assignment count is not an enforced bound. The ordinary semantic writer takes the first nonempty result without matching its returned ID to the current bookmark, unlike the separate bulk helper's keyed lookup. These are source-supported limits, not observed model violations ([RT-RTE-enrich-categorize](runtime.md#rt-rte-enrich-categorize), [EPI-RTE-semantic-tags](epistemic.md#epi-rte-semantic-tags)).

Each model receives a selected projection, not the whole retained evidence. Text and metadata have field/count truncations rather than a demonstrated global token budget. Categorization's multi-image path can join JSON objects before one parse, falling back to a 300-character raw slice instead of structured summaries of all images. Separate semantic enrichment summarizes each image first. Keeping complete fields in SQLite therefore does not establish their complete delivery to a later model ([RT-RTE-model-dispatch](runtime.md#rt-rte-model-dispatch); [memory enrichment annotation](memory.md#on-rt-rte-enrich-categorize); [EPI-RTE-image-context](epistemic.md#epi-rte-image-context)).

### Reuse retained material and change guidance

The strongest supported adaptive contribution is durable, behavior-shaping organization: retained annotations guide later classification and retrieval, and admitted category descriptions enter subsequent categorization prompts. Suggested descriptions derive from sampled collection content; the UI affords selection before adoption. That is a real guidance-update path, but API admission does not prove human review, and stored descriptions omit the suggestion examples and confidence displayed during proposal. Direct caller-authored categories and empty-store default seeding are additional, incompletely assessed admission paths. Custom descriptions need not originate in model suggestions ([MEM-OBJ-category](memory.md#mem-obj-category), [RT-RTE-category-admission](runtime.md#rt-rte-category-admission), [RT-BAP-category-guidance](runtime.md#rt-bap-category-guidance), [EPI-OBJ-category-description](epistemic.md#epi-obj-category-description)).

Later search is a separate request, not an automatic continuation of import. AI search combines lexical candidates, category intent and a conditional recent-content fallback, then asks a model to judge relevance over bounded retained fields. Hydration rejects noncandidate IDs, but requested score, count and uniqueness constraints are not all enforced. The merged candidate set is not universally capped at 150. The direct CLI instead searches without model reranking and returns JSON; detail output includes retained enrichment. Browsing and graph routes expose thinner projections. Export writes selected content rather than a lossless backup; imageTags can affect exported categories or semantic tags upstream without being directly exported as a payload ([RT-RTE-search-content](runtime.md#rt-rte-search-content), [RT-RTE-cli-export](runtime.md#rt-rte-cli-export), [MEM-RTE-browse-memory](memory.md#mem-rte-browse-memory), [MEM-OBJ-export-copy](memory.md#mem-obj-export-copy)).

These query returns fulfill consumer requests. Separately, the application automatically supplies retained per-bookmark metadata and available category guidance to pipeline models, using identity matches and broad processing-state predicates. This is automatic context supply inside processing, not unsolicited injection into an external agent. Tags influence candidate eligibility and relevance; descriptions guide classification; slugs constrain allowed outputs. None grants imported content general tool-execution authority ([RT-RTE-enrich-categorize](runtime.md#rt-rte-enrich-categorize), [RT-BAP-category-guidance](runtime.md#rt-bap-category-guidance), [RT-BAP-enrichment-search](runtime.md#rt-bap-enrichment-search); [profile verification](profile-verification.md#verification)).

Reliance is stronger than demonstrated warrant. Categorization instructs the model to trust prior tags heavily; search describes them as highly reliable. No independent accuracy evidence establishes either premise. Imported assertions retain unknown source warrant, while actual generated semantic edges remain indeterminate without outputs and their input evidence. Narrow code-domain deductions and structural checks are supported, but retention and operational use do not establish evidence-consuming acceptance of factual truth ([RT-CLM-category-policy](runtime.md#rt-clm-category-policy), [EPI-CLM-tags-reliability](epistemic.md#epi-clm-tags-reliability), [EPI-RTE-entity-extraction](epistemic.md#epi-rte-entity-extraction); [epistemic bounded conclusion](epistemic.md#bounded-conclusion)).

### Recover, deliver and assess the supported contribution

Recovery is selective. Failed vision can persist `{}` and suppress ordinary retry. Force clears designated empty/failure markers, not every successful annotation. Semantic failure can leave tags null while successful categorization sets enrichedAt; a later ordinary invocation then skips that bookmark. Explicit IDs or force can reselect it. Stop is cooperative: in-flight work and final queue draining can still write, while the final FTS rebuild is skipped. Browser idle/done and attempted counts are delivery signals, not per-row success or correctness proofs ([MEM-OBJ-image-tags](memory.md#mem-obj-image-tags), [EPI-RTE-semantic-tags](epistemic.md#epi-rte-semantic-tags), [RT-RTE-enrich-categorize](runtime.md#rt-rte-enrich-categorize); [workflow delivery annotation](workflow.md#on-rt-rte-enrich-categorize)).

Search visibility and withdrawal have independent horizons. A stale nonempty FTS index need not trigger fallback. Five-minute cached hydrated responses can survive source mutation or clearing. Exported notes remain independent files; default export skips existing notes while rewriting indexes. Database deletion is therefore neither immediate universal withdrawal nor epistemic refutation ([MEM-OBJ-bookmark-fts](memory.md#mem-obj-bookmark-fts), [MEM-OBJ-search-cache](memory.md#mem-obj-search-cache), [MEM-RTE-clear-collection](memory.md#mem-rte-clear-collection), [MEM-OBJ-export-copy](memory.md#mem-obj-export-copy)).

For collection organization and request-directed retrieval, the implementation establishes acquisition, annotation, retained guidance and several concrete delivery paths. For verified factual knowledge or downstream agent performance, the supplied evidence establishes neither accuracy nor benefit. Retained guidance change does not by itself show that criticism of a consumed theory improved future capacity. The reports do not establish a theory-builder loop: category guidance is not demonstrated explanatory-theory criticism, and conditions 1–4 are not supplied as separately supported theory-route findings. Reflection, autonomous theory building and self-improvement also remain separately unestablished at this boundary; application-owned automatic progression is narrower than those properties. Trace learning is unresolved, not established absent. Provider parameter mutation remains uninspected, and configured model names do not pin exact weights ([RT-BAP-category-guidance](runtime.md#rt-bap-category-guidance), [RT-RTE-settings-change](runtime.md#rt-rte-settings-change), [RT-CMP-anthropic](runtime.md#rt-cmp-anthropic), [RT-CMP-openai](runtime.md#rt-cmp-openai), [RT-CMP-minimax](runtime.md#rt-cmp-minimax); [epistemic bounded conclusion](epistemic.md#bounded-conclusion); [profile verification](profile-verification.md#verification)).

Linked import-to-delivery traces would establish exercised progression. Ground-truth annotation and retrieval evaluations would change the accuracy assessment. To establish improvement from retained guidance, a comparison must vary that guidance while tracing its later consumer and holding relevant alternatives fixed; merely switching providers or observing a better answer would not isolate the guidance effect. A self-improvement claim would additionally need objective-bearing evidence shaping an organizational update and subsequent operation causally depending on it. Per-stage completion state, revision-aware cache/index maintenance or explicit withdrawal propagation would alter the corresponding recovery guarantees only if implemented and checked across the affected routes.
