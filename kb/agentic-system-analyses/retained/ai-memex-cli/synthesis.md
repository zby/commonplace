# ai-memex-cli synthesis

## Bounded synthesis

### From captured material to durable knowledge

ai-memex-cli is a Markdown knowledge system whose deterministic CLI supplies tools and delegates semantic maintenance to external coding agents. It aims to capture sources, integrate them into a cross-linked wiki and make accumulated knowledge available to later sessions. This account covers the shipped repository at commit `4adb274a33cbb9ff0f03a6aeeb9c8d2525a5ac3f`, with applicability cutoff 2026-10-15. SRC-1 supplies inspected implementation and separately attributed doctrine/design. The whole-system repository boundary includes commands, prompts, maintenance and later-consumer integrations, but not external agent inference, provider persistence or live services. No real vault, execution trace or causal comparison was supplied. Wiring therefore does not establish successful operation or benefit ([boundary](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)).

Capture has distinct admission paths. Direct fetch writes extracted web content with URL/date attribution; keyword capture can require an operator's source selection or admit all results automatically. Delegated capture asks an external agent to retrieve and write material. These operations acquire claims rather than verify them. Extraction can omit source context, and a repeated direct fetch can replace a same-named raw file. Thus the vault's description of raw sources as immutable is a maintenance policy, not a system-wide storage invariant ([RT-RTE-capture-source](runtime.md#rt-rte-capture-source), [EPI-RTE-fetch-render](epistemic.md#epi-rte-fetch-render), [MEM-OBJ-raw](memory.md#mem-obj-raw)).

Session capture also has two materially different meanings. The no-argument default mechanically converts recognized session messages to Markdown; it does not extract lessons. Structured conversion can preserve nonempty system text and some textual tool messages while discarding nested tool results and arguments. If nothing parses, it renders the entire input as user text. The retained document is neither a guaranteed complete transcript nor a verified redacted record. Delegated distillation instead requests decisions, practices and rationale, plus a brief learning note appended to the live vault schema. Those are requested model outputs, not supplied artifacts ([RT-RTE-session-distill](runtime.md#rt-rte-session-distill), [MEM-OBJ-session-markdown](memory.md#mem-obj-session-markdown), [EPI-RTE-session-render](epistemic.md#epi-rte-session-render)).

### Delegate, write, inspect and try again

The representative workflow is `memex ingest <target> --loop`, because one shipped controller actually joins delegation, inspection, another attempt and delivery. The caller supplies a target hint, vault and optional agent/cap. Each child receives freshly loaded schema and catalog, the target and any prior lint findings. It runs in the vault directory and discovers sources through its own tools. The external model selects semantic edits and admits them directly into live wiki files, with requested index/log updates. The CLI owns dispatch; it does not validate an approved edit set or enclose edits in a rollback transaction ([RT-RTE-ingest-write](runtime.md#rt-rte-ingest-write), [workflow account](workflow.md#request-and-delegation)).

This separates maintenance context from the foreground conversation: memex passes selected inputs rather than replaying the entire parent session. Filesystem effects and child output cross back. Temporary prompt cleanup is not evidence that the provider discards child history or that an enclosing host evicts context. Raw preservation and discussion before writing remain interpreted instructions, not a filesystem sandbox or enforced human veto. Starting a command is not approval of each resulting claim ([RT-OBJ-ingest-prompt](runtime.md#rt-obj-ingest-prompt), [runtime control cases](runtime.md#four-forcing-cases-and-control-strength)).

After ingestion, mechanical lint reloads the wiki and checks orphan pages, link-target membership and frontmatter. These checks produce meaningful but narrow structural findings. They do not check factual bodies, citation support or source reliability; provenance fields are not all required. Even linking a page from the root catalog need not satisfy the wiki-to-wiki orphan predicate ([EPI-RTE-mechanical-check](epistemic.md#epi-rte-mechanical-check), [MEM-OBJ-page-metadata](memory.md#mem-obj-page-metadata)).

Nonzero findings can become up to 200 repair priorities in the next child's prompt. Zero issues permits a clean stop and best-effort context refresh. The criterion accepts structural completion, not factual content. Ingestion failure can still be followed by clean lint on unchanged files; cap or stall leaves prior edits in place. The selected ingest loop defaults to three iterations, whereas watch defaults to unlimited, and force can bypass the repeat guard. No convergence, bounded spend or rollback follows from this feedback mechanism ([RT-RTE-watch-repair](runtime.md#rt-rte-watch-repair), [EPI-RTE-loop-disposition](epistemic.md#epi-rte-loop-disposition), [workflow recovery](workflow.md#failure-stalled-repair-and-recovery-ownership)).

Semantic criticism is not absent. A separate optional semantic-lint child is asked to inspect contradictions and other content defects, apply safe repairs and retain ambiguous findings for review. However, a findings page is ordinary retrievable wiki prose, not a quarantine or an implemented mandatory adjudication queue. No supplied finding establishes correct criticism, completed review or evidence-consuming factual acceptance. Repository-local instructions also afford a foreground scan and user review, so child delegation is not uniform across all shipped instruction variants ([RT-RTE-semantic-lint](runtime.md#rt-rte-semantic-lint), [MEM-OBJ-lint-results](memory.md#mem-obj-lint-results), [report-verification limit](report-verification.md#limits)).

### Make retained material available to later work

The retained store combines natural-language bodies and guidance with symbolic access fields. Page bodies supply context to interpreting agents; IDs, names, tags and descriptions feed fixed ranking or link predicates; schema instructions guide maintenance; registry entries route host-file refresh. These are different consumers and forces, not one blanket authority granted to everything stored in the wiki ([MEM-OBJ-wiki-body](memory.md#mem-obj-wiki-body), [MEM-OBJ-page-metadata](memory.md#mem-obj-page-metadata), [MEM-OBJ-wiki-schema](memory.md#mem-obj-wiki-schema), [profile verification](profile-verification.md#verification)).

Later use can pull search results and full pages, request injection through includes/keywords, or read a copied project subset. Search caps and filters can omit relevant material, and backend errors can appear as empty results. Injection accepts task/token options without using them to select or budget content. Keyword selection ranks metadata, not page bodies. These routes establish delivery mechanisms, not complete retrieval or accurate answering ([RT-RTE-context-delivery](runtime.md#rt-rte-context-delivery)).

Automatic supply also exists: management calls preselect schema/catalog for a child, and clean-loop refresh writes a bootstrap into registered host files. The latter contains consultation instructions and, in full mode, an ordered digest of up to five pages per scene with shortened descriptions, not full evidence. Bound scene names select manifest guidance but do not filter the full digest. Refresh is best effort, and a later external host must load and use the file. Bulk refresh can lose saved scene bindings, while registry entries lack per-vault identity. Forced local copies can leave old unselected files behind; neither refresh nor uninstall revokes material already loaded into a host ([RT-BAP-host-bootstrap](runtime.md#rt-bap-host-bootstrap), [MEM-OBJ-host-bootstrap](memory.md#mem-obj-host-bootstrap), [MEM-OBJ-context-registry](memory.md#mem-obj-context-registry), [MEM-OBJ-local-projection](memory.md#mem-obj-local-projection)).

For a source-integration scenario, this architecture supports durable external memory, structural repair feedback and selected later context. The README says contradictions have already been flagged, not adjudicated or resolved; this synthesis withdraws its earlier attribution of resolution to that claim. Failure to demonstrate semantic success does not establish that the README promises resolution. The separate README claim that synthesis reflects everything read remains unestablished by the supplied evidence. Synthetic page labels and citation requests do not identify whether an actual output reshapes, derives or adds a claim. Retention and operational use do not establish accepted new knowledge or integration following acceptance. Foreground answer saving is itself instruction-mediated: the installed query reference requires a save request, while vault doctrine asks the agent to file durable answers ([EPI-CLM-memory-compounds](epistemic.md#epi-clm-memory-compounds), [EPI-CLM-synthetic-pages](epistemic.md#epi-clm-synthetic-pages), [MEM-RTE-query-save](memory.md#mem-rte-query-save)).

### Adaptation without an improvement result

The strongest supported learning contribution is the wired session-to-durable-guidance pathway: delegated distillation requests a schema learning note, and later maintenance reloads that schema. A parallel summary-to-later-context path can preserve session-derived decisions for reuse. The verified memory classification recognizes these automatic trace-fed write/read routes without requiring observed benefit. The unresolved question is whether useful notes were written, retained their reasons, affected later decisions and improved capacity; no before/after comparison was performed ([RT-RTE-session-distill](runtime.md#rt-rte-session-distill), [RT-BAP-schema-prompt](runtime.md#rt-bap-schema-prompt), [MEM-OBJ-wiki-schema](memory.md#mem-obj-wiki-schema), [profile verification](profile-verification.md#verification)).

The independent theory-builder conditions are not established by the mechanical feedback account: **1**, no concrete formulated explanatory theory is identified; **2**, dependence of decisions on such a theory's content is not shown; **3**, localized defects and requested semantic scans do not demonstrate stated theory-directed criticism and changed reliance; **4**, forwarding defects demonstrates iteration, but not retention and reuse of the result of theory criticism. These are limits of this account, not claims that opaque model processing lacks those properties. Criticism of a consumed theory improving future capacity is separately unestablished ([RT-RTE-watch-repair](runtime.md#rt-rte-watch-repair), [epistemic conclusion](epistemic.md#bounded-conclusion)).

Reflection is likewise unestablished: session capture and schema adaptation provide relevant surfaces, but no supplied account closes both causal directions through a self-representation of the selected system aspects. Autonomy is narrower than success: software can dispatch watcher maintenance without per-edit human approval, while reliable semantic work and autonomy of every theory-building role remain unestablished. Neither uncertainty cancels the known dispatch mechanism ([RT-RTE-watch-repair](runtime.md#rt-rte-watch-repair), [RT-RTE-session-distill](runtime.md#rt-rte-session-distill)).

For self-improvement at this repository-plus-vault boundary across sessions, schema adaptation is a candidate route into the system's own behavior-guiding organization, not merely a wiki product change. Yet no supplied note or trace establishes objective-bearing evidence determining an actual update, actual organizational change, or subsequent operation causally depending on it. The reload channel alone supports neither exercised self-improvement nor successful improvement. Package update is instead explicit replacement from upstream, not an evaluated self-directed improvement loop ([RT-BAP-schema-prompt](runtime.md#rt-bap-schema-prompt), [RT-RTE-install-update](runtime.md#rt-rte-install-update)).

A source/output pair with provenance would sharpen transformation and rationale judgments. A linked trace from session evidence through schema edit to a later decision would establish operation beyond wiring. A controlled comparison of later work with and without that retained change would address benefit, with attribution limited to what was varied. Enforced approval, transactional recovery, implemented task/token selection or persistent vault-scoped context bindings would change the corresponding architectural assessment; none can be credited at this revision merely because a prompt requests related behavior.
