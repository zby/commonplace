# Agent-R synthesis

## Bounded synthesis

Agent-R's strongest supported contribution is an inspectable pipeline for collecting scored agent experience and constructing corrective training material. It is an offline builder/improvement plane, not a captured closed self-training service. This account covers the repository at commit `82fcc1ca7873b460949ed49022146dd988c32e31`, with an applicability cutoff of 2026-10-12. SRC-1 supplies implementation and README design evidence. No target execution, generated artifacts, checkpoint comparison or causal experiment was supplied. The boundary is **complete artifact, partial loop**: collection, revision construction and evaluation are shipped, while the advertised training configuration and checkpoint-promotion machinery are missing. These are source-level capacities and defects, not observations of successful operation. See [the boundary and Source register](boundary.md#source-register), [RT-CLM-iterative-training](runtime.md#rt-clm-iterative-training) and [RT-ABS-training-machinery](runtime.md#rt-abs-training-machinery).

### From a bounded task to retained experience

A caller configures a task server, task range, model directory and search budgets. WebShop and TextCraft selection excludes test indices and tasks outside the clean-training list; SciWorld uses server-provided indices. Local inference loads caller-selected weights from `MODEL_DIR`. A model-name label does not pin those weights or ensure that a later verifier uses the same checkpoint. The shipped drivers select local inference; the hosted API wrapper is an injectable alternative, not an automatically selected provider. Neither inspected wrapper updates parameters. See [RT-CMP-func-call-offline](runtime.md#rt-cmp-func-call-offline), [RT-RTE-tree-collection](runtime.md#rt-rte-tree-collection) and [RT-RTE-provider-alternate](runtime.md#rt-rte-provider-alternate).

The actor proposes text actions, software owns execution and search successors, and the external environment supplies observations, reward and completion. Search generates candidates serially. For each candidate it resets a shared client, replays earlier actions and executes the new action. This reconstructs a branch only if reset and transitions are repeatable and the client is used exclusively. It is not an isolated worker or a saved environment snapshot. Terminal rewards update ancestors; unvisited nonterminal children have priority, otherwise value/exploration rules and random ties select the next branch. Negative rewards become terminal zero-valued disasters. These signals prioritize sampled outcomes; they do not certify the actor's explanation or identify why an action succeeded. See [RT-RTE-tree-collection](runtime.md#rt-rte-tree-collection), [RT-BAP-model-action](runtime.md#rt-bap-model-action) and [EPI-RTE-reward-check](epistemic.md#epi-rte-reward-check).

SciWorld adds lexical action substitution before new steps, unlike WebShop/TextCraft and replay. Exact matching or positive token overlap can replace the proposal, but a zero-overlap fallback retains it. This is a compatibility heuristic, not an all-actions-valid guarantee. The retained actor response can consequently differ from the executed action. See [RT-RTE-sciworld-action](runtime.md#rt-rte-sciworld-action) and [MEM-OBJ-extended-node](memory.md#mem-obj-extended-node).

After search returns, collection saves a recursive JSON tree rather than a selected solution. Natural-language interaction content and symbolic score/branch metadata share a file but have different consumers. Reloading reconstructs children and message mappings, not parents, environment clients or a live FastChat conversation. It supports later dataset traversal, not established search resumption. An existing filename suppresses recollection without a freshness or provenance check. See [MEM-OBJ-extended-node](memory.md#mem-obj-extended-node) and [MEM-OBJ-node-statistics](memory.md#mem-obj-node-statistics).

Context shortening is deletion rather than retained semantic summarization. Search trims the actor-call copy and then restores full node history for storage. Ordinary evaluation saves its pruned conversation; the supplied-prefix helper keeps a separate full history. These paths do not establish unconditional context fit: fixed-position deletion can cease making progress, and token counts need not match provider serialization. See [the memory annotations](memory.md#annotations) and [the runtime guarantees](runtime.md#runtime-account).

### From retained paths to a synthetic correction example

The representative workflow is WebShop collection followed by a separately invoked revision builder. Both stages and their filesystem handoff are shipped; the caller owns inter-stage scheduling and recovery. The builder pulls trees from a requested directory, selects terminal childless paths and ranks them by average value. This is requested batch consumption of retained experience, not unsolicited memory injection into a later actor. See [the workflow account](workflow.md#workflow-account), [RT-RTE-revision-export](runtime.md#rt-rte-revision-export) and [the memory read-back account](memory.md#read-back).

The shipped export is materially defective. `ALPHA` and `BETA` remain environment strings but are compared with numeric values. Every nonempty CLI export path must pass a defective comparison; nonpositive roots or empty candidates can return earlier without delivering examples. Good-only mode and disabling critique do not repair the comparisons. Beneath this defect, pairing compares distinct paths without enforcing the README's same-parent condition. Thus neither successful nonempty export nor adjacent-branch recovery is established by the shipped route. See [RT-RTE-revision-export](runtime.md#rt-rte-revision-export) and [the report verification](report-verification.md#verification).

Conditional on reaching the critique helper, the verifier receives task description and low-path action/observation text, not the successful alternative or reward statistics. It is asked for reasons and a usefulness judgment. Software continues the low prefix when the extracted string contains `good` or `uncertain`; otherwise it includes the current node and stops. A hypothetical `not good` judgment also continues under this substring rule. The judgment therefore has operational authority over prefix length, not correctness-certifying authority or acceptance of a diagnosis as true. See [EPI-RTE-critique-check](epistemic.md#epi-rte-critique-check), [EPI-RTE-prefix-disposition](epistemic.md#epi-rte-prefix-disposition) and [RT-BAP-verifier-prefix](runtime.md#rt-bap-verifier-prefix).

Software then assembles a low prefix, a randomly selected stock error admission, `Action: wait`, a fabricated `ok.` acknowledgement and a high-path continuation. It does not replay that assembled sequence to check compatibility with the low branch's reached state. The correction rationale is not authored from the verifier's reasons; those reasons remain sidecar feedback. Copied observations retain their original branch attribution, while the inserted self-error claim is not entailed by them. A constructed example is therefore neither an observed recovery trajectory nor evidence of model self-recognition. Good-only mode omits the synthetic correction; paired no-critique mode uses the complete low path. See [EPI-RTE-conversation-splice](epistemic.md#epi-rte-conversation-splice), [MEM-OBJ-revise-log](memory.md#mem-obj-revise-log) and [MEM-OBJ-revise-feedback](memory.md#mem-obj-revise-feedback).

Loss flags express intended training eligibility, but no captured optimizer interprets them. An exposed, separately callable converter copies content into positional conversation fields while dropping roles, loss flags, feedback and an unmatched trailing message. It has no shipped driver or trainer caller. Metadata loss on this afforded branch cannot be attributed to every possible external training path; conversely, JSONL retention cannot establish that reasons or masks reach training. See [MEM-OBJ-loss-flags](memory.md#mem-obj-loss-flags) and [MEM-RTE-dataset-rewrite](memory.md#mem-rte-dataset-rewrite).

### What the improvement account establishes

Automatic transformation of linked state/action/outcome experience into durable training material is an implemented, conditional trace-fed artifact construction. This is a positive architectural contribution even though nonempty CLI export is blocked. Callable conversion is a separate afforded contribution; parameter training is only declared. These distinctions, checked in [profile verification](profile-verification.md#verification), do not establish improved capacity for future action. No evidence shows that criticism of a consumed theory produced such improvement. The inspected correction route judges actions and constructs examples, not a formulated method theory that is revised and later consumed. See [RT-RTE-revision-export](runtime.md#rt-rte-revision-export), [RT-CLM-iterative-training](runtime.md#rt-clm-iterative-training) and [the epistemic conclusion](epistemic.md#bounded-conclusion).

The theory-builder conditions remain separate: **1**, a localized formulated theory is not established for this correction route; **2**, theory-content-dependent consumption is not established by use of action histories; **3**, action usefulness judgments do not establish claim-directed criticism with placement of blame and changed reliance on a theory; **4**, retention of logs and feedback does not establish a next round shaped by theory criticism. These are bounded non-establishments, not absences inferred about inaccessible model processing or all auxiliary helpers. Reliable reflective operation is likewise not established by requested critique or stock admissions. Collection does independently implement computational action proposal and successor control after batch launch, but autonomous completion of training and checkpoint admission is not established. See [RT-RTE-revision-export](runtime.md#rt-rte-revision-export), [RT-CLM-iterative-training](runtime.md#rt-clm-iterative-training) and [the report-verification limit](report-verification.md#limits).

For the declared collection → export → retraining → later-actor horizon, the improvement objective is better task completion/reward. Scores and judgments shape candidate-example determination at source level, qualified by export defects. The remaining self-improvement links are unestablished: change to the system's own deployed organization, entry of that change into a live behavioral-authority path, and subsequent behavior causally depending on it. Agent-R therefore supports an improvement-directed design, not established exercised self-improvement or demonstrated successful improvement at this boundary. This conclusion is independent of the partial trace-fed construction contribution. See [RT-CLM-iterative-training](runtime.md#rt-clm-iterative-training).

The evaluator performs direct sequential rollout, not MCTS or verifier-assisted correction, and writes final reward/history without a shipped later checkpoint-admission consumer. Its referenced `test_id/` input directory is missing. Loading a caller-selected `MODEL_DIR` in a later process does not identify a derivative of this dataset. For the scenario of offline experience collection, source wiring supports the tree-to-builder handoff. For a delivered correction dataset, the numeric defect requires repair. For iterative actor improvement, training ingestion, mask semantics, checkpoint lineage/admission and later use require additional evidence. Replay-checked splices and calibrated critique would change the warrant for correction examples; a traced training/deployment loop would change the architectural assessment; controlled checkpoint comparisons would support benefit attribution only at the treatment level actually varied. See [RT-RTE-agent-evaluation](runtime.md#rt-rte-agent-evaluation), [MEM-OBJ-final-result](memory.md#mem-obj-final-result) and [RT-ABS-training-machinery](runtime.md#rt-abs-training-machinery).
