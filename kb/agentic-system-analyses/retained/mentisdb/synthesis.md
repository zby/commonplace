# MentisDB synthesis

## Bounded synthesis

### A memory service, not the task agent

MentisDB supplies durable memory admission, selective retrieval and a versioned skill registry. Its host agent still owns task execution, tool-call timing, context eviction and interpretation of returned material. This account covers the shipped Rust engine, daemon, CLI, service transports, dashboard, Python consumer, instructions and retrieval evaluators at commit `4c9b95041da68c5a26dece9f8776ff54b05b910c`, with an applicability cutoff of 2026-10-14. SRC-1 supplies inspected implementation and doctrine/design; no target execution, benchmark result or causal experiment was established. The whole-system functional boundary is not an exhaustive correctness audit. External hosts, dependencies, provider internals and deployed state are not frozen evidence. See the [boundary](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The ordinary progression is caller-authored text → structural admission → retained chain → later requested selection → host context. REST and MCP serve this progression; direct Rust callers, local stdio and dashboard paths have different enforcement envelopes. The embedded operating skill asks hosts to load prior state, search before writing and checkpoint before losing context. These are available instructions, not append prerequisites. [RT-RTE-memory-roundtrip](runtime.md#rt-rte-memory-roundtrip), [RT-RTE-access-control](runtime.md#rt-rte-access-control), [RT-BAP-core-skill](runtime.md#rt-bap-core-skill).

### Admission retains statements without certifying them

A thought separates natural-language content from a symbolic envelope containing identifiers, attribution, types, relations and hashes. The core validates references, constructs a hash-linked record and appends through storage before updating derived retrieval state. Hash verification on reopen checks representation integrity under the storage contract; it does not establish truth, authenticated authorship or protection against rewriting an entire chain. Canonical admission precedes fallible derived work, so an error can follow a retained write. Buffered flushing and alternate adapters do not establish unconditional power-loss durability. [RT-OBJ-thought](runtime.md#rt-obj-thought), [MEM-OBJ-thought-content](memory.md#mem-obj-thought-content), [RT-RTE-memory-roundtrip](runtime.md#rt-rte-memory-roundtrip).

Optional extraction asks an external OpenAI-compatible model for candidate statements. The parser checks JSON, recognized types and nonempty content, then trims text and normalizes metadata. It returns candidates without appending them. Caller review is declared, but no universal factual review gate or actual review episode is established. Without an input/output instance, the semantic relation between source and generated statement remains indeterminate: conservative prompting alone establishes neither faithful compression, checked derivation nor ampliative conjecture. Ordinary append similarly consumes no world evidence for the truth of supplied statements. [RT-RTE-memory-extraction](runtime.md#rt-rte-memory-extraction), [EPI-RTE-extraction-schema](epistemic.md#epi-rte-extraction-schema), [EPI-OBJ-extracted-thoughts](epistemic.md#epi-obj-extracted-thoughts), [RT-CLM-extraction-review](runtime.md#rt-clm-extraction-review).

### Maintenance changes availability and retrieval

Explicit `Corrects`, `Invalidates` and `Supersedes` relations suppress targeted thoughts in covered default readers while preserving their history. Optional token-set deduplication can create supersession automatically. That changes selection, not the epistemic status of either proposition: lexical similarity does not establish equivalent meaning or a truthful replacement. Audit and direct-access alternatives can expose old text. Markdown export/import, agent copying and merge can lose graph lineage and reintroduce old content under fresh identities. Whole-chain deletion also makes “permanent” history conditional on administrative retention. [MEM-RTE-correction-update](memory.md#mem-rte-correction-update), [MEM-RTE-markdown-exchange](memory.md#mem-rte-markdown-exchange), [MEM-RTE-agent-copy](memory.md#mem-rte-agent-copy), [RT-RTE-state-maintenance](runtime.md#rt-rte-state-maintenance), [MEM-RTE-chain-withdrawal](memory.md#mem-rte-chain-withdrawal).

The strongest supported trace-fed contribution is automatic construction of durable retrieval machinery. Retained conversational messages can feed embedding generation and semantic-neighbor updates; later search consumes those numerical and symbolic derivatives to select content. This is a wired trace-fed behavior-shaping update, not merely raw-log storage. It supports a local trace-learning classification without establishing a semantic lesson, trained model weights or improved capacity for future action. Actual mixed input provenance, complete backend freshness and semantic-update alternatives remain unresolved. [MEM-OBJ-embedding-vector](memory.md#mem-obj-embedding-vector), [MEM-OBJ-retrieval-state](memory.md#mem-obj-retrieval-state), [MEM-RTE-derived-update](memory.md#mem-rte-derived-update), [MEM-RTE-retrieval-evaluation](memory.md#mem-rte-retrieval-evaluation), [profile verification](profile-verification.md#verification).

Inference weights are separate from these accumulated outputs. The local MiniLM adapter performs inference, with a hash-based fallback if initialization fails; its model label does not pin an exact weight digest. The extraction endpoint likewise does not freeze provider parameters. Neither adapter establishes weight training. [RT-CMP-fast-embed-provider](runtime.md#rt-cmp-fast-embed-provider), [RT-CMP-extraction-model](runtime.md#rt-cmp-extraction-model).

### Later context is selected, not restored wholesale

Recent-context returns a bounded chronological slice of valid thoughts; ranked search uses lexical, vector, graph and metadata signals and can traverse ancestors. Context bundles instead use lexical seeds and optional graph expansion to return original text with paths. A path explains connectivity, not evidential warrant. These are requested returns, not autonomous startup injection, and their limits are record/page/graph budgets rather than guaranteed model token budgets. Webhooks push new append events through a bounded, droppable queue; they do not establish historical memory read-back or an external consumer's later behavior. [RT-RTE-memory-roundtrip](runtime.md#rt-rte-memory-roundtrip), [MEM-RTE-bundle-read](memory.md#mem-rte-bundle-read), [MEM-RTE-webhook-delivery](memory.md#mem-rte-webhook-delivery).

The shipped Python adapter closes a producer-to-prompt path: it stores raw messages and later formats up to twenty type-filtered hits into `chat_history`. It does not target the current input, preserve original speaker class or use its configured session ID to isolate these writes and reads. Retrieval exceptions become empty history, and `clear` does nothing. Thus this path demonstrates prompt delivery wiring, not faithful transcript resurrection or reliable session partitioning. Memory-scope tags and branch names also do not establish identity isolation: enabled HTTP checks cover explicit request scope, while discovered ancestor traversal and local/direct paths have different boundaries. [RT-RTE-memory-roundtrip](runtime.md#rt-rte-memory-roundtrip), [RT-BAP-retained-context](runtime.md#rt-bap-retained-context), [MEM-CLM-scope-visibility](memory.md#mem-clm-scope-visibility), [RT-RTE-access-control](runtime.md#rt-rte-access-control).

Summary candidates only identify source windows. A caller must retrieve, author and separately append a summary or checkpoint. Stored `Summarizes` targets suppress already-covered windows without verifying summary adequacy or current validity of the summarizer. The report verifier also found a Compression-role convention using positional refs that become `References`, not that coverage relation. No complete comparison of compression bookkeeping follows. Limited reload and unchecked summaries afford continuity but do not support the advertised loss of no decisions. [MEM-RTE-summary-selection](memory.md#mem-rte-summary-selection), [MEM-OBJ-summary-candidate](memory.md#mem-obj-summary-candidate), [EPI-CLM-context-continuity](epistemic.md#epi-clm-context-continuity), [report verification limits](report-verification.md#limits).

### Handoff delivery stops before task success

The representative cookbook workflow records an unfinished flaky-auth investigation, retrieves a Handoff-role/concept-filtered hit and appends the next agent's accepting checkpoint with a backlink. It preserves done, pending and next action. However, one function uses the same open chain and already holds the handoff index; it does not demonstrate restart or an independently starting agent resolving the target from retrieval. Assertions check a hit and reference, not the proposed fixed-clock rerun or a repaired application. Invalid refs can block admission; recovery remains caller-owned, and post-write failures require care before retry. The core skill's Summary/Checkpoint convention is not automatically interchangeable with this Handoff-role selector. [WF-RTE-session-continuation](workflow.md#wf-rte-session-continuation).

For a scenario requiring retrievable state and explicit continuation markers, the implementation supplies meaningful coordination mechanisms. For one requiring lossless context recovery, verified diagnosis, automatic delegation or accepted application repair, the same evidence stops short. A persisted intention is delivered memory, not delivered task execution.

### Instruction evolution is not yet demonstrated improvement

Skill uploads retain immutable versions through full bodies and patches; requested reads reconstruct instructions, with latest meaning newest rather than evaluated best. Service signatures are conditional on active keys and do not cover direct registry/dashboard admission. Revocation returns a separate status alongside readable content; authored warnings do not necessarily carry the entry's retirement reason. Host nonexecution and behavioral rollback depend on the consumer honoring status. [RT-RTE-skill-admission](runtime.md#rt-rte-skill-admission), [MEM-OBJ-skill-body](memory.md#mem-obj-skill-body), [EPI-RTE-skill-withdrawal](epistemic.md#epi-rte-skill-withdrawal).

Together with numerical retrieval updates, this supports retained behavior-shaping state and available instruction evolution. The unresolved learning question is whether a retained criticism or update improves capacity for future action, not whether files can change. No such comparison was supplied. Theory-builder conditions remain separately unestablished for live uploaded theories: concrete localized theory content, decisions depending on that content, content-directed criticism and a next round shaped by its result are not demonstrated by version storage. Criticism of a consumed theory improving future capacity is likewise uninspected. Reflection's bidirectional self-representation and autonomy's role-by-role computational ownership are not established; automatic derivatives do not settle either property. These are independent uncertainties, not a combined negative verdict. [EPI-CLM-fleet-improvement](epistemic.md#epi-clm-fleet-improvement), [RT-RTE-skill-admission](runtime.md#rt-rte-skill-admission), [MEM-RTE-derived-update](memory.md#mem-rte-derived-update).

At the declared memory-system boundary, exercised self-improvement is unestablished over the claimed project horizon. There is no independently evaluated objective/update episode showing evidence caused update determination, the update changed MentisDB's own organization, that organization entered live later use, and subsequent operation causally depended on it. Host skill consumption and effects are outside captured execution evidence; release installation is operator-directed maintenance, not a memory-derived improvement. This does not deny the available evolution pathways or turn missing episodes into architectural absence. [EPI-CLM-fleet-improvement](epistemic.md#epi-clm-fleet-improvement), [RT-RTE-release-update](runtime.md#rt-rte-release-update).

Shipped evaluators compare retrieved text with dataset evidence using bidirectional substring matching. Partial or empty strings can satisfy that predicate; LoCoMo broadens evidence with neighboring turns, and ConvoMem abstention measures missing evidence matches rather than an answer model refusing to answer. Diagnostics do not establish generated-answer accuracy, causal benefit or an automatic diagnostic-to-successor update. [MEM-RTE-retrieval-evaluation](memory.md#mem-rte-retrieval-evaluation).

The assessment would change with linked restart/compaction traces testing retained decisions, concrete extraction and reviewed-admission pairs, live skill criticism/update/consumption episodes against an independently specified objective, and controlled subsequent-task comparisons. Enforcing summary adequacy, preserving graph exclusions across transfers or checking revoked status at actual execution would change particular guarantees only on the routes covered.
