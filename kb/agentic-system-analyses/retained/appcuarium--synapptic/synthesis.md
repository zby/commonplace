# Synapptic synthesis

## Bounded synthesis

### From coding sessions to reusable guidance

Synapptic implements a durable trace-to-guidance pathway: recorded coding conversations feed observations, weighted profiles and narrative instructions; retained profiles also shape later extraction. A separate benchmark can change which guards qualify for future synthesis. These are implemented contributions, not demonstrated improvements in future coding work. The analysis covers the shipped repository at commit `bcde026770daa5cd9a8ca18ca7182b0aeaa87d1f`, with an applicability cutoff of 2026-10-15. Its source, SRC-1, supplies inspected implementation and first-party doctrine, but no observed-run or causal-experiment evidence. No target code, tests or model calls were executed. The whole-system boundary includes the optional relay and operator browser; it excludes external assistants' instruction-loading behavior and model-service internals. See the [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The claimed work is learning preferences and assistant weaknesses from sessions, then supplying preventive rules to later sessions. Architecturally this is a memory and context-processing system, not the coding assistant's enclosing reasoning-and-tool runtime. Python selects work, sequences stages and writes files. Models propose observations and narrative wording. External assistants retain ownership of coding decisions, tools and instruction precedence. The representative source-supported workflow is operator `synapptic ingest`, with Claude Code publication as one concrete branch; it is a reconstructed implementation path, not a successful execution trace. See [RT-RTE-ingest-profile](runtime.md#rt-rte-ingest-profile), [RT-RTE-publish-archetypes](runtime.md#rt-rte-publish-archetypes) and the [workflow account](workflow.md#workflow-account).

Ingest discovers sessions not represented by observation filenames, optionally restricts the project, and processes them in descending file-size order. Filtering retains user and assistant text, prioritizes correction/preference/reaction turns and recent content, and omits tool-result bodies and thinking. This creates a separate extraction context rather than compacting the live assistant window. The character-based budget is approximate; template and profile overhead are added afterward. Omitted evidence remains in the original file if available, but the extractor receives no retrieval tool to reopen it. Internal model calls disable tools or omit tool definitions; this is a provider-contract restriction, not a sandbox for Synapptic's local file, subprocess or network effects. See [RT-RTE-ingest-profile](runtime.md#rt-rte-ingest-profile) and the [runtime guarantees account](runtime.md#runtime-account).

Existing profile text can enter extraction as already-established context. The ingest path activates this only when the global profile has dimensions; a project-only profile does not suffice. Selection uses weight at least 0.7 and the first eight entries per dimension after global-first combination, not task-semantic retrieval or a globally re-sorted top eight. Exclusions and model verdicts do not filter this summary. Models therefore receive selected retained claims without a new truth check. See [RT-RTE-ingest-profile](runtime.md#rt-rte-ingest-profile) and its [memory annotation](memory.md#annotations).

### Admission, retention and publication have different force

The observation parser rejects unusable JSON shapes, unknown dimensions and missing observation text. It does not require or verify supporting evidence, calibrate confidence, or independently adjudicate a failure diagnosis. A user correction establishes that a correction was uttered, not that its technical explanation is correct. The model's semantic transformation remains indeterminate without generated instances: the evidence does not distinguish faithful reshaping, entailed diagnosis and extrapolation in actual outputs. This is operational admission of candidates, not evidence-consuming acceptance for factual reliance. See [EPI-RTE-extract-candidates](epistemic.md#epi-rte-extract-candidates) and [EPI-RTE-observation-admission](epistemic.md#epi-rte-observation-admission).

Per-session JSON may retain a model-supplied evidence string. Newly constructed profile entries retain observation text, weights, counts and coarse session lineage, but omit that separate evidence field. Synthesis reads profiles rather than reopening those evidence files. Similarity matching reinforces entries and can replace wording with longer text; decay and pruning reduce availability; cross-project grouping can promote entries to global scope. These operations change future reliance without establishing semantic agreement, independent corroboration or contradiction resolution. Counts can increase twice from one session, and capped source lists are not a permanent once-only merge ledger. See [MEM-OBJ-observations](memory.md#mem-obj-observations), [MEM-OBJ-profile-observations](memory.md#mem-obj-profile-observations), [MEM-OBJ-profile-metadata](memory.md#mem-obj-profile-metadata) and [EPI-RTE-profile-curation](epistemic.md#epi-rte-profile-curation).

Synthesis selects guards and assistant-failure entries at weight 0.5; ordinary dimensions use weight 0.3 and evidence count one. Global exclusions apply, while model-specific redundant/backfire verdicts apply only when an explicit target model is supplied. The model is asked to produce a user archetype, imperative guards, reasons and known weaknesses. Nonempty prose is accepted without a grounding, heading or word-count gate. Requested failure-grounded reasons are therefore stronger than the storage chain guarantees. See [EPI-RTE-narrative-inputs](epistemic.md#epi-rte-narrative-inputs), [MEM-OBJ-archetype](memory.md#mem-obj-archetype) and [EPI-CLM-failure-grounding](epistemic.md#epi-clm-failure-grounding).

Integration reloads saved global/project narratives, combines them, and dispatches configured writers to discovered destinations. Claude Code receives `user_archetype.md` and a reference in an existing `MEMORY.md`; a missing index is not created. Other writers use always-apply rules, marked instruction sections or whole-file outputs. Local publication is wired. Later host loading and instruction influence are afforded, not observed or enforced by Synapptic. Integration computes model-filter counts but writes the saved narrative unchanged; explicit target-model synthesis is the path that actually filters its source entries. See [RT-BAP-archetype-host](runtime.md#rt-bap-archetype-host) and [RT-CLM-target-filtering](runtime.md#rt-clm-target-filtering).

Delivery also has stage-specific failure boundaries. Empty extraction results can create processed markers that ordinary ingest subsequently skips. Failed or empty synthesis can leave an older narrative available for integration. Integration's five-element update tuples conflict with ingest's three-name unpacking, so a nonempty update list can produce an exception after output writes. These are inspected conditional defects, not observed incidents. Per-file atomic replacement does not make the pipeline transactional. Global rollback, reset and uninstall do not jointly retract every saved narrative or published platform copy. See the [workflow terminal-state account](workflow.md#workflow-account) and [MEM-RTE-state-maintenance](memory.md#mem-rte-state-maintenance).

The installed SessionEnd hook is a different route: on selected exit reasons it detaches extraction, merge and synthesis, without integration or success chaining. A live PID can cause an event to be skipped without scheduled retry. Automatic internal maintenance is therefore supported, but automatic refreshed external guidance after every session is not. See [RT-RTE-session-hook](runtime.md#rt-rte-session-hook) and [EPI-CLM-background-learning](epistemic.md#epi-clm-background-learning).

### Feedback changes eligibility, not established warrant

The benchmark is consequential: models generate scenarios, respond under alternative profile conditions, and judge textual rule compliance; code derives categories and writes per-model verdicts before optional human confirmation of global exclusions. Later explicit-target synthesis can consume those verdicts. Re-inclusion removes global exclusion flags, not model verdicts. Detailed result reasons are retained separately rather than automatically consumed by synthesis. See [RT-RTE-benchmark-feedback](runtime.md#rt-rte-benchmark-feedback), [EPI-RTE-benchmark-disposition](epistemic.md#epi-rte-benchmark-disposition) and [MEM-OBJ-benchmark-results](memory.md#mem-obj-benchmark-results).

The comparison's scope matters. Per-guard mode heuristically removes a matching narrative block or adds a missing guard; default batch mode contrasts the whole archetype with no archetype. Batch per-rule labels cannot isolate individual guard effects. Judges see response snippets—2,000 characters per-guard and 300 in batch—not coding outcomes. Same-model judging, resumed condition histories, mode-dependent cache freshness, respondent instructions that disclaim following embedded profile instructions, and possible positional shifts after missing batch verdicts further restrict interpretation. Categories such as effective or backfire follow scoring conventions; they do not establish prevention or regression in real tasks. See [EPI-RTE-benchmark-judgment](epistemic.md#epi-rte-benchmark-judgment), [MEM-OBJ-benchmark-cases](memory.md#mem-obj-benchmark-cases), [MEM-OBJ-claude-session](memory.md#mem-obj-claude-session) and [EPI-CLM-individual-impact](epistemic.md#epi-clm-individual-impact).

The optional relay separately forwards external host requests and retains SQLite metrics, derived request displays, transcript indexes and session bookkeeping for operator read-back. It does not inherit internal inference's tool restriction. Browser search is requested retrieval over indexed titles/first-user snippets, not full-conversation semantic search or demonstrated automatic profile learning. Raw transport, stored display and reduced browser view are different representations. An OpenAI session-return mismatch prevents assuming provider-handler equivalence. See [RT-RTE-relay-forwarding](runtime.md#rt-rte-relay-forwarding), [MEM-OBJ-request-log](memory.md#mem-obj-request-log), [MEM-OBJ-session-index](memory.md#mem-obj-session-index) and [MEM-RTE-browser-readback](memory.md#mem-rte-browser-readback).

### Independent capacity assessments and what would change them

For repeated-session preference accumulation, the supported result is automatic durable trace-fed updating with later prompt consumers. For verified failure diagnosis, isolated guard efficacy or fewer recurrent coding failures, the present evidence is insufficient. Retention, heuristic eligibility and publication do not establish accepted ampliative knowledge or post-acceptance integration in the traced routes. This is not a whole-repository negative about every possible truth-apt transformation. See the [epistemic bounded conclusion](epistemic.md#bounded-conclusion).

The runtime separately assesses theory-builder conditions: **1, localized guidance: afforded; 2, decisions depending on that guidance: afforded; 3, content-directed criticism naming claim, result and blame: uninspected; 4, criticism shaping another round: afforded.** None is inferred from another. Editable profile entries and whole narratives provide localized guidance surfaces, but no supplied generated criticism closes the criticism/revision cycle. Benchmark scores changing reliance do not themselves supply that criticism. Consequently improved future capacity from criticism of a consumed theory is not established. See [RT-RTE-publish-archetypes](runtime.md#rt-rte-publish-archetypes).

Reflection has a representational return path across the host-plus-Synapptic boundary—host failures can inform guidance returned to the host—but representation-mediated behavioral change is unobserved. Automatic stage sequencing is wired; autonomous theory building is not established role by role, independently of whether the workflow needs human per-item approval. Self-improvement toward fewer recurrent coding failures across future host sessions remains dispositional at that wider boundary: trace-fed updates exist, but later live behavioral dependence and successful improvement are unestablished. Synapptic alone does not own the external host's behavior. These conclusions do not negate the wired trace-fed update mechanisms. See [RT-RTE-publish-archetypes](runtime.md#rt-rte-publish-archetypes) and [RT-RTE-benchmark-feedback](runtime.md#rt-rte-benchmark-feedback).

Retained transcript-to-observation-to-profile-to-narrative histories would permit fidelity and rationale assessment. Traces linking published versions to actual host context and later decisions would address activation. Matched coding-outcome comparisons with independently varied guards would address benefit and component attribution. Preserved claim/result/blame/revision artifacts consumed in another round would address theory criticism. Implementation changes that propagate target filtering into published text, bind narratives to profile versions and repair retry/delivery contracts would change the source-level assessment of those paths; they would still need separate execution and outcome evidence for reliability or improvement. The [report verification](report-verification.md#verification) supports the bounded implementation account; the [profile verification](profile-verification.md#verification) adds no publication limit.
