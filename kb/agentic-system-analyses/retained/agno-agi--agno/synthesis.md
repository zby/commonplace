# Agno synthesis

## Bounded synthesis

### From request to model and effect

Agno's Python SDK and AgentOS server form an enclosing runtime: they prepare model context, grant tools, issue model calls and coordinate execution. This account covers that subsystem at commit `00497422d4a386d93ab3b45c1a11faf42fcc932f`, with an applicability cutoff of 2026-10-13. It excludes terminal operations, infrastructure provisioning, the hosted UI and external provider implementations. SRC-1 supplies inspected implementation and declared intent, not execution traces or causal experiments. No target runs, tests or provider calls were performed. The mechanisms below are wired capacities; successful delivery, actual reliance and benefit remain unobserved. See [boundary and evidence](boundary.md#boundary-and-evidence) and the [Source register](boundary.md#source-register).

A caller configures an Agent's model, instructions, tools and context policies. Host code loads session state, resolves dependencies, runs input hooks and prepares messages. The model proposes text or calls from the granted tool set; host code resolves local Functions, executes their Python entrypoints and feeds results back into the model loop. Host stages then handle output conversion, post-hooks, background-task completion, optional summaries and separate session/run writes. The return is a RunOutput or streamed events, with completion, pause, cancellation or error status. Arbitrary tools, hooks and dependencies can act with host-process or service credentials: this loop is not a sandbox, and cleanup does not reverse earlier tool effects. [RT-RTE-agent-run](runtime.md#rt-rte-agent-run), [RT-BAP-function-dispatch](runtime.md#rt-bap-function-dispatch).

The shipped market-brief example grants financial tools and asks for a current brief. Its price wrapper acquires and formats a Yahoo provider field without independently checking its truth or timestamp. Instructions not to invent values are model guidance, not a factual oracle. Tool-backed generation is therefore supported as implementation; accurate financial conclusions are not established. [RT-CLM-market-brief](runtime.md#rt-clm-market-brief), [EPI-RTE-finance-import](epistemic.md#epi-rte-finance-import), [RT-BAP-agent-instructions](runtime.md#rt-bap-agent-instructions).

Admission controls have distinct boundaries. Marked local Functions pause before execution and accept confirmation or rejection on continuation; a program can provide that confirmation, so the protocol does not itself identify a human approver. Provider-native tools and direct callbacks are alternative effect paths. AgentOS HTTP admission depends on configured authentication and does not govern direct SDK calls. For queueable background requests, a committed ticket precedes acceptance and a worker re-enters execution under retained identities. Media, factory and remote cases can instead receive an in-process, nondurable 202. Leases and retries do not imply exactly-once external effects; retry safety requires tool/service contracts. [RT-RTE-tool-confirmation](runtime.md#rt-rte-tool-confirmation), [RT-RTE-queue-dispatch](runtime.md#rt-rte-queue-dispatch), [report verification](report-verification.md#verification).

### Handoffs, failure and delivery

Team delegation lets a model choose a configured member and task. The member receives selected input, optional history and a separate model context, while linked runs, media and shallow-copied state can cross back. This isolates messages, not all state or effects. A Workflow instead can fix executor order in host configuration. Its normal agent handoff uses the last output's deepest content rather than automatically forwarding the original question and every intermediate source. [RT-RTE-team-delegation](runtime.md#rt-rte-team-delegation), [RT-RTE-workflow-step](runtime.md#rt-rte-workflow-step).

The representative shipped workflow fixes Data Gathering → Analysis → Report Writing for an NVIDIA investment request. The gatherer has financial tools; the analyst receives gathering content; the writer receives analyst content and is asked for a short outlook and metrics table. The writer has no automatic raw-tool-evidence reload in this caller. Shared session state crosses stages, but workflow history is not enabled. Neither a reference answer nor a dedicated reviewer is configured, and the word limit and financial fidelity are prompt requests rather than measured acceptance criteria. [WF-RTE-sequential-delivery](workflow.md#wf-rte-sequential-delivery).

Delivery follows lifecycle policy, not an all-stages-success guarantee. After Step retries, the outer Workflow's default error policy can skip a failed stage and continue, passing failure text to the next agent. Completion can therefore coexist with failed steps. Configured fail or pause policies offer different recovery, but no rollback of completed effects is shown. The final content is the last step's output. The cookbook supplies no database; more generally, persistence can fail after return preparation or terminal-event emission. A WorkflowCompletedEvent also serves as a cancellation stream-end sentinel, so its name alone does not prove completed research or durable receipt. Nested synchronous workflows additionally can pause internally while the parent continues. [WF-RTE-sequential-delivery](workflow.md#wf-rte-sequential-delivery), [RT-RTE-workflow-step](runtime.md#rt-rte-workflow-step).

### Retain, select and reuse

Agno offers several independent retention horizons rather than one memory ledger. Sessions retain runs/state and optionally summaries. MemoryManager retains user facts across sessions. LearningMachine combines user profile, user memory, session context, learned knowledge, entity memory and decision logs. Knowledge holds imported sources or caller/model-authored content. These stores have different admission and later-selection rules. [MEM-OBJ-agent-session](memory.md#mem-obj-agent-session), [MEM-RTE-user-memory](memory.md#mem-rte-user-memory), [MEM-RTE-learning-context](memory.md#mem-rte-learning-context), [MEM-RTE-knowledge-context](memory.md#mem-rte-knowledge-context).

Host-triggered context supply selects personal/profile/session rows by identity, learned insights by the current query and namespace, entities through a bounded directory and relevant expansion, and decisions through recency/agent filters with a smaller display cap. Requested searches offer additional pull routes. These are not one relevance algorithm or a shared global token budget. The foreground model receives rendered text, not necessarily stored provenance or all reasons: ordinary personal-memory delivery shows memory content, while decision recall can show reasoning/outcomes and learned knowledge can show applicability context. System-message delivery gives interpretation a privileged channel, not a symbolic truth or freshness guarantee. [MEM-RTE-learning-context](memory.md#mem-rte-learning-context), [MEM-RTE-entity-memory](memory.md#mem-rte-entity-memory), [MEM-RTE-decision-memory](memory.md#mem-rte-decision-memory), [MEM-OBJ-learned-knowledge](memory.md#mem-obj-learned-knowledge), [MEM-BAP-retained-context](memory.md#mem-bap-retained-context).

Automatic extraction can change retained facts, profiles and continuity without per-content human approval. The background learning path snapshots messages concurrently with foreground generation; waiting for it at completion does not make its input a completed-outcome trace. Entity and decision stores instead have no-op automatic process methods and foreground capture tools. Direct API and AgentOS edits are additional admission doors whose generic caller identity leaves human control unresolved. PROPOSE asks the model to obtain approval, but the inspected learning writer checks no approval artifact. This is distinct from the local Function confirmation protocol. [MEM-RTE-profile-extraction](memory.md#mem-rte-profile-extraction), [MEM-RTE-memories-extraction](memory.md#mem-rte-memories-extraction), [MEM-RTE-memory-editing](memory.md#mem-rte-memory-editing), [MEM-RTE-learned-knowledge](memory.md#mem-rte-learned-knowledge).

Budget control also has several mechanisms. Compaction replaces a history prefix with summary/tail, leaving session history separately intact where retained. Its optional archive is a rendered transcript with clipped tool text and backend-dependent persistence, not universal lossless recovery. Offload preserves an output string outside the window and exposes a preview plus explicit capped range/search reads. A result ID does not dereference itself, and refused offload loses reload of omitted detail. Tool compression adds condensed wording alongside original content; its instruction to remove hedging and unresolved provider replay prevent a semantic-preservation guarantee. [RT-RTE-context-window](runtime.md#rt-rte-context-window), [MEM-OBJ-compaction-archive](memory.md#mem-obj-compaction-archive), [MEM-CLM-nonlossy-archive](memory.md#mem-clm-nonlossy-archive), [MEM-RTE-result-offload](memory.md#mem-rte-result-offload), [MEM-RTE-tool-compression](memory.md#mem-rte-tool-compression).

Withdrawal is equally local. Entity retirement suppresses ordinary live display while retaining searchable history; Curator prunes and string-deduplicates only compatible user profiles. Normalization collisions need not preserve meaning. Managed-page pruning requires complete error-free discovery, and failed generic deletion can preserve retry anchors. These are maintenance mechanisms, not general factual criticism, secure erasure or whole-corpus atomic replacement. [MEM-RTE-entity-memory](memory.md#mem-rte-entity-memory), [MEM-RTE-profile-curation](memory.md#mem-rte-profile-curation), [EPI-OBJ-profile-memories](epistemic.md#epi-obj-profile-memories), [MEM-RTE-page-knowledge](memory.md#mem-rte-page-knowledge), [MEM-RTE-knowledge-context](memory.md#mem-rte-knowledge-context), [report verification](report-verification.md#verification).

### Checks and changes to later operation

Optional output generation and parser rewriting can substitute the answer, but consume different inputs. Output generation uses modified run messages after the last entry is removed; the parser uses resulting content with schema-oriented guidance. Parser substitution follows output generation, and RunOutput may select parsed rather than text content. Neither stage independently owns finality, proves fidelity or guarantees later replay. [EPI-RTE-output-generation](epistemic.md#epi-rte-output-generation), [EPI-RTE-parser-rewriting](epistemic.md#epi-rte-parser-rewriting).

Evaluators supply scoped licenses. Criteria judges produce model judgments and optional failure callbacks; their post-hook does not automatically reject failed output. Accuracy evaluation assumes a supplied reference correct. Reliability evaluation checks recorded clean tool calls against expected names/arguments, with an explicit assertion gate, not external effect success. PII regex checks can mask or reject lexical matches. Check exceptions can mark an Agent run error while preserving generated content; rejection is not automatic revocation. [EPI-RTE-judge-check](epistemic.md#epi-rte-judge-check), [EPI-RTE-accuracy-check](epistemic.md#epi-rte-accuracy-check), [EPI-RTE-reliability-check](epistemic.md#epi-rte-reliability-check), [EPI-RTE-pii-input](epistemic.md#epi-rte-pii-input), [EPI-RTE-output-hooks](epistemic.md#epi-rte-output-hooks).

A consequential evaluator consumer does exist: scored rollout export admits conversational-SFT examples using score and text/trace eligibility. Default export rejects failed scores; disabling only_passed permits scored failures, while other eligibility checks remain. It emits files and provenance, not a trained model. Versioned component configuration is another later-behavior change route: PostgreSQL enforces published-row immutability and published current pointers, and reconstruction can change instructions/model/tool references. Explicit version loads, live Python objects and mutable callable/provider implementations limit that invariant. Neither route alone closes an evidence-fed improvement loop. [EPI-RTE-sft-selection](epistemic.md#epi-rte-sft-selection), [RT-RTE-config-admission](runtime.md#rt-rte-config-admission).

### Scenario-relative assessment and unresolved properties

The strongest learning-related contribution is implemented trace-fed durable context: conversational extraction and retained session/compaction summaries have later-consumer paths. This supports wired trace learning, not merely raw log storage. It does not establish improved capacity for future action, actual consumer dependence or causal benefit. No such comparison was performed. Similarly, reusable insights and decision reasons can inform later work, but the inspected routes do not establish accepted ampliative claims or post-acceptance integration. Unknown semantic relations remain unknown, not presumed conjecture or derivation. [MEM-RTE-context-extraction](memory.md#mem-rte-context-extraction), [MEM-RTE-session-summary](memory.md#mem-rte-session-summary), [RT-RTE-context-window](runtime.md#rt-rte-context-window), [EPI-RTE-learning-extraction](epistemic.md#epi-rte-learning-extraction), [EPI-RTE-learning-save](epistemic.md#epi-rte-learning-save), [profile verification](profile-verification.md#verification).

The runtime establishes no formulated-theory route to which theory-builder conditions 1–4 can be separately assigned as met. Condition 1's localized theory, condition 2's content-dependent consumption, condition 3's stated content-directed criticism and condition 4's retained criticism shaping iteration are each unestablished by this account; delivery, scores and persistence cannot substitute for them. This is not evidence of their absence in unassessed stores or caller hooks. Criticism of a consumed theory improving future-action capacity is likewise unestablished. Reflection and autonomous theory-building remain independently unestablished: model-controlled task/tool choice shows computational decision roles, not a complete self-representation loop or every internal theory-building operation. [RT-RTE-agent-run](runtime.md#rt-rte-agent-run), [RT-RTE-config-admission](runtime.md#rt-rte-config-admission), [EPI-RTE-learning-extraction](epistemic.md#epi-rte-learning-extraction), [epistemic bounded conclusion](epistemic.md#bounded-conclusion).

For self-improvement, retained guidance has a live delivery channel and configuration can change later organization. But the accepted records do not establish an independently specified improvement objective whose evidence determines an update, followed by operation causally depending on it. Export also stops short of training or installation. Thus neither exercised nor successful self-improvement is established at this SDK/AgentOS boundary; this does not negate the supported retention/update capacities or the platform's learning-loop enablement claim. [EPI-RTE-learning-recall](epistemic.md#epi-rte-learning-recall), [EPI-RTE-sft-selection](epistemic.md#epi-rte-sft-selection), [EPI-CLM-learning-loop](epistemic.md#epi-clm-learning-loop).

For the financial pipeline, the decisive issue is evidence surviving handoffs and failure policy, not the mere presence of multiple agents. For continuity, it is the particular retained part selected and consumed, not total storage volume. A trace connecting raw data through analyst and writer outputs with an independent answer check would alter the workflow assessment. A pinned retained update with objective-bearing evidence, later consumer dependence and a controlled outcome comparison would alter learning/self-improvement conclusions. Enforced approval artifacts, configured fail/review policies and a verified durable submission/storage path would change the corresponding admission and delivery guarantees, but none supplies factual warrant by itself.
