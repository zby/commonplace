# llm-context-base synthesis

## Bounded synthesis

### Prepare a file-capable assistant, not an internal runtime

llm-context-base is a personal knowledge-base template. It retains captures, project thinking, decisions, personal context and operating guidance in files, then instructs an external assistant to read, use and maintain them. This analysis covers the shipped substrate at Git commit **6d01cba8e2c22f9ca2519c70073a05cd54378a8c**, with cutoff **2026-10-14**. The whole-system boundary includes its prompts, templates, configuration, maintenance utility and integration recipes, not the external hosts that execute them. SRC-1 supplies predominantly doctrine/design evidence; the Python metadata converter supplies a narrow implementation layer. No observed target run or causal experiment is supplied ([boundary and evidence](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)).

The repository does not own inference, model selection, actual filesystem execution or permission enforcement. The foreground external assistant interprets natural-language protocols and owns sequencing; the host supplies tools and context handling. No exact model is selected, and provider parameter changes remain uninspected. Committed host permissions are configuration inputs, not a repository-enforced sandbox ([RT-CMP-ai-assistant](runtime.md#rt-cmp-ai-assistant), [RT-CLM-host-permissions](runtime.md#rt-clm-host-permissions)).

In an ordinary initialized personal instance, a discovered bootstrap directs the assistant to configuration, general instructions and personal context. Phase-dependent loading reduces proactive questions and omits some introductory material over time; task routing loads additional modules when needed. Framework mode instead bypasses personal initialization and prohibits personal retention. Claude setup questions have an additional startup exception. These are prescribed branches, not an observed state machine ([RT-RTE-session-start](runtime.md#rt-rte-session-start)).

### Capture, decide disposition and preserve only selected inputs

The representative workflow is capturing a process, choosing whether to file it, then asking about it in a later invocation. The shipped protocols explicitly connect those stages, but no trace demonstrates their completion. The same foreground assistant performs the work; the consequential handoffs are user task input, host file operations and user filing/structure decisions, not separate-agent delegation ([workflow account](workflow.md#workflow-account)).

Ordinary agent capture creates a dated inbox draft with summary, tags, update date and attribution, then asks whether to file it or leave it parked. A parked draft is a delivered capture, not a completed knowledge article. Filing selects a destination and template, updates relevant navigation/logs and applies type-specific completion criteria. The knowledge checklist includes accuracy, metadata, final placement, active status and related links. These criteria are instructions interpreted by the assistant, not an executable write barrier or an independent factual oracle ([RT-RTE-capture-file](runtime.md#rt-rte-capture-file), [EPI-RTE-completion-check](epistemic.md#epi-rte-completion-check), [EPI-RTE-completion-status](epistemic.md#epi-rte-completion-status), [EPI-RTE-completion-links](epistemic.md#epi-rte-completion-links)).

Filing approval selects disposition; it does not establish review of every sentence. Explicit destinations, append-only structural logs and immediate rule capture have different controls. Independent editor/clipper admission and the converter add further paths outside ordinary inbox review. Consequently, human-reviewable admission is a policy objective rather than universal quarantine ([RT-CLM-review-policy](runtime.md#rt-clm-review-policy)).

Working articles may replace fuller inputs. Original preservation is off by default; when enabled, the assistant judges which originals warrant retention. Preserved originals are immutable by policy, not filesystem enforcement. Attribution identifies origin without establishing truth or faithful extraction. Decision records are more explicit about reasons: they provide context, alternatives, rationale and later outcomes, but outcome measurement and entry timing are not instrumented by the template ([MEM-OBJ-sources](memory.md#mem-obj-sources), [MEM-OBJ-knowledge](memory.md#mem-obj-knowledge), [MEM-OBJ-decision](memory.md#mem-obj-decision)).

File storage and conditional Git persistence provide continuity. Ignored journal/private bodies and uncommitted changes do not automatically obtain version-history recovery. Partial filing recovery is unspecified; available Git revert is not a transaction or automatic rollback ([RT-RTE-capture-file](runtime.md#rt-rte-capture-file), [MEM-OBJ-knowledge](memory.md#mem-obj-knowledge)).

### Reload selected material for answers and decisions

A later question initiates a separate invocation. The assistant routes by question type to a directory, reads its index, scans summaries/tags and selects one to three relevant files. Files over 500 lines may be reduced to their first major section. Delivery is a cited synthesis with paths/update dates and applicable freshness warnings; a search miss calls for an explicit missing-document response and an offer to capture it. Saving an answer is a further write decision, not an automatic query effect ([RT-RTE-knowledge-query](runtime.md#rt-rte-knowledge-query), [workflow query annotation](workflow.md#on-rt-rte-knowledge-query)).

This mechanism limits loaded context through file selection rather than an inspected vector engine. Summaries are relevance proxies, not complete content. Unloaded files remain reachable on disk but are not live pointers in the model window: their text must be read again. Startup/task routing supplies learned context and current guidance without a separate retrieval request; ordinary question answering is requested retrieval. Decision conversations also trigger proactive selection of relevant completed outcomes and failure constraints. Those reports are evidence offered to deliberation, not expected-answer references or proof of a transferable causal mechanism ([MEM-OBJ-metadata](memory.md#mem-obj-metadata), [MEM-OBJ-decision](memory.md#mem-obj-decision), [memory query annotation](memory.md#on-rt-rte-knowledge-query)).

The strongest supported decision-learning contribution is this prescribed reuse of rationale and outcomes. Whether it improves future decision capacity remains uninspected at the template boundary. The public experience-learning claim exceeds demonstrated benefit, not the existence of its prescribed consumer path ([EPI-CLM-decision-learning](epistemic.md#epi-clm-decision-learning)).

Optional manual-compaction hooks supply a different context-control mechanism: a sentinel triggers reinitialization on the next prompt. This affords rereading durable files, not restoration of discarded turns or recovery of unsaved discoveries. Host summary contents and hook deployment remain opaque. Linked-code documentation separately affords wiki-context consultation by an assistant in another repository; actual deployment and full-window delivery are unobserved ([MEM-RTE-compact-reload](memory.md#mem-rte-compact-reload), [MEM-BAP-linked-context](memory.md#mem-bap-linked-context)). Other external-consumer recipes are incompletely inventoried, as the report verification explicitly records ([report-verification limits](report-verification.md#limits)).

### Retain conversational discoveries and revise operating guidance

The main adaptation contribution is a prescribed conversation-to-durable-text chain. Clear rules, preferences and usage observations are selected into configuration, personal context, instructions, templates or structure. Future sessions and tasks are instructed to consume the changed files. Static shipped guidance becomes retained behavioral memory when use revises it. This is textual adaptation, not established weight training; reasons and original turns need not accompany every retained rule ([MEM-RTE-pattern-capture](memory.md#mem-rte-pattern-capture), [MEM-OBJ-config](memory.md#mem-obj-config), [MEM-OBJ-context](memory.md#mem-obj-context), [RT-BAP-instruction-load](runtime.md#rt-bap-instruction-load)).

Admission depends on the branch. Clear established rules request immediate writes; ambiguous capture asks the user. New directories require approval. Instruction optimization separately requires approval before restructuring. It diagnoses large/repeated reads, proposes splitting, conditional loading or compaction, and retains approved text changes, a review date and log. Line counts and perceived slowness motivate review but do not demonstrate faster or more capable later action ([MEM-RTE-pattern-capture](memory.md#mem-rte-pattern-capture), [RT-RTE-context-review](runtime.md#rt-rte-context-review)).

The accepted trace-learning classification recognizes these automatic conversation-fed durable writes at the **claimed** layer. It does not assert observed activation or improved capacity. The profile verification preserves unresolved outcome, saved-synthesis and operation-summary chains rather than declaring them absent ([profile verification](profile-verification.md#verification)).

The theory and improvement properties remain independent, at the personal-instance operating-text boundary and intended horizon of later sessions:

- **Theory-builder condition 1 — localized content:** afforded. Whole written rules/guidance units are inspectable and revisable.
- **Condition 2 — consumption:** claimed. Later decisions are prescribed to apply retained guidance; actual dependence is unobserved.
- **Condition 3 — content-directed criticism:** uninspected. No supplied episode establishes a challenged explanatory claim, blame placement and resulting revision or changed reliance.
- **Condition 4 — iteration:** claimed. Retained edits and later correction/review support a prescribed next round, not observed criticism-fed iteration.
- **Criticism improving future-action capacity:** uninspected. Neither revision nor persistence establishes this learning result.
- **Reflection:** a representation-mediated feedback loop is prescribed for selected usage and instruction organization; exercised two-way causal dependence remains uninspected. Reflective theory-builder status is likewise uninspected.
- **Autonomy:** autonomous theory-builder status is uninspected; explicit human approval contributes to some internal selections. This does not negate automatic writes on other branches.
- **Self-improvement:** a claimed dispositional, improvement-directed path targets adaptation to user needs and lean useful context. Evidence-responsive determination, operative installation and subsequent causal dependence are not demonstrated by a run. Exercised and successful self-improvement remain uninspected.

These statuses come from the separately bounded pattern-capture and optimization accounts, not a system-wide grade ([MEM-RTE-pattern-capture](memory.md#mem-rte-pattern-capture), [RT-RTE-context-review](runtime.md#rt-rte-context-review)).

### Maintain structure without inferring factual acceptance

Lint requests structural/age checks and cleanup; archive/supersede retains reasons and usually reduces retrieval priority rather than universally blocking consumption. Completion names accuracy but supplies no demonstrated evidence-consuming acceptance of a newly produced ampliative claim. Query synthesis has no concrete input/output witness establishing reshaping, entailment or non-entailed conjecture. Blog review addresses presentation readiness; publication gives content operational exposure without adding factual warrant ([MEM-RTE-lint-maintenance](memory.md#mem-rte-lint-maintenance), [EPI-RTE-lint-check](epistemic.md#epi-rte-lint-check), [EPI-RTE-blog-review](epistemic.md#epi-rte-blog-review), [EPI-RTE-blog-publish](epistemic.md#epi-rte-blog-publish), [epistemic conclusion](epistemic.md#bounded-conclusion)).

The executable exception is bulk metadata conversion. Fixed code selects matching files and overwrites them without per-file approval, backup or transaction. Static analysis establishes possible pre-title loss and duplicate-key replacement; a converted label proves neither YAML validity nor semantic preservation ([RT-RTE-metadata-migrate](runtime.md#rt-rte-metadata-migrate), [EPI-RTE-metadata-transform](epistemic.md#epi-rte-metadata-transform)).

For the documented scenario of modest file-based capture, selective answering and personalized continuity, the template provides a coherent prescribed progression and editable durable state. For a scenario requiring universally reviewed admission, complete retrieval, factual acceptance, privacy enforcement or demonstrated improvement, these records do not establish the required guarantees. Aligned templates/metadata/link conventions would remove specific contract ambiguities. Authentic write-to-later-consumer traces would establish activation; evidence-consuming acceptance records would support bounded epistemic conclusions; comparable before/after tasks with controlled interventions would be needed to attribute improvement. Installed integration records would change deployment findings without by themselves proving benefit.
