**Delta freshness qualification.** Memory's first integration issue qualifies the combined cache account using [MEM-OBJ-cache-compressed](memory.md#mem-obj-cache-compressed): the inspected delta baseline compares compressed data without the exact-reference freshness test, SRC-1, `sqz_engine/src/cache_manager.rs`. The epistemic ledger's “Fresh reference/delta/recovery consumption” label must be read with those route-specific limits, not as evidence that every delta baseline passes reference freshness. The records do not explicitly assert opposing implementations, so this is a scope qualification rather than an established cross-report disagreement. A uniform freshness guarantee cannot be concluded; downstream reconstruction remains unobserved.

**Session acquisition and checkpoint alternatives.** Memory's second and third integration issues add information where runtime and epistemic leave acquisition open. [MEM-OBJ-session](memory.md#mem-obj-session) establishes that dashboard-only rows may fail typed loading; [MEM-RTE-session-continuity](memory.md#mem-rte-session-continuity) supplies the installed SessionStart compact command and latest-session selection without project scoping. The memory checkpoint record distinguishes the budgeted snapshot builder/store/load capability from CLI resume's direct projection of sessions.data. Its no-original checkpoint save also does not establish normal output indexing. No report may be connected into an automatic full-session acquisition → PreCompact snapshot save → checkpoint restoration loop on these findings.

The unresolved scope in the epistemic maintenance coverage is not a disagreement with memory's additional inspection.
