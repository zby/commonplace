# Hermes Agent synthesis

## Bounded synthesis

Hermes Agent is an enclosing runtime: shipped callers construct an agent, assemble model context, execute proposed tools, retain session state and return results. This account uses the repository at commit `0e427d788d253630d38a3a51cd76849e73cd6925`, with an applicability cutoff of 2026-10-14. SRC-1 supplies implementation and doctrine/design evidence, not execution traces or causal experiments. The complete repository was frozen, but inspection covers only part of its operational loop. External model and memory services, actual user state and deployed permissions are not established. See the [boundary](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register). This synthesis introduces no source reads.

### Admit a request and execute work

The selected ordinary invocation is the finite non-interactive `hermes -z` path. The caller resolves optional resumed history and its stored model route, configures the agent, invokes a conversation and prints the final response. The model proposes content and tool calls; program code owns phase order, retry and iteration budgets, dispatch and termination. The configured inference endpoint is not a frozen numerical checkpoint, and foreground, child, review and summary calls need not share weights. These findings are wired implementation, with operation uninspected ([RT-RTE-oneshot-turn](runtime.md#rt-rte-oneshot-turn), [RT-CMP-inference-model](runtime.md#rt-cmp-inference-model); SRC-1 `hermes_cli/oneshot.py`, `agent/conversation_loop.py`).

Generic tool rounds stage calls and test transcript persistence before execution. An explicit failed append stops dispatch. This fence requires an enabled working session store and passage through the generic tool round; a missing store or persistence-isolated agent does not trigger that failure branch. It establishes neither an atomic transcript/effect transaction nor exactly-once external effects. Result shaping can replace raw output with previews or pointers before the next model receives it ([RT-RTE-tool-dispatch](runtime.md#rt-rte-tool-dispatch); SRC-1 `agent/turn_tool_round.py`, `agent/session_persistence.py`, `agent/tool_executor.py`).

Consequential effects do not all pass through one human or durability gate. One-shot enables approval bypass. Terminal authorization depends on backend and policy, and isolated-backend fast paths retain deny checks while skipping other guards. Approved Python can perform direct file and subprocess operations; its RPC allowlist does not confine all script behavior. Opt-in Codex app-server mode delegates the turn before the generic loop, uses separate native approvals and projects transcript rows afterwards. Plugin loading separately admits executable handlers through configuration, compatibility and override controls; managed registration cleanup does not undo arbitrary import-time effects. None of these inspected controls establishes deployed OS isolation ([RT-RTE-command-approval](runtime.md#rt-rte-command-approval), [RT-RTE-code-execution](runtime.md#rt-rte-code-execution), [RT-RTE-codex-turn](runtime.md#rt-rte-codex-turn), [RT-RTE-plugin-admission](runtime.md#rt-rte-plugin-admission); SRC-1 `tools/approval.py`, `tools/code_execution_tool.py`, `agent/codex_runtime.py`, `hermes_cli/plugins_loader.py`).

### Delegate, check and deliver

The representative multi-step workflow is a one-shot request that conditionally delegates subtasks. Children receive selected goals/context, separate sessions, resolved tools and configuration-owned budgets. Construction skips context files and memory rather than automatically inheriting the parent window. A finite caller cannot use detached completion delivery, so a background request falls back to a synchronous join. Separate model contexts are not separate filesystems ([RT-RTE-child-delegation](runtime.md#rt-rte-child-delegation); SRC-1 `tools/delegate_tool.py`, `tools/delegate_tool_dispatch.py`).

An optional output schema checks extracted JSON and permits one correction turn. If `jsonschema` is unavailable, parsed JSON is accepted without schema validation. Invalid text can still return after correction, and a completed child status does not certify task success. Host-owned summary reduction happens after checking: oversized output becomes head/tail and, when storage succeeds, a pointer to the full answer. That reduction can invalidate JSON without recomputing the schema flag. The foreground model decides whether to read omissions, recover failures, test the product or finalize. Terminal delivery is printing its final text, not semantic acceptance of child work. This is a reconstructed conditional workflow, not a successful observed run ([WF-RTE-output-contract](workflow.md#wf-rte-output-contract), [WF-RTE-summary-return](workflow.md#wf-rte-summary-return); SRC-1 `tools/delegation_output_schema.py`, `tools/delegate_tool_child_run.py`, `tools/delegate_tool_results.py`).

### Retain experience and shape the next invocation

The strongest supported learning-related contribution is an automatic trace-fed write/read architecture. Completed conversation and tool traces can feed a detached review model, which proposes notes or skill changes through restricted tools. The fork has no real session database but shares the built-in store. Admitted updates have later prompt or skill-view consumers; pending proposals do not yet have that authority. Existing-skill review writes require fresh reads, while unattended destructive memory operations are staged. Configured extra tools can broaden review dispatch, and interruption does not roll back prior writes. This supports a wired pathway, not reliable lesson formation or improved capacity ([MEM-RTE-review-write](memory.md#mem-rte-review-write), [EPI-RTE-review-candidate](epistemic.md#epi-rte-review-candidate); SRC-1 `agent/background_review.py`, `tools/memory_tool.py`, `tools/skill_manager_guards.py`).

Built-in notes and user profiles are bounded text files delivered as whole enabled prompt snapshots. Ordinary mid-turn writes change live state without replacing the cached prefix. Admitted local compaction reloads memory and rebuilds the prompt, although seeded detached compression can retain earlier bytes. Thus adoption is neither universally immediate nor limited strictly to session start. Optional per-content approval can admit or reject selected pending payloads, but it is not a universal gate. Shipped learning-node edits/deletes bypass the memory tool's optional approval path; their full authorization and refresh remain untraced ([MEM-RTE-notes-cycle](memory.md#mem-rte-notes-cycle), [MEM-RTE-pending-review](memory.md#mem-rte-pending-review), [EPI-RTE-memory-gate](epistemic.md#epi-rte-memory-gate); SRC-1 `agent/system_prompt.py`, `tools/write_approval.py`, `agent/learning_mutations.py`).

Skill catalogs expose eligible descriptions; requested views load procedures and support files. Review read marks, ownership rules and optional scans constrain mutation, not procedure quality. Agent-created security scanning defaults off and scan exceptions permit writes; a rejecting covered scan restores the original target or removes a new one. Separate project-skill quarantine affects loading. Activity-driven curation lowers availability and archives packages, with guarded restore; age is not evidence of correctness ([MEM-RTE-skill-cycle](memory.md#mem-rte-skill-cycle), [EPI-RTE-skill-guard](epistemic.md#epi-rte-skill-guard), [MEM-RTE-skill-curation](memory.md#mem-rte-skill-curation); SRC-1 `tools/skill_manager_tool.py`, `tools/skills_guard.py`, `agent/curator.py`).

Local compaction automatically reduces selected history into a model-generated or deterministic continuation handoff. It preferentially prunes tool/media content and preserves bounded anchors/tails, not a lossless transcript. Depending on failure conditions it aborts or uses an explicitly incomplete fallback; required provider checkpoint capability/success can gate admission. Raw summarized rows can remain archived for requested session search. The narrow summary guard rejects invented user attribution when no real user turn exists; it does not validate all summary claims. Encrypted native checkpoints are separate opaque payloads, not readable summaries. Delegation isolates a window and returns selected results; compaction instead replaces part of a window with derived content. In both cases, durable sessions, files and external effects can outlive what remains visible ([MEM-RTE-local-compaction](memory.md#mem-rte-local-compaction), [MEM-RTE-session-recall](memory.md#mem-rte-session-recall), [MEM-OBJ-native-checkpoint](memory.md#mem-obj-native-checkpoint), [EPI-RTE-summary-check](epistemic.md#epi-rte-summary-check); SRC-1 `agent/context_compressor.py`, `hermes_state_messages.py`, `agent/native_compaction.py`).

Optional external recall supplies shaped prose under an authoritative-reference instruction. Exact duplicate removal and fence sanitization do not authenticate its claims; sanitization can remove content. RetainDB consumes cached results selected by earlier queued queries, whereas ByteRover queries at prefetch time. A current turn triggering delivery therefore does not establish current-query targeting for every block. Historical API sidecars can replay the delivered bytes. Remote derivation, warrant and matching algorithms remain opaque, and local deletion does not establish withdrawal of external copies ([MEM-RTE-provider-cycle](memory.md#mem-rte-provider-cycle), [EPI-RTE-recall-reshape](epistemic.md#epi-rte-recall-reshape), [EPI-RTE-recall-consume](epistemic.md#epi-rte-recall-consume); SRC-1 `agent/memory_manager.py`, `agent/turn_context.py`, `plugins/memory/retaindb/__init__.py`, `plugins/memory/byterover/__init__.py`).

### Evaluate completion without generalizing its warrant

Optional goal mode supplies consequential evaluation beyond ordinary open requests. Configured shell gates run first; failure can produce repair guidance. When gates pass, an auxiliary model judges bounded goal/contract and response evidence. The manager consumes results to continue, pause, park or stop, saving verdict/status for later boundaries. Exit-zero checks license only the command-status proposition. Completion acceptance is for stopping the current goal, not endorsing every output claim or retaining a verified procedure ([EPI-RTE-goal-check](epistemic.md#epi-rte-goal-check), [EPI-RTE-goal-disposition](epistemic.md#epi-rte-goal-disposition); SRC-1 `hermes_cli/goals.py`, `hermes_cli/cli_loops_mixin.py`, `gateway/run_goals.py`).

For a finite delegated task, Hermes therefore has joined execution and bounded structural correction, but leaves semantic recovery to the foreground. For continuing work, it has trace-derived handoffs, review retention and saved goal feedback that can shape later invocations. The independently checked memory classifications remain partial on all ten axes; provider ingress does not establish a qualifying remote trace-learning update or its source ([profile verification](profile-verification.md#verification)). These positive architectural contributions do not demonstrate the product's claimed improvement from experience ([RT-CLM-product-work](runtime.md#rt-clm-product-work)).

The theory-builder properties remain separate. Condition 1, localized formulated theory, is unestablished for unavailable actual skills or notes. Condition 2, decisions depending on what that theory says, is not established by delivery. Condition 3, stated content-directed criticism with blame and changed reliance/revision, is not established by review instructions or gate failures alone. Condition 4, retaining that criticism's result to shape a next round, is likewise unestablished; ordinary continuation does not supply it. No theory route is classified in the runtime baseline. Criticism of a consumed theory improving future capacity is unestablished independently of the wired trace-fed pathways. Reflection's two-way self-representation mechanism is not established by reviewing one's traces alone. Bounded automated scheduling and goal continuation are wired, but autonomous theory building is unestablished role by role. These are not system-wide absences ([EPI-RTE-review-candidate](epistemic.md#epi-rte-review-candidate), [epistemic conclusion](epistemic.md#bounded-conclusion), [runtime account](runtime.md#runtime-account)).

For the post-turn review pathway, the independently stated objective is more effective and correct reusable task procedures, not merely more stored text. There is a dispositional, improvement-directed self-change pathway: operation records feed review, admitted notes/skills change retained guidance, and later consumers are wired. Exercised self-improvement over later requests/sessions is unestablished because no subsequent operation is traced as causally depending on such a change. Successful improvement also lacks outcome comparison. This conclusion does not depend on resolving reflection, autonomy or theory-builder status. A retained before/after update linked to its trace and later action would change the exercised-path assessment; a suitable comparison independently varying the update would be needed to attribute improved capacity. A factual acceptance route consuming evidence against named criteria, or a verified post-reduction child-output check, would separately change the warrant currently available for retained claims or delivered child output.
