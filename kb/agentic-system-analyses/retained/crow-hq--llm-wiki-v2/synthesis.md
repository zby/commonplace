# LLM Wiki v2 synthesis

## Bounded synthesis

### From supplied material to a durable knowledge bundle

LLM Wiki v2 is a Python-controlled knowledge pipeline, not an enclosing agent that chooses arbitrary tools. It files documents or client-supplied memories into a folder tree of Markdown notes, then answers separately requested questions from selected retained material. This account covers the shipped library, CLI, HTTP/web application, MCP integration, maintenance and evaluation consumers at SRC-1 commit `e0a205afe60bd1913d083a3ed4cdab81e38e4c26`, with cutoff 2026-11-08. The whole-system boundary includes classic and CROW modes, not the external MCP client's agent loop or provider internals. Evidence is inspected implementation, shipped instructions and attributed benchmark reports. No target execution or causal experiment establishes successful operation here ([boundary](boundary.md#boundary-and-evidence), [Source register](boundary.md#source-register)).

The central division is between semantic proposals and code-owned progression. A caller supplies text and optional origin, title and fields. Preparation produces a candidate before reading the current tree. Locked filing rechecks origins, reloads state, routes the candidate, restricts merge candidates by conflicting fields, matches a note and decides whether to consolidate. Code then merges or creates, saves raw provenance and the note, and attempts related-link enrichment. Starting ingest does not approve each generated sentence: model/software decisions admit ordinary rewritten content without per-note human sign-off. Python checks types, names, tree membership and other structural preconditions, not every proposition's truth ([RT-RTE-source-filing](runtime.md#rt-rte-source-filing), [EPI-RTE-step-check](epistemic.md#epi-rte-step-check)).

Classic asks a generative model for semantic decisions. CROW replaces route, match, consolidation, relation and retrieval decisions with classifier calls while retaining classic writing. CROW retrieval can fall back to classic on empty selection or classifier ModelError; missing/refused credentials instead fail configuration. Batch preparation uses threads, followed by ordered locked filing. Planning can place items directly, and automatic splitting can change taxonomy. These are fixed alternate paths, not delegated autonomous workers ([runtime account](runtime.md#runtime-account), [RT-RTE-batch-sync](runtime.md#rt-rte-batch-sync)).

The persistence boundary matters to recovery. Cooperating thread/process locks and stale-file checks protect writes, with atomic replacement of individual files. They do not provide a transaction across raw copies, notes, indexes, archives, links and logs, or an atomic compare-and-swap against arbitrary editors. A relating ModelError after admission can leave the note successfully filed without related links. Other failures may leave partial effects; forgetting cached tree state is not rollback. The representative workflow therefore supports caller-owned retry and local fallbacks, not universal automatic recovery ([workflow account](workflow.md#workflow-account), [RT-RTE-source-filing](runtime.md#rt-rte-source-filing)).

### Retention preserves more than answering receives

The durable bundle separates extracted raw source text from rewritten note bodies and machine-consumed metadata. Folder descriptions, titles and summaries influence later placement and relevance. Hashes, fields, source references and predecessor paths control repeat-work suppression, merge/replacement eligibility and historical loading. Retained classifier responses in SQLite can substitute for new inference; benchmark replay separately retains writer and classifier responses under different keys. Neither cache is model-weight storage or evidence of current-provider behavior ([MEM-OBJ-raw](memory.md#mem-obj-raw), [MEM-OBJ-note-body](memory.md#mem-obj-note-body), [MEM-OBJ-note-metadata](memory.md#mem-obj-note-metadata), [MEM-OBJ-folder-index](memory.md#mem-obj-folder-index), [MEM-RTE-answer-reuse](memory.md#mem-rte-answer-reuse)).

Context is reconstructed for individual calls, not accumulated as a continuing conversation. Oversized sources are split into blocks; bounded part notes, rather than the original blocks, reach the combine call. Only the final note and raw source persist through this route. Missing-value detection at combination warns rather than vetoes. Raw retention therefore does not establish that omitted material survives into a later answer. Each call resembles an isolated input frame with a returned value, but stored paths are not automatically dereferenced: code must explicitly reload their content ([MEM-RTE-source-reduction](memory.md#mem-rte-source-reduction), [memory read-back](memory.md#read-back)).

A later question starts a fresh Researcher. Selection uses structure and summaries before chosen note displays reach the answer writer. That display contains title, summary and main body, not most frontmatter or See-also links. Optional historical loading follows predecessor paths; spreadsheet expansion can add rows and, as report verification found, numeric-column statistics. The statistics are derived context, not necessarily values copied from selected rows. No selection yields a fixed no-answer message. Otherwise the result includes text and citation metadata; it is not automatically saved as another note ([RT-RTE-question-answer](runtime.md#rt-rte-question-answer), [MEM-OBJ-note-body](memory.md#mem-obj-note-body), [report-verification limits](report-verification.md#limits)).

Question/recall and explicit MCP note reads are requested retrieval. Internal filing also automatically supplies retained structure and matched content to decision calls; split and sync operations supply retained control state. These internal deliveries do not establish proactive memory injection into an enclosing client. Nor are all direct reads the same: MCP returns the selected display, whereas HTTP `/note` exposes body and frontmatter. The display omission is channel-specific, not global unavailability ([MEM-RTE-note-read](memory.md#mem-rte-note-read), [MEM-BAP-retained-knowledge](memory.md#mem-bap-retained-knowledge), [profile verification](profile-verification.md#verification), [report-verification limits](report-verification.md#limits)).

### Consequential guards have local warrant

The system does more than store unchecked model output. Merge guards detect selected lexical value losses, request bounded retries and choose a retry when it loses fewer old values. Revision replacement checks generated-body untouchedness and source identity; classifier-equipped revision additionally filters selected old sentences against source passages. Failure of replacement eligibility falls back to merge. These checks can change what is filed, but value presence does not establish correct attribution, negation or factual completeness. Sentence agreement is relative to selected supplied source text, not external truth ([EPI-RTE-merge-guard](epistemic.md#epi-rte-merge-guard), [EPI-RTE-guard-choice](epistemic.md#epi-rte-guard-choice), [EPI-RTE-revision-check](epistemic.md#epi-rte-revision-check), [EPI-RTE-revision-admit](epistemic.md#epi-rte-revision-admit)).

At answer time, conflict classification over selected passages can add a request to report competing values and provenance. It neither adjudicates truth nor rejects the final answer, and runs before spreadsheet-row expansion. Parsed citation metadata is restricted to delivered note identities, but answer text is not rewritten or checked for entailment. The `where` fields filter is not authorization: historical expansion follows it, and direct reads are separate paths. Source-only answers and complete factual preservation remain prompt goals, not enforced guarantees ([EPI-RTE-conflict-check](epistemic.md#epi-rte-conflict-check), [EPI-RTE-conflict-hint](epistemic.md#epi-rte-conflict-hint), [RT-RTE-question-answer](runtime.md#rt-rte-question-answer), [RT-CLM-factual-preservation](runtime.md#rt-clm-factual-preservation), [EPI-CLM-source-answers](epistemic.md#epi-clm-source-answers)).

Maintenance also has distinct consequences. Marking a source removed leaves derived notes available; rebuild can refile that content without its removal mark. Purge instead deletes notes citing the origin, including mixed-source notes, then refiles surviving sources. This is reference-based withdrawal, not semantic erasure of every copied claim or retraction from external clients. Archive replacement retains a predecessor for conditional historical reads. Route audit can propose and, with apply requested, perform moves; health and lint return diagnostics rather than factual endorsement ([memory maintenance annotation](memory.md#annotations), [EPI-RTE-origin-purge](epistemic.md#epi-rte-origin-purge), [MEM-OBJ-archive](memory.md#mem-obj-archive), [EPI-RTE-route-audit](epistemic.md#epi-rte-route-audit), [EPI-RTE-audit-apply](epistemic.md#epi-rte-audit-apply)).

### Adaptation, method criticism and assessed use

A concrete retained-experience contribution is wired: split attempts enter a durable log, and later splitting reads folder-specific attempt counts to suppress another attempt at the same count multiple. This is a local automatic trace-fed behavior-shaping update from operational events. It does not demonstrate improved future competence. Client `remember` can retain decisions and reasons, but the server does not establish their original trace inputs or automatic client extraction. Cache/replay, sync and custom update alternatives remain incompletely classified; the split-history witness neither resolves them nor supports a system-wide learning negative ([MEM-OBJ-log](memory.md#mem-obj-log), [RT-RTE-batch-sync](runtime.md#rt-rte-batch-sync), [profile verification](profile-verification.md#verification)).

The separate method-level questions remain bounded. Localized method instructions exist, satisfying the formulation minimum of theory-builder condition 1. Their delivery and operational wiring are established, but condition 2's dependence on what a formulated theory says is not demonstrated by delivery alone. Content-directed criticism of the system's methods and retained iteration on that criticism—conditions 3 and 4—are unestablished in the traced defaults. The shipped multi-pass example does critique and rewrite a note relative to its source; it must not be erased by a system-wide claim that no critic/rewrite route exists. It does not establish revision of the system's own methods. Improvement of future capacity from criticism of a consumed theory, reflective self-representation with both causal directions, and role-complete autonomous theory building are not established by these records ([RT-OBJ-prompts](runtime.md#rt-obj-prompts), [RT-BAP-model-instructions](runtime.md#rt-bap-model-instructions), [epistemic bounded conclusion](epistemic.md#bounded-conclusion), [report-verification limits](report-verification.md#limits)).

Exercised self-improvement at this repository boundary is likewise unestablished: retained control changes can reach later decisions, but no supplied subsequent-operation trace closes causal dependence on an improvement-directed organizational change. The split-history path remains a positive architectural adaptation, not evidence of successful improvement. Prompt overrides, settings and custom Steps enable caller-directed changes, not a demonstrated autonomous method-revision cycle ([RT-RTE-runtime-configuration](runtime.md#rt-rte-runtime-configuration), [MEM-OBJ-log](memory.md#mem-obj-log), [epistemic bounded conclusion](epistemic.md#bounded-conclusion)).

For a scenario of filing documents and later answering questions, the source establishes the necessary durable handoff, selective context construction, local checks and partial-success handling. It does not establish lossless transformation or reliably grounded answers. For experience retention through MCP, storage and later requested delivery are supported, while client extraction, isolation and behavioral activation remain external or unobserved. Client-model relay lets requests leave the server and replies resume filing; instructions recommending restricted subagents do not enforce client tool isolation ([workflow account](workflow.md#workflow-account), [RT-RTE-client-relay](runtime.md#rt-rte-client-relay)).

Paired source/candidate/final-note/answer traces would permit bounded preservation and grounding judgments. Retained criticisms linked to method updates and their later consumers would change the method-learning assessment; subsequent causally dependent operation would be needed for exercised self-improvement. Controlled comparisons varying one mechanism would support finer attribution than the repository's reported bundled comparisons. The inspected retrieval evaluator checks selected-note identity without answering; lexical fact scores test string presence, not proposition truth. Reported benchmark tradeoffs therefore do not settle answer correctness, successful learning or individual component effects ([MEM-OBJ-evaluation-results](memory.md#mem-obj-evaluation-results), [EPI-RTE-fact-score](epistemic.md#epi-rte-fact-score), [EPI-CLM-benchmark-results](epistemic.md#epi-clm-benchmark-results)).
