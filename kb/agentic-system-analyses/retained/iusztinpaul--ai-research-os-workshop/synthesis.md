# AI Research OS Workshop synthesis

## Bounded synthesis

### A research-memory plugin, not an enclosing runtime

AI Research OS Workshop preserves topic research as a local Markdown wiki and canonical YAML catalog. This account covers its shipped plugin, prompts, connectors' usage instructions and Python helpers at **dc6660555266239cd36483cf51b5ab39febacf02**, with cutoff **2026-10-12**. It is a whole-system boundary for that plugin, not for Claude Code, Codex or the external source services. The registered repository supplies implementation and doctrine/design evidence. No supplied execution trace or causal experiment establishes successful operation, factual quality or benefit. Generated examples were not treated as execution verification. See the [boundary and evidence](boundary.md#boundary-and-evidence) and [Source register](boundary.md#source-register).

The host owns inference, agent dispatch, tools and the enclosing session. Natural-language skill instructions ask its orchestrator to select sources, delegate writing, join outputs and return results. Python helpers own narrower symbolic transformations. The plugin does not supply an inspected scheduler or deployment permission envelope. Model versions, parameter updates and endpoint substitution remain uninspected in the host and NotebookLM services. Static skill guidance, accumulated research context and executable effects are separate authority channels: [RT-BAP-skill-guidance](runtime.md#rt-bap-skill-guidance), [MEM-BAP-retained-knowledge](memory.md#mem-bap-retained-knowledge), [RT-BAP-helper-execution](runtime.md#rt-bap-helper-execution), [RT-CMP-host-model](runtime.md#rt-cmp-host-model) and [RT-CMP-notebooklm-model](runtime.md#rt-cmp-notebooklm-model).

### From request to retained research

The representative workflow adds explicit web URLs to an existing research directory without discovery. The user supplies topic and source identities; the orchestrator checks layout and prior catalog identities, shows a plan, and normally proceeds unless confirmation was requested. Missing canonical YAML blocks mutation while permitting a stricter read-only query fallback. These are interpreted policy gates, not intercepted tool permissions. The user authorizes the route, not every generated proposition. See [RT-RTE-append-ingest](runtime.md#rt-rte-append-ingest) and the [workflow account](workflow.md#workflow-account).

The orchestrator fetches and strips web text, with WebFetch fallback. A builder receives seed JSON and raw-only instructions, persists source content and returns compact metadata. One source writer per successful raw source writes a source page. The orchestrator joins their reports and delegates entity/concept pages when current-run mentions reach two distinct sources. Those writers aggregate assigned source pages rather than raw files. Overview and thesis writers then discover selected wiki content under a five-full-page budget. The driver finally augments pointers, builds YAML with prior-index carry-forward, regenerates navigation, logs the operation, cleans scratch JSON and reports counts, paths and skips. Lint is suggested afterward, not a mandatory final acceptance gate. Local fetch retries and skips permit partial progress; no multi-file rollback or complete semantic-worker retry protocol is established. See [RT-RTE-append-ingest](runtime.md#rt-rte-append-ingest), [RT-RTE-index-build](runtime.md#rt-rte-index-build) and [workflow annotations](workflow.md#annotations).

The layers preserve different material. Raw files contain imported or extracted sources, not necessarily original bytes. Manual highlights are a separate optional layer; some sources have highlights but no full text. Source pages compress individual sources, topic pages aggregate them, and `wiki/synthesis.md` is an argumentative thesis with assumptions, supporting moves, counter-evidence and revision conditions. Catalog strings supply summaries; identities, scores and URIs supply access and selection structure. Research files therefore combine interpreted prose with fixed symbolic fields; generated charts add executable data snapshots, while visual payloads remain separately qualified. See [MEM-OBJ-raw-documents](memory.md#mem-obj-raw-documents), [MEM-OBJ-key-highlights](memory.md#mem-obj-key-highlights), [MEM-OBJ-source-pages](memory.md#mem-obj-source-pages), [MEM-OBJ-wiki-pages](memory.md#mem-obj-wiki-pages), [MEM-OBJ-synthesis](memory.md#mem-obj-synthesis), [MEM-OBJ-index-summary](memory.md#mem-obj-index-summary) and [MEM-OBJ-index-metadata](memory.md#mem-obj-index-metadata).

Model writers select and admit claims without routine per-claim human approval. Optional discussion changes propagation after source pages already exist; it need not withdraw those sources. Deliberate human KEEP blocks request preservation in later eligible rewrites, but do not enforce a filesystem veto. Catalog persistence is wired code: seed scores become 1.0, supplied prior rows survive unless superseded, and navigation uses both YAML and the live wiki tree. These guarantees depend on the actual inputs. Omitting the prior index loses carry-forward; seed precedence is not complete deduplication; missing pointers are projected rather than validated. See [MEM-BAP-keep-preservation](memory.md#mem-bap-keep-preservation) and [RT-CLM-index-contract](runtime.md#rt-clm-index-contract).

Deep discovery is an alternate admission route, not unrestricted autonomous research. A user selects a bounded preset; researchers filter and cap hits from available Obsidian, Readwise and NotebookLM sources. Fixed dedup retains the longest summary per identity, while a gap analyzer uses metadata to propose successor queries. Neither relevance, summary richness nor seed priority measures truth. GitHub ingestion instead uses a reusable mutable clone and model-written architecture/module specifications, with one catalog seed per repository commit; curated specifications are not a complete retained code snapshot. See [RT-RTE-deep-discovery](runtime.md#rt-rte-deep-discovery) and [RT-RTE-github-ingest](runtime.md#rt-rte-github-ingest).

### Later consumption and criticism

A subsequent query selects catalog summaries and follows source-page, highlight, full-text or wiki pointers only as needed. This is requested progressive read-back, not a demonstrated activation trace. Within an ingest, assigning a matching prior page to a delegated writer is a distinct upstream push operation; summary writers and lint judges instead request their own selected inputs. No independent unsolicited-memory scheduler is established by those routes. Query bookmarks or answers citing at least two sources can trigger save-back, but its knowledge-document landing recipe conflicts with the authoritative question-page-only addition map. The missing-YAML fallback disables saves, logging and navigation writes. See [RT-RTE-query-answer](runtime.md#rt-rte-query-answer), [RT-CLM-query-safety](runtime.md#rt-clm-query-safety), [MEM-OBJ-question-pages](memory.md#mem-obj-question-pages) and [profile verification](profile-verification.md#verification).

Lint offers two different checks. Fixed programs derive structural findings about recognized body wikilinks, catalog pointers, link counts and target-file existence. They do not verify headings, ordinary Markdown citations or claim support. Model judges inspect bounded wiki content for contradictions, stale assertions and research gaps. Contradictions and questions append to rolling files; stale assertions are flags for user judgment, not automatic withdrawals. The summary writer can later read retained criticism, but changed reliance or correction is unobserved. See [EPI-RTE-lint-mechanical](epistemic.md#epi-rte-lint-mechanical), [RT-RTE-lint-maintenance](runtime.md#rt-rte-lint-maintenance), [MEM-OBJ-contradictions](memory.md#mem-obj-contradictions) and [MEM-OBJ-open-questions](memory.md#mem-obj-open-questions).

Source links and synthesis markers make intended attribution inspectable. They do not authenticate imported content or check summary fidelity. Thesis confidence uses source counts and agreement, not independently calibrated warrant. A comparison writer can refuse missing subjects or thin support, but routine integrated dispatch is unresolved. A two-source save trigger licenses recall, not correctness. No supplied run identifies a produced ampliative proposition, its premises and an evidence-consuming acceptance decision for a named use. Semantic relations of model outputs therefore remain indeterminate rather than being inferred from the word “synthesis.” Retention and operational consumption are not established lifecycle integration after acceptance. See [EPI-CLM-source-attribution](epistemic.md#epi-clm-source-attribution), [EPI-CLM-synthesis-confidence](epistemic.md#epi-clm-synthesis-confidence), [MEM-RTE-comparison-writing](memory.md#mem-rte-comparison-writing) and the [epistemic conclusion](epistemic.md#bounded-conclusion).

Distill selects research relative to a supplied writing corpus, not seed importance, and exports a compact appendix for a documented later writer role. Actual delivery is unobserved. Render delegates selected wiki pages to slides, brief, canvas or chart writers. Charts retain Python with embedded numerical constants and request host execution without separate program-content approval. Re-execution uses that snapshot, not fresh wiki data. A prompt/path-only noop gate can preserve an older render after source bodies change. Neither executable success nor reproducible pixels would certify the selected data. See [RT-RTE-distill-export](runtime.md#rt-rte-distill-export), [MEM-OBJ-research-appendix](memory.md#mem-obj-research-appendix), [RT-RTE-render-output](runtime.md#rt-rte-render-output) and [MEM-OBJ-chart-script](memory.md#mem-obj-chart-script).

### What this establishes for research across sessions

The strongest supported contribution is a designed chain from selected sources to retained, inspectable thesis and criticism, with later consumption affordances and wired catalog persistence. It gives subsequent work places to recover an argument and its objections rather than requiring a fresh source search. It does **not** establish improved capacity for future action: there is no retained criticism-to-revision-to-capacity comparison. Original conversations are outside the local research artifacts; operation summaries do not establish automatic trace-fed learning. The trace-learning and trace-source classifications remain not determinable, not system-wide negatives. See [RT-RTE-append-ingest](runtime.md#rt-rte-append-ingest), [RT-RTE-lint-maintenance](runtime.md#rt-rte-lint-maintenance), [MEM-OBJ-log](memory.md#mem-obj-log) and [profile verification](profile-verification.md#verification).

The runtime supports separate **afforded**, not observed, theory-builder conditions: (1) a localized whole thesis; (2) requested content-dependent consumption; (3) counter-evidence guidance requesting weakening or splitting; and (4) retained criticism eligible to shape another ingest. Condition 3 is not an observed challenged claim, placement of blame and resulting revision, and condition 4 is not exercised iteration. Headings make assumptions and argumentative moves inspectable and revisable, without a fine-grained semantic revision API. Criticism of consumed theory improving future capacity remains unestablished independently of these four affordances. See [RT-RTE-append-ingest](runtime.md#rt-rte-append-ingest) and [RT-RTE-lint-maintenance](runtime.md#rt-rte-lint-maintenance).

Reflection is also not established: these routes represent external research, not demonstrated bidirectional self-representation of the plugin's operations. Computational writing and selection coexist with optional human redirection and human stale-claim resolution; a complete exercised autonomous theory cycle is not established. Exercised self-improvement at the plugin boundary is separately unestablished: the records show research-product updates but do not establish an evidence-responsive change to its own organization followed by later operation causally depending on that change. This does not classify every retained output as necessarily external to organization, nor deny a dormant pathway; it withholds the stronger claim. See [RT-RTE-append-ingest](runtime.md#rt-rte-append-ingest), [RT-RTE-lint-maintenance](runtime.md#rt-rte-lint-maintenance) and the [epistemic conclusion](epistemic.md#bounded-conclusion).

For explicit-source research followed by a later question, the supported architecture is layered persistence and selective reuse, not an independently accepted knowledge pipeline. For accumulated cross-run synthesis, current-run propagation and bounded reads prevent a completeness guarantee. For an audit, structural predicates and advisory criticism must remain distinct. Assessment would change with inspectable handoff traces, paired source/output fidelity checks, criterion-based acceptance decisions, retained criticism and resulting changed reliance, and later capacity evidence. Corrected pointer schemas, catalog-before-summary ordering, failure filtering, consistent query permissions, isolated commit caches and content-sensitive render refresh would address specific source seams; their presence alone would still not demonstrate benefit.
