# Analyse memory and context

Give reconciliation a source-grounded account of the included memory mechanisms, their retained results, later consumers and unresolved integration questions.

Read this instruction first, then complete the invocation's Input reading
batches. Follow `worker-rules`, `collection`, `sources-contract`,
`records-contract` and `memory-contract`.

## Inputs and results

`boundary` fixes scope and evidence. `opening` is JSON metadata with the
prepared `command-path`. `runtime` is the provisional runtime account and
an order-only input: it must exist initially, but a runtime revision alone
will not schedule another memory attempt. Read the version supplied in this
invocation, not a reconstructed current-member path.

Write the complete memory report to `output`, and answers to `output-answers`
under the shared correction protocol. Write empty answers on a first attempt.
A retry may supply `previous-report` and `previous-answers`; use them as
read-only baselines and act on `refusal` when present. The epistemic analyst
works separately; do not read its whole report unless supplied.

## Analyse mechanisms and integration

Follow `memory-contract` for fields and exact sections. Cover every included
part along the record contract's coverage dimensions, not only a primary
store or the best-understood route. Choose the memory scope from runtime
routes and state inclusions and exclusions. Declare new records with `MEM-`;
annotate supplied `RT-` records rather than redeclaring their referents.

Treat runtime as a starting account, not an inspection limit. Check frozen
CLI dispatch, hooks, registered tools and exposed library or service
operations against its routes. Trace evaluation, cleanup, rejection and
withdrawal through retained results to later consumers. Challenge strong
source claims, misleading labels and partial ontology mappings. A thin
memory boundary warrants short sections with explicit limits.

Under Integration issues, record each overlap disposition, correction to a
supplied fact and unresolved question, with evidence, consequences and full
IDs. Side-channel messages do not substitute for this section. Retain
supported facts beside unresolved parts; do not erase positives to make
coverage uniform.

Describe source-native mechanisms. Do not assign controlled comparison
values, compare systems or recommend Commonplace adoption. Cite the supplied
runtime records, boundary sources, your own declarations and peer declarations
in refusal feedback. Read only frozen evidence; do not execute the target.
A needed scope change or missing required input requires `problem`.

## Check and return

Run the shared content check and repair findings. Put its actual result and
prevented conclusions under Limitations and checks. Code additionally checks
source identity, frozen-source integrity, record preservation and correction
answers. Do not claim acceptance from a content pass. Return one line naming
the files written.
