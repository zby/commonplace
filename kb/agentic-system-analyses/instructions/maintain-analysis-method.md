# Maintain the collection-owned analysis method

Keep analysis method edits executable and update every affected consumer.

## Consumption and authority

The method author loads this instruction before an applicable edit, together
with the owning collection and selected instruction/type-spec contract. The
collection contract supplies this mandatory route to method authors along with
the collection's purpose and artifact quality standards.

When changing analysis code, worker instructions, report contracts, or
publication design, apply these method-evolution priorities as design intent
(operator direction, 2026-10-05; they do not override adopted execution
contracts):

- Treat KB theories as potential workflow inputs to apply and test.
- Judge method changes by learning, comparison, and useful borrowing at
  reasonable total cost (producing, reviewing, and consuming analyses), not
  report counts, defect counts, or completion alone.
- Discover main constraints through use, keeping operator requirements,
  observed limits, and design hypotheses distinct (the current arrangement is
  not itself a requirement).
- Treat worker roles, correction ownership, report boundaries, review
  placement, and round budgets as means to test, not fixed architecture.

Analyst job packets do not load this instruction. This instruction grants no
mutation authority beyond the commissioned edit.

## Composition

Use executability and precision as the quality goal. State goal, authority,
inputs, result, acceptance and stop conditions. Keep the goal first and retain
reasons only when an edge case needs them. Put transferable explanations in notes.
Use imperative instruction titles and trigger descriptions. Plain procedures
use the instruction type; shared definition contracts may use the note type.

An instruction is complete for its declared consumption path. Inherit doctrine,
collection/type contracts and skills only when the runtime supplies them with
binding force. Carry exceptions explicitly. Give delegated packets purpose,
consequential choices, authority, inputs, owned output, coordination, acceptance
and return conditions beyond the verified baseline. Delegation grants no extra
authority; scheduling, integration and recovery remain with the parent.
Unstated consequential choices follow an inherited default, deliberately delegated
judgment from evidence, or return as a gap. Use clean context for a named benefit.

## Editing and verification

Name each consumer and its loading channel before changing a rule. Search this
collection and generic instructions for exact filenames, skill names and result
literals. Read direct callers, callees, conditional loads and argument/result
consumers. Update affected interfaces together or report the unresolved mismatch.
A changed inherited rule reopens the packets commissioned against that baseline.

Execution does not depend on incidental link following. Instruction links provide
context transfer, conditional deviations or maintainer context; keep chains
shallow and never add reciprocal links only to mirror an edge. Search local
method/types and generic instructions, notes, reference and tags as needed.
Workflow execution inputs enter through declared dependencies. Do not make
reviews, archives or workshops execution inputs.

For run evidence records and failed-run retention, follow the collection
contract. Keep audit files out of analyst, verifier and publication inputs.
The advisory meta-analyser consumes its own saved scan and attempt inventory;
its report never drives acceptance or correction.

State each rule once, in its owner ([ADR 117](../../reference/adr/117-plans-derive-their-structural-jobs-from-the-type.md)):
a member type owns its member's content, the
[record contract](./agentic-analysis-records.md) the shared record grammar
and evidence rules, the worker rules execution, and a mission what its job
establishes. Keep a second statement only when it adds an obligation, a
specialization or a delivery path the first lacks; an interface stated from
both sides, grammar beside its procedure, a prompt binding beside its
definition, and a template's headings are not duplicates. Before moving a
clause, confirm every consumer receives its new home; the instruction
composition tests check that each worker reading a type that defers to the
record contract receives it.

Edit canonical instructions. Inspect projection, promotion and stub generation
when names, skill metadata or promotion status change. Test the affected loading,
authority, validation and result paths. Commit method changes before a new run;
never rewrite the opening method commit of an existing run.

still gives workers what they need without following background links:

- [Addressable theory](../../theory/definitions/addressable-theory.md): individual inspection and revision are graded and boundary-relative.
