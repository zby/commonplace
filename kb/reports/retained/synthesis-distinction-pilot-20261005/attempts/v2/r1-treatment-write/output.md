## Description
Dynamic Cheatsheet builds prompts from curated text or prior examples and carries returned text through caller or benchmark state; source wiring is visible, but use and benefit are unobserved.

## Bounded synthesis

At the registered repository revision, evidence is source inspection of the complete shipped repository; no live provider run or independent experiment was supplied ([boundary](boundary.md)). Dynamic Cheatsheet is an inference-time prompt and memory workflow: it leaves model parameters untouched in the inspected code and passes natural-language text or prior input/output examples into later model calls. The configured model first generates an answer; cumulative modes then ask it to propose a replacement cheatsheet. The parser accepts text marked with `<cheatsheet>` and otherwise retains the old text. The prompt requests correctness assessment, but code does not check that assessment or gate the write on the benchmark target ([RT-RTE-cumulative-loop](runtime.md), [MEM-RTE-cumulative-write](memory.md), [RT-OBJ-cheatsheet](runtime.md)).

The benchmark carries returned text across questions and saves rows that can be loaded on continuation. Its answer evaluator compares the answer with task-specific targets only after curation, updates counters, and does not admit, revise, or roll back the text. Other modes rank prior input/output pairs by cosine similarity over fixed precomputed vectors, synthesize selected examples into prompt text, append all prior examples, or use retrieved examples directly. The parts are distinct: linguistic example history and numeric selector vectors ([RT-RTE-checkpoint-resume](runtime.md), [EPI-RTE-benchmark-answer-check](epistemic.md), [MEM-OBJ-example-history](memory.md), [MEM-OBJ-embedding-table](memory.md), [RT-RTE-retrieval-synthesis](runtime.md), [RT-RTE-cumulative-retrieval](runtime.md), [RT-RTE-direct-retrieval](runtime.md), [RT-RTE-full-history](runtime.md)).

These mechanisms establish delivery and retention paths, not that a model relies on the delivered content, that curated or prior answers are correct, or that either improves later answers. The README's performance and learning claims are not established by the inspected implementation or supplied run evidence; target scores do not feed curation. The evidence therefore supports prompt-guided memory and context selection, while learning, improved capacity, and causal performance gains remain undemonstrated ([EPI-CLM-performance-gains](epistemic.md), [EPI-CLM-zero-shot-learning](epistemic.md), [RT-RTE-cumulative-loop](runtime.md)).

The repository also exposes local Python execution when model output meets a trigger pattern, with a short timeout but no source-level sandbox or rollback; deployed host permissions are unknown. An optional provider code tool is attached in supported modes, but execution and isolation are external. The generic client separately exposes chat history and optional search, not configured as the benchmark's memory route ([RT-RTE-local-python](runtime.md), [RT-RTE-provider-code](runtime.md), [EPI-RTE-client-chat](epistemic.md), [EPI-RTE-client-search](epistemic.md)).
