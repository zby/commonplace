## Description

Dynamic Cheatsheet uses model prompts to curate or retrieve text and examples across inference calls, but code shows delivery and persistence, not validated memory or demonstrated improvement.

## Bounded synthesis

At the registered whole-repository boundary, this is an implementation-grounded account of Dynamic Cheatsheet’s shipped prompt-driven generator, curator, retrieval routes, benchmark driver, and persistence path; no live provider run is evidenced ([boundary record](boundary.md); [runtime.md](runtime.md)). In the cumulative route, the configured model answers a question, then receives the question, raw answer, and prior cheatsheet in a curator prompt. Tagged replacement text is extracted; without the opening tag, the old text is retained. The benchmark scores the answer only after curation and does not use that score to admit or undo the text ([RT-RTE-cumulative-loop](runtime.md); [MEM-RTE-cumulative-write](memory.md); [EPI-RTE-benchmark-answer-check](epistemic.md)).

The retained material is prompt-visible text and prior input/output pairs, not a repository-owned memory service. In benchmark mode, returned state and outputs are written to JSONL and can be restored on continuation; direct callers must pass state themselves. Other modes retrieve top-k prior pairs using cosine similarity over fixed precomputed vectors, combine such pairs with cumulative text, or append all prior pairs. The vectors select context, not correctness; direct retrieval stores a text field that its next call does not consume. These routes wire material into later prompts, while whether a model uses it is unobserved ([RT-OBJ-cheatsheet / RT-OBJ-run-checkpoint](runtime.md); [MEM-OBJ-example-history](memory.md); [MEM-OBJ-embedding-table](memory.md); [RT-RTE-retrieval-synthesis](runtime.md); [RT-RTE-direct-retrieval](runtime.md)).

The benchmark’s task-specific answer checks provide bounded post-answer comparisons to task targets, but only update counters; they do not govern curation, memory admission, or carry-forward. The curator is instructed to assess correctness, but its judgment has no independently supplied answer evidence or recorded rationale. The README’s performance and learning claims therefore exceed what these implementation routes establish ([EPI-RTE-benchmark-answer-check](epistemic.md); [EPI-CLM-performance-gains](epistemic.md); [EPI-CLM-zero-shot-learning](epistemic.md)).

The available prompts and instructions are natural-language guidance, but the records do not establish a formulated theory that is consumed, criticized against operational evidence, and iterated as a theory-building process; thus conditions 1–4 are not established as met. No evidence shows that criticism of a consumed theory improved future capacity. The system is not shown to be reflective: although it retains text about problem solving and prompts a model to assess answers, neither self-representation with both causal directions nor resulting behavioral effects are evidenced. It is not shown to be autonomous, since execution depends on caller-selected configuration and external provider services, and the records do not establish every internal role as computationally performed. Changes to cheatsheet text and reuse of examples alone do not establish a self-improving system or improved future capacity ([cumulative write](memory.md); [epistemic.md](epistemic.md); [EPI-RTE-client-search](epistemic.md)).
